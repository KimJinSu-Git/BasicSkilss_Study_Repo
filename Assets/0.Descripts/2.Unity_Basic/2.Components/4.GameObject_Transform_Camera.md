# [Componenets] 4. GameObject, Transform, Camera

## 1. 3대 핵심 컴포넌트 란?
유니티의 씬(Scene)은 결국 세 가지 질문으로 굴러갑니다.\
"무엇이 있는가?(`GameObject`)", "그것이 어디에 어떻게 놓여 있는가?(`Transform`)", "그중 무엇을 화면에 보여 줄 것인가?(`Camera`)".

> **'연극 무대'**
> * **`GameObject` (배우)** : 무대 위의 빈 배우입니다. 그 자체로는 아무 능력이 없고, 어떤 배역(컴포넌트)의 옷을 입히느냐에 따라 괴물도 되고 총알도 됩니다.
> * **`Transform` (동선 지시서)** : 배우가 밟고 설 위치, 바라볼 방향, 몸집의 크기를 지시합니다.
> * **`Camera` (관객의 눈)** : 무대 위에 아무리 많은 것이 있어도, 카메라 렌즈에 담기지 않으면 관객(유저)에게는 존재하지 않는 것과 같습니다.

**왜 필요한가?**\
유니티 씬에 놓인 모든 것은 예외 없이 `GameObject`이며, 모든 `GameObject`는 태어날 때부터 강제로 `Transform`을 하나씩 부여받습니다.\
즉, **"공간 좌표를 갖지 않는 오브젝트"는 유니티에 존재하지 않습니다.** 이 세 가지를 손에 익히면 이후 배우는 모든 기능이 "GameObject에 부품을 갈아 끼우는 과정"으로 깔끔하게 정리됩니다.

## 2. 핵심 요약

| 컴포넌트 / 개념 | 핵심 설명 |
| :--- | :--- |
| **GameObject** | 씬에 존재하는 모든 것의 껍데기. 그 자체로는 기능이 없는 텅 빈 그릇 |
| **컴포넌트 시스템**| 상속(Inheritance)이 아닌, 블록 조립식(CBD)으로 기능을 덕지덕지 붙여 캐릭터를 창조하는 유니티의 핵심 방식 |
| **Transform** | 위치, 회전, 크기를 담당하며 모든 `GameObject`에 기본 장착됨 |
| **Local vs World** | `local~`은 부모를 기준으로 한 상대 값, 접두어가 없으면 우주 전체(씬) 기준의 절대 값 |
| **Camera** | 3D 월드의 허상을 유저의 2D 모니터 픽셀로 변환해 주는 최종 번역기 |
| **참조(캐싱) 순위** | 1순위: 인스펙터 `[SerializeField]` ➔ 2순위: `GetComponent` 캐싱 ➔ 최악: `GameObject.Find` |

## 3. 세부 개념 및 원리

### 3.1 GameObject 의 기능 분리 (부품 조립식 개발)
유니티는 `Component Based Development(CBD)`라는 패러다임을 씁니다.\
"날아다니는 적"을 만들 때 `FlyingEnemy` 클래스를 새로 코딩하는 대신, 빈 `GameObject` 그릇에 `Rigidbody`(물리) + `Collider`(충돌) + `EnemyAI`(머리) + `FlyMovement`(날개) 부품을 블록처럼 조립해서 완성합니다.\
이 조립 방식 덕분에 언제든 부품만 갈아 끼워 새로운 종류의 적을 순식간에 만들 수 있습니다.

### 3.2 `activeSelf` 와 `activeInHierarchy` 의 치명적 차이
`GameObject`를 켜고 끌 때 가장 많이 당하는 함정입니다.

```csharp
// 1. 내 인스펙터 체크박스가 체크되어 있는가?
bool self = gameObject.activeSelf;         

// 2. 내 부모, 조부모의 체크박스까지 모두 켜져서, 내가 '진짜로 화면에 살아 숨 쉬고' 있는가?
bool shown = gameObject.activeInHierarchy; 
```
부모가 꺼져있으면 자식은 아무리 `SetActive(true)` 발악을 해도 화면에 나오지 않습니다.\
무언가 작동하지 않을 때 `activeInHierarchy`를 찍어보면 단번에 원인을 알 수 있습니다.

### 3.3 Transform: 로컬(Local)과 월드(World)의 분리
```csharp
// World 기준 (내 절대 좌표)
transform.position      = new Vector3(0f, 1f, 0f);  
transform.rotation      = Quaternion.identity;      

// Local 기준 (부모로부터 얼마나 떨어져 있는가)
transform.localPosition = new Vector3(0f, 1f, 0f);  
transform.localRotation = Quaternion.identity;      
transform.localScale    = Vector3.one;              

// 읽기 전용 편의 기능들
Vector3 lossy = transform.lossyScale;  // 부모 크기 뻥튀기까지 반영된 찐 최종 크기
Vector3 fwd   = transform.forward;     // 오브젝트가 바라보는 정면 (파란색 화살표 Z축)
Vector3 right = transform.right;       // 우측 (빨간색 화살표 X축)
Vector3 up    = transform.up;          // 위쪽 (초록색 화살표 Y축)
```

### 3.4 공간 변환 마법: `TransformPoint`와 `TransformDirection`
```csharp
Vector3 localDir = new Vector3(0, 0, 1); // "내 앞쪽으로 1칸"

// TransformDirection: 내 캐릭터가 보는 정면을 기준으로, 월드 좌표계의 동서남북 벡터로 변환
Vector3 worldDir = transform.TransformDirection(localDir);  

// TransformPoint: 방향뿐만 아니라 '나의 현재 위치'까지 더해서 실제 도착할 좌표(Point)를 찍어줌
Vector3 worldPoint = transform.TransformPoint(localDir);           
```

## 4. 코드로 보기 (나쁜 탐색 vs 좋은 탐색)

### 최악의 방법 (`Find`의 남용과 침묵의 버그)
```csharp
public class BadFollowCamera : MonoBehaviour
{
    void Update() // 매 프레임 초당 60번씩
    {
        // 최악 1: 매 프레임 씬 전체를 이름으로 스캔하느라 프레임 박살
        // 최악 2: 기획자가 "Player" 이름을 "Hero"로 바꾸는 순간 빨간 에러도 없이 조용히 null 터짐
        GameObject player = GameObject.Find("Player");
        
        // 최악 3: MainCamera 태그 스캔 비용 낭비
        Camera cam = Camera.main;

        // 최악 4: Update에서 따라가면 카메라 덜덜 떨림 현상 발생
        transform.position = player.transform.position + new Vector3(0, 5, -8);
        transform.LookAt(player.transform);
    }
}
```

### 정석 방법 (인스펙터 의존 및 `LateUpdate` 활용)
```csharp
public class GoodFollowCamera : MonoBehaviour
{
    // 정석 1: 인스펙터에서 직접 끌어다 꽂으면 이름이 바뀌든 말든 평생 안전함
    [SerializeField] private Transform _target;   
    [SerializeField] private Vector3 _offset = new Vector3(0, 5, -8);

    private Camera _cam;

    void Awake()
    {
        // 정석 2: 딱 1번만 찾아서 멤버 변수(필드)에 저장해 두고 평생 씀
        _cam = Camera.main;                       

        // 인스펙터 연결을 잊어버린 실수를 대비한 보조 낙하산
        if (_target == null)
        {
            // 이름 검색보다 태그 검색이 훨씬 안전하고 빠릅니다.
            GameObject found = GameObject.FindWithTag("Player"); 
            if (found != null) _target = found.transform;
        }
    }

    // 정석 3: 타겟이 Update에서 이동을 모두 마친 후, 뒤늦게 쫓아가야 카메라가 안 떨림
    void LateUpdate()
    {
        if (_target == null) return;

        transform.position = _target.position + _offset;
        transform.LookAt(_target);
    }
}
```

## 5. 실전 활용 예시: 3인칭 어깨너머 카메라 릭(Rig)

3인칭 게임에서 카메라가 캐릭터의 어깨너머를 쫓아가며, 캐릭터 머리 위의 체력바가 항상 카메라 렌즈와 평행을 이루게(Billboard) 만드는 고급 템플릿입니다.

```csharp
public class ThirdPersonRig : MonoBehaviour
{
    [SerializeField] private Transform _player;         
    [SerializeField] private Transform _healthBarUI; // 플레이어 머리 위에 동동 떠다니는 HP 바
    [SerializeField] private Vector3 _cameraOffset = new Vector3(0, 4f, -7f);
    
    private Camera _cam;

    private void Awake() => _cam = Camera.main; 

    private void LateUpdate()
    {
        if (_player == null) return;

        // 1) TransformPoint: 플레이어가 뒤를 돌면 카메라도 부드럽게 엉덩이 뒤쪽으로 따라 돈다
        Vector3 desiredPos = _player.TransformPoint(_cameraOffset);

        // 2) Lerp를 통해 즉시 안 꽂히고 부드럽게 쫓아감
        _cam.transform.position = Vector3.Lerp(_cam.transform.position, desiredPos, 5f * Time.deltaTime);
        _cam.transform.LookAt(_player.position + Vector3.up * 1.5f); // 발등이 아닌 가슴팍 쳐다보기

        // 3) 체력바의 Z축 방향을 카메라의 Z축 방향과 똑같이 맞춰버림 (항상 렌즈 정면 응시)
        if (_healthBarUI != null)
        {
            _healthBarUI.forward = _cam.transform.forward; 
        }
    }
}
```

## 6. Unity 최적화 팁

### 6.1 오브젝트를 찾는 우선순위 (무조건 지킬 것)
| 방법 | 비용 | 견고함 (이름 변경 대처) | 쓸 때 |
| :--- | :--- | :--- | :--- |
| **`[SerializeField]` 인스펙터** | **0** | **완벽함** | 1순위. 씬에 이미 존재하는 타겟을 찍을 때 무조건 씀 |
| **`GetComponent<T>` + `Awake`** | 낮음 | 완벽함 | 내 자신이나, 부모/자식 관계에 있는 부품을 찾을 때 |
| **`GameObject.FindWithTag`** | 중간 | 좋음 | 총알처럼 런타임 중에 태어나는 프리팹이 타겟을 찾을 때 |
| **`GameObject.Find("Name")`** | **최악** | **최악** (침묵의 킬러) | 코딩하기 싫고 퇴사하고 싶을 때 |

### 6.2 `Transform`을 코드로 맘대로 옮겨도 되는가?
* **타겟에 `Rigidbody`가 붙어 있다면?**
    * `transform.position = ...`으로 강제 이동시키면 유니티 물리 엔진은 눈을 감습니다.
    * "분명 얇은 벽이 있었는데 얘가 갑자기 텔레포트해서 뚫고 나갔네?" 하며 충돌 처리를 무시합니다.
    * 물리가 적용된 캐릭터는 반드시 `Rigidbody.MovePosition`을 사용해 `FixedUpdate`에서 멱살을 잡고 끌고 가야 합니다.
* **타겟이 UI 마커나, 장식물, 카메라라면?**
    * 편하게 `transform.position`으로 만져도 아무 문제 없습니다.

### 6.3 하이어라키(부모-자식) 계층 구조의 딜레마
* **장점**: 탱크의 차체(부모)가 돌면 포탑(자식)이 알아서 따라 도는 구조를 날로 먹을 수 있습니다.
* **함정(런타임 SetParent)**: 게임 중에 초당 50발씩 발사되는 총알을 `탄창` 오브젝트의 자식으로 계속 묶고 풀면(`transform.SetParent`), 유니티 내부에서 위치 계산 트리 연산을 매번 리셋하느라 성능이 터집니다. 런타임 계층화는 가급적 피하세요.
* **함정(비율의 저주)**: 부모 오브젝트의 크기(Scale)가 (1, 2, 1)처럼 비균등한데, 자식이 그 안에서 회전을 하면 자식이 찌그러진 호떡처럼 기괴하게 늘어납니다. 부모는 반드시 (1, 1, 1)을 유지하세요.

## 7. 실습 문제 및 복습

**Q1. `transform.localScale`에 `(2, 2, 2)`를 대입하는 것과, `transform.lossyScale`에 `(2, 2, 2)`를 대입하려 하는 것의 차이점은 무엇인가요?**
> `localScale`은 부모와 상관없이 "나 자신의 원본 크기를 2배로 불리겠다"는 의미로 대입(수정)이 가능한 변수입니다.\
> 반면 `lossyScale`은 내 크기에 부모와 조부모의 뻥튀기 배율까지 싹 다 곱해져서 화면에 출력되는 '최종 결과값'이므로 읽기 전용(Read-Only) 변수입니다. 대입을 시도하면 즉시 컴파일 에러가 발생합니다.

**Q2. `TransformDirection`과 `TransformPoint`는 모두 로컬 기준을 월드 기준으로 번역해 주는 함수입니다. 어느 상황에서 어떤 것을 골라 써야 할까요?**
> 캐릭터가 쏜 총알이 날아갈 **'방향'** 만 알고 싶을 때는 `TransformDirection(Vector3.forward)`를 써서 캐릭터의 회전(어디를 보는지) 값만 반영합니다.\
> 반면, 적을 소환할 마법진의 **'실제 도착 좌표'**를 알고 싶을 때는 `TransformPoint`를 써서 캐릭터의 현재 회전값뿐만 아니라 좌표 이동값까지 몽땅 더해 실제 3D 월드 상의 점(Point) 좌표를 얻어내야 합니다.

**Q3. 코드 리뷰 중 `Camera.main.transform.position` 코드가 `Update` 문 안에 있는 것을 발견했습니다. 이 코드가 렌더링 성능과 게임 플레이 조작감에 미치는 두 가지 심각한 악영향을 설명하세요.**
> 첫째, 성능 악영향입니다. `Camera.main`은 엔진 내부적으로 하이어라키 전체를 뒤지며 'MainCamera' 태그를 가진 오브젝트를 찾는 비용을 지불하므로 프레임 드랍을 유발합니다.\
> 둘째, 조작감 악영향입니다. `Update` 안에서 카메라를 갱신하면, 플레이어가 `Update`나 `FixedUpdate`에서 이동을 마치기 전에 카메라가 먼저 선수를 치며 이동해버릴 확률(순서 엇갈림)이 생겨 화면이 심하게 덜덜 떨리게(Jitter) 됩니다.

## 8. 주의사항 및 안전 습관

* **`SetActive(true)`의 배신 주의**: 스크립트로 코드를 짜서 백날 `gameObject.SetActive(true)`를 외쳐봤자 부모나 조부모 폴더 오브젝트가 꺼져 있다면 화면에 절대 나오지 않습니다. 안 보일 땐 `activeInHierarchy`가 켜져 있는지 확인하세요.
* **`TryGetComponent`의 활용**: `GetComponent`로 찾았는데 부품이 없으면 얄짤없이 `NullReference` 폭탄을 던집니다. 유니티 최신 문법인 `TryGetComponent`를 쓰면, 부품이 없을 때는 가볍게 `false`만 뱉고 넘어가므로 방어 코드 1줄이 절약됩니다.
* **로컬이냐, 월드냐, 헷갈리면 무조건 찍어보기**: 이 챕터 버그의 절반 이상은 월드 좌표가 들어가야 할 곳에 내 기준 로컬 좌표를 넣었을 때 터집니다. 머릿속으로 계산하지 말고 항상 `Debug.Log`나 `DrawRay`로 빨간 선을 그어서 눈으로 방향을 확인하는 습관을 들이세요.
* **태그(Tag)는 상수로 관리**: `"Player"`라는 문자열을 여기저기 흩뿌리지 마세요. `public const string TAG_PLAYER = "Player";` 하나로 묶어 관리해야 오타를 막습니다.
