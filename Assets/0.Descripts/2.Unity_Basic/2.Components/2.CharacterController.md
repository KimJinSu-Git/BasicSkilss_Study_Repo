# [Componenets] 2. CharacterController (캐릭터 컨트롤러)

## 1. CharacterController 란?
> **'굴러가는 상자'와 '내가 걷는 몸'**
> * **[Rigidbody]**: 힘을 주면 물리 엔진(유니티)이 알아서 마찰력과 질량을 섞어 저 멀리 굴려줍니다. 멈추는 시점도 엔진 맘입니다.
> * **[CharacterController]**: 내가 직접 한 걸음의 보폭(속도)과 방향을 정해 걷는 몸입니다. 대신 중력이나 점프 같은 자연현상도 내 코드로 직접 계산해서 떠먹여 줘야 합니다.

**왜 Rigidbody를 안 쓰고 이걸 쓰나요?**\
물리 엔진에 사람(캐릭터)의 조작을 맡기면 4가지 문제점이 발생합니다.
1. **미끄러짐**: 키보드에서 손을 뗐는데도 관성 때문에 캐릭터가 얼음판처럼 스르륵 밀립니다.
2. **문턱 걸림**: 고작 10cm짜리 문지방을 못 넘고 캡슐이 걸려서 멈춥니다.
3. **경사로 미끄럼**: 비탈길에 가만히 서 있으면 아래로 줄줄 흘러내립니다.
4. **예측 불가**: 같은 입력(힘)을 줘도 프레임 드랍이나 마찰 상태에 따라 점프 높이나 도착지가 널뜁니다.

이 모든 통제권을 물리 엔진에서 빼앗아 내 코드로 가져오기 위해 쓰는 것이 `CharacterController` 컴포넌트입니다.

---

## 2. 핵심 요약

| 항목 | CharacterController 의 특징 |
| :--- | :--- |
| **충돌** | 캡슐 형태의 콜라이더가 자체 내장되어 있음 (Collider2D 등 따로 안 붙임) |
| **중력 & 점프** | 엔진이 안 해줌. 코드로 직접 `Y축` 속도를 계산해 넣어야 함 |
| **관성 & 마찰** | 없음. 방향키를 놓는 순간 그 1프레임에 칼같이 멈춤 |
| **문턱 & 경사** | 인스펙터의 `Step Offset`과 `Slope Limit` 설정으로 알아서 자연스럽게 넘어감 |
| **접지 판정** | `isGrounded`가 땅에 닿았는지 알려주지만, `Move` 함수를 부른 직후에만 갱신됨 |

> **[원칙]**
> 1. 캐릭터 이동은 `transform.position += ...`으로 하면 안 됩니다. 충돌 판정을 뚫고 벽 안으로 파고드니, 무조건 **`controller.Move()`** 함수를 써야 합니다.
> 2. 바닥에 서 있을 때(접지)도 중력을 아주 살짝(-2f 정도) 아래로 계속 눌러주지 않으면, 내리막길에서 캐릭터가 하늘로 붕 뜹니다.
> 3. 캐릭터의 시야 회전은 **좌우는 몸통**에, **상하는 자식 카메라**에 줘야 몸이 안 뒤집힙니다.

## 3. 세부 개념 및 원리

### 3.1 인스펙터 필수 세팅
* **`Slope Limit`**: 이 각도보다 가파른 언덕은 벽으로 취급해 못 올라갑니다. (보통 45도)
* **`Step Offset`**: 계단이나 문턱을 자연스럽게 밟고 올라갈 수 있는 최대 높이입니다. (0.3m 정도)
* **`Skin Width`**: 충돌 계산의 여유(쿠션) 두께입니다. 너무 얇으면 덜덜 떨리고, 너무 크면 벽에서 살짝 뜬 채로 안 부딪힙니다. (Radius의 10% 권장)

### 3.2 Move 와 SimpleMove 의 차이점
이동 함수는 딱 두 개뿐인데, 실무에서는 **`Move`를 주로 사용합니다.**

| 구분 | `Move()` | `SimpleMove()` |
| :--- | :--- | :--- |
| **중력** | 내가 직접 코드로 누적해서 넣어줘야 함 | 엔진이 알아서 줌 |
| **Time.deltaTime**| 내가 직접 곱해줘야 함 | 내부에 곱해져 있어서 또 곱하면 안 됨 |
| **Y축(상하) 이동** | 가능함 (점프 가능) | **무시됨 (점프 불가)** |

점프 기능이 들어가는 99%의 게임은 Y축 이동을 무시하는 `SimpleMove`를 쓸 수 없으므로 `Move`를 씁니다.

### 3.3 '점프 높이' 역산 공식
보통 개발자들은 점프 속도에 "10f"를 넣고 끝내지만, 기획자는 "점프를 2m 높이까지만 뛰게 해 줘"라고 요구합니다. 높이를 알면 물리학 공식을 역산해 완벽한 초기 점프 속도를 구할 수 있습니다.

```csharp
// 공식 : 초기 속도 = √(희망 높이 × -2 × 중력)
// 중력(gravity) 변수가 음수(-9.8)이므로, 앞에 -2f를 곱해 루트 안을 양수로 만들어야 NaN 에러가 안 터집니다.
float jumpVelocity = Mathf.Sqrt(jumpHeight * -2f * gravity); 
```

### 3.4 2단 접지 판정 (SphereCast)
기본 내장된 `controller.isGrounded`는 경사면이나 얇은 판자 위에서 1프레임씩 튀며 `false`를 뱉어 점프가 씹히는 고질병이 있습니다.\
실무에서는 구체(Sphere) 레이저를 발밑으로 한 번 더 쏘아서 바닥을 이중으로 체크합니다.

```csharp
[SerializeField] private LayerMask _groundMask; // 땅 레이어만 체크
[SerializeField] private float _groundCheckDistance = 0.1f;

private bool IsGroundedBySphereCast()
{
    // 캡슐의 중심(Center)에서 쏜다
    Vector3 origin = transform.position + _controller.center 
                     - (Vector3.up * (_controller.height * 0.5f - _controller.radius));
    
    // 내 캡슐 반지름보다 살짝 작은 구를 발사해 벽 스침을 방지
    float radius = _controller.radius * 0.9f;
    float maxDistance = _groundCheckDistance + (_controller.radius * 0.1f);

    return Physics.SphereCast(origin, radius, Vector3.down, out _, maxDistance, _groundMask);
}
```

## 4. 코드로 보기 (걷기 + 달리기 + 점프)
`CharacterController`의 **'이동과 중력 누적 순서'** 를 1프레임 안에 배치한 코드입니다.

### 이동 정석 코드
```csharp
using UnityEngine;

[RequireComponent(typeof(CharacterController))]
public class PlayerMovement : MonoBehaviour
{
    [SerializeField] private float walkSpeed = 5f;
    [SerializeField] private float jumpHeight = 1.2f;
    [SerializeField] private float gravity = -19.62f; // 조작감을 위해 현실 중력의 2배 적용

    private CharacterController _controller;
    
    // 캐릭터컨트롤러 내장 변수가 아닙니다. 내가 Y축 중력을 매 프레임 누적해서 기억해둘 독자 변수입니다.
    private Vector3 _velocity; 

    private void Awake() => _controller = GetComponent<CharacterController>();

    private void Update()
    {
        // 1) 수평 이동 — (isGrounded 갱신을 위해 가장 먼저 이동시킴)
        float h = Input.GetAxisRaw("Horizontal");
        float v = Input.GetAxisRaw("Vertical");
        
        Vector3 move = transform.right * h + transform.forward * v;
        _controller.Move(move.normalized * (walkSpeed * Time.deltaTime));

        // 2) 접지 판정 — 내장된 녀석이 불안하면 내가 만든 SphereCast로 이중 체크
        bool isGrounded = _controller.isGrounded || IsGroundedBySphereCast();

        // 3) [매우 중요] 서 있는 동안에도 계속 아래로 살짝(-2f) 눌러줘야 내리막길에서 안 뜸
        if (isGrounded && _velocity.y < 0f)
            _velocity.y = -2f;

        // 4) 점프 — 공식을 써서 목표 점프 높이까지 완벽하게 도달할 초기 속도를 강제 주입
        if (isGrounded && Input.GetKeyDown(KeyCode.Space))
            _velocity.y = Mathf.Sqrt(jumpHeight * -2f * gravity);

        // 5) 중력 누적 후 최종 수직(Y축) 이동
        _velocity.y += gravity * Time.deltaTime;
        _controller.Move(_velocity * Time.deltaTime);
    }
    
    // 보조 접지 체크 함수 (코드 생략)
    private bool IsGroundedBySphereCast() { return false; }
}
```

## 5. 실전 활용 예시: 1인칭 카메라 마우스 회전 (분업화)
1인칭(FPS) 시점의 캐릭터 고개 돌리기 템플릿입니다. 핵심은 **"좌우 회전은 몸통이, 상하 회전은 자식 카메라가"** 담당하게 나누는 것입니다.

```csharp
public class FirstPersonLook : MonoBehaviour
{
    [SerializeField] private Transform _cameraTransform; // 자식으로 둔 메인 카메라
    [SerializeField] private float _mouseSensitivity = 2f;
    [SerializeField] private float _maxLookAngle = 80f; // 목 꺾임 방지 한계치

    private float _pitch; // 상하 고개 숙임 누적치

    private void Start()
    {
        // 실습 방해 금지: 커서 가두기
        Cursor.lockState = CursorLockMode.Locked;
        Cursor.visible = false;
    }

    // 화면 덜덜거림을 막기 위해 시점 회전은 무조건 모든 이동이 끝난 후(LateUpdate)에 처리합니다
    private void LateUpdate()
    {
        float mouseX = Input.GetAxis("Mouse X") * _mouseSensitivity;
        float mouseY = Input.GetAxis("Mouse Y") * _mouseSensitivity;

        // 1) 좌우 회전 (Yaw) ➔ 몸통 자체를 돌려버림 (그래야 transform.forward 앞쪽으로 걸어감)
        transform.rotation *= Quaternion.AngleAxis(mouseX, Vector3.up);

        // 2) 상하 회전 (Pitch) ➔ 고개(카메라)만 돌림! 몸통까지 숙이면 전진 시 땅으로 파고듦
        _pitch = Mathf.Clamp(_pitch - mouseY, -_maxLookAngle, _maxLookAngle);
        _cameraTransform.localRotation = Quaternion.Euler(_pitch, 0f, 0f);
    }
}
```

## 6. Unity 최적화 팁

### 6.1 `Rigidbody`로 돌아가고 싶을 때 고민할 것
"CharacterController는 물리 충돌 반응이 없네? 그냥 Rigidbody 쓸래!"라고 쉽게 결정해선 안 됩니다.
* 3D 액션이나 플랫포머에서 Rigidbody를 쓰면, 미끄러짐(관성)을 없애려고 마찰력을 억지로 올리고, 캡슐이 눕지 않게 회전을 잠그고(Constraints), 계단을 못 올라서 Raycast로 인공 턱오르기를 구현하는 등 **'물리 엔진을 억지로 끄기 위한 고통의 코드'** 를 수백 줄 작성하게 됩니다.
* 폭발에 날아가거나 래그돌(인형)처럼 뒹굴어야 할 때만 일시적으로 `CharacterController`를 끄고 `Rigidbody`를 켜는(Switching) 방식이 훨씬 정신건강에 좋습니다.

### 6.2 밀기(Push) 기능의 한계점
`CharacterController`는 단단한 쇳덩어리 무적 판정이라서 굴러다니는 상자(`Rigidbody`)를 밀고 갈 수가 없습니다.\
상자를 밀고 싶다면 내장 콜백 함수인 `OnControllerColliderHit`를 이용해, 부딪힌 상대방 `Rigidbody`에게 억지로 힘(`AddForce`)을 가해주는 코드를 따로 작성해야 합니다.

## 7. 실습 문제 및 복습

**Q1. 점프를 구현하기 위해 `SimpleMove()` 함수를 썼는데 캐릭터가 바닥에 붙어서 죽어도 뛰지를 않습니다. 왜 그런가요?**
> `SimpleMove()` 함수는 엔진 내부적으로 자동으로 중력을 적용하여 무조건 바닥으로 잡아당기고, **Y축 방향의 사용자 입력(속도)을 완전히 무시**해버리는 함수이기 때문입니다.\
> 점프나 수직 비행이 필요한 게임에서는 무조건 `Move()` 함수를 사용하고 중력을 직접 계산해 누적해 주어야 합니다.

**Q2. 가만히 서 있다가 앞(W)으로 걸어가면, 캐릭터가 1프레임 동안 땅을 확 뚫고 지하로 꺼졌다가 올라오거나 계단에서 순간이동 하듯 툭 떨어집니다. `Update` 함수 내에 어떤 로직을 빼먹었을 확률이 높나요?**
> 캐릭터가 접지(`isGrounded`) 중일 때, 내가 선언한 독자 변수 `_velocity.y` 값을 초기화하지 않고 계속 냅둔 탓입니다.\
> 서 있는 동안에도 `gravity * Time.deltaTime`이 무한정 누적되어 Y축 하강 속도가 수천, 수만에 달하게 되고, 이때 한 걸음 움직여서 낭떠러지를 벗어나면 누적된 미친 속도가 1프레임 만에 적용되어 땅을 뚫어버립니다.\
> 반드시 땅에 닿아있을 때는 `_velocity.y = -2f;` 정도로 고정해 속도 누적을 막아주어야 합니다.

**Q3. `isGrounded` 값은 매 프레임 언제 갱신(업데이트)되나요?**
> `controller.Move()` 함수를 호출하는 찰나의 순간에 캡슐 하단부가 무언가와 충돌했는지를 바탕으로 딱 그 시점에만 갱신됩니다.\
> 따라서 `Move()`를 호출하기 전(이전 프레임의 낡은 값)에 `isGrounded`를 믿고 점프 처리를 해버리면, 착지하자마자 점프 키를 눌렀을 때 입력이 씹히는 고질적인 버그가 생깁니다. 항상 수평 이동 `Move`를 먼저 날려 접지 여부를 최신화한 뒤에 점프를 체크해야 합니다.

## 8. 주의사항 및 안전 습관

* **`gravity`는 음수인가 양수인가?**: 프로젝트마다 중력 필드를 양수로 적어두고 연산할 때 빼는 방식과, 음수(-9.8)로 적어두고 연산 시 더하는(+=) 방식이 혼용됩니다. 점프 `Mathf.Sqrt` 공식을 쓸 때 이 부호가 틀리면 루트 안이 음수가 되어 `NaN`(Not a Number) 폭탄이 터지고 캐릭터 좌표가 우주로 날아갑니다. 항상 절대값(`Mathf.Abs`)이나 부호 반전을 꼼꼼히 체크하세요.
* **`Skin Width`의 중요성**: 이 값이 0이면 캡슐이 벽에 닿았을 때 부동소수점 오차로 인해 벽 안으로 미세하게 파고들었다 튕겨나오며 화면이 덜덜 떨립니다(Jitter). 기본값 0.08을 존중하되, 벽에서 너무 떠 보인다면 캡슐 `Radius`의 10% 미만으로만 타협하여 줄이세요.
* **조작감 튜닝 변수는 최상단으로**: 이동 속도, 점프 높이, 중력 배수, 마우스 감도 등 조작감과 관련된 모든 수치는 반드시 `[SerializeField]`로 빼두세요. 플레이 도중 인스펙터 슬라이더를 실시간으로 만져가며 손맛을 깎아야 퇴근 시간이 빨라집니다.
