# [Fundamentals] 1. 게임 세계의 눈, Camera (카메라)

## 1. 카메라(Camera) 란?
> **무대와 촬영 기기**
> * 씬(Scene)은 화려한 세트가 꾸며진 **'무대'** 이고, 카메라는 객석에 놓인 단 한 대의 **'촬영 카메라'** 입니다.
> * 플레이어는 게임 세계를 직접 보지 못하고, 이 카메라 렌즈에 담겨 스크린에 맺힌 2D 영상(결과물)만 봅니다.
> * 어디에 두는가 ➔ 1인칭, 3인칭, 쿼터뷰 등 **장르**가 결정됨
> * 어떤 렌즈를 끼우는가 ➔ 3D 원근(Perspective)인지 2D 평면(Orthographic)인지가 결정됨
> * 얼마나 넓게 담는가 ➔ 미니맵을 만들지 말지 등 **게임의 기획(재미 요소)** 이 결정됨

카메라는 단순한 연출 도구가 아니라 게임 규칙의 일부를 설계하는 핵심 장치입니다.

---

## 2. 핵심 요약

| 속성 (Property) | 한 줄 설명 | 실무 팁 |
| :--- | :--- | :--- |
| **Projection (투영)** | 3D(Perspective)로 볼지, 2D(Orthographic)로 볼지 결정 | 2D 게임은 무조건 Orthographic |
| **Size (직교 사이즈)** | 카메라에 담기는 화면의 세로 크기 절반 값 | 이 값이 커지면 줌 아웃(Zoom Out)됨 |
| **Clipping Planes** | 카메라가 인식하는 최소(Near) - 최대(Far) 거리 한계 | 최솟값을 너무 줄이면 화면이 깜빡임 |
| **Culling Mask** | 카메라가 그려낼 특정 레이어(Layer)들을 선택 | UI 전용, 미니맵 전용 카메라 세팅 시 필수 |
| **Depth / Priority** | 여러 대의 카메라가 있을 때 화면에 덮어쓰는 순서 | 숫자가 클수록 제일 마지막(맨 앞)에 그려짐 |

> **[원칙]**
> 1. 2D 직교 카메라 화면의 **세로 절반은 `Size`**, **가로 절반은 `Size * Aspect(비율)`** 입니다. 맵 제한(Clamp) 연산은 무조건 여기서 나옵니다.
> 2. 카메라의 Z축은 항상 2D 대상 평면(0)보다 뒤쪽(예: -10)에 물러나 있어야 합니다. Z축을 무심코 대상과 같게 0으로 덮어쓰면 화면이 까맣게 먹통이 됩니다.
> 3. 카메라 추적 코드는 무조건 **`LateUpdate`** 에 둡니다. 플레이어가 `Update`에서 이동을 싹 끝낸 뒤에 카메라가 움직여야 화면이 떨리지 않습니다.

## 3. 세부 개념 및 원리

### 3.1 렌즈 갈아 끼우기 (투영 방식 - Projection)
3차원 세계를 모니터라는 평면(2D)에 그릴 때, 거리 정보를 어떻게 처리할 것인지 정합니다.

* **Perspective (원근 투영)**: 사람 눈처럼 가까우면 크게, 멀면 작게 그립니다. 시야각(`FOV`)으로 넓이를 조절하며, 3D FPS, RPG 게임에 필수입니다.
* **Orthographic (직교 투영)**: 거리를 완전히 무시하고 도면처럼 똑같은 크기로 찍어 누릅니다. 타일의 크기가 항상 일정해야 하는 2D 플랫포머, 쿼터뷰(아이소메트릭) 타이쿤 게임에 사용됩니다.

### 3.2 허공에 버려지는 것들 (절두체와 클리핑 평면)
카메라는 렌즈 앞 `Near` 평면부터 `Far` 평면 사이의 공간(절두체)에 있는 물건만 화면에 그립니다.
* **Far를 1000처럼 너무 크게 두면**: 카메라가 닿지도 않는 우주 끝의 물체까지 그리려고 헛심을 써서 게임 최적화가 무너집니다.
* **Near를 0.001처럼 너무 작게 두면**: 깊이 정밀도(Z-Buffer) 연산에 오차가 생겨 멀리 겹쳐 있는 폴리곤 두 개가 서로 앞으로 나오려고 깜빡거리는 **Z-Fighting 버그**가 생깁니다.

### 3.3 화면의 바탕색 지우기 (Clear Flags)
매 프레임 카메라가 새로운 화면을 그리기 전에, 이전 프레임의 화면(찌꺼기)을 무엇으로 닦아낼지 정합니다.
* **Skybox (스카이박스)**: 유니티의 가상 하늘 그림으로 닦아냅니다. (일반적인 3D 게임)
* **Solid Color (단색)**: 단일 색상(주로 파란색 계열)으로 닦아냅니다. (2D 게임)
* **Depth Only (깊이만 지움)**: 바탕색을 지우지 않고 냅둡니다. 주로 화면 위에 UI용 카메라를 한 겹 더 투명하게 겹칠(Stacking) 때 씁니다.

## 4. 코드로 보기 (부드러운 카메라 추적)

플레이어를 부드럽게 쫓아가는 카메라는 `Lerp` 대신 **`SmoothDamp`** 를 써야 잔떨림(멀미)이 사라집니다. 또한, 열거형(`enum`)을 써서 상태(상황)별로 카메라의 행동을 통제하는 코드입니다.

```csharp
using UnityEngine;

public class SmoothFollowCamera : MonoBehaviour
{
    // 카메라의 현재 상태를 나타내는 명확한 열거형 설계
    public enum States { Stopped, Holding, Following }

    [SerializeField] private Transform _target;
    [SerializeField] private Vector3 _offset; // 캐릭터 머리 위로 띄울 오프셋
    [SerializeField] private float _smoothTime = 0.2f; // 목표에 도달하는 데 걸리는 대략의 시간

    private States _state = States.Stopped;
    private Vector3 _velocity = Vector3.zero; // SmoothDamp가 내부적으로 사용하는 가속도 메모리

    public void ChangeState(States newState)
    {
        if (newState == States.Following && _target == null)
        {
            Debug.LogWarning("[Camera] 타겟이 없는데 Following 상태로 갈 수 없습니다");
            return;
        }
        
        if (newState == States.Stopped) _target = null;
        
        _state = newState;
    }

    // 카메라는 무조건 타겟이 이동을 마친 직후인 LateUpdate에서 움직인다
    private void LateUpdate()
    {
        if (_state != States.Following || _target == null) return;

        Vector3 desiredPosition = _target.position + _offset;

        // 정석: Lerp 대신 SmoothDamp를 써야 카메라 덜덜거림(멀미)이 100% 사라짐
        Vector3 nextPosition = Vector3.SmoothDamp(transform.position, desiredPosition, ref _velocity, _smoothTime);

        // 2D 카메라는 Z축이 타겟과 겹치면 화면이 먹통이 되므로, 내 기존 Z축을 강제로 보존한다
        nextPosition.z = transform.position.z; 

        transform.position = nextPosition;
    }
}
```

## 5. 실전 활용 예시: 맵 밖으로 화면 안 넘어가게 가두기(Clamp)

2D 농장 게임에서 카메라(화면)가 맵 끝을 넘어가면 새까만 허공이 보여 유저가 길을 잃습니다.\
이를 막기 위해 카메라 렌즈 사각형 자체를 맵 테두리 안에 가두는(Clamp) 공식입니다.

```csharp
using UnityEngine;

[RequireComponent(typeof(Camera))]
public class CameraBoundsClamp : MonoBehaviour
{
    [SerializeField] private Vector2 _mapMin; // 맵의 왼쪽 아래 끝단 좌표
    [SerializeField] private Vector2 _mapMax; // 맵의 오른쪽 위 끝단 좌표

    private Camera _cam;

    private void Awake()
    {
        _cam = GetComponent<Camera>();
        
        if (!_cam.orthographic)
            Debug.LogError("[Camera] 2D 경계 클램프는 Orthographic 카메라에서만 동작합니다");
    }

    private void LateUpdate()
    {
        // ... (타겟을 따라가는 로직 생략) ...

        transform.position = ClampCameraPosition(transform.position);
    }

    // 카메라가 보는 2D 렌즈 사각형이 맵 테두리를 넘지 못하게 가둔다
    private Vector3 ClampCameraPosition(Vector3 targetPos)
    {
        // 1. 카메라 렌즈의 세로 절반 사이즈
        float halfHeight = _cam.orthographicSize;
        
        // 2. 카메라 렌즈의 가로 절반 사이즈 (세로 절반 * 16:9 화면 비율)
        float halfWidth = halfHeight * _cam.aspect;

        // 3. 맵 끝단(최소/최대)에서 카메라 렌즈의 절반 크기만큼 안쪽으로 가드레일을 친다.
        float minX = _mapMin.x + halfWidth;
        float maxX = _mapMax.x - halfWidth;
        float minY = _mapMin.y + halfHeight;
        float maxY = _mapMax.y - halfHeight;

        // 4. 가드레일 안에 현재 위치를 우겨 넣는다 (Clamp)
        float clampedX = Mathf.Clamp(targetPos.x, minX, maxX);
        float clampedY = Mathf.Clamp(targetPos.y, minY, maxY);

        return new Vector3(clampedX, clampedY, targetPos.z);
    }
}
```

## 6. Unity 최적화 팁

### 6.1 `Camera.main` 호출은 독약이다
`Camera.main`은 엔진 내부적으로 하이어라키 전체를 뒤지며 `MainCamera` 태그를 가진 오브젝트를 찾는 비용이 엄청나게 무거운 탐색 함수입니다.\
절대 `Update` 문 안에서 매 프레임 부르면 안 되며, 무조건 `Awake`나 `Start`에서 한 번만 찾아 변수에 캐싱해 두고 써야 합니다.\
*(참고: 유니티 최신 버전에서는 캐싱 기능이 조금 개선되었지만, 여전히 변수에 직접 할당해 두는 것이 성능상 유리합니다.)*

### 6.2 카메라 분할과 스태킹(Stacking)
3D 오브젝트 위에 체력바나 인벤토리 UI를 띄워야 하는데 3D 벽에 파묻히는 버그가 자주 생깁니다.\
이때 카메라를 2대 써서 레이어 순서를 통제합니다.
1. **메인 카메라**: `Depth`를 -1로 두고 3D 세상만 찍습니다. (`Culling Mask`에서 UI 레이어 체크 해제)
2. **UI 전용 카메라**: `Depth`를 1로 두고 UI만 찍습니다. 배경은 지우지 않아야 하므로 `Clear Flags`를 **Depth Only**로 세팅합니다.

### 6.3 카메라의 일시정지(`TimeScale = 0`) 예외 처리
게임 팝업창을 띄우고 `Time.timeScale = 0`으로 게임 시간을 멈췄을 때, 카메라만은 부드럽게 팝업창을 향해 줌인(Zoom)되거나 이동해야 하는 경우가 있습니다.\
이때 이동 공식에 `Time.deltaTime`을 곱하면 게임 시간과 함께 카메라의 시간도 얼어붙습니다.\
반드시 현실의 흘러가는 시계인 **`Time.unscaledDeltaTime`** 을 곱해줘야 일시정지 중에도 카메라가 독자적으로 살아서 움직입니다.

## 7. 실습 문제 및 복습

**Q1. 카메라가 플레이어를 쫓아가게 하는 로직을 작성하려고 합니다. 이동 코드를 `Update` 함수가 아닌 `LateUpdate` 함수에 작성해야 하는 유니티의 렌더링 파이프라인 상의 이유는 무엇인가요?**
> 플레이어의 이동 로직(키보드 입력 및 물리 반영)은 보통 `Update`나 `FixedUpdate`에서 모두 처리가 완료됩니다.\
> 만약 카메라도 똑같이 `Update`에서 움직이게 되면, 어떤 프레임에는 카메라가 먼저 움직이고 플레이어가 나중에 움직이는 등 순서가 뒤죽박죽 섞여(Race Condition) 화면이 심하게 덜덜 떨리게 됩니다.\
> 플레이어의 이동이 100% 확정된 직후인 `LateUpdate`에서 카메라를 이동시켜야 잔떨림 없는 완벽한 추적이 가능합니다.

**Q2. 인벤토리 UI를 그리는 전용 카메라(UI Camera)를 추가로 만들고, 메인 3D 카메라(Main Camera)의 화면 위에 UI를 겹쳐서 투명하게 띄우려 합니다. UI 카메라 인스펙터의 `Depth` 값과 `Clear Flags` 옵션을 어떻게 설정해야 화면이 까맣게 덮이지 않을까요?**
> UI가 메인 3D 화면보다 나중에(위에) 그려져야 하므로 UI 카메라의 `Depth` 값을 메인 카메라(보통 -1)보다 더 큰 숫자(예: 1)로 설정해야 합니다.\
> 또한 매 프레임 UI를 그리기 전에 이전 프레임의 바탕색을 단색(Solid Color)이나 스카이박스로 덧칠해버리면 애써 그린 메인 3D 화면이 가려지므로, UI 카메라의 `Clear Flags`는 투명도를 유지하는 **Depth Only**로 반드시 설정해야 합니다.

**Q3. 2D 아이소메트릭 게임에서 카메라 렌즈 사각형의 화면 밖으로 맵이 벗어나지 않게 가드레일 제한(Clamp)을 걸려고 합니다. 현재 카메라 컴포넌트의 `orthographicSize` 값이 5이고, 기기 화면의 종횡비(`aspect`)가 16:9 (약 1.77)일 때, 현재 카메라가 한 화면에 비추고 있는 '가로 전체 폭'의 월드 길이는 얼마인가요?**
> `orthographicSize`는 렌즈 사각형의 '세로 절반'을 의미하므로 세로 전체 길이는 10입니다.\
> 가로 절반 사이즈는 `orthographicSize * aspect` 공식에 따라 5 * 1.77 = 8.85입니다. 따라서 화면에 보이는 렌즈 사각형의 가로 전체 폭은 8.85의 두 배인 **17.7**이 됩니다.

## 8. 주의사항 및 안전 습관

* **카메라를 플레이어의 자식(Child)으로 넣지 마세요**: 가장 1차원적이고 하수 같은 1인칭 카메라 세팅입니다. 플레이어 오브젝트에 걷기 반동(애니메이션)이나 미세한 충돌 떨림이 생기면 카메라 렌즈가 그대로 흔들려 유저가 극심한 멀미를 느낍니다. 카메라는 무조건 하이어라키 최상단(Root)에 따로 빼두고, 코드로 부드럽게(`SmoothDamp`) 쫓아가게 만들어야 합니다.
* **시연용 테스터 키 입력 분리**: 카메라 추적 스크립트 안에 키보드 Z키를 누르면 시점이 바뀐다거나 하는 시연용 키 입력을 섞어 넣지 마세요. 카메라는 플레이어가 누구인지 몰라야 재활용성이 높아집니다. 키 입력과 상태 전환 명령을 내리는 조종기 클래스는 반드시 별도로 분리하세요.
* **Cinemachine (시네머신)의 활용**: 이 문서의 내용은 카메라의 기초 뼈대를 이해하기 위한 완벽한 지식입니다. 다만 현업에서는 카메라 흔들림(Shake), 데드존 설정, 다중 타겟 추적 등 방대하고 복잡한 기능이 필요할 땐 직접 수학으로 짜지 않고 유니티 내장 패키지인 **Cinemachine**을 100% 활용합니다.
