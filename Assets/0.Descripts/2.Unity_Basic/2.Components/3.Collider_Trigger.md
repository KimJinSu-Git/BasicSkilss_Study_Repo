# [Componenets] 3. Collider & Trigger (충돌체와 트리거)

## 1. Collider 란?
> **'눈에 보이는 그림(Mesh)'과 '실제 만져지는 뼈대(Collider)'**
> * 눈에 보이는 3D/2D 그래픽 모델(Mesh)은 홀로그램과 같아서 아무리 예뻐도 물리적으로는 통과되어 버립니다.
> * 이 그래픽 위에 **투명한 플라스틱 상자(Collider)** 를 씌워주어야 비로소 게임 세상에서 다른 물체와 부딪히고 만져질 수 있습니다.

**핵심 역할**
* **충돌 감지**: 벽에 막히고, 바닥에 서 있게 해줍니다.
* **물리 연산 적용**: `Rigidbody`와 결합하여 당구공처럼 튕기거나 중력에 떨어지게 합니다.
* **Trigger (방아쇠)**: 투명한 감지 센서망을 쳐두고, 누군가 들어오면 이벤트를 발생시킵니다.

---

## 2. 핵심 요약

| 개념 | 역할 | 특징 |
| :--- | :--- | :--- |
| **Collider** | 물리적인 튕겨남(막힘) 처리 | `OnCollisionEnter` 함수 호출 |
| **Trigger** | 물리적 충돌 없이 통과 여부만 감지 | 인스펙터에서 `is Trigger` 체크 ➔ `OnTriggerEnter` 호출 |
| **Rigidbody 조건**| 충돌이 발생하려면 두 오브젝트 중 **최소 하나(움직이는 쪽)에 무조건 `Rigidbody`가 있어야 함** |

## 3. 세부 개념 및 원리

### 3.1 Collider의 형태별 분류와 최적화
모양에 따라 물리 연산(CPU) 비용이 천차만별입니다.

| 종류 | 특징 및 활용 예시 | 성능 비용 |
| :--- | :--- | :--- |
| **Box Collider** | 직육면체. (상자, 벽, 문) | 매우 가벼움 (추천) |
| **Sphere Collider**| 구형. (공, 폭탄 폭발 범위, 어그로 범위) | 가장 가벼움 (강추) |
| **Capsule Collider**| 캡슐형. (플레이어, 적 NPC 등 사람 형태) | 가벼움 |
| **Mesh Collider** | 3D 모델의 생긴 모양 그대로 충돌망을 짬 | **매우 무거움** |
| **Terrain Collider**| 유니티 지형 시스템 전용 | 지형 연산에 최적화됨 |
| **Wheel Collider** | 자동차 바퀴 전용 (마찰력, 서스펜션 등) | 무거움 |

> **최적화 팁 (Mesh Collider의 배신)**\
> 성(Castle)이나 드래곤처럼 복잡한 3D 모델에 `Mesh Collider`를 통째로 씌우면, 폴리곤 수만 개를 매 프레임 충돌 검사하느라 게임 프레임이 박살 납니다.\
> ➔ **보이는 메시(그래픽)와 충돌 메시(판정)를 완벽히 분리**하여, 복잡한 성이라도 눈에 안 보이는 거대한 `Box Collider` 서너 개를 덕지덕지 이어 붙여서 가짜로 충돌 처리를 하는 것이 정석입니다

### 3.2 Collision 과 Trigger 콜백 이벤트
콜라이더 세팅에 따라 엔진이 불러주는 이벤트 함수가 완전히 다릅니다.

| 상태 | 물리적 충돌 발생 시 (`Collision`) | 센서 통과 시 (`Trigger`) |
| :--- | :--- | :--- |
| **진입하는 1프레임** | `OnCollisionEnter()` | `OnTriggerEnter()` |
| **머무는(비비는) 동안**| `OnCollisionStay()` ➔ 과부하 주의 | `OnTriggerStay()` ➔ 과부하 주의 |
| **빠져나가는 1프레임**| `OnCollisionExit()` | `OnTriggerExit()` |

### 3.3 충돌(이벤트)이 일어나기 위한 최소 조건
충돌 검사는 유니티 물리 엔진 입장에서 꽤 피곤한 작업입니다.\
그래서 엔진은 **`Rigidbody`가 없는 `Collider`는 "영원히 움직이지 않는 무거운 돌덩이(Static)"로 취급**하여 자기들끼리의 검사를 끄고 최적화해 버립니다.
* ➔ **결론**: 충돌 이벤트(`Enter`, `Stay`, `Exit`)가 터지려면 두 오브젝트가 닿았을 때 **최소 한 명(가해자)에게는 반드시 `Rigidbody`가 붙어 있어야 합니다**

## 4. 코드로 보기

`Collision`은 튕겨 나간 반동력 정보가 필요하므로 **'충돌 사고 정보지(`Collision`)'** 덩어리를 받아오고, `Trigger`는 누가 선을 넘었는지만 알면 되므로 **'침입자의 신분증(`Collider`)'** 만 받아옵니다.

### 4.1 물리 충돌 감지 (`OnCollisionEnter`)
```csharp
public class BumperCar : MonoBehaviour
{
    // 부딪힌 상대방의 정보뿐만 아니라 '어느 각도로 얼마나 세게 부딪혔는지' 정보가 담겨 옵니다.
    private void OnCollisionEnter(Collision collision)
    {
        // 안전 습관: Tag로 먼저 필터링
        if (collision.gameObject.CompareTag("Wall"))
        {
            // 충돌한 표면의 첫 번째 접촉점(ContactPoint) 정보 빼오기
            Vector3 contactPoint = collision.contacts[0].point;
            Debug.Log($"벽과 꽝! 부딪힌 위치: {contactPoint}");
        }
    }
}
```

### 4.2 센서 영역 감지 (`OnTriggerEnter`)
```csharp
public class SpeedBuffZone : MonoBehaviour
{
    // 튕겨 나가지 않고 스윽 통과하므로, '누가 통과했는지' 신분증(Collider)만 담겨 옵니다.
    private void OnTriggerEnter(Collider other)
    {
        if (other.CompareTag("Player"))
        {
            Debug.Log($"{other.name} 님이 버프 존에 입장하셨습니다");
            // other.GetComponent<Player>().SpeedUp(); 
        }
    }
}
```

### 5. 실전 활용 예시: 보스방 입구 함정

플레이어가 보스방 입구를 지나가면(Trigger 감지), 퇴로를 거대한 철창(Collider)으로 닫아버리는 패턴입니다.\
이처럼 **길을 감지하는 것은 Trigger, 물리적으로 막는 것은 일반 Collider**로 분업화합니다.

```csharp
using UnityEngine;

[RequireComponent(typeof(Collider))]
public class BossRoomEntrance : MonoBehaviour
{
    [SerializeField] private GameObject _ironDoor; // Is Trigger 가 꺼져있는 문 (길을 막음)
    [SerializeField] private BossSpawner _bossSpawner;
    
    private bool _hasStarted = false; // 중복 감지 방지용 플래그

    private void Reset() 
    {
        // 이 스크립트를 컴포넌트에 붙이면 실수 방지를 위해 입구 자체를 자동으로 Trigger로 만듦
        GetComponent<Collider>().isTrigger = true; 
    }

    private void OnTriggerEnter(Collider other)
    {
        if (_hasStarted) return; // 이미 보스전 시작됐으면 무시
        
        // 총알이나 굴러다니는 돌멩이가 지나가도 문이 닫히면 안 됨. 반드시 태그 검사.
        if (!other.CompareTag("Player")) return; 

        _hasStarted = true;
        _ironDoor.SetActive(true); // 퇴로 차단 (물리 문 생성)
        
        _bossSpawner.BeginBattle();
        Debug.Log("보스전 시작. 도망칠 수 없다");
    }
}
```

## 6. Unity 최적화 팁

### 6.1 `Trigger`로 만들 것과 `Collider`로 만들 것

| 만들 것 | 설정 | 이유 |
| :--- | :--- | :--- |
| **벽, 바닥, 문, 장애물** | `Collider` 유지 | 실제로 통과를 물리적으로 막아야 하니까 |
| **총알, 수류탄 판정** | `Collider` 유지 | 맞은 지점(`contactPoint`)과 세기(충격량)가 필요하니까 |
| **회복 아이템, 포탈, 컷씬 밟는 곳** | `Trigger` 켬 | 막히면 안 되고 스윽 지나가야 하니까 |
| **적의 어그로 시야, 공격 판정 범위**| `Trigger` 켬 | 범위 안에 들어왔는지만 알면 되니까 |
| **낙사 판정 존 (절벽 밑)** | `Trigger` 켬 | 밟고 서 있으면 안 되고 무조건 통과하면서 죽어야 하니까 |

### 6.2 `Rigidbody`를 어디에 붙일 것인가? (그리고 `isKinematic`)
* **원칙**: 유니티 물리 엔진은 `Rigidbody`가 붙은 쪽을 주인공(가해자)으로 봅니다. **움직이는 쪽에 붙이세요** (플레이어, 몬스터, 총알)
* 고정된 벽, 바닥, 아이템에는 절대로 `Rigidbody`를 붙이지 마세요. 최적화를 망칩니다.
* **딜레마 (엘리베이터, 무빙워크)**: 어쩔 수 없이 스크립트나 애니메이션으로 계속 움직여야 하는 함정이나 발판인데, 중력을 받아서 밑으로 떨어지거나 플레이어랑 부딪혀서 뒤로 튕겨 날아가면 안 되는 상황이라면?
    * ➔ **해결책**: `Rigidbody`를 붙이되 인스펙터에서 **`Is Kinematic`** 체크박스를 켜주세요. "나는 움직이긴 할 건데, 엔진 너는 물리력으로 날 밀거나 떨어뜨리지 마!"라는 뜻의 '무적의 이동체'가 됩니다.

### 6.3 쓸데없는 연산 원천 차단 (Layer Collision Matrix)
`Edit ➔ Project Settings ➔ Physics`에 들어가면 하단에 **Layer Collision Matrix (레이어 충돌 표)** 가 있습니다.
* 총알끼리 부딪힐 일도 없고, 적군끼리 길을 막을 이유도 없는데 유니티는 매 프레임 이들끼리 닿았는지 계산하며 CPU를 낭비합니다.
* 교차하는 체크박스를 꺼버려서 **서로 부딪힐 일이 없는 레이어 쌍은 아예 엔진단에서 충돌 검사를 무시하게 만들어야 합니다.**
* *(참고: "아무리 겹쳐도 이벤트 콜백이 안 와요" 하는 버그의 1순위 원인이기도 하니 꼭 확인하세요.)*

## 7. 실습 문제 및 복습

**Q1. `OnTriggerEnter` 이벤트가 발생하려면, 충돌하는 두 개의 게임 오브젝트 중 최소 몇 개에 `Rigidbody` 컴포넌트가 부착되어 있어야 할까요?**
> **최소 1개 이상**입니다. 유니티는 최적화를 위해 `Rigidbody`가 둘 다 없는 `Collider`끼리의 만남은 움직이지 않는 정적(Static) 물체들의 의미 없는 비빔으로 간주하여 충돌 이벤트를 아예 무시해 버립니다.

**Q2. 함수 서명을 보면 `OnCollisionEnter(Collision collision)`은 `Collision` 클래스를 받고, `OnTriggerEnter(Collider other)`는 `Collider` 클래스를 받습니다. 타입이 다른 이유는 무엇인가요?**
> `Collision`(충돌)은 두 물체가 물리적으로 '꽝' 하고 부딪혀 반발력이 생기는 현상입니다.\
> 따라서 부딪힌 상대방의 정보뿐만 아니라 **접촉 지점 좌표(contacts), 상대 속도(relativeVelocity), 충격량(impulse)** 등 자세한 '물리적 사고 경위서'가 담긴 `Collision` 덩어리를 줍니다.\
> 반면 `Trigger`는 그냥 통과 센서이므로, "어떤 녀석이 센서를 밟았어?"라는 침입자의 신분증인 `Collider` 정보 하나만 달랑 던져주는 것입니다.

**Q3. 두 오브젝트(A와 B)가 화면상 분명히 눈에 보이게 겹치고 뚫고 지나가는데도 `OnTriggerEnter`가 단 한 번도 호출되지 않고 침묵합니다. 가장 먼저 의심하고 확인해야 할 인스펙터/설정 항목 3가지는 무엇인가요?**
> 1. 두 오브젝트 중 최소 하나에 **`Rigidbody`** 가 붙어 있는지 확인합니다.
> 2. 센서 역할을 할 오브젝트의 `Collider`에 **`Is Trigger`** 체크박스가 제대로 켜져 있는지 확인합니다.
> 3. `Project Settings -> Physics`의 **Layer Collision Matrix** 표에서, A의 레이어와 B의 레이어가 서로 교차하는 칸의 체크박스가 실수로 꺼져(무시) 있는지 확인합니다.

## 8. 주의사항 및 안전 습관

* **2D와 3D 혼용 금지**: 게임이 2D인데 `BoxCollider`를 붙이거나, 코드를 `OnTriggerEnter2D`가 아닌 `OnTriggerEnter`로 적으면 엔진이 아예 다른 차원의 물리로 인식해서 영원히 이벤트가 터지지 않습니다. 2D인지 3D인지 접미사를 통일하세요.
* **`OnTriggerStay` 지옥**: 이 함수는 센서 영역 안에서 비비고 있는 내내 **물리 프레임(`FixedUpdate`)마다 1초에 50번씩 호출**됩니다. 여기서 무거운 탐색 함수나 복잡한 계산을 넣으면 그 즉시 폰에 발열이 생기고 프레임이 무너집니다. 가급적 `Enter`로 플래그를 켜고, `Exit`로 끄는 방식을 쓰세요.
* **가짜 `Mesh Collider` 만들기**: 정말 복잡한 지형지물이 아니라면 웬만하면 `Mesh Collider`는 쓰지 마세요. 돌기둥 오브젝트라면 둥그런 기둥 부분엔 긴 `Capsule Collider` 하나, 네모난 받침대 부분엔 넙데데한 `Box Collider` 하나를 자식으로 넣어서 **싸구려 도형 2~3개로 비슷하게 가짜 충돌망(Compound Collider)을 짜깁기해 주는 것**이 메모리 최적화의 기본입니다.
* **태그(Tag) 필터링은 무조건 1순위로**: `OnTriggerEnter` 안에 들어오자마자 `if(!other.CompareTag("Player")) return;` 부터 치는 습관을 들이세요. 이거 안 치면 날아다니는 총알, 파편, 심지어 내 그림자까지 감지해서 스크립트가 오작동을 일으킵니다.
