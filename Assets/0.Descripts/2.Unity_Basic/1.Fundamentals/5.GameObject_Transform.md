# [Fundamentals] 5. 게임 오브젝트와 트랜스폼 (GameObject & Transform)

## 1. GameObject와 Transform 이란?

> **연극 무대와 배우**
> * **`GameObject` (배우)** : 배우 그 자체로는 아무 일도 하지 못하는 텅 빈 껍데기입니다. 의상을 입고(MeshRenderer), 대본을 받고(Script), 마이크를 달아야(AudioSource) 비로소 배역이 완성됩니다.
> * **`Transform` (무대 동선)** : 그 배우가 무대 위의 '어디에 서서(위치)', '어느 쪽을 바라보고(회전)', '얼마만 한 크기(스케일)'로 보이는지를 기록해 두는 필수 장기입니다.
> * **계층 구조 (부모-자식)** : 배우가 칼(소품)을 손에 쥐면, 배우가 이동할 때 칼도 완벽하게 따라 움직입니다. 이것이 부모-자식 구조의 "따라 움직임"입니다.

**왜 이 둘을 명확히 구분해야 할까?**\
초보자들은 흔히 스크립트 안에서 `이 오브젝트를 움직여라`라고 명령할 때 누구에게 명령해야 하는지 헷갈립니다.\
유니티에서 "누구"를 지칭할 때는 언제나 `GameObject`이고, "움직이거나 회전한다"는 행위는 100% `Transform` 컴포넌트의 수치를 바꾸는 일입니다. 이 둘의 역할을 명확히 쪼개서 이해해야 유니티 좌표계의 함정을 피할 수 있습니다.

## 2. 핵심 요약

| 개념 | 한 줄 설명 |
| :--- | :--- |
| **`GameObject`** | 씬에 존재하는 모든 개체의 기본 단위. 그 자체는 기능이 없는 깡통 상자. |
| **`Transform`** | **모든 `GameObject`가 떼려야 뗄 수 없이 반드시 가지는 필수 컴포넌트.** |
| **월드 좌표 (World)** | 우주 전체(씬 원점 0,0,0)를 기준으로 한 절대적인 위치 ➔ `transform.position` |
| **로컬 좌표 (Local)** | 내 부모의 중심점을 원점으로 삼은 상대적인 위치 ➔ `transform.localPosition` |
| **계층 구조 (Hierarchy)**| 부모의 이동, 회전, 크기 변화는 자식에게 100% 누적되어 똑같이 적용됨. |

> **인스펙터 창에 보이는 Position, Rotation, Scale 값은 무조건 'Local(부모 기준) 좌표'입니다** (부모가 없을 때만 우연히 World 좌표와 일치할 뿐입니다.)

## 3. 세부 개념 및 원리

### 3.1 `GameObject` — 기능이 없는 빈 상자
`GameObject` 스스로는 화면에 그려지지도, 부딪히지도 않습니다. 오직 부착된 **컴포넌트(Component)** 들이 일을 합니다.\
단, **`Transform`은 절대 지울 수 없는 유일한 컴포넌트**입니다. "유니티 씬에 존재한다"는 말 자체가 "좌표계 어딘가에 위치를 점유하고 있다"는 뜻이기 때문입니다.

### 3.2 월드 좌표 vs 로컬 좌표의 함정
* **`transform.position`** : 내가 우주 전체에서 어디에 있는가? (절대 좌표)
* **`transform.localPosition`** : 내 부모의 배꼽을 기준으로 내가 어느 방향으로 얼만큼 떨어져 있는가? (상대 좌표)

만약 플레이어 손(부모)에 무기(자식)를 쥐여줄 때 `weapon.transform.position = Vector3.zero;`라고 쓰면, 무기가 캐릭터 손이 아니라 맵의 정중앙(0,0,0) 한가운데로 날아가 버립니다\
부모의 손 위치와 정확히 겹치게 하려면 반드시 **`weapon.transform.localPosition = Vector3.zero;`** 를 써야 합니다.

### 3.3 스크립트에서 맨날 쓰는 `Transform` 멤버들
```csharp
// MonoBehaviour를 상속받은 스크립트 안에서는 
// 'gameObject'와 'transform' 변수를 선언 없이 바로 쓸 수 있습니다 (자기 자신을 가리킴)

// 1. 상태 제어
bool isActive = gameObject.activeSelf; // 내가 켜져 있나?
gameObject.SetActive(false);           // 나 자신을 꺼버린다 (화면에서 사라짐)

// 2. 좌표와 회전 제어
transform.position = new Vector3(10, 0, 0); // 월드 좌표로 강제 순간이동
transform.localPosition = Vector3.zero;     // 부모 품(원점)으로 찰싹 붙기

// 3. 내 방향(로컬 축)을 알려주는 꿀 벡터 3인방
Vector3 myRight   = transform.right;   // 내 오른쪽 화살표 방향 (빨강)
Vector3 myUp      = transform.up;      // 내 위쪽 화살표 방향 (초록)
Vector3 myForward = transform.forward; // 내 앞쪽 화살표 방향 (파랑)

// 4. 이동과 회전 메서드
transform.Translate(Vector3.forward * speed * Time.deltaTime); // 기본적으로 '내 앞쪽'으로 전진
transform.LookAt(target.transform);                            // 목표물을 향해 휙 쳐다보기
transform.SetParent(handSocket);                               // 부모를 갈아타기
```

## 4. 실전 활용: 안전하게 컴포넌트 가져오기 (Caching)

내가 아닌 남의 컴포넌트나, 내 몸통에 붙은 다른 컴포넌트를 조작해야 할 때가 90%입니다.\
이때 `GetComponent`를 남발하면 게임에 엄청난 렉이 걸립니다.

### 4.1 나쁜 예 (프레임 폭하)
```csharp
private void Update()
{
    // 최악의 코드: 1초에 60번씩 씬 전체를 뒤져서 이름을 찾고, 부품을 뜯어옴
    GameObject.Find("Player").GetComponent<Rigidbody2D>().linearVelocity = Vector2.up;
}
```

### 4.2 정석 예 (캐싱 Caching)
무거운 작업은 게임이 시작될 때(`Awake`나 `Start`) 딱 한 번만 찾아서 **내 클래스의 변수(필드)에 저장(Cache)** 해 두고, `Update`에서는 그 변수만 가져다 씁니다

```csharp
public class Player : MonoBehaviour
{
    private Rigidbody2D _rb;      // 내 몸에 붙은 부품 캐싱용
    private Animator _childAnim;  // 내 자식 몸에 붙은 부품 캐싱용

    private void Awake()
    {
        // 1. 내 몸(GameObject)에 붙어있는 Rigidbody2D 부품을 딱 1번만 찾아서 저장
        _rb = GetComponent<Rigidbody2D>();

        // 2. 내 자식들(자식의 자식 포함)을 싹 뒤져서 Animator 부품을 찾아 저장
        _childAnim = GetComponentInChildren<Animator>();
    }

    private void Update()
    {
        // 이제 1초에 60번을 불러도 전혀 렉이 걸리지 않습니다
        _rb.linearVelocity = Vector2.up;
    }
}
```

### 4.3 `TryGetComponent`
충돌한 적이 일반 몹인지, 보스인지 모를 때는 에러를 내지 않고 찔러보는 `Try` 패턴을 씁니다.
```csharp
private void OnTriggerEnter2D(Collider2D other)
{
    // 상대방 몸에 'Boss' 컴포넌트가 달려있다면 true, 없다면 false로 조용히 빠져나감
    if (other.TryGetComponent(out Boss bossObj))
    {
        bossObj.TakeMassiveDamage(100);
    }
}
```

## 5. 코드로 보는 치명적인 이동 버그 (Space.Self vs Space.World)

전진(`Translate`)을 시켰는데, 캐릭터가 회전할 때마다 이동 방향이 삐뚤어지는 최악의 버그입니다.

### 버그 코드 (기준점 누락)
```csharp
// 오른쪽 화살표를 누르면 오른쪽으로 가야 함.
if (keyboard.rightArrowKey.isPressed)
    transform.Translate(Vector3.right * moveSpeed * Time.deltaTime); 
    // Translate는 마지막 인자(Space)를 생략하면 기본값이 'Space.Self(내 로컬 축)'입니다.
    // 만약 캐릭터가 위를 보고 누워있다면, 우측 방향키를 눌렀는데 하늘로 솟구쳐 버립니다
```

### 수정된 코드 (축 명시하기)
원하는 의도에 따라 기준 축을 명확히 명시해야 합니다.
```csharp
// 1. [절대 축] 캐릭터가 자빠져 있든 뒤집혀 있든, 무조건 '모니터의 오른쪽'으로 이동시키고 싶을 때
transform.Translate(Vector3.right * speed * Time.deltaTime, Space.World);

// 2. [로컬 축] 캐릭터가 바라보고 있는 '자신의 앞쪽' 방향으로 전진시키고 싶을 때
transform.Translate(Vector3.forward * speed * Time.deltaTime, Space.Self);
// 또는
transform.position += transform.forward * speed * Time.deltaTime;
```

## 6. Unity 최적화 팁

### 6.1 `GameObject.Find("이름")` 은 절대 쓰지 마라
* 이름으로 씬 전체를 뒤지는 것은 최악의 성능을 자랑합니다.
* 기획자가 실수로 하이어라키에서 오브젝트 이름을 `Player_01`로 바꾸는 순간, 스크립트 연결이 조용히 끊어지며 `NullReferenceException` 폭탄이 터집니다.
* **[해결책]**: 웬만하면 `[SerializeField] private GameObject target;`을 써서 인스펙터 창에서 마우스 드래그로 꽉 묶어두세요. 빠르면 눈에 띄고 성능 코스트도 0입니다.

### 6.2 활성 상태(`activeSelf` vs `activeInHierarchy`)
오브젝트가 꺼져 있는지 확인할 때 많이 헷갈리는 두 녀석입니다.
* `activeSelf`: 내 이름 옆 체크박스가 켜져 있는가? (부모가 꺼져서 내가 화면에 안 보여도, 내 체크박스만 켜져 있으면 `true`라고 뻥을 칩니다.)
* **`activeInHierarchy`**: 내 부모, 조부모까지 다 켜져서 **"실제로 게임 화면에 살아서 숨 쉬고 있는가?"** (이걸 써야 진짜 활성화 여부를 알 수 있습니다.)

### 6.3 움직이지 않는 배경 오브젝트는 `Static`을 켜라
하이어라키의 건물, 바닥, 나무 같은 오브젝트는 인스펙터 최상단의 **`Static`** 체크박스를 꼭 켜주세요.\
"얘네는 게임 중에 절대 `Transform`이 안 변해!"라고 유니티 엔진에 알려주는 맹세입니다. 엔진이 이걸 믿고 그림자와 렌더링 연산을 엄청나게 최적화해 주어 게임 프레임이 대폭 상승합니다. (대신 코드로 이 녀석들을 움직이려 하면 안 됩니다.)

## 7. 실습 문제 및 복습

**Q1. `Transform` 컴포넌트를 유니티 인스펙터에서 강제로 `Remove Component` 하려고 하면 어떤 일이 벌어지나요? 그 이유는 무엇인가요?**
> 지울 수 있는 삭제 메뉴 자체가 아예 나타나지 않습니다. `Transform`은 해당 게임 오브젝트가 3D/2D 가상 우주 공간에서 "어디에 존재하는가(좌표)"를 증명하는 핵심 장기이므로, 이것이 없으면 씬에 존재할 수 없기 때문입니다.

**Q2. `weapon.transform.position`과 `weapon.transform.localPosition`의 결정적 차이는 무엇인가요? 캐릭터의 손(자식)에 무기를 쥐여줄 때는 어떤 것을 써서 `Vector3.zero`로 초기화해야 하나요?**
> * `position`은 씬 전체(월드 원점)를 기준으로 한 절대 좌표이고, `localPosition`은 내 직속 부모의 중심점을 기준으로 한 상대 좌표입니다.
> * 무기를 부모(손)의 정확한 위치에 겹치게 장착하려면, 부모로부터 거리가 0만큼 떨어져야 하므로 반드시 **`localPosition = Vector3.zero;`** 를 사용해야 합니다.

**Q3. 매 프레임 실행되는 `Update()` 문 안에서 `GetComponent<Rigidbody2D>()`를 호출하면 왜 치명적인가요? 올바른 구조로 수정해 보세요.**
> `GetComponent`는 해당 오브젝트에 붙은 모든 부품 목록을 싹 뒤져서 타입을 찾아오는 무거운 연산입니다. 이를 1초에 60번씩 반복하면 엄청난 성능 저하가 발생합니다.\
> **수정**: `Awake()`나 `Start()`에서 딱 1번만 찾아서 `private Rigidbody2D _rb;` 같은 멤버 변수에 캐싱(저장)해 두고, `Update`에서는 그 변수 `_rb`만 가져다 써야 합니다.

## 8. 주의사항 및 안전 습관

* **부모의 스케일(Scale) 장난질을 조심하라**: 부모 오브젝트의 `Scale`을 `(2, 2, 2)`로 뻥튀기하면, 그 아래에 있는 자식들의 스케일 1짜리 오브젝트들도 눈에 보기에는 2배로 커집니다. 부모의 `Scale`이 찌그러져 있으면 자식이 회전할 때 기괴하게 일그러지는 버그가 생기니, **부모 역할의 빈 오브젝트는 무조건 `Scale`을 (1,1,1)로 유지하세요.**
* **물리 엔진(`Rigidbody`)이 달린 오브젝트의 트랜스폼을 코드로 직접 조작하지 마라**: 물리가 적용된 캐릭터를 `transform.position += ...` 로 억지로 이동시키면 유니티 물리 엔진과 충돌하여 덜덜 떨리거나 벽을 뚫고 나가는 기괴한 현상이 발생합니다. 물리가 달린 애들은 무조건 `rigidbody.linearVelocity`나 `rigidbody.AddForce` 등 물리 컴포넌트의 기능을 이용해 움직여야 합니다.
