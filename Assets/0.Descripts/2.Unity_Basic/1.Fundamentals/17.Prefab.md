# [Fundamentals] 17. 프리팹 (Prefab)

## 1. 프리팹(Prefab) 이란?
> **붕어빵 굽는 무쇠 틀**
> * 붕어빵 백 개를 만들 때 밀가루 반죽을 손으로 일일이 백 번 빚지 않습니다.
> * **'틀'** 을 하나 만들고 붕어빵을 무한정 찍어냅니다.
> * 만약 팥을 슈크림으로 바꾼다면, 만들어진 백 개의 붕어빵 배를 가를 것이 아니라 **'틀'** 자체를 고치면 그다음에 찍히는 붕어빵은 전부 슈크림으로 나옵니다.
> * 유니티에서 이 무쇠 틀이 바로 **프리팹(Prefab)* 이며, 씬(화면)에 구워져 나온 붕어빵들이 그 틀을 가리키는 **인스턴스(사본)** 입니다.

**왜 필요한가?**
1. **유지보수 지옥 탈출**: 동전을 30개 배치해 뒀는데 크기를 키워달라는 요청이 오면, 30개를 하나씩 클릭해서 고쳐야 합니다. 프리팹으로 만들었다면 원본 틀 하나만 고치면 30개가 일제히 커집니다.
2. **실행 중(Runtime) 무한 스폰**: 총알이나 몬스터는 게임이 시작된 후 코드에 의해 무수히 생성되어야 합니다. 코드가 텅 빈 허공에서 총알을 만들 순 없으니, **"이 틀(프리팹) 모양대로 복사해 줘"** 라고 지시할 설계도 파일이 필요합니다.

## 2. 핵심 요약

| 개념 | 한 줄 설명                                              |
| :--- |:----------------------------------------------------|
| **프리팹 (에셋)** | `Assets` 폴더에 `.prefab` 확장자로 저장되는 **원본 설계도 파일**.     |
| **프리팹 인스턴스** | 원본 파일을 참조하여 씬(Hierarchy)에 복사된 **사본** (이름이 파란색으로 뜸). |
| **오버라이드(Override)**| 사본이 원본의 말을 듣지 않고 자기 맘대로 값을 바꾼 항목 (파란 막대표시).         |
| **`Instantiate()`** | 게임 실행 중 코드로 사본(붕어빵)을 찍어내는 유니티 핵심 생성 함수.             |
| **`Destroy()`** | 사본을 파괴하도록 **'예약'** 하는 함수.                           |

## 3. 세부 개념 및 원리

### 3.1 프리팹 만들고 고치기
1. **만들기**: 하이어라키 창에 예쁘게 조립된 게임 오브젝트를 마우스로 잡고 프로젝트(Project) 창 `Assets` 폴더로 드래그 앤 드롭하면 파란색 상자 모양의 프리팹 파일이 생성됩니다.
2. **고치기 (Open vs Override)**:
    * **[정석] 프리팹 모드 진입**: 프리팹 에셋을 더블클릭하면 시퍼런 전용 방(프리팹 모드)으로 들어갑니다. 여기서 고치면 **모든 사본이 동시에 똑같이 바뀝니다.**
    * **[덮어쓰기] 씬에서 개별 수정**: 씬에 널려있는 사본 중 하나만 잡고 크기를 키우면 그 녀석의 인스펙터에 **파란색 막대(Override)** 가 생깁니다. 얘는 원본 틀을 고쳐도 더 이상 크기가 따라 변하지 않는 '이단아'가 됩니다. 이단아의 수정을 취소하려면 우클릭 후 `Revert`, 원본 틀 전체에 적용해 버리려면 `Apply`를 누릅니다.

### 3.2 중첩 프리팹과 프리팹 배리언트(Variant)
* **중첩 프리팹 (Nested)**: '로봇' 프리팹의 자식으로 '머신건' 프리팹이 끼워져 있는 상태입니다. 머신건 틀을 고치면 모든 로봇의 총이 다 바뀝니다.
* **배리언트 (Variant)**: 일반 오크(원본) 프리팹을 우클릭하여 `Create ➔ Prefab Variant`를 누르면, 원본의 유전자를 물려받은 '돌연변이 프리팹'이 생깁니다. 체력과 피부색(오버라이드)만 빨간색으로 고쳐서 **'엘리트 오크'** 로 관리합니다. 나중에 원본 오크의 '공격력'을 올리면 빨간 오크도 유전자를 물려받아 공격력이 오르는 객체 지향 구조입니다

### 3.3 코드로 프리팹 찍어내기 (`Instantiate`)
프리팹은 에셋이므로 `[SerializeField]`로 빈 슬롯을 파고 인스펙터에서 직접 끌어다 꽂습니다.
```csharp
// [팁] GameObject로 받지 말고, 내가 진짜 쓸 클래스(컴포넌트) 타입으로 바로 받으세요
[SerializeField] private Bullet _bulletPrefab; 
[SerializeField] private Transform _spawnPoint;

void Shoot()
{
    // 1. 가장 기본: 월드 좌표 (0,0,0)에 부모 없이 덜렁 생성
    Bullet a = Instantiate(_bulletPrefab);

    // 2. 부모 지정: 사본을 찍어내면서 특정 오브젝트의 자식으로 집어넣기
    Bullet b = Instantiate(_bulletPrefab, transform); 

    // 3. 완벽한 위치 지정: 원하는 좌표와 회전값을 주면서 찍어내기
    Bullet c = Instantiate(_bulletPrefab, _spawnPoint.position, _spawnPoint.rotation);
}
```
*(참고: 회전을 안 주고 싶을 때는 `Quaternion.identity`라고 적습니다.)*

### 3.4 자식으로 낳을 때 발생하는 좌표의 배신
`Instantiate(prefab, parent)`를 쓰면 가장 많이 하는 질문이 나옵니다.
> **"부모를 지정해 줬는데 왜 부모 위치로 안 태어나고 이상한 허공에 떠 있죠?"**

사본이 태어날 때, 사본의 **로컬 좌표(localPosition)** 는 프리팹 원본 파일에 저장되어 있던 이상한 좌표를 그대로 가져옵니다. 부모를 만나서 그 좌표가 월드 기준으로 뻥튀기되니 엉뚱한 곳에 맺히는 것입니다.\
따라서 **부모품 정중앙에 정확히 안기게 하려면 반드시 태어난 직후 `localPosition = Vector3.zero;`로 교정을 해줘야 합니다**
```csharp
// 부모(Gun)의 자식으로 총알을 생성
Bullet bullet = Instantiate(_bulletPrefab, gunTransform);

// 척추 교정: "네 로컬 좌표를 부모품 정중앙(0,0,0)으로 강제 리셋한다"
bullet.transform.localPosition = Vector3.zero; 
```

## 4. 실전 활용: 데이터 테이블 대신 프리팹 꽂기

2048이나 머지(Merge) 게임처럼 같은 레벨의 사물 두 개가 만나 상위 레벨로 진화하는 로직입니다. 복잡한 엑셀 파일 없이 **배열의 순서(Index)** 를 계약으로 삼아 게임을 굴립니다.
```csharp
public class MergeManager : MonoBehaviour
{
    // 인덱스 0 = 레벨 1 프리팹, 인덱스 1 = 레벨 2 프리팹... (암묵적 약속)
    [SerializeField] private GameObject[] _ballPrefabs;

    // 공 두 개가 부딪혔을 때 합쳐주는 함수
    public void Merge(GameObject ballA, GameObject ballB, int currentLevel)
    {
        // 1. 다음 진화할 단계 (현재가 1레벨이면 다음은 2레벨)
        int nextLevelIndex = currentLevel; // (인덱스는 0부터 시작하므로 currentLevel 값과 일치)

        if (nextLevelIndex >= _ballPrefabs.Length) return; // 최고 레벨이면 무시

        // 2. 두 공의 정중앙 좌표 계산
        Vector3 centerPos = (ballA.transform.position + ballB.transform.position) / 2f;

        // 3. 삭제 예약 전에 무조건 화면에서 치워버리기
        // (안 치우면 파괴되는 1프레임 찰나에 제3의 공과 또 부딪혀 3단 합체 버그가 터짐)
        ballA.SetActive(false);
        ballB.SetActive(false);
        Destroy(ballA);
        Destroy(ballB);

        // 4. 진화된 공 생성
        Instantiate(_ballPrefabs[nextLevelIndex], centerPos, Quaternion.identity);
    }
}
```

## 5. Unity 최적화: 오브젝트 풀링 (Object Pooling)

총알이나 이펙트를 매 프레임 `Instantiate`로 찍어내고 `Destroy`로 박살 내면, 유니티의 가비지 컬렉터(GC)가 비명을 지르며 게임에 끊김(스파이크 렉)이 발생합니다.\
**실무에서는 게임 로딩 창이 떠 있을 때 미리 수백 개를 만들어 둔 뒤(예열), 껐다 켰다 하면서 재활용(풀링)합니다.**

### 기초적인 오브젝트 풀의 순환 구조
```csharp
public class SimpleBulletPool : MonoBehaviour
{
    [SerializeField] private GameObject _bulletPrefab;
    [SerializeField] private int _poolSize = 50;

    // 사용 대기 중인 총알들이 쉬고 있는 대기실(Queue)
    private Queue<GameObject> _bulletQueue = new Queue<GameObject>();

    private void Start()
    {
        // 1. 예열(Warm-up): 게임 시작 시 50개를 미리 찍어내서 비활성화 해둔다.
        for (int i = 0; i < _poolSize; i++)
        {
            GameObject bullet = Instantiate(_bulletPrefab, transform); // 씬 안 어지럽게 내 자식으로 모음
            bullet.SetActive(false); // 휴식 상태
            _bulletQueue.Enqueue(bullet); // 대기실 입장
        }
    }

    // 2. 발사 (대여): 총알 줘
    public GameObject GetBullet(Vector3 spawnPos)
    {
        if (_bulletQueue.Count == 0) return null; // 총알 다 떨어짐

        GameObject bullet = _bulletQueue.Dequeue(); // 대기실에서 하나 뽑음
        bullet.transform.position = spawnPos;
        bullet.SetActive(true); // 활성화 (총알 날아감)
        return bullet;
    }

    // 3. 파괴 대신 반납(Return): 총알이 벽에 맞았을 때
    public void ReturnBullet(GameObject bullet)
    {
        bullet.SetActive(false); // Destroy 대신 화면에서 안 보이게 끄기만 함
        _bulletQueue.Enqueue(bullet); // 다시 대기실로 반납. 무한 재활용
    }
}
```
*(참고: 유니티 2021부터는 엔진 내부에 `UnityEngine.Pool.ObjectPool`이라는 훌륭한 내장 기능이 생겼으므로, 실무에서는 이 내장 API를 주로 씁니다.)*

## 6. 실습 문제 및 복습

**Q1. `Instantiate` 함수를 사용할 때 반환받을 변수를 `GameObject` 대신 `Bullet`과 같은 스크립트(컴포넌트) 타입으로 곧바로 받으면 어떤 큰 장점이 있나요?**
> `GameObject`로 받게 되면, 생성 직후 그 총알의 데미지나 발사 함수를 부르기 위해 비싼 연산인 `GetComponent<Bullet>()`을 또 강제로 한 번 호출해야 합니다.\
> 반면 인스펙터 슬롯 자체를 `Bullet` 컴포넌트 타입으로 연결해 두고 `Instantiate`하면 제네릭 오버로드 덕분에 타입 캐스팅 없이 총알 스크립트를 즉시 제어할 수 있어 성능과 코드 길이가 압도적으로 절약됩니다.

**Q2. `Destroy(gameObject);` 를 호출한 바로 아랫줄에 `gameObject.transform.position = Vector3.zero;` 라는 코드를 적으면 에러가 날까요? 나지 않는다면 유니티의 렌더링 파이프라인 상 어떤 이유 때문인가요?**
> **에러가 나지 않고 정상적으로 좌표가 이동합니다.** 유니티에서 `Destroy` 명령은 냅다 즉결 처형하는 것이 아니라, 엔진에게 "이번 1프레임 렌더링과 물리 연산이 싹 다 끝나고 나면 제일 마지막에 얘 좀 지워줘"라고 메모장에 **파괴 예약**만 걸어두는 함수입니다.\
> 따라서 그 프레임 안에서는 버젓이 살아 숨 쉬며 코드가 멀쩡하게 작동합니다.

**Q3. 게임 내에 배치된 30개의 코인(프리팹 인스턴스) 중 유독 1개만 다른 코인들과 색깔이 다릅니다. 원본 코인 프리팹을 더블클릭(프리팹 모드)하여 황금색으로 색을 바꿨는데도, 그 1개의 코인은 여전히 은색을 유지하고 있습니다. 원인이 무엇인가요?**
> 씬에 배치된 그 1개의 코인을 클릭해 보면, 누군가 인스펙터에서 강제로 은색으로 색상을 수정(덮어쓰기)하여 파란색 막대가 그어진 **'오버라이드(Override)'** 상태가 되어 있을 것입니다.\
> 오버라이드된 속성은 원본 틀(프리팹)의 유전자보다 항상 우선하기 때문에 원본을 아무리 고쳐도 바뀌지 않습니다. 해당 속성을 우클릭하고 `Revert`를 눌러서 덮어쓰기를 취소해야 원본의 황금색을 따라가게 됩니다.

## 7. 주의사항 및 안전 습관

* **NullReference를 막지 마라**: 인스펙터 프리팹 연결 슬롯(`_bulletPrefab`)을 비워뒀을 때, 친절하게 `if(prefab == null) return;`으로 덮어두면 안 됩니다. 조용히 총알이 안 나가는 버그는 원인을 찾기 너무 힘듭니다. 냅다 빨간 에러를 뿜으며 게임이 멈춰버리게 놔두어야 프로그래머가 인스펙터를 확인하고 즉시 연결 고리를 꽂을 수 있습니다.
* **비활성화 후 `Destroy` 콤보**: 죽어가는 몬스터나 융합되는 공을 파괴할 때는, 1프레임 뒤에 터지는 `Destroy` 특성상 시체가 제3의 공격을 또 맞고 버그를 낼 수 있습니다. 무조건 파괴 선고 전에 `gameObject.SetActive(false);`를 콤보로 갈겨서 물리 충돌과 렌더링에서 즉시 도려내세요.
* **프리팹 슬롯에 씬 오브젝트 꽂기 금지**: 씬 하이어라키 창에 널브러져 있는 오브젝트를 인스펙터 `Prefab` 슬롯에 꽂아도 `Instantiate`가 작동하긴 합니다. 하지만 이건 미친 짓입니다. 그 씬을 벗어나면 복제 원본이 사라져 에러가 터지고 메모리 낭비가 극심해집니다. 설계도(Prefab)는 무조건 씬 바깥인 `Project ➔ Assets` 폴더 안에 박혀 있어야 합니다.
