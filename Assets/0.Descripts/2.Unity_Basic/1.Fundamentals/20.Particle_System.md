# [Fundamentals] 20. Particle System (Built-in)

## 1. Particle System 이란?
> **불꽃 한 덩이와 불티 하나**
> * 타오르는 불꽃 한 덩어리를 통째로 코드로 그리려고 하면 막막합니다.
> * 그런데 아주 작은 **불티 하나(Particle)** 는 쉽습니다. "위로 오르다가, 흐려지다가, 사라진다."
> * 이 불티를 초당 200개씩 만들어 조금씩 다르게 던지면 우리 눈에는 거대한 화염으로 보입니다.
> * `Particle System`은 이 불티 하나의 **'규칙'** 만 인스펙터에서 정해 두면, 나머지는 엔진이 알아서 수천 개를 반복 생성해 주는 화려한 마법 상자입니다.

**왜 필요한가? (직접 구현의 한계)**
폭발 파편을 `GameObject`로 직접 만들고 코루틴을 돌려 날려 보낸다고 가정해 봅시다.
1. **관리 지옥**: 파편 50개가 터지면, 50개의 오브젝트 수명을 코드가 다 기억하고 지워야 합니다.
2. **단조로움**: 50개가 똑같은 속도로 날아가면 폭발이 아니라 기하학 도형 전개도처럼 보입니다.
3. **조정의 고통**: 파편이 빠른지 느린지 확인하려면 코드를 고치고 매번 유니티의 Play 버튼을 눌러야 합니다.
4. **성능 폭발**: 파편 500개는 곧 `GameObject` 500개입니다. 몬스터 10마리가 동시에 죽으면 프레임이 바닥을 칩니다.

`Particle System`은 수천 개의 파티클을 무거운 `GameObject`가 아닌 **가벼운 알맹이 데이터**로 취급하여 이 모든 문제를 컴포넌트 하나로 해결합니다.

## 2. 핵심 요약

| 모듈(Module) | 하는 일 | 대표 설정 값 |
| :--- | :--- | :--- |
| **Main (기본)** | 파티클 전체의 수명, 속도, 크기 등 뼈대 | `Start Lifetime`, `Start Speed` |
| **Emission** | 한 번에 몇 개를 터뜨릴지, 초당 몇 개 뿜을지 | `Rate over Time`, `Bursts` |
| **Shape** | 어떤 모양(원, 뿔)의 범위에서 어떤 방향으로 쏠지 | `Cone`, `Circle`, `Sphere` |
| **Over Lifetime**| 살아있는 동안 변하는 곡선 데이터 (색상, 크기) | `Color / Size over Lifetime` |
| **Renderer** | 어떤 그림(Material)으로, 스프라이트 기준 앞뒤 어디에 그릴지 | `Sorting Layer`, `Order in Layer` |

> **[원칙]**
> 1. `Duration`(시스템이 뿜어내는 총 시간)과 `Start Lifetime`(알맹이 하나가 살아있는 시간)을 헷갈리지 마세요.
> 2. 고정된 숫자(상수) 1개를 쓰지 말고, 우측 화살표를 눌러 **'두 값 사이의 무작위(Random Between Two Constants)'** 를 쓰는 것이 이펙트를 자연스럽게 만드는 핵심입니다.
> 3. 달리는 캐릭터의 먼지 이펙트가 캐릭터를 쫓아온다면 `Main` 모듈의 **`Simulation Space`를 `World`로** 바꾸세요.

## 3. 세부 개념 및 원리

### 3.1 가장 많이 헷갈리는 시간 개념
둘 다 단위가 '초(Second)'라서 많이 헷갈립니다.

* **`Duration` (5초)** : 팝콘 기계가 팝콘을 튀겨내는 시간입니다. 5초 동안 뿜어내고 기계는 멈춥니다.
* **`Start Lifetime` (2초)** : 튀어나온 팝콘 한 알이 바닥에 떨어져 썩어 사라지는 시간입니다.
* ➔ **결론**: 기계가 5초에 멈춰도 마지막에 튀어나온 팝콘은 2초 더 살아있습니다. 이펙트가 화면에서 완전히 사라지는 시간은 대략 **`Duration + Start Lifetime` (7초)** 입니다!

### 3.2 2D 게임의 단골 모듈 세팅
모듈이 20개가 넘지만, 2D 게임에서는 주로 아래 설정들만 만집니다.

* **[Shape]** : 3D용인 `Cone`이나 `Sphere`를 쓰면 2D 카메라 앞뒤로 파티클이 퍼져 찌그러져 보입니다. 2D에서는 **`Circle`** 이나 **`Edge`** 를 씁니다.
* **[Color over Lifetime]** : 파티클이 끝에서 자연스럽게 스르륵 투명해지려면(Fade-Out), 여기서 상단 화살표(Alpha)의 오른쪽 끝 점을 0으로 깎아 내립니다.
* **[Renderer]** : 이펙트가 맵이나 캐릭터 뒤로 숨어버린다면, `Sorting Layer`를 `Effect` 같은 최상위 레이어로 지정해 주어야 합니다.

### 3.3 C# 코드로 파티클 제어하기 (구조체의 비밀)
코드에서 재생과 정지는 직관적입니다.
```csharp
ParticleSystem ps = GetComponent<ParticleSystem>();

ps.Play();  // 재생
ps.Stop();  // 방출 중지 (남은 파티클은 자연스레 죽음)
ps.Clear(); // 화면에 남은 파티클 즉시 싹 다 지움
```

하지만, 코드에서 모듈 안의 세부 수치(예: 시작 속도)를 바꿀 때는 **C# 문법의 함정**이 존재합니다.
```csharp
// 컴파일 에러 발생
ps.main.startSpeed = 5f; 

// 정석: 지역 변수에 모듈 복사본을 담아서 수정한다
var main = ps.main;
main.startSpeed = 5f; 
```
> **왜 윗줄은 에러가 나나요?**\
> `ps.main`은 클래스가 아니라 **구조체(Struct)** 복사본을 던져줍니다. C# 컴파일러는 "어차피 임시 복사본 값 바꿔봤자 진짜 파티클엔 적용 안 되고 날아갈 텐데?"라며 에러로 막아버립니다.\
> 하지만 유니티는 지역 변수 `var main` 구조체 내부에 C++ 엔진을 가리키는 **포인터**를 심어두었습니다. 그래서 지역 변수의 값을 고치면 그 포인터를 타고 진짜 엔진 속 파티클 설정이 마법처럼 바뀝니다

## 4. 코드로 보기

몬스터가 죽을 때 파편을 뿌리는 로직을 수동으로 짰을 때와, 파티클 시스템에 맡겼을 때의 비교입니다.

### 잘못된 방법 (GameObject + Coroutine 하드코딩)
```csharp
public class ManualExplosion : MonoBehaviour
{
    [SerializeField] private GameObject _fragmentPrefab; // 파편 스프라이트
    
    public void Explode()
    {
        for (int i = 0; i < 30; i++) // 파편 30개를 생성함
        {
            GameObject frag = Instantiate(_fragmentPrefab, transform.position, Quaternion.identity);
            
            // 방향과 힘을 일일이 수학으로 계산 (Shape + Start Speed 모듈 흉내내기)
            float angle = Random.Range(0f, 360f);
            Vector2 dir = new Vector2(Mathf.Cos(angle * Mathf.Deg2Rad), Mathf.Sin(angle * Mathf.Deg2Rad));
            
            // 파편마다 코루틴을 돌려서 투명도(Alpha)를 깎음 (가비지 폭발)
            StartCoroutine(FadeOutAndDestroy(frag, dir * 3f)); 
        }
    }
}
```

### 정석 방법 (Particle System 프리팹 1개 호출)
```csharp
public class EnemyDeath : MonoBehaviour
{
    // 인스펙터에서 폭발 파티클 프리팹을 끌어다 놓습니다.
    [SerializeField] private ParticleSystem _explosionPrefab; 

    public void Die()
    {
        // 프리팹의 [Play On Awake]가 켜져 있으므로, 낳자마자 스스로 30개를 펑 터뜨림.
        Instantiate(_explosionPrefab, transform.position, Quaternion.identity);
        Destroy(gameObject); // 몬스터는 사망
    }
}
```
* **프리팹 설정**: `Emission`의 `Rate over Time`은 0으로 끄고, **`Bursts`** 에 30을 넣으면 한방에 터집니다.
* **자동 삭제**: `Main` 모듈 맨 밑의 **`Stop Action`을 `Destroy`로** 두면, 폭발이 끝나고 이펙트 찌꺼기가 남지 않고 스스로 자결합니다! (추가 코딩 필요 없음)

## 5. 실전 활용 예시: 파티클에 맞으면 불 꺼지기 (Collision)

물총을 쏴서 파티클(물방울)이 모닥불 콜라이더에 닿았을 때만 로직을 처리하는 코드입니다.
* 조건: 인스펙터 `Collision` 모듈에서 `Type`을 2D로, **`Send Collision Messages`** 를 체크해야 합니다.

```csharp
public class WaterSplash : MonoBehaviour
{
    // "물방울 몇 개" 가 아니라 "물방울이 닿아 있던 프레임 수" 입니다
    [SerializeField] private int _touchedFramesToExtinguish = 30;
    private int _touchedFrames;

    // Send Collision Messages가 켜져 있어야 엔진이 이 함수를 찔러줍니다.
    private void OnParticleCollision(GameObject other)
    {
        // 주의: 파티클 100개가 한 번에 닿아도 이 함수는 '1프레임당 1번'만 불립니다.
        _touchedFrames++;

        if (_touchedFrames < _touchedFramesToExtinguish) return; // 아직 물이 덜 묻음

        // 닿은 상대방이 캠프파이어라면 불을 끈다
        if (other.TryGetComponent(out Campfire campfire))
            campfire.Extinguish();

        _touchedFrames = 0; // 초기화
    }
}
```
* **성능 팁**: 물방울 수천 개가 맵 전체를 스캔하면 렉이 걸립니다. `Collision` 모듈의 `Collides With`에서 몬스터나 불꽃 등 **반응할 레이어만 한정**시켜야 프레임 저하를 막습니다.

## 6. Unity 최적화 팁 (VFX 풀링)

적 30마리가 한 번에 광역 마법에 맞아 죽으면 `Instantiate`가 30번 불리면서 순간적으로 게임이 끊깁니다(Spike). 이럴 땐 자주 쓰는 타격 이펙트를 **오브젝트 풀(Object Pool)** 로 관리해야 합니다.

* **[설정 팁]**: 프리팹의 `Stop Action`을 `Destroy`가 아니라 **`Disable`** 로 바꿉니다. 파티클이 재생을 마치면 파괴되지 않고 화면에서 비활성화(`SetActive(false)`)됩니다.
* **[풀링 로직]**: 꺼진 이펙트를 다시 대기열(Queue)로 주워와서 반납 처리(`Return`)합니다.
* **[재사용 팁]**: 다시 꺼내 쓸 때는 예전 파편이 1프레임 깜빡거리는 현상을 막기 위해, 켜기 전에 **`effect.Clear();`** 로 찌꺼기를 날려준 뒤 **`effect.Play();`** 를 호출해야 깔끔하게 새것처럼 터집니다.

## 7. 실습 문제 및 복습

**Q1. `Main` 모듈의 `Gravity Modifier` 값이 1일 때와, 인스펙터 아래쪽의 `Velocity over Lifetime`에서 Y축으로 힘을 주었을 때의 시각적인 차이는 무엇인가요?**
> `Gravity Modifier`는 파티클 전체에 실제 중력(포물선)을 부여하여 위로 튀어 올랐다가 아래로 떨어지게 만듭니다.\
> 반면 `Velocity over Lifetime`은 매 프레임 정해진 방향으로 강제 이동(등속 운동 등)을 시키는 것이라, 포물선을 그리지 않고 계속 그 방향으로 둥둥 떠가게 됩니다. (연기 같은 이펙트에 적합).

**Q2. 자동차 배기구에서 나오는 연기를 만들었는데, 자동차가 앞으로 달리면 연기가 뒤로 안 남고 자동차 배기구 끝에 뭉쳐서 같이 따라다닙니다. 어느 모듈의 어떤 옵션을 고쳐야 하나요?**
> `Main` 모듈 중간에 있는 **`Simulation Space`** 값이 `Local`로 되어 있기 때문입니다.\
> 이를 **`World`** 로 바꿔주면, 연기가 태어난 월드 좌표의 허공에 그대로 머물며 뒤로 흩날리는 궤적을 그리게 됩니다.

**Q3. 코드에서 `ps.Stop();` 을 호출했는데 뿜어져 나오던 폭발 파티클이 그 자리에서 멈추지 않고 계속 날아가서 끝까지 재생된 후 사라집니다. 화면에서 즉시 싹 지워버리려면 어떤 함수를 추가로 호출해야 하나요?**
> `Stop()`은 "지금부터 새로운 파티클(알맹이)의 방출(Emission)을 중단해라"라는 명령입니다.\
> 이미 공중에 태어나버린 알맹이들은 자기 수명(`Start Lifetime`)을 다할 때까지 살아남습니다. 화면에서 1프레임 만에 찌꺼기까지 싹 지워버리려면 **`ps.Clear();`** 를 호출해야 합니다.

## 8. 주의사항 및 안전 습관

* **곡선과 그라데이션은 에디터에서**: 웬만하면 C# 코드로 `AnimationCurve`를 짜지 마세요. 결과를 눈으로 볼 수 없어서 이펙트 타이밍 맞추는 데 하루 종일 걸립니다. 세세한 곡선은 인스펙터(에디터)에서 마우스로 그리고, 코드는 켜고 끄기(`Play`/`Stop`)나 색상(`Start Color`) 정도만 건드려야 합니다.
* **Playback Speed 활용하기**: 빠르고 짧게 터지는 이펙트는 에디터에서 타이밍 맞추기가 힘듭니다. 씬 뷰 우측 하단의 `Particle Effect` 창에서 **`Playback Speed`를 0.1~0.2 배속으로 늦춰놓고 눈으로 보면서** 색상이나 크기가 변하는 타이밍(Over Lifetime)을 깎는 것이 원칙입니다.
* **Max Particles 조절**: 기본값이 1000개로 잡혀있습니다. 아주 사소한 흙먼지인데 1000개까지 설정되어 있으면, 방출량을 실수로 높였을 때 메모리가 낭비됩니다. 이펙트 규모에 맞게 상한선을 30~100개 사이로 빡빡하게 잠가두는(`Capping`) 습관을 들이세요.
