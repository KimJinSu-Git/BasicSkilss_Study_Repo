# [Fundamentals] 9. SpriteRenderer (스프라이트 렌더러)

## 1. SpriteRenderer 란?
> **그림 조각과 그것을 붙이는 손**
> * **Sprite**는 오려낸 '그림 조각'입니다.
> * **SpriteRenderer**는 그 조각을 무대(화면)에 붙이는 '손'입니다.
> * `Transform`이 "어디에" 붙일지를 정한다면, `SpriteRenderer`는 **"무엇을 · 어떤 색으로 · 몇 번째로"** 붙일지를 정합니다.

**왜 필요한가?**\
`GameObject`는 텅 빈 상자입니다. `Transform`으로 위치와 크기를 정해줘도, 그 자리에 "무엇을 그릴지" 아는 컴포넌트가 없으면 화면에는 아무것도 나타나지 않습니다. 2D 게임에서 이 시각화를 전담하는 필수 부품이 바로 `SpriteRenderer`입니다.

3D 게임은 카메라와의 거리(Z축)가 앞뒤를 자동으로 정해주지만, 2D는 모든 그림이 같은 평면 위에 겹쳐 있으므로 **"누가 더 앞에 오는가(정렬 순서)"** 를 사람이 직접 정해주어야 합니다. 따라서 이 컴포넌트는 '그리기'와 '정렬하기'라는 두 가지 핵심 역할을 수행합니다.

---

## 2. 핵심 요약

| 역할 | 대표 멤버 (C#) | 인스펙터 항목 |
| :--- | :--- | :--- |
| **무엇을 그리는가** | `sprite` | Sprite |
| **어떤 색으로 그리는가** | `color` | Color |
| **어느 쪽을 보게 하는가**| `flipX` / `flipY` | Flip X / Flip Y |
| **크기가 변할 때 규칙** | `drawMode` / `size` | Draw Mode |
| **몇 번째로 그리는가** | `sortingLayerName`, `sortingOrder` | Sorting Layer, Order in Layer |
| **무엇에 가려지는가** | `maskInteraction` | Mask Interaction |

* **색상(Color)은 원본 픽셀에 '덮어씌우는' 것이 아니라 '곱해지는(Tint)' 것입니다.** 흰색이 기본값인 이유는 1을 곱해 원본을 그대로 보여주기 때문입니다.
* **2D의 앞뒤 정렬은 Z 좌표가 아니라 Sorting Layer와 Order in Layer로 정합니다.**
* **충돌은 렌더러와 철저히 무관합니다.** 그림을 뒤집거나 바꾼다고 해서 `Collider2D`의 형태나 위치가 자동으로 따라 바뀌지 않습니다

## 3. 세부 개념 및 원리

### 3.1 인스펙터 항목의 이해
`SpriteRenderer`는 스스로 그림 데이터를 갖지 않고, 프로젝트 내의 `Sprite` 에셋을 가리킬 뿐입니다. (PNG 이미지를 넣고 Texture Type을 `Sprite (2D and UI)`로 바꿔야 슬롯에 넣을 수 있습니다.)

* **Color**: 원본 색상에 특정 색을 곱합니다(Tint). 피격 시 빨갛게 번쩍이거나, 독에 걸려 초록색으로 변할 때 씁니다.
* **Flip**: 그림의 좌우(X)나 상하(Y)를 뒤집습니다. 캐릭터가 뒤돌아볼 때 가장 가볍게 쓰는 방법입니다.
* **Sprite Sort Point**: 앞뒤를 가릴 때, 거리를 재는 기준점입니다. 탑다운 게임에서 캐릭터가 겹칠 때는 기본값(Center) 대신 발밑(`Pivot`)으로 두어야 자연스럽게 가려집니다.

### 3.2 색상(Color)의 진실: 0~255가 아니라 0.0~1.0 입니다
유니티의 `Color` 구조체는 R, G, B, A(투명도) 네 값으로 이루어지며, **각 값은 0.0f ~ 1.0f 사이의 실수**입니다.
이유는 색을 '비율'로 곱하기 때문입니다. 1.0은 100%(그대로), 0.5는 50%(어둡게), 0.0은 0%(색상 제거)입니다.

```csharp
Color skyBlue = new Color(0.2f, 0.6f, 1f);        // 불투명한 하늘색
Color halfBlue = new Color(0.2f, 0.6f, 1f, 0.5f); // 알파(A)값을 0.5로 주어 반투명하게
```

**[꿀팁] Hex 코드(#FFFFFF) 변환하기**\
디자이너가 주는 색상은 보통 `#FF5733` 같은 16진수입니다. 이를 코드로 쉽게 적용하려면 `ColorUtility`를 씁니다.
```csharp
if (ColorUtility.TryParseHtmlString("#FF5733", out Color myColor))
{
    sr.color = myColor; // Hex 문자열을 유니티 Color 객체로 변환
}
```
만약 정수(0~255)를 그대로 쓰고 싶다면 `Color` 대신 **`Color32`** 구조체를 사용하면 자동 변환됩니다.

### 3.3 정렬 순서 (Sorting Layer & Order in Layer)
2D 공간의 앞뒤는 Z 좌표가 아니라 2가지 설정값으로 결정됩니다.
1. **Sorting Layer**: 큼직한 그룹입니다. (예: `Background` ➔ `Default` ➔ `Character` ➔ `UI`)
2. **Order in Layer**: 같은 그룹 내에서의 순서입니다. (숫자가 클수록 유저 눈에 가깝게, 즉 앞에 그려집니다.)

```csharp
sr.sortingLayerName = "Character";
sr.sortingOrder = 5; 
```

### 3.4 9분할 렌더링 (Sliced Draw Mode)
말풍선이나 플랫폼 지형처럼, 크기를 늘렸을 때 "가장자리 테두리는 뭉개지지 않고 가운데만 늘어나게" 하고 싶을 때 사용합니다.
* **적용 조건**:
    1. 스프라이트 에셋의 `Mesh Type`을 `Full Rect`로 설정.
    2. Sprite Editor에서 `Border`를 지정해 늘어나지 않을 테두리 영역 설정.
* **코드 적용**: 크기를 키울 때 `transform.localScale`이 아니라 **`sr.size`** 속성을 직접 늘려야 테두리가 유지됩니다.

```csharp
sr.drawMode = SpriteDrawMode.Sliced;
sr.size = new Vector2(4f, 1f); // Transform 스케일이 아닌 Size를 제어!
```

## 4. 코드로 보는 위력 (피격 점멸 시스템)

캐릭터가 맞았을 때 잠시 빨갛게 깜빡거리는 연출을 작성합니다.
이때 `Color.white`로 무작정 되돌리면, 캐릭터가 원래 가지고 있던 틴트 색상이나 반투명도가 전부 날아가는 참사가 발생합니다.

### 안전한 점멸 코드 (원본 색상 보존 + 코루틴 클린업)
```csharp
using System.Collections;
using UnityEngine;

[RequireComponent(typeof(SpriteRenderer))]
public class HitBlink : MonoBehaviour
{
    [SerializeField] private Color hitColor = Color.red;
    [SerializeField] private int blinkCount = 3;
    [SerializeField] private float blinkInterval = 0.05f;

    private SpriteRenderer _sr;
    private Color _originalColor; // 현재 오브젝트의 고유 틴트/알파를 기억해둘 변수
    private Coroutine _blinkCoroutine;

    private void Awake()
    {
        _sr = GetComponent<SpriteRenderer>();
        _originalColor = _sr.color; // 태어날 때의 색을 영구 기억
    }

    public void OnHit()
    {
        // 연타로 맞았을 때 점멸이 중첩되지 않도록 기존 코루틴을 끊어준다
        if (_blinkCoroutine != null) StopCoroutine(_blinkCoroutine);
        _blinkCoroutine = StartCoroutine(BlinkRoutine());
    }

    private IEnumerator BlinkRoutine()
    {
        for (int i = 0; i < blinkCount; i++)
        {
            _sr.color = hitColor;
            yield return new WaitForSeconds(blinkInterval);
            _sr.color = _originalColor;
            yield return new WaitForSeconds(blinkInterval);
        }
        _blinkCoroutine = null; // 완료 후 깔끔하게 핸들 비우기
    }

    // 점멸 도중 캐릭터가 죽어서 비활성화될 경우를 대비한 안전장치
    private void OnDisable()
    {
        if (_sr != null) _sr.color = _originalColor; // 굳어버린 빨간색을 원상 복구
        _blinkCoroutine = null;
    }
}
```

## 5. 실전 활용 예시 (좌우 반전과 알파 페이드)

플레이어의 이동 방향에 따라 그림을 뒤집고, 은신 스킬을 썼을 때 반투명하게 만드는 컴포넌트입니다.

```csharp
using UnityEngine;

[RequireComponent(typeof(SpriteRenderer))]
public class CharacterVisuals : MonoBehaviour
{
    private SpriteRenderer _sr;

    private void Awake() => _sr = GetComponent<SpriteRenderer>();

    // 1. 이동 방향에 따른 좌우 반전 (물리 콜라이더에는 영향 없음)
    public void FaceDirection(float moveX)
    {
        if (Mathf.Abs(moveX) < 0.01f) return; // 제자리걸음일 땐 기존 방향 유지
        
        // 왼쪽(음수)으로 가면 flipX를 true로 켠다
        _sr.flipX = moveX < 0f; 
    }

    // 2. 투명도(알파) 조절 로직
    public void SetFade(float alpha)
    {
        // sr.color.a = alpha; (컴파일 에러. Color는 구조체라 직접 수정 불가)
        
        Color c = _sr.color;           // 1. 통째로 꺼내고
        c.a = Mathf.Clamp01(alpha);    // 2. 값을 수정하고 (0~1 사이 안전하게 고정)
        _sr.color = c;                 // 3. 통째로 덮어씌운다
    }
}
```

## 6. Unity 최적화 팁

### 6.1 `flipX` vs `localScale.x = -1` (보이는 것과 부딪히는 것은 남남이다)
유니티에서 **그림을 그리는 것(`SpriteRenderer`)과 물리적으로 부딪히는 것(`Collider2D`)은 철저히 별개의 시스템**입니다.
* **`sr.flipX = true;`** : 오직 렌더링(그림)만 거울처럼 뒤집힙니다. 캐릭터가 오른손에 쥐고 있던 칼의 `Collider`는 여전히 오른쪽에 남아있습니다. 그림만 뒤집힌 채 허공에서 칼이 맞는 기괴한 버그가 발생할 수 있습니다. 단순한 연출에 가볍게 쓰기 좋습니다.
* **`transform.localScale = new Vector3(-1, 1, 1);`** : 캐릭터 오브젝트 통째로(자식들까지 전부) 뒤집어 버립니다. 들고 있는 무기 콜라이더 위치나 총구의 발사 위치까지 완벽하게 좌우 대칭이 되어야 한다면 **스케일을 반전시키는 것이 정석**입니다.

### 6.2 화면에 보일 때만 연산하기 (`isVisible`)
`SpriteRenderer`는 지금 카메라 화면에 자기가 노출되어 있는지를 판별하는 강력한 기능을 부모(`Renderer`)로부터 상속받아 들고 있습니다.
화면 밖에 나간 적의 AI나 무거운 연산을 잠시 멈춰두고 싶을 때 활용하세요.
```csharp
// 유니티 엔진이 알아서 화면에 들어올 때 / 나갈 때 콜백을 쏴줍니다.
private void OnBecameVisible() { /* 최적화 해제, AI 활성화 */ }
private void OnBecameInvisible() { /* 연산 일시정지, 또는 풀링 회수 */ }
```
*(주의: 씬 뷰(Scene View) 카메라에 비치고 있어도 `Visible`로 판정되니 테스트할 때는 씬 뷰 화면을 딴 데로 치워야 합니다.)*

## 7. 실습 문제 및 복습

**Q1. `SpriteRenderer`의 `Color` 값을 스크립트에서 수정할 때, 단순히 하얗게(`Color.white`) 돌려놓는 것이 왜 위험할 수 있나요?**
> 캐릭터가 기본적으로 은신 중이라 반투명(알파값 0.5) 상태였거나, 기획자가 인스펙터에서 틴트 컬러를 약간 어둡게 설정해 두었을 수 있습니다. 무작정 `Color.white`를 덮어씌우면 투명도와 고유 틴트 색상이 모두 초기화되어 버리므로, `Awake`에서 기존 `color` 변수를 미리 캐싱해두고 그 값으로 되돌리는 것이 안전합니다.

**Q2. `SpriteDrawMode.Sliced`를 사용하여 UI 말풍선의 가운데 부분만 늘어나게 조작했습니다. 그런데 늘려보니 말풍선의 둥근 테두리 모서리까지 같이 쭉 늘어나 뭉개졌습니다. 확인해야 할 2가지 원인은 무엇인가요?**
> 1. 해당 스프라이트 에셋의 임포트 세팅에서 `Mesh Type`이 `Tight`로 되어있는지 확인합니다. (`Full Rect`여야 슬라이싱이 작동합니다.)
> 2. 스크립트나 트랜스폼 툴로 크기를 늘릴 때 `transform.localScale`을 늘렸기 때문입니다. 스케일을 늘리면 9분할 무늬까지 같이 늘어납니다. 스케일은 (1,1,1)로 고정하고, **`sr.size`** 값을 조작해서 크기를 키워야 합니다.

**Q3. 2D 게임에서 두 캐릭터가 겹쳤을 때 누가 앞에 보일지 결정하는 우선순위 판정 기준을 순서대로 말해보세요.**
> 1순위: **Sorting Layer** (어느 그룹에 속해 있는가?)
> 2순위: **Order in Layer** (같은 그룹 내에서 숫자가 더 큰가?)
> 3순위: 위 두 개가 모두 같다면, **카메라와의 Z축 거리**(또는 `Sprite Sort Point` 기준 거리)로 결정됩니다.

## 8. 주의사항 및 안전 습관

* **`sr.color.a = 0.5f;` 접근 금지**: Color는 구조체(값 타입)이므로 내부 프로퍼티를 직접 수정할 수 없습니다. 변수에 `Color` 전체를 복사해서 빼낸 뒤, `a`를 수정하고 다시 통째로 덮어씌우세요.
* **`sortingLayerName`의 스펠링 오타 주의**: 층(Layer) 이름을 스트링으로 타이핑할 때 오타가 나면 컴파일러가 잡아주지 않고 조용히 `Default` 레이어로 던져버립니다. 하드코딩보다는 `public const string` 등으로 상수를 모아두고 쓰세요.
* **알파 0을 투명 인간 최적화로 착각하지 마라**: 투명도를 0으로 낮춰 눈에 안 보이게 만들어도 유니티는 "보이지 않는 투명한 그림을 계속 그리는" 연산을 수행합니다. 아예 숨길 거라면 렌더링 비용을 아끼기 위해 **`sr.enabled = false`** 로 컴포넌트를 직접 꺼주세요.
