# [Fundamentals] 16. New Input System 입문

## 1. New Input System 이란?
> **행동(Action) 중심의 번역기**
> * **[과거 Legacy]**: "지금 `W` 키 눌렸어?" 라고 키보드에게 직접 묻는 하드웨어 중심 방식.
> * **[현재 New]**: "지금 `전진(Forward)` 명령 들어왔어?" 라고 행동에게 묻는 논리 중심 방식.
> * 전진을 `W` 키로 할지, 게임패드의 스틱으로 할지, 폰의 터치 패드로 할지는 번역기(Input Action)가 알아서 처리합니다.

**왜 이걸 써야 하는가? (Legacy의 한계)**\
기존의 `Input.GetKeyDown(KeyCode.Space)` 방식은 너무나 직관적이고 편하지만, 조금만 게임이 커져도 지옥문이 열립니다.
1. **멀티 플랫폼 지옥**: 패드용 코드, 모바일 터치 코드를 전부 `if-else`로 따로 짜야 합니다.
2. **키 설정 변경 불가**: 유저가 "점프를 스페이스 말고 Z키로 바꿀래요"라고 옵션을 건드리는 순간, 모든 하드코딩된 `KeyCode`를 뜯어고쳐야 합니다.
3. **로컬 멀티플레이 불가**: 2P 모드를 만들 때, 키보드 한 개에서 누구의 입력인지 쪼갤 수단이 없습니다.

이 모든 문제를 **입력과 행동 사이에 이름을 붙인 층(`InputAction`)** 을 하나 끼워 넣음으로써 완벽하게 해결한 것이 New Input System입니다.

## 2. 핵심 요약

| 계층 (Layer) | 하는 일 | 대표 코드 / 에셋 |
| :--- | :--- | :--- |
| **장치 직접 읽기** | 레거시처럼 특정 장치를 하드코딩해서 상태 묻기 | `Keyboard.current.spaceKey.isPressed` |
| **액션 (`InputAction`)**| 입력을 '행동'으로 번역하여 값이나 이벤트로 받음 | `moveAction.ReadValue<Vector2>()` |
| **액션 에셋 (`.inputactions`)**| 어떤 키가 어떤 행동인지 맵핑해두는 설정 파일 | `PlayerInputActions` (에디터 생성 창) |
| **PlayerInput 컴포넌트**| 에셋을 인스펙터에서 편하게 꽂아주는 도우미 | `OnMove(InputValue value)` |

> **[입문자 주의사항]**
> * 설치 후 `Edit ➔ Project Settings ➔ Player ➔ Active Input Handling`을 **`Input System Package (New)`** 또는 **`Both`** 로 맞춰야 코드가 돌아갑니다. (에디터 재시작 필요)
> * New 모드로 바꾸는 순간 기존 UI 버튼 클릭이 먹통이 됩니다. 씬에 있는 `EventSystem` 오브젝트를 눌러서 **`Replace with InputSystemUIInputModule`** 버튼을 꼭 눌러줘야 UI가 부활합니다

## 3. 세부 개념 및 원리

### 3.1 1단계: 장치에서 직접 읽기 (하위 호환)
레거시 방식처럼 키보드를 직접 후벼 파서 묻는 방식입니다. 급할 때 씁니다.
```csharp
using UnityEngine.InputSystem; // 필수 네임스페이스

void Update()
{
    // 3가지 상태는 서로 배타적이지 않음 (else if로 엮으면 안 됨)
    
    // 1. 누른 그 1프레임 (GetKeyDown)
    if (Keyboard.current.spaceKey.wasPressedThisFrame) 
        Debug.Log("스페이스 막 누름");

    // 2. 누르고 있는 동안 내내 (GetKey)
    if (Keyboard.current.spaceKey.isPressed) 
        Debug.Log("스페이스 꾹~ 누르는 중");

    // 3. 손을 뗀 1프레임 (GetKeyUp)
    if (Keyboard.current.spaceKey.wasReleasedThisFrame) 
        Debug.Log("스페이스 뗌");
}
```

### 3.2 마우스 이동량(`delta`)의 함정
마우스로 카메라를 1인칭으로 돌리거나 드래그할 때 `delta(변화량)`를 씁니다.
```csharp
Vector2 moveDelta = Mouse.current.delta.ReadValue();
```
> 주의: delta는 이미 '이전 프레임 대비 움직인 픽셀량'이므로, 여기에 `Time.deltaTime`을 곱하면 절대 안 됩니다. 곱하는 순간 프레임이 높을수록 덜 움직이는 기괴한 역전 현상이 생깁니다.

### 3.3 액션 타입 (Button vs Value)
기획자가 에셋 창에서 행동(Action)을 만들 때 고르는 타입에 따라 코딩 방식이 180도 바뀝니다.

| 액션 타입  | 값의 성격            | 언제 performed 이벤트가 쏘아지나?                   |
|:-------|:-----------------|:------------------------------------------|
| Button | 단발성 (점프, 발사)     | 누르는 순간 `started -> performed` 가 파박 쏘아집니다    |
| Value  | 연속성 (WASD 2D 이동) | 값이 변할 때만 쏘아짐. (키를 꾹 누른 채로 가만히 있으면 이벤트 안 옴 |
* [결론]
  * 점프나 공격은 이벤트 구독(+=)으로 짭니다. 
  * 이동이나 조준은 무조건 `Update()` 안에서 `ReadValue<T>()`로 매 프레임 물어봐야(Polling) 합니다!

## 4. 코드로 보는 위력 (C# 래퍼 클래스 활용)
`InputActionAsset`을 에디터에서 만들고, 우측 인스펙터에서 `Generate C# Class`를 체크하면 유니티가 내가 쓸 전용 코드를 예쁘게 자동 생성해 줍니다.\
이 래퍼(Wrapper) 방식을 쓰는 것이 가장 안전하고 버그 없는 100% 정석입니다.

### 정석 이동/점프 코드
```csharp
using UnityEngine;
using UnityEngine.InputSystem;

public class PlayerController : MonoBehaviour
{
    private PlayerInputActions _input; // 자동 생성된 C# 클래스
    private Vector2 _moveDir;

    private void Awake()
    {
        _input = new PlayerInputActions(); // 래퍼 클래스 장착

        // 1. 단발성 점프는 람다식 콜백으로 이벤트 구독
        _input.Player.Jump.performed += ctx => Jump();
    }

    private void OnEnable() => _input.Enable();   // 입력 활성화 (필수)
    private void OnDisable() => _input.Disable(); // 입력 비활성화 (필수)

    private void OnDestroy()
    {
        // 래퍼 클래스 방식의 장점: 
        // 일일이 -= 로 이벤트를 해제할 필요 없이 Dispose() 한방이면 가비지/메모리릭 싹 청소됨
        _input.Dispose(); 
    }

    private void Update()
    {
        // 2. 연속적인 이동은 이벤트가 아니라 Update에서 매 프레임 값(Value)을 직접 캐물어야 함
        _moveDir = _input.Player.Move.ReadValue<Vector2>();
        
        transform.position += new Vector3(_moveDir.x, _moveDir.y, 0f) * 5f * Time.deltaTime;
    }

    private void Jump() { Debug.Log("점프"); }
}
```

## 5. 실전 활용 예시 (마우스 드래그로 조작하기)
머지 퍼즐 등에서 마우스로 발사대를 쥐고 드래그하는 조작입니다. 커서를 화면에 가두고 델타(변화량)만 쏙 빼먹는 고급 기법입니다.
```csharp
public class LauncherDragger : MonoBehaviour
{
    private void Update()
    {
        Mouse mouse = Mouse.current;
        if (mouse == null) return; // 모바일 등 마우스 없는 환경 방어

        // 1. 누른 순간: 마우스 포인터 숨기고 화면 중앙에 족쇄 채움
        if (mouse.leftButton.wasPressedThisFrame)
        {
            Cursor.visible = false;
            Cursor.lockState = CursorLockMode.Locked; 
        }

        // 2. 누르는 동안: 마우스가 얼마나 움직였는지 델타만 훔쳐옴
        if (mouse.leftButton.isPressed)
        {
            // delta는 이미 프레임 단위 이동량이므로 deltaTime을 곱하지 않음
            Vector3 moveDelta = new Vector3(mouse.delta.ReadValue().x * 0.02f, 0, 0);
            transform.position += moveDelta;
        }

        // 3. 뗀 순간: 마우스 포인터 부활 및 족쇄 풀기
        if (mouse.leftButton.wasReleasedThisFrame)
        {
            Cursor.visible = true;
            Cursor.lockState = CursorLockMode.Confined; // 창 밖으로 안 나가게만 함
        }
    }
}
```

## 6. Unity 최적화 팁
### 6.1 `Update` 안에서 배열의 `normalized` 대각선 보정
WASD를 직접 계산할 때 쌩으로 합치면 대각선으로 갈 때 (1, 1)이 되어 루트 2배(약 1.41배) 빨리 뛰어갑니다.
```csharp
// 레거시식 하드코딩
Vector2 axis = new Vector2(x, y);

// 단순히 axis.normalized 해버리면 아날로그 스틱을 살짝 기울였을 때 무조건 최대속도로 튀는 버그 발생
// 따라서 길이가 1을 넘어갈 때만(대각선일 때만) 깎아주어야 패드 유저의 미세 컨트롤이 보장됨.
if (axis.sqrMagnitude > 1f) 
    axis = axis.normalized;
```
(참고: New Input System 에셋의 `Action Type`을 `Value`, `Control Type`을 `Vector2`로 맞추면 유니티가 내부적으로 이 대각선 깎기 보정을 알아서 다 해줍니다)

### 6.2 핫플러그(장치 변경) 감지하기
게임 도중 키보드를 쓰다가 엑스박스 패드를 USB에 꽂았을 때 "패드가 연결되었습니다" UI 띄우기.
```csharp
private void OnEnable() => InputSystem.onDeviceChange += OnDeviceChange;
private void OnDisable() => InputSystem.onDeviceChange -= OnDeviceChange;

private void OnDeviceChange(InputDevice device, InputDeviceChange change)
{
    if (device is Gamepad && change == InputDeviceChange.Added)
        Debug.Log("게임패드가 방금 연결되었습니다");
}
```

## 7. 실습 문제 및 복습
**Q1. `Keyboard.current.spaceKey.wasPressedThisFrame` 과 `isPressed`를 `else if`로 묶어서 코딩하면 어떤 심각한 논리 오류가 발생하나요?**
> 스페이스바를 누른 바로 그 1프레임째에는 저 두 상태가 동시에 `true`가 됩니다.\
> `else if`로 묶어버리면 위의 단발성 조건만 실행되고, 꾹 누르고 있다는 지속성 조건 코드는 씹혀버려서 그 프레임의 판정이 꼬이게 됩니다. 무조건 각각 독립된 if 문으로 분리해야 합니다.

**Q2. 유니티 6에서 `New Input System` 패키지를 설치하고 `Active` 모드를 바꿨더니, 멀쩡하던 UI 캔버스의 버튼들이 아무리 클릭해도 안 눌립니다. 어디를 고쳐야 할까요?**
> 씬의 하이어라키 창에 있는 `EventSystem` 오브젝트를 선택하고, 인스펙터 창에서 경고를 띄우고 있는 기존 모듈 버튼 `Replace with InputSystemUIInputModule`을 눌러서 새 입력 시스템용 UI 감지 모듈로 갈아 끼워줘야 합니다.

**Q3. 자동 생성된 래퍼 클래스(`PlayerInputActions`)를 쓸 때, 점프나 공격 같은 단발성 스킬은 이벤트 콜백(+=)을 쓰고, WASD나 아날로그 스틱 같은 이동은 콜백을 안 쓰고 `Update()`에서 `ReadValue`를 매 프레임 물어보는 이유는 무엇인가요?**
> WASD 같은 `Value` 타입 액션은 유저가 키를 누른 채 방향을 안 바꾸고 가만히 있으면, 값이 변하지 않았으므로 유니티가 `performed` 이벤트를 쏴주지 않습니다.\
> 이벤트에 이동 로직을 걸어두면 한 번 찔끔 움직이고 멈춰버리는 호러쇼를 보게 되므로, 연속적인 값은 무조건 `Update`에서 매 프레임 능동적으로 상태를 캐물어야(Polling) 합니다.

## 8. 주의사항 및 안전 습관
* 활성화(`Enable`)를 까먹지 마라: C# 클래스를 생성해서 연결 다 해놓고 "왜 입력이 안 먹지?" 하며 3시간 삽질하는 주니어들의 100% 공통점입니다. `OnEnable()`에서 `_input.Enable();` 코드를 빼먹으면 아예 엔진에서 입력을 무시합니다.
* `delta`와 `deltaTime` 혼동 금지: `ReadValue`로 읽어온 마우스의 델타값에는 프레임 정보가 이미 반영되어 있습니다. `deltaTime`을 또 곱하면 프레임 속도에 따라 감도가 미친 듯이 널뛰게 됩니다.
* `Dispose()`로 분리수거: 래퍼 클래스는 `IDisposable` 인터페이스를 구현하고 있습니다. `OnDestroy`에서 이벤트 해제(-=)를 일일이 할 필요 없이 `_input.Dispose()`; 한 줄 쳐주면 깔끔하게 다 해제되고 메모리 누수도 막습니다.
