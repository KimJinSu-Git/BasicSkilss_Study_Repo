# [Fundamentals] 2. Unity Editor

## 1. Unity Editor 란?
Unity Editor는 Unity Engine으로 콘텐츠를 만들기 위한 종합 작업 환경입니다. 에셋(재료)을 들여오고, 씬(무대)을 짜고, 속성값을 조절하고, 그 자리에서 바로 게임을 실행해 보고, 최종 빌드까지 내보내는 모든 과정이 이 한 화면 안에서 이뤄집니다.

> **만능 작업실**
> * **작업대 (Scene View)** — 공간을 직접 만지고 객체를 조립하는 3D/2D 캔버스
> * **미리보기 거울 (Game View)** — 플레이어 입장에서 카메라를 통해 어떻게 보이는지 확인하는 창
> * **재료 보관함 (Project)** — 모델, 이미지, 사운드, 스크립트 등 파일(Asset)을 보관하는 곳
> * **부품 트리 (Hierarchy)** — 지금 무대(Scene) 위에 올라와 있는 모든 객체(배우)들의 목록과 가족 관계
> * **상세 설정 (Inspector)** — 현재 선택된 객체나 파일의 모든 속성(컴포넌트)을 뜯어보고 편집하는 패널
> * **메모장 (Console)** — 작업 중 발생한 로그, 경고, 심각한 오류(에러)가 기록되는 곳

**왜 알아야 하는가?**\
유니티는 코드를 짜는 것이 작업의 전부가 아니라, 에디터 화면에서 컴포넌트를 조립하고 수치를 맞추는 비주얼 작업의 비중이 매우 큽니다. 어느 창이 무슨 역할을 하는지 모르면, 코드를 완벽하게 짰는데도 화면에 아무 일도 일어나지 않을 때 원인을 찾을 수가 없습니다.

## 2. 핵심 요약

| 창(Window) | 하는 일 | 여는 곳 (실수로 닫았을 때) |
| :--- | :--- | :--- |
| **Scene View** | 게임 월드를 신의 시점(개발자 시점)으로 보며 편집합니다. | `Window -> General -> Scene` |
| **Game View** | 카메라가 비추는 실제 유저 플레이 화면입니다. | `Window -> General -> Game` |
| **Hierarchy** | 현재 씬에 배치된 모든 `GameObject`의 목록입니다. | `Window -> General -> Hierarchy` |
| **Project** | 디스크에 저장된 프로젝트의 모든 에셋(원본 파일)입니다. | `Window -> General -> Project` |
| **Inspector** | 선택한 객체에 붙어있는 부품(컴포넌트)과 수치를 보여줍니다. | `Window -> General -> Inspector` |
| **Console** | 로그(`Log`), 경고(`Warning`), 오류(`Error`)가 찍히는 곳입니다. | `Ctrl+Shift+C` |

> **문서를 덮고도 기억해야 할 3가지 절대 원칙**
> 1. **Play 모드 중에 수정한 값은 Play를 끄는 순간 날아갑니다.** (휘발성) 영구적인 변경은 반드시 Play를 끄고 하세요.
> 2. 에셋 파일의 이름 변경과 이동은 무조건 **Project 창 안에서만** 하세요. 윈도우 탐색기에서 함부로 건드리면 파일 연결이 통째로 박살 납니다 (`.meta` 파일 꼬임).
> 3. **Console 창은 항상 깨끗하게 비워두세요.** 노란색 경고를 무시하고 쌓아두면, 진짜 치명적인 빨간색 오류가 그 안에 파묻혀 버립니다.

## 3. 세부 개념 및 원리

### 3.1 툴바와 Play 모드의 함정
에디터 최상단 가운데에 있는 세 개의 버튼이 실행을 담당합니다.
1. **Play (▶️)** : 씬을 실제 게임처럼 실행합니다. (`Ctrl+P`)
2. **Pause (⏸️)** : 실행 중인 게임을 그 프레임에 일시 정지시킵니다.
3. **Step (⏭️)** : 일시 정지 상태에서 딱 '1 프레임'씩만 찔끔찔끔 진행시킵니다. (정밀 디버깅용)

**[Play 모드의 축복과 저주]**\
Play 모드는 에디터의 가장 큰 장점이지만, 입문자들이 가장 많이 겪는 눈물의 함정입니다.
> **"분명히 몬스터 속도를 5로 고쳤는데 다시 1이 됐어요!"**\
> Play(▶️) 버튼이 눌려 게임이 돌아가는 중에 인스펙터 값을 바꾸면, **Play를 끄는 순간 원래 값으로 완벽하게 복구(Roll-back)됩니다.** 중요한 맵 배치나 설정은 반드시 Play를 끈 상태에서 하세요.

### 3.2 에셋 임포트와 `.meta` 파일의 비밀
Project 창에 `hero.png` 이미지를 넣으면, 유니티는 몰래 `hero.png.meta` 라는 텍스트 파일을 옆에 하나 더 만듭니다. 이 파일 안에는 해당 이미지의 고유 주민등록번호(**GUID**)가 적혀 있습니다.\
씬에 배치된 몬스터나 스크립트는 파일 이름이 아니라 바로 이 **GUID**를 쳐다보고 있습니다.\
만약 윈도우 탐색기에서 이미지 폴더를 몰래 옮겨버리면 `.meta` 파일과 이별하게 되어 새로운 GUID가 발급되고, 기존에 연결해 두었던 모든 인스펙터가 `Missing (None)` 에러를 뿜게 됩니다. **반드시 에디터의 Project 창 내부에서 폴더 정리를 하세요.**

### 3.3 [심화] 프리팹 (Prefab) 맛보기
Hierarchy 창에 있는 몬스터를 온갖 컴포넌트로 예쁘게 꾸민 뒤, 마우스로 잡고 Project 창으로 끌어내리면 **파란색 상자(Prefab)** 가 됩니다.\
이 프리팹은 무대 위의 객체를 영구적인 '도장(원본 에셋)'으로 만든 것입니다. 이제 이 프리팹을 무대에 100개 던져놓고, 프리팹 원본 하나의 공격력만 수정하면 100마리의 공격력이 동시에 바뀌게 됩니다.

## 4. 코드로 보는 에디터 연동

### 4.1 Inspector에 값을 노출하는 세 가지 방법 (캡슐화 딜레마)
```csharp
using UnityEngine;

public class Player : MonoBehaviour
{
    // [비권장] 인스펙터에 보이지만, 다른 클래스에서 맘대로 체력을 바꿀 수 있음 (캡슐화 파괴)
    public int health = 100;                 

    // [유니티의 정석] 인스펙터에 예쁘게 노출되지만, 코드에서는 외부 접근을 완벽히 차단
    [SerializeField] private float moveSpeed = 5f;

    // [내부 변수] 인스펙터에 안 보이고 코드 내부에서만 씁니다.
    private int score;                       

    // [프로퍼티] 코드로 열어두지만, 기본적으로 인스펙터에는 보이지 않습니다.
    public int Level { get; set; }           
}
```
> **[SerializeField] private** 조합이 유니티 프로그래밍의 정석입니다. 기획자가 에디터에서 만지는 일(노출)과 다른 프로그래머가 코드에서 값을 함부로 바꾸는 일(캡슐화)은 별개이므로 분리해야 합니다.

### 4.2 Console에 기록을 남기는 로그 (`Debug` 클래스)
```csharp
// 에디터 Console 창에 글자를 찍어줍니다. (실제 빌드된 폰에서는 안 보임)
Debug.Log("게임 시작");                        // 흰색 줄 (단순 정보 확인)
Debug.LogWarning("체력이 너무 낮습니다");      // 노란색 줄 (안 죽지만 조심해야 할 상태)
Debug.LogError("연결된 무기가 없습니다");      // 빨간색 줄 (치명적인 상태, 디버깅 1순위)

// 꿀팁: 둘째 인자에 this(나 자신)를 넘겨주면, 콘솔 로그를 클릭했을 때 
// 하이어라키에서 이 로그를 쏜 몬스터가 누구인지 노란색으로 하이라이트 해줍니다
Debug.Log("여기서 불났어요", this);
```

## 5. 지침서: 에디터 활용 꿀팁

### 5.1 Play 모드 중 찾아낸 '갓벽한' 수치 저장하기
게임을 플레이하면서 몬스터 점프력을 이것저것 만져보다가 딱 맞는 수치를 찾았습니다. Play를 끄면 날아가 버리는데 어떡하죠?
1. Play가 켜진 상태에서 몬스터 컴포넌트의 우상단 세로점 3개(`⋮`) 클릭 ➔ **Copy Component**
2. Play 버튼을 눌러 게임 종료 (수치가 리셋됨)
3. 다시 컴포넌트 우상단 점 3개 클릭 ➔ **Paste Component Values** ➔ 플레이 중 만졌던 수치들이 안전하게 덮어씌워집니다

### 5.2 Playmode Tint 설정 (실수 방지)
"Play 중인 줄 모르고 30분 동안 맵 디자인을 했는데 Play를 끄니까 다 날아갔다..." ➔ 게임 개발자라면 한 번쯤 겪는 트라우마입니다.\
`Edit -> Preferences -> Colors` 로 들어가서 **`Playmode tint`** 를 살짝 붉은색이나 녹색으로 바꿔두세요. Play를 누르면 에디터 전체 화면이 그 색으로 물들어서 절대로 헷갈리지 않게 됩니다.

### 5.3 Inspector에 둘 값 vs 코드에 감출 값
| 종류 | 어디에 둘까? | 이유 |
| :--- | :--- | :--- |
| **밸런스 수치** (체력, 이속, 공격력) | **Inspector** (`[SerializeField]`) | 코드를 재빌드 할 필요 없이 기획자가 직접 맞추며 테스트해야 함 |
| **씬 객체 참조** (카메라, 타겟, UI) | **Inspector** (드래그 앤 드롭) | 코드로 `Find`해서 찾는 것보다 훨씬 성능이 빠르고 눈에 직관적임 |
| **런타임 객체** (생성된 총알 등) | **코드** 내부 변수 | 인스펙터에 존재하지도 않으므로 코드로만 관리함 |
| **절대 불변의 값** (중력 가속도 등) | **코드** (`const`, `readonly`) | 기획자가 인스펙터에서 실수로 건드리면 게임이 터지는 값들 |

## 6. 실습 문제 및 복습

**Q1. `Scene View`와 `Game View`는 각각 무엇을 보여주는 화면인지 설명하세요.**
> * **Scene View**: 개발자와 디자이너가 월드를 이리저리 돌려보고 객체를 배치하는 '전지적 개발자 시점'의 작업용 캔버스입니다.
> * **Game View**: 유니티 씬에 배치된 `Main Camera`가 비추는 화면으로, 실제 유저가 스마트폰이나 모니터를 통해 보게 될 최종 플레이 화면입니다.

**Q2. 탐색기 폴더에서 에셋(이미지 등)의 이름을 바꾸거나 폴더를 옮기면 안 되는 이유를 `.meta` 파일과 연관 지어 설명하세요.**
> 에셋을 유니티로 가져오면 고유한 아이디(GUID)가 적힌 `.meta` 파일이 짝꿍으로 생성됩니다. 유니티는 파일 경로가 아니라 이 GUID로 에셋을 연결합니다. 윈도우 탐색기에서 이름이나 경로를 막 바꿔버리면 이 `.meta` 파일과 어긋나게 되어, 기존에 인스펙터에 연결해 둔 몬스터나 텍스처 정보가 모두 끊어지는(`Missing`) 대참사가 발생합니다. **에셋 관리는 무조건 유니티의 Project 창 내부에서 해야 합니다.**

**Q3. `public int health = 100;` 과 `[SerializeField] private int health = 100;` 은 인스펙터에서 볼 때 완전히 똑같이 보입니다. 그런데도 실무에서 뒤쪽 코드를 압도적으로 권장하는 이유는 무엇인가요?**
> 두 코드 모두 에디터(기획자)에게는 값을 열어주어 편의성을 제공합니다. 하지만 `public`은 **다른 프로그래머의 코드(외부 스크립트)** 에게까지 값을 무방비로 열어버려 누군가 체력을 맘대로 바꾸는 버그를 초래합니다. `[SerializeField] private`은 인스펙터의 편집 기능은 살려두면서, 코드 레벨에서는 `private`으로 캡슐화를 완벽히 지켜내기 때문입니다.

## 7. 주의사항 및 안전 습관

* **Ctrl + S (씬 저장)를 숨 쉬듯이 눌러라**: 유니티 에디터가 갑자기 크래시로 뻗는 일은 아주 흔합니다. 방금 30분 동안 배치한 마을 지형이 날아가기 전에 무조건 습관적으로 저장하세요. (참고로 C# 코드는 비주얼 스튜디오/라이더에서 따로 저장해야 유니티로 반영됩니다.)
* **에디터 작업엔 컴파일러(보호막)가 없다**: 코드는 틀리면 빨간 줄이 그어지지만, 인스펙터에 UI 버튼 스크립트를 드래그 앤 드롭으로 연결하는 작업은 까먹어도 에디터가 안 알려줍니다. 클릭해도 아무 반응이 없다면 코드가 아니라 '인스펙터 연결'을 빼먹은 것입니다.
* **컴파일 바퀴가 돌 땐 기다려라**: C# 스크립트를 수정하고 저장한 뒤 유니티 창으로 돌아오면 우측 하단에 조그맣게 동그라미(컴파일 로딩)가 돕니다. 이 바퀴가 다 돌기 전에 Play를 누르면 렉이 걸리거나 방금 친 코드가 미반영 상태로 실행됩니다. 인내심을 가지세요.
