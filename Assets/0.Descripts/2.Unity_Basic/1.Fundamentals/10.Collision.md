# [Fundamentals] 10. Collision (충돌)

## 1. Collision(충돌) 이란?
> **당구대 위의 공**
> * 당구대 위의 공은 서로 닿는 순간 튕겨 나가며 진로가 바뀝니다.
> * 게임 개발에서는 이 현상을 두 가지로 쪼개서 봅니다. **① 닿았다는 '사실(판정)'** 과 **② 닿았으니 '무엇을 할 것인가(로직)'**.
> * 유니티는 이 둘을 완벽히 갈라 놓았습니다. 닿았는지는 **`Collider`**(물리 엔진)가 알아서 판정해 주고, 우리는 닿은 순간에 유니티가 찔러주는 **'콜백 함수'** 안에 무엇을 할지만 적으면 됩니다.

**왜 필요한가?**\
충돌 엔진이 없다면 매 프레임 `Vector3.Distance`로 수십 마리 적과 총알의 거리를 직접 재야 합니다. 몬스터가 원형이 아니라 복잡한 인간형이라면 수학적으로 계산할 방법조차 없습니다. 물리 엔진(`Physics`)은 이 끔찍한 계산을 대신 처리해 주고, 닿은 순간에만 우리 코드를 톡 치며 알려줍니다.

---

## 2. 핵심 요약

| 구성 요소 | 역할 | 기억할 한 줄 |
| :--- | :--- | :--- |
| **`Collider`** | 부딪히는 물리적 경계선(껍데기) | **이게 없으면 유령처럼 쓱 통과해 버립니다.** |
| **`Rigidbody`** | 물리법칙(중력, 마찰)을 받는 몸통 | **충돌하는 둘 중 최소 한 명은 무조건 갖고 있어야 합니다.** |
| **`OnCollision` 계열**| 벽에 부딪혀 밀려나거나 튕길 때 | 닿은 위치(좌표)와 튕긴 힘의 정보를 알려줍니다. |
| **`OnTrigger` 계열** | 센서처럼 영역을 통과할 때 (`Is Trigger` 켜짐) | 튕겨나가지 않고 스르륵 통과하며 진입 사실만 알려줍니다. |

* 충돌이 일어나면 부딪힌 **양쪽 오브젝트 모두에게 각각 한 번씩 콜백 함수가 호출**됩니다.
* 2D 게임에서는 무조건 클래스명과 함수명 뒤에 **`2D`** 를 붙여야 합니다. (`Collider2D`, `Rigidbody2D`, `OnCollisionEnter2D`)

## 3. 세부 개념 및 원리

### 3.1 "왜 안 부딪혀요?" (충돌 발생의 절대 조건)
유니티 물리 엔진이 충돌을 인식하려면 아래 조건이 무조건 지켜져야 합니다.

| 부딪히는 두 오브젝트의 조합 | 결과                           |
| :--- |:-----------------------------|
| `Rigidbody + Collider` 💥 `Rigidbody + Collider` | 완벽한 물리적 충돌 및 콜백 발생           |
| `Rigidbody + Collider` 💥 `Collider` (가만히 있는 벽) | 물리적 충돌 및 콜백 발생               |
| `Collider` 💥 `Collider` (둘 다 Rigidbody 없음) | **충돌 무시. 유령처럼 통과함 (콜백 안 옴)** |

### 3.2 밀어내기(Collision) vs 통과하기(Trigger)
인스펙터 창에서 Collider의 **`Is Trigger`** 체크박스를 켜면, 딱딱한 벽이 아니라 띠링~ 소리가 나는 **'센서 영역'** 으로 바뀝니다.

* **밀어내기 (Collision)**: 벽, 바닥, 총알, 당구공. 물리적으로 튕겨 나가야 할 때.
    * `OnCollisionEnter(Collision col)` : 처음 닿은 순간 딱 1번
    * `OnCollisionStay(Collision col)` : 비비적대며 닿아있는 동안 매 프레임
    * `OnCollisionExit(Collision col)` : 떨어지는 순간 딱 1번
* **통과하기 (Trigger)**: 독 장판, 아이템 획득, 포탈, 적 시야 범위. 물리적 튕김 없이 지나가야 할 때.
    * `OnTriggerEnter(Collider other)` : 영역에 들어간 순간 딱 1번
    * `OnTriggerStay(Collider other)` : 영역 안에 머무는 동안 매 프레임
    * `OnTriggerExit(Collider other)` : 영역에서 빠져나간 순간 딱 1번

> 매개변수 타입이 다릅니다. `Collision` 객체 안에는 닿은 좌표와 충격량이 들어있지만, `Trigger`는 그냥 통과한 거라 부딪힌 껍데기(`Collider`) 정보만 던져줍니다.

## 4. 코드로 보는 충돌과 트리거

### 4.1 Collision (총알이 적을 맞히고 불꽃을 튈 때)
부딪힌 '위치'와 '각도' 정보가 필요하므로 반드시 Collision으로 짜야 합니다.
```csharp
[RequireComponent(typeof(Rigidbody))]
public class Bullet : MonoBehaviour
{
    [SerializeField] private int damage = 10;
    [SerializeField] private GameObject hitEffect;

    private void OnCollisionEnter(Collision collision)
    {
        // 1. 태그로 적군인지 먼저 가볍게 거른다
        if (collision.gameObject.CompareTag("Enemy"))
        {
            if (collision.gameObject.TryGetComponent(out Health health))
                health.TakeDamage(damage);
        }

        // 2. 부딪힌 정확한 지점(point)과 튕겨나갈 법선 방향(normal)을 가져온다
        if (collision.contactCount > 0 && hitEffect != null)
        {
            ContactPoint contact = collision.GetContact(0);
            Instantiate(hitEffect, contact.point, Quaternion.LookRotation(contact.normal));
        }

        Destroy(gameObject); // 적이든 벽이든 맞으면 총알은 파괴됨
    }
}
```

### 4.2 Trigger (플레이어가 골인 지점 포탈에 들어갈 때)
튕겨나가지 않고 부드럽게 흡수되듯 통과해야 합니다.
```csharp
public class GoalZone : MonoBehaviour
{
    // 에디터에서 BoxCollider의 [Is Trigger]를 반드시 체크할 것
    private void OnTriggerEnter(Collider other)
    {
        if (other.CompareTag("Player"))
        {
            Debug.Log("게임 클리어");
            // GameManager.Instance.StageClear();
        }
    }
}
```

## 5. 실전 활용 예시 (양쪽 콜백 중복 실행 막기)

수박 게임처럼 같은 스크립트(`PuzzleBall`)를 가진 두 개의 공이 부딪혀서 합쳐지는 상황입니다.
콜백은 양쪽 공에서 동시에 울리기 때문에, 방어 코드가 없으면 공이 2개가 생겨버립니다.

```csharp
using UnityEngine;

[RequireComponent(typeof(Rigidbody2D))] // 2D 퍼즐 게임
public class PuzzleBall : MonoBehaviour
{
    [SerializeField] private PuzzleBall mergedPrefab; // 다음 단계 공
    
    // 두 공 중 하나만 융합 처리를 주도하기 위한 방어막(플래그)
    public bool IsMerged { get; private set; } 
    public void MarkMerged() => IsMerged = true;

    private void OnCollisionEnter2D(Collision2D collision)
    {
        if (IsMerged) return; // 뒤늦게 도는 2번째 공의 콜백은 여기서 컷

        if (!collision.gameObject.TryGetComponent(out PuzzleBall other)) return;
        if (other.IsMerged) return; // 상대 공이 이미 다른 공과 융합 중이면 컷

        // 처리를 시작하기 전에 양쪽 모두의 플래그를 켜버린다
        MarkMerged();
        other.MarkMerged();

        Vector3 center = (transform.position + other.transform.position) * 0.5f;

        // 즉시 물리 연산에서 빼버려서 파괴 대기 1프레임 동안 제3의 공과 부딪히는 걸 막음
        gameObject.SetActive(false); 
        other.gameObject.SetActive(false);

        Destroy(gameObject);
        Destroy(other.gameObject);

        Instantiate(mergedPrefab, center, Quaternion.identity);
    }
}
```

## 6. Unity 최적화 팁

### 6.1 가장 무서운 '터널링(Tunneling)' 현상 막기
총알이 너무 빠르거나 프레임 드랍이 생기면, 물리 엔진이 계산하기도 전에 총알이 벽을 '순간이동'하여 뚫고 지나가는 끔찍한 현상이 생깁니다.
* **해결책**: 빠른 물체의 Rigidbody 인스펙터에서 **`Collision Detection`** 모드를 `Discrete(기본값)`에서 **`Continuous`** 로 바꿔주세요.
* **[최적화]**: 이 모드는 CPU를 미친 듯이 잡아먹습니다. **움직이는 총알에만 `Continuous`** 를 주고, 가만히 있는 **벽이나 몬스터는 무조건 `Discrete`** 로 두어야 게임이 버벅이지 않습니다.

### 6.2 비교 연산은 무조건 `CompareTag`
`if (other.gameObject.tag == "Enemy")` ➔ 이 코드를 쓰는 순간 1초에 60번씩 메모리에 쓰레기(문자열 GC)가 생깁니다.\
가능하면 유니티가 최적화해 둔 **`if (other.CompareTag("Enemy"))`** 를 쓰세요.

### 6.3 물리 엔진 최적화: `Layer Collision Matrix`
총알 수십 발이 날아다니는데, 유니티는 멍청하게 "총알끼리 부딪혔나?"를 매 프레임 검사합니다.
* `Edit -> Project Settings -> Physics (또는 Physics 2D)`로 갑니다.
* 맨 밑에 있는 **`Layer Collision Matrix`** 표에서 `Bullet`과 `Bullet`이 만나는 체크박스를 꺼버리세요
* 코드로 `if(총알) return;`을 짜는 것보다, 애초에 유니티 물리 엔진단에서 연산 자체를 안 하게 차단해 버리는 것이 압도적으로 성능이 좋습니다.

## 7. 실습 문제 및 복습

**Q1. 2D 게임에서 총알을 만들었는데 아무리 적을 관통해도 `OnTriggerEnter` 로그가 찍히지 않습니다. 원인이 될 수 있는 3가지를 순서대로 나열해보세요.**
> 1. 오타: 2D 게임이므로 함수명을 `OnTriggerEnter2D`로, 매개변수를 `Collider2D`로 적었는지 확인합니다.
> 2. 리지드바디 부재: 총알이나 적 둘 중 하나라도 `Rigidbody2D` 컴포넌트가 달려있는지 확인합니다.
> 3. 트리거 세팅: 둘 중 하나 이상의 콜라이더에 `Is Trigger` 체크박스가 켜져 있는지 확인합니다.

**Q2. 플레이어가 독 구름(독 장판) 안에 들어가 있는 동안 매 초 5의 데미지를 입게 하려 합니다. 어떤 콜백 함수를 써야 하며, 이 함수 내부에 무거운 로직을 넣으면 안 되는 이유는 무엇인가요?**
> **`OnTriggerStay(Collider other)`** 를 써야 합니다. 이 함수는 플레이어가 독구름에 겹쳐있는 동안 매 물리 프레임(기본 초당 50번) 호출되므로, 이 안에 `GetComponent`나 `Find` 같은 무거운 탐색 로직을 넣으면 게임 프레임이 심각하게 떨어집니다.

**Q3. '플레이어'가 '체력 회복 아이템'을 먹고 아이템이 사라져야 합니다. 콜백 로직을 플레이어 스크립트에 짜야 할까요, 아이템 스크립트에 짜야 할까요?**
> **상태가 변하거나 사라지는 쪽(주도하는 쪽)** 에 짜는 것이 원칙입니다. 따라서 아이템 스크립트 안에 `OnTriggerEnter`를 구현하고, 자신을 건드린 `other`가 플레이어면 플레이어의 체력을 올린 뒤 `Destroy(gameObject);`로 자결하는 것이 설계상 가장 깔끔합니다.

## 8. 주의사항 및 안전 습관

* **이벤트 함수를 직접 호출하지 마라**: `OnCollisionEnter` 같은 콜백 함수를 스크립트 내부에서 일반 함수 부르듯 직접 호출하지 마세요. "이 함수는 유니티 엔진 물리 시스템이 부르는 곳이다"라는 절대 원칙이 깨지면 코드를 읽을 수 없게 됩니다. 공통 로직은 별도의 `private void ProcessHit()` 같은 메서드로 빼서 호출하세요.
* **`Destroy`는 즉시 삭제되지 않는다**: `Destroy(gameObject)`를 호출해도 오브젝트는 그 프레임이 끝날 때까지 씬에 좀비처럼 살아있습니다. 그 찰나의 순간에 콜백이 또 터질 수 있으니, 물리 연산에서 즉시 제외시키려면 **`gameObject.SetActive(false);`** 를 콤보로 섞어 써주세요.
* **2D 함수명 오타 주의**: 2D 게임인데 3D 충돌 함수(`OnCollisionEnter`)를 적어놓고 "왜 안 부딪히지?" 고민하는 시간이 주니어 시절의 절반을 차지합니다. 무조건 뒤에 **`2D`** 가 붙었는지 두 번 확인하세요.
