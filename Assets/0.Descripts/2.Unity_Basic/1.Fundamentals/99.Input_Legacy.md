# [Fundamentals] 99. Input (Legacy)

## 1. Input (Legacy) 란?
> **오케스트라의 지휘자**
> * Unity에서 Input (입력) 시스템은 키보드, 마우스, 조이스틱 등 다양한 입력 장치(악기)의 신호를 받아 게임 로직에 전달하여 연주를 조율하는 **지휘자**입니다.
> * Legacy Input System (레거시 입력 시스템)은 Unity의 가장 전통적인 방식으로, 이름 그대로 `Input.GetKey(KeyCode.W)`처럼 매우 간단하고 직관적인 API를 제공합니다.

**왜 알아야 하는가?**\
Unity 2019부터 훨씬 강력한 패키지인 'New Input System'이 등장했지만, 수많은 기존 프로젝트와 유니티 생태계의 에셋들은 여전히 Legacy Input으로 짜여 있습니다. 빠른 프로토타이핑(게임잼 등)을 하거나 기존 코드베이스를 유지 보수할 때 반드시 알아야 하는 기초 문법입니다.

## 2. 핵심 요약

| 분류 | 특징 및 하는 일 |
| :--- | :--- |
| **작동 방식 (Polling)** | 매 프레임(`Update`)마다 특정 키가 눌렸는지 지휘자가 일일이 물어봄 |
| **Input 클래스** | 키보드, 마우스, 조이스틱의 상태를 직접 감지하는 핵심 클래스 |
| **Input Manager** | `Edit ➔ Project Settings`에서 입력 축(Axis)의 이름과 가감속 속성 등을 세팅 |
| **단점** | 로컬 멀티플레이 분리 불가, 인게임 키 리매핑 어려움, 잦은 하드코딩 유발 |

> **[원칙]**
> 1. 단발성 입력(`GetKeyDown`)은 무조건 **`Update`** 에서 감지하세요. 물리(`FixedUpdate`)에서 읽으면 입력을 놓쳐서(씹혀서) 키보드를 박살 내게 됩니다.
> 2. 한 가지 동작에 키(Key)와 축(Axis)을 섞어 쓰지 마세요. 이동량이 2배로 뻥튀기됩니다.
> 3. 대각선 이동 시 루트 2배로 빨라지는 버그를 막을 땐 `Normalize` 대신 **`ClampMagnitude`** 를 써야 아날로그 스틱 유저도 천천히 걸을 수 있습니다.

## 3. 세부 개념 및 원리

### 3.1 가장 많이 쓰는 멤버 삼형제 (Key, Mouse, Axis)

**[1. 키보드 입력]**
* 이동처럼 계속 꾹 누르는 동작은 `GetKey`를 쓰고, 점프처럼 한 번만 발생해야 하는 동작은 `GetKeyDown`을 씁니다.
```csharp
bool held     = Input.GetKey(KeyCode.A);          // 꾹 누르는 내내 true
bool pressed  = Input.GetKeyDown(KeyCode.Space);  // 누르는 그 1프레임 찰나만 true
bool released = Input.GetKeyUp(KeyCode.Escape);   // 떼는 그 1프레임 찰나만 true
```

**[2. 마우스 입력]**
* 마우스 버튼 번호는 0(좌클릭), 1(우클릭), 2(휠 클릭) 순서입니다.
* `mousePosition`은 픽셀 단위의 화면(Screen) 좌표이므로, 월드(3D 공간) 좌표로 바꾸려면 카메라를 거쳐 변환(`ScreenToWorldPoint`)해야 합니다.
```csharp
bool lPressed  = Input.GetMouseButtonDown(0); // 왼쪽 클릭
Vector3 mousePos = Input.mousePosition;       // 현재 마우스 커서의 모니터 좌표 (Z는 항상 0)
Vector2 scroll   = Input.mouseScrollDelta;    // 휠 스크롤 굴린 변화량
```

**[3. 가상 축 (Axis) 입력]**
* 키보드의 WASD, 방향키, 패드의 아날로그 스틱을 모두 묶어서 "가로(Horizontal)축 / 세로(Vertical)축"이라는 이름표로 퉁쳐서 가져옵니다.
```csharp
// -1.0 ~ 1.0 사이를 미끄러지듯 부드럽게 오르내림 (가감속 있는 얼음판 느낌)
float h = Input.GetAxis("Horizontal"); 

// -1, 0, 1 딱 3가지 정수 값만 즉시 뱉어냄 (칼같이 멈추는 플랫포머 게임에 필수)
float v = Input.GetAxisRaw("Vertical"); 
```

## 4. 코드로 보기 (이동 + 조준 + 점프)
플랫포머 액션 게임에서 가장 흔히 쓰는 3가지 입력을 한 번에 처리하는 템플릿입니다.
* **입력 감지는 `Update`**, **물리 적용은 `FixedUpdate`** 라는 뼈대를 기억하세요

```csharp
using UnityEngine;

[RequireComponent(typeof(Rigidbody2D))]
public class PlayerInputExample : MonoBehaviour
{
    [SerializeField] private float moveSpeed = 6f;
    [SerializeField] private float jumpForce = 9f;

    private Rigidbody2D rb;
    private float moveInput;      
    private bool jumpQueued; // 씹힘 방지용 플래그

    private void Awake() => rb = GetComponent<Rigidbody2D>();

    private void Update()
    {
        // 1. 축(Axis) 입력: 좌우 이동은 즉각적으로 반응하도록 Raw를 쓴다.
        moveInput = Input.GetAxisRaw("Horizontal");

        // 2. 점프 입력: 찰나의 1프레임(Down)을 안 놓치기 위해 깃발(bool)만 꽂아둔다.
        if (Input.GetKeyDown(KeyCode.Space))
            jumpQueued = true;

        // 3. 마우스 조준: 픽셀 좌표를 게임 월드 좌표로 번역해서 총구를 돌린다.
        Vector3 mouseWorldPos = Camera.main.ScreenToWorldPoint(Input.mousePosition);
        Vector2 aimDirection = ((Vector2)mouseWorldPos - rb.position).normalized;
        Debug.DrawRay(rb.position, aimDirection * 2f, Color.red);
    }

    private void FixedUpdate()
    {
        // 물리 연산 턴이 돌아오면 이동과 점프를 실제 힘(Force)으로 적용
        rb.linearVelocity = new Vector2(moveInput * moveSpeed, rb.linearVelocity.y);

        if (jumpQueued)
        {
            rb.AddForce(Vector2.up * jumpForce, ForceMode2D.Impulse);
            jumpQueued = false; // 힘을 줬으니 반드시 깃발을 내린다(초기화)
        }
    }
}
```

## 5. 실전 활용 예시: 대각선 이동 속도 뻥튀기 막기
조이스틱과 키보드를 혼용하는 탑뷰 게임에서 가장 자주 발생하는 버그를 잡는 정석 코드입니다.

```csharp
public class TopDownMovement : MonoBehaviour
{
    public float moveSpeed = 5f;

    void Update()
    {
        // 1. WASD 및 조이스틱 입력을 한꺼번에 받음
        float h = Input.GetAxis("Horizontal"); 
        float v = Input.GetAxis("Vertical");   

        Vector3 moveDirection = new Vector3(h, 0, v);

        // [주의] moveDirection.Normalize()를 쓰지 마세요
        // 아날로그 스틱을 살짝만 밀어서 (0.2, 0.1) 값이 들어왔는데 Normalize를 해버리면 
        // 길이가 강제로 1로 늘어나 무조건 전력질주하게 됩니다.
        
        // [정석] 길이가 1을 초과할 때(대각선 1.414)만 1로 깎아냅니다.
        moveDirection = Vector3.ClampMagnitude(moveDirection, 1f);

        transform.Translate(moveDirection * moveSpeed * Time.deltaTime);
    }
}
```

## 6. Unity 최적화 팁

### 6.1 실수: 이중 이동 버그
키보드 입력을 받을 때 `Input.GetKey`와 `Input.GetAxis`를 아무 생각 없이 같이 쓰면 벌어지는 참사입니다.

```csharp
void Update()
{
    // W 키를 누르면 얘도 작동해서 앞으로 가고...
    if (Input.GetKey(KeyCode.W)) transform.Translate(Vector3.forward);

    // 같은 프레임에 얘도 작동해서 또 앞으로 감 ➔ 이동속도 2배 뻥튀기 버그
    float v = Input.GetAxis("Vertical");
    transform.Translate(Vector3.forward * v);
}
```
**해결책**: 프로젝트를 시작할 때 이동을 '축(Axis)'으로 할지 '키(Key)'로 할지 하나만 정해서 통일해야 합니다. 보통 게임패드 확장을 고려해 `Axis`로 통일하는 것이 정석입니다.

### 6.2 Legacy Input 언제 탈출해야 하나요?
다음 3가지 요구사항이 기획서에 들어오는 순간, `New Input System` 패키지로 갈아타야 합니다.
1. **"유저가 인게임 설정창에서 키를 마음대로 바꾸게 해주세요" (Key Rebinding)** ➔ 레거시로는 매우 불편한 작업이 됩니다.
2. **"한 화면에서 키보드 유저랑 패드 유저가 같이 2인용 코옵 플레이하게 해주세요"** ➔ 레거시는 1P와 2P 입력을 깔끔하게 쪼개지 못합니다.
3. **"PC뿐만 아니라 콘솔(Switch, PS5)로도 포팅해주세요"** ➔ 기기별 전용 컨트롤러 대응 시 하드코딩이 폭발합니다.

## 7. 실습 문제 및 복습

**Q1. `Input.GetKeyDown(KeyCode.Space)` 코드를 물리 연산 함수인 `FixedUpdate()` 안에 작성했습니다. 플레이어가 스페이스바를 눌렀는데도 점프를 할 때도 있고 씹힐 때도 있는 심각한 버그가 발생했습니다. 원인이 무엇인가요?**
> `GetKeyDown`은 유저가 키를 누른 바로 그 찰나의 '1프레임(`Update`)' 동안만 `true`를 반환합니다.\
> 그런데 `FixedUpdate`는 모니터 프레임과 무관하게 0.02초마다 도는 독립된 시계이므로, 키가 눌렸던 그 1프레임을 미처 감지하지 못하고 타이밍이 엇갈려 지나쳐 버리면서(씹힘) 입력이 소실된 것입니다.\
> 단발성 입력은 무조건 `Update`에서 읽고 변수(`bool`)에 저장해야 합니다.

**Q2. `Input.GetAxis("Horizontal")`과 `Input.GetAxisRaw("Horizontal")`의 게임 플레이 시 조작감 차이는 무엇인가요?**
> `GetAxis`는 유니티 엔진이 값을 부드럽게 보간(Smoothing)해주어 0에서 1까지 서서히 오르내립니다. 자동차 레이싱 게임처럼 빙판을 미끄러지듯 부드러운 가감속이 필요할 때 씁니다.\
> 반면 `GetAxisRaw`는 키를 누르는 즉시 -1, 0, 1 세 가지 정수 값 중 하나로 딱 떨어집니다. 슈퍼 마리오나 셀레스테처럼 캐릭터가 즉시 최고 속도로 달리고 즉시 멈춰야 하는 조작감(플랫포머, 액션)에 필수적입니다.

**Q3. 마우스의 현재 위치를 이용해 총알을 발사하려 합니다. `transform.position = Input.mousePosition;` 이라고 코드를 짰더니 총알이 내 시야를 벗어난 엉뚱한 우주 공간으로 날아가 버렸습니다. 이유가 무엇인가요?**
> `Input.mousePosition`은 3D 게임 월드의 좌표가 아니라, 유저 모니터 화면의 해상도 픽셀 좌표(예: 1920x1080)를 반환하기 때문입니다.\
> 게다가 Z축 깊이 값도 항상 0입니다. 이 픽셀 좌표를 게임 세상의 좌표로 써먹으려면 반드시 카메라가 렌즈를 통해 통역해주는 `Camera.main.ScreenToWorldPoint()` 함수를 거쳐야 합니다.

## 8. 주의사항 및 안전 습관

* **매직 넘버(하드코딩) 회피**: `Input.GetKey(KeyCode.Space)`처럼 코드 여기저기에 키보드 알파벳을 흩뿌려놓지 마세요. 나중에 키보드 레이아웃을 바꿀 때 지옥을 봅니다. 가급적 유니티 `Input Manager`에 이름을 등록하고 `Input.GetButtonDown("Jump")`처럼 이름으로 묶어서 호출하는 습관을 들이세요.
* **`GetAxisDown`은 없습니다**: "GetAxis가 축 값이니까 눌린 순간은 GetAxisDown이겠지?"하고 찾는 분들이 많은데 그런 함수는 없습니다. 축의 눌린 순간은 `Input.GetButtonDown("축 이름")`으로 감지해야 합니다.
* **갈아탈 땐 미련 없이 한 번에**: 기존 프로젝트를 `New Input System`으로 마이그레이션하기로 결정했다면, 두 시스템을 절대 섞어 쓰지 마세요. 버그가 터졌을 때 입력이 레거시에서 씹힌 건지, 뉴 시스템에서 씹힌 건지 추적조차 불가능해집니다.
