# [Fundamentals] 6. Vector3 (벡터 3)

## 1. Vector3 란?
지도에서 "광화문"이라고 말하면 특정 **위치(한 지점)** 가 정해집니다. 반면 "여기서 북쪽으로 300미터"라고 말하면 **방향과 거리**가 정해집니다.\
`Vector3`는 이 '위치', '방향', '크기'라는 전혀 다른 개념을 **(X, Y, Z)라는 3개의 숫자 묶음 하나로 표현하는 만능 그릇**입니다.

> **네비게이션**
> * 만약 `Vector3`가 없었다면, 캐릭터를 대각선으로 움직일 때 `x = x + 속도`, `y = y + 속도`, `z = z + 속도` 처럼 3줄의 코드를 매번 써야 했을 것입니다.
> * `Vector3`는 이 3개의 축을 하나로 묶어줄 뿐만 아니라, 묶었기 때문에 가능해지는 마법들 — *"이 방향으로 얼마나 멀리 떨어져 있는가?(거리)", "어느 쪽을 향하는가?(정규화)", "나와 시야각이 얼마나 일치하는가?(내적)"* — 을 계산해 주는 수학 도구함입니다.

**왜 필요한가?**\
유니티 3D/2D 공간에서 무언가를 '배치하고', '움직이고', '바라보게' 하려면 100% `Vector3`를 다룰 줄 알아야 합니다. (참고로 2D 게임의 `Vector2`는 `Vector3`에서 `Z`축만 버린 하위 호환이므로, `Vector3`를 마스터하면 `Vector2`는 덤으로 딸려옵니다.)

## 2. 핵심 요약

| 분류 | 내용 |
| :--- | :--- |
| **정체** | `float x, y, z` 3개를 담고 있는 **값 타입 구조체(`struct`)** |
| **의미하는 것** | **위치**(`transform.position`), **방향**(`transform.forward`), **크기**(`transform.localScale`) |
| **가능한 연산** | `벡터 + 벡터` (방향 합성) / `벡터 × 숫자` (길이 늘이기) |
| **불가능한 연산**| `벡터 + 숫자` (방향에 숫자를 더할 순 없음) / `벡터 × 벡터` (내적/외적 함수로 따로 존재) |
| **자주 쓰는 상수**| `Vector3.zero`(0,0,0) / `Vector3.one`(1,1,1) / `Vector3.up`(0,1,0) / `Vector3.forward`(0,0,1) |

> **절대 원칙**
> 1. 이동할 때는 반드시 **방향(`normalized`)** 과 **속도(`speed`)** 를 분리해서 곱해야 합니다.
> 2. `transform.position.x = 5f;` 는 불가능합니다. (구조체라 사본만 반환하기 때문). 통째로 `new Vector3`에 담아서 덮어씌워야 합니다.

## 3. 세부 개념 및 원리

### 3.1 가장 헷갈리는 빼기의 방향 (나 → 목표)
* **공식**: `목표 위치 - 내 위치 = 나에게서 목표를 향하는 화살표(벡터)`
* 순서를 반대로 빼면, 적이 플레이어를 향해 오는 게 아니라 엉덩이를 보이고 도망갑니다

### 3.2 길이와 방향 찢기 (`magnitude` vs `normalized`)
적과 내 거리를 계산하고, 그쪽으로 걸어갈 방향을 뽑아냅니다.
```csharp
Vector3 offset = target.position - transform.position; // 목표를 향한 거대한 화살표

// 1. 길이(거리) 구하기
float length = offset.magnitude; // 실제 거리 (내부적으로 무거운 제곱근 루트 계산 발생)
float sqrLen = offset.sqrMagnitude; // 루트를 씌우지 않은 거리의 제곱 (비교용으로 초고속)

// 2. 방향만 뽑아내기 (정규화)
Vector3 dir = offset.normalized; // 거리는 1로 압축하고 '방향'만 남긴 순수 단위 벡터
```

### 3.3 두 벡터의 고급 연산 (내적, 외적)
```csharp
// 1. 내적 (Dot Product): 두 방향이 얼마나 비슷한가? (시야각 계산에 99% 씀)
// 내적값이 1이면 정면, 0이면 직각, -1이면 완전 등 뒤에 있음
float dot = Vector3.Dot(transform.forward, enemyDir);

// 2. 외적 (Cross Product): 두 벡터에 수직인 새로운 벡터 구하기 (주로 평면의 법선 찾기)
Vector3 cross = Vector3.Cross(Vector3.up, Vector3.right); // 결과는 Vector3.forward
```

## 4. 코드로 보는 `Vector3` 이동의 진화

### 최악의 이동 (방향과 거리가 섞임)
```csharp
// 의도: 적이 플레이어를 향해 다가옴
// 실제: 플레이어가 멀리 있으면 텔레포트급으로 튀어 오고, 가까워질수록 개미처럼 느려짐
Vector3 direction = target.position - transform.position; 
transform.position += direction * speed * Time.deltaTime; // 정규화를 안 함
```

### 정석 이동 (방향과 속도의 분리)
```csharp
// 공식을 외우세요: 이동량 = (목표 - 현재).normalized × 원하는 속도 × 델타타임
Vector3 direction = (target.position - transform.position).normalized;
transform.position += direction * speed * Time.deltaTime; // 깔끔한 등속 이동
```

## 5. 실전 활용: 부드러운 이동 3대장 비교

유니티에서 점 A에서 점 B로 이동시킬 때, 쌩으로 `+=`를 더하지 않고 유니티가 제공하는 3가지 우아한 수학 함수를 주로 씁니다.

### 1. `MoveTowards` (기계적인 등속 이동)
* **특징**: 목표지점까지 절대 속도가 변하지 않고 뚜벅뚜벅 걸어갑니다. 목표 지점을 오버해서 지나치지 않도록 안전장치가 걸려 있습니다.
* **용도**: 총알 날아가기, 순찰 도는 경비병.
```csharp
transform.position = Vector3.MoveTowards(transform.position, target.position, speed * Time.deltaTime);
```

### 2. `Lerp` (부드러운 직선 감속 이동, 선형 보간)
* **특징**: 남은 거리의 `t` 비율만큼씩만 이동합니다. 처음엔 휙! 빠르게 가다가 목표에 다가갈수록 스르륵~ 느려지며 부드럽게 멈춥니다.
* **용도**: 캐릭터를 부드럽게 따라다니는 카메라 추적, 체력바 게이지가 차오르는 연출.
```csharp
// 0.1f 비율만큼씩 계속 섞어 들어갑니다 (스무스 효과)
transform.position = Vector3.Lerp(transform.position, target.position, 0.1f);
```

### 3. `Slerp` (부드러운 곡선 이동, 구면 선형 보간)
* **특징**: `Lerp`와 똑같이 부드럽게 가지만, 직선이 아니라 **둥근 궤적(호)** 을 그리며 날아갑니다.
* **용도**: 대포알의 포물선 궤적, 몬스터가 고개를 부드럽게 휙 돌리는 회전 처리(`Quaternion.Slerp`).
```csharp
transform.position = Vector3.Slerp(transform.position, target.position, 0.1f);
```

## 6. Unity 최적화 팁

### 6.1 `magnitude` vs `sqrMagnitude` (최적화의 단골 손님)
거리가 특정 범위(예: 사거리 5m) 안으로 들어왔는지 확인할 때, `Vector3.Distance`나 `magnitude`를 쓰면 내부적으로 무거운 루트(`√`) 계산이 발생합니다.\
적 100마리가 매 프레임 이 계산을 돌리면 심각한 렉이 걸립니다. 루트를 씌우지 않은 날것의 값인 **`sqrMagnitude`** 를 쓰고, 비교할 사거리도 똑같이 제곱해서 비교하세요

```csharp
// 나쁜 예 (무거움)
if (offset.magnitude < 5f) { /* 사거리 진입 */ }

// 정석 (초고속 연산)
if (offset.sqrMagnitude < 25f) { /* 5의 제곱인 25와 비교 (루트 계산 아예 생략) */ }
```

### 6.2 겹침 방어 (`normalized`의 반란)
적과 플레이어가 완벽하게 겹쳐서 좌표가 `(0, 0, 0)`이 된 상태에서 `.normalized`를 때리면 방향을 상실하고 `NaN(Not a Number)` 에러를 뿜으며 위치가 증발하는 버그가 생깁니다.
```csharp
float sqrDist = offset.sqrMagnitude;

// 거리가 사실상 0이면 방향 계산을 멈추고 튕겨냅니다.
if (sqrDist < 0.0001f) return; 

Vector3 dir = offset.normalized; // 이제 안전
```

### 6.3 구조체(struct) 한계 극복하기
`Vector3`는 참조가 아닌 '값(Value)'이기 때문에, 클래스 속성에서 일부분만 고칠 수 없습니다.
```csharp
// 에러: Cannot modify the return value (컴파일 불가)
transform.position.x = 5f; 

// 정석: 통째로 꺼내서 고치고 통째로 덮어씌운다
Vector3 tempPos = transform.position;
tempPos.x = 5f;
transform.position = tempPos;
```

## 7. 실습 문제 및 복습

**Q1. 내 위치가 (1,0,0)이고 적의 위치가 (4,0,0)입니다. 내 위치에서 적을 바라보는 방향 벡터를 구하는 공식을 쓰세요.**
> 목표 위치에서 내 위치를 빼야 합니다. `(4,0,0) - (1,0,0) = (3,0,0)`이며, 이를 정규화(`.normalized`)하면 길이가 1인 순수 방향 벡터 `(1,0,0)`(즉, 오른쪽 방향)을 얻을 수 있습니다.

**Q2. 두 객체가 서로를 바라보고 있는지 확인하고 싶을 때 `Vector3`의 어떤 수학적 함수를 사용해야 하며, 결괏값이 몇에 가까워야 정면을 바라보는 것인가요?**
> **`Vector3.Dot(내 앞방향, 적을 향한 방향)` (내적)** 을 사용합니다. 내적의 결과가 **`1`** 에 가까울수록 서로 완벽한 정면을 바라보는 것이며, `0`이면 수직(옆면), `-1`이면 완벽히 등 뒤를 바라보고 있다는 뜻입니다.

**Q3. 캐릭터 이동 구현 시, `position += Vector3.forward * speed;` 라고만 적으면 발생하는 치명적인 문제 2가지는 무엇인가요?**
> 1. `Vector3.forward`는 무조건 씬의 북쪽(절대 축 0,0,1)만을 가리킵니다. 캐릭터가 오른쪽으로 고개를 돌려도 영원히 북쪽으로만 전진하는 문워크 버그가 발생합니다. (캐릭터가 바라보는 앞쪽으로 가려면 `transform.forward`를 써야 합니다.)
> 2. `Time.deltaTime`을 곱하지 않았기 때문에, 모니터 주사율이나 컴퓨터 성능이 좋을수록 캐릭터가 미친 듯이 빨리 달려 나가는 '사양 종속성 프레임 버그'가 발생합니다.

## 8. 주의사항 및 안전 습관

* **`Vector3.up`과 `transform.up`을 헷갈리지 마라**: 전자는 지구의 하늘(절대 북쪽)이고, 후자는 캐릭터의 정수리(기울어지면 같이 기울어짐)입니다. 상황에 맞게 명확히 골라 쓰세요.
* **`Time.deltaTime` 빼먹지 않기**: 매 프레임 연속적으로 더해지는 이동 값(`Update` 내부)에는 무조건 델타타임을 곱해 "1 프레임당"을 "1 초당" 속도로 보정해야 합니다. (단, 물리 엔진인 `FixedUpdate`나 `AddForce` 계열에는 델타타임을 곱하지 않는 경우가 많으니 주의하세요.)
* **정규화(`.normalized`) 잊지 않기**: 방향 벡터를 구할 때 정규화를 빼먹으면, 타겟이 멀어질수록 내 캐릭터가 순간이동급으로 튀어나가는 호러쇼를 보게 됩니다.
