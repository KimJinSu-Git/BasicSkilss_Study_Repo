# [Fundamentals] 19. Animator 기초 (2D)

## 1. Animator 컴포넌트란?
> **'비디오 플레이어'와 '인공지능 감독'**
> * **[직접 재생]**: "지금 걷기 비디오 틀어"라고 코드가 비디오 플레이어의 버튼을 냅다 누르는 방식입니다.
> * **[Animator]**: "지금 이동량이 0.8이고, 달리기 버튼은 안 눌렸어"라고 코드가 사실만 보고서로 올리면, 인공지능 감독(Animator)이 알아서 **규칙에 따라 클립을 골라 자연스럽게 재생**해 주는 방식입니다.

**왜 필요한가? (직접 재생의 한계)**
애니메이션 클립을 코드에서 이름으로 직접 골라 재생(`animator.Play("Walk")`)하면 곧 4가지 지옥이 열립니다.
1. **뚝뚝 끊김**: 걷기에서 달리기로 그냥 갈아 끼우면 다리 위치가 튑니다. (섞어주는 구간 부재)
2. **코드 스파게티**: "공격 중에는 걷기로 못 간다" 같은 예외 규칙이 늘어날 때마다 `if`문이 누더기처럼 쌓입니다.
3. **협업 불가**: 클립 이름을 바꾸거나 모션을 추가하는 순간 기획자가 아닌 프로그래머가 코드를 뜯어고쳐야 합니다.
4. **종료 시점 파악 불가**: 공격 모션이 끝났는지 알려면 클립 길이를 코드가 기억해야 합니다.

이 모든 문제를 **상태 기계(State Machine)** 라는 층을 끼워 넣어, 코드는 '상황 보고(Parameter)'만 하고 재생 로직은 에디터(Animator)로 넘겨버려 완벽히 분리하는 것이 이 챕터의 핵심입니다.

## 2. 핵심 요약

| 이름 | 무엇인가 | 어디서 만지는가 |
| :--- | :--- | :--- |
| **Animation Clip** (`.anim`) | 시간에 따른 이미지/위치 변화 데이터 (비디오 테이프) | Animation 창 |
| **Animator Controller** (`.controller`) | 클립 간의 상태·전이·파라미터 재생 규칙 (감독의 뇌) | Animator 창 |
| **Animator 컴포넌트** | 규칙을 오브젝트에 부여하는 부품 | 인스펙터 |
| **Parameter** (파라미터) | 코드가 감독에게 넘기는 사실 보고서 | Float, Bool, Int, Trigger |
| **Transition** (전이) | 상태에서 상태로 넘어가는 화살표와 조건 | Animator 창 |

> **[원칙]**
> 1. 스크립트는 파라미터만 세웁니다. 어떤 클립을 재생할지는 컨트롤러가 고릅니다.
> 2. 파라미터 이름은 대소문자까지 에디터와 똑같아야 합니다. (틀려도 오류가 나지 않고 침묵합니다.)
> 3. 파라미터 문자열은 가급적 **`Animator.StringToHash`** 로 캐싱한 `int` 상수로 다루세요.

## 3. 세부 개념 및 원리

### 3.1 가장 많이 헷갈리는 파라미터: `Trigger` vs `Bool`
* **`Bool` (상태 유지)**: `true`로 켜두면 내가 다시 `false`로 끌 때까지 그 상태가 쭉 유지됩니다.
    * ➔ **(예시) 걷기(`IsWalk`), 달리기(`IsRun`), 방어(`IsGuard`)**
* **`Trigger` (단발성 신호)**: 총 방아쇠처럼 한 번 당기면(true), 목표 상태로 넘어간 뒤 **스스로 즉시 해제(false)** 됩니다. 일회성 사건에 씁니다.
    * ➔ **(예시) 점프(`Jump`), 피격(`Hit`), 공격(`Attack`), 사망(`Die`)**

### 3.2 전이(Transition)의 3대 손잡이
화살표(전이)를 클릭하면 나오는 인스펙터 설정 중 가장 중요한 3가지입니다.

| 항목 | 하는 일 | 실무 팁 |
| :--- | :--- | :--- |
| **Conditions** | 넘어가는 조건 설정 | `Float`은 == 비교가 안 되므로 `Greater`, `Less`를 씁니다. |
| **Has Exit Time** | 현재 클립을 일정량 다 본 뒤에 넘길지 여부 | 즉시 넘어가려면 **끄고**, 모션이 끝난 뒤 이어지게 하려면 **켭니다.** |
| **Transition Duration**| 두 클립을 섞는(블렌딩) 시간 | 2D 사이드뷰/도트 게임에서는 이미지가 뭉개지므로 대개 **0**으로 둡니다. |

### 3.3 상태 폭발을 막는 마법: 블렌드 트리 (Blend Tree)
"대기 ➔ 걷기 ➔ 달리기"를 각각 상태 노드로 쪼개고 화살표로 이으면 맵이 거미줄처럼 변합니다.\
**블렌드 트리(Blend Tree)** 는 이 클립들을 하나의 노드 안에 욱여넣고, `Movement`라는 `Float` 파라미터 하나로 **0일 땐 대기, 0.5일 땐 걷기, 1일 땐 달리기를 알아서 부드럽게 섞어주는** 혁명적인 기능입니다. (2D에서는 주로 `1D` 타입을 씁니다.)

### 3.4 상태 자체에 코드 붙이기 (`StateMachineBehaviour`)
애니메이션이 재생될 때 훅(Hook)을 걸어 코드를 실행하는 강력한 기능입니다.\
Animator 창에서 상태 노드를 고르고 `Add Behaviour`를 누르면 부착됩니다.

```csharp
public class AttackBehaviour : StateMachineBehaviour
{
    // 공격 노드에 진입하는 첫 프레임에 불림
    public override void OnStateEnter(Animator animator, AnimatorStateInfo stateInfo, int layerIndex)
    {
        animator.GetComponent<Player>().SetAttackLock(true); // 공격 중 이동 잠금
    }

    // 공격 노드에서 빠져나가는 마지막 프레임에 불림
    public override void OnStateExit(Animator animator, AnimatorStateInfo stateInfo, int layerIndex)
    {
        animator.GetComponent<Player>().SetAttackLock(false); // 공격 잠금 해제
    }
}
```
이걸 쓰면 `Update` 문 안에서 진행도가 몇 퍼센트인지 계산할 필요가 없어집니다

## 4. 코드로 보기 (직접 재생 vs 파라미터 구동)

### 잘못된 방법 (하드코딩 직접 재생)
```csharp
public class BadAnimation : MonoBehaviour
{
    private Animator _animator;
    private string _currentState = "Idle";

    private void Awake() => _animator = GetComponent<Animator>();

    private void Update()
    {
        float movement = Input.GetAxisRaw("Horizontal");
        string nextState = (Mathf.Abs(movement) > 0.1f) ? "Walk" : "Idle";

        // 하드코딩: 매 프레임 Play를 부르면 진행 중인 전이가 취소되므로 직접 막아줘야 함.
        if (nextState != _currentState)
        {
            _animator.Play(nextState);
            _currentState = nextState;
        }
    }
}
```

### 정석 방법 (해시 캐싱 + 파라미터 구동)
```csharp
public class GoodAnimation : MonoBehaviour
{
    // 1. 무거운 문자열 대신 가벼운 정수(Hash)로 1번만 미리 변환해서 캐싱해 둔다
    private static readonly int HASH_SPEED = Animator.StringToHash("Speed");
    
    private Animator _animator;

    private void Awake() => _animator = GetComponent<Animator>();

    private void Update()
    {
        float movement = Input.GetAxisRaw("Horizontal");
        
        // 2. 코드는 그저 "지금 이동량이 이만큼이야" 라고 보고만 한다. 재생은 에디터가 알아서 함.
        _animator.SetFloat(HASH_SPEED, Mathf.Abs(movement)); 
    }
}
```

## 5. 실전 활용 예시: 피격(Hit) 후 남은 트리거 청소하기

`Trigger` 파라미터는 한 번 불이 켜지면, 애니메이터가 그 신호를 소비해서 다른 상태로 넘어가기 전까지 계속 켜져 있습니다.\
만약 플레이어가 연속으로 3대 맞아서 `Hit` 트리거가 3번 쌓였다면, 몬스터가 때리지도 않는데 혼자 3번 피격 모션을 반복하는 참사가 일어납니다.

```csharp
public class PlayerCombat : MonoBehaviour
{
    private static readonly int HASH_HIT = Animator.StringToHash("Hit");
    private Animator _animator;

    private void Awake() => _animator = GetComponent<Animator>();

    public void TakeDamage(int damage)
    {
        // 피격 모션이 아직 안 끝났는데 또 맞았다면?
        // 기존에 남아있던 피격 트리거 예약건을 캔슬(Reset)하고 새로 덮어씌운다
        _animator.ResetTrigger(HASH_HIT);
        _animator.SetTrigger(HASH_HIT);
    }
}
```

## 6. Unity 최적화 팁

### 6.1 `AnyState`는 독이 든 성배다
`AnyState`는 내가 밥을 먹든 잠을 자든 무조건 그 상태로 직행하게 해주는 만능 출발점입니다. `Hit(피격)`이나 `Die(사망)`처럼 긴급 끼어들기 이벤트에는 아주 좋습니다.
* **함정**: "어? 걷기도 뛸 때나 멈춰있을 때 다 갈 수 있으니까 `AnyState`로 이어야지" ➔ 지옥의 시작입니다.
* 조건이 조금만 참이어도 달리는 도중 자기 자신(걷기)을 계속 무한 호출하여 클립이 되감기며 부르르 떱니다. (인스펙터의 `Can Transition To Self` 체크 해제 필수). **실무에서는 피격, 사망 등 확실한 상태 2~3개 외에는 `AnyState`를 쳐다보지도 마세요.**

### 6.2 배속 조절과 반복(Loop)의 주체
* **반복(Loop Time)**: 걷기나 뛰기가 한 바퀴만 돌고 굳어버린다면, Animator 창이 아니라 Project 창의 원본 **Animation Clip (`.anim`) 파일**을 눌러서 인스펙터의 `Loop Time` 체크박스를 켜야 합니다.
* **배속 조절**: 클립 자체의 샘플 레이트를 건드리기보다, 스크립트에서 `_animator.speed = 1.5f;` 처럼 배속을 조절하거나 Animator 노드 인스펙터의 `Speed` 값을 조절하는 것이 실무 정석입니다.

## 7. 실습 문제 및 복습

**Q1. 에디터에서 `Jump`라는 이름의 Trigger 파라미터를 만들고 코드로 `_anim.SetTrigger("jump");`를 호출했습니다. 점프 애니메이션이 재생되지 않는데도 콘솔에는 아무런 빨간 에러가 뜨지 않습니다. 이유가 무엇인가요?**
> `Animator`의 파라미터 문자열 비교는 대소문자를 완벽하게 가립니다. 대문자 `J`와 소문자 `j`가 다르기 때문에 신호가 전달되지 않았지만, 유니티는 파라미터 오타를 에러로 띄워주지 않고 조용히 무시해(침묵) 버립니다. 이를 막기 위해 반드시 `Animator.StringToHash("Jump")`를 사용해 상수화 시켜두어야 합니다.

**Q2. 2D 도트 게임을 만드는데, 캐릭터가 `Idle` 상태에서 `Walk` 상태로 넘어갈 때 이미지가 기괴하게 찌그러지고 잔상이 생깁니다. 인스펙터의 전이(Transition) 화살표 설정 중 어느 부분을 고쳐야 하나요?**
> 도트 그래픽은 3D 뼈대(Bone) 애니메이션과 달라서 이미지 두 장을 억지로 반반 섞어버리면(블렌딩) 투명도가 겹치면서 이미지가 뭉개집니다. 두 상태를 잇는 화살표를 클릭하고, 인스펙터 창에서 **`Transition Duration (s)`의 값을 0으로** 만들어주어야 중간 과정 없이 즉시 이미지가 딱! 교체됩니다.

**Q3. `Idle` ➔ `Attack` 으로 넘어가는 조건에 `Attack Trigger`를 넣고, `Attack` ➔ `Idle` 로 돌아오는 화살표에는 아무런 조건(Conditions)을 넣지 않았습니다. 그런데 공격 버튼을 누르자마자 공격 모션이 0.1초 만에 끝나고 바로 `Idle`로 돌아가 버립니다. 어떤 세팅이 누락되었나요?**
> 공격 모션을 '끝까지 다 보고' 돌아가라는 의미의 **`Has Exit Time`** 체크박스가 꺼져있기 때문입니다. 이 체크박스를 켜고 `Exit Time`을 1로 두어야만 클립 재생이 100% 진행된 뒤에 다음 상태(`Idle`)로 넘어가게 됩니다.

## 8. 주의사항 및 안전 습관

* **초기화 순서 주의**: `Animator`는 꽤 무거운 컴포넌트라 `Awake`에서 `GetComponent<Animator>()`로 미리 멱살을 잡아 캐싱해 두는 것이 기본입니다. 절대 `Update` 안에서 매 프레임 `GetComponent`를 부르지 마세요.
* **`SetTrigger`의 미세 프레임 함정**: `SetTrigger`를 세우고 같은 프레임 안에서 즉시 `GetCurrentAnimatorStateInfo`로 상태를 물어보면, 아직 애니메이터가 갱신되기 전이라 '이전 상태'가 튀어나옵니다. 상태 전이는 다음 프레임 갱신 때 일어나므로 한 프레임을 양보(`IsInTransition` 활용)해야 합니다.
* **그림이 먼저, 이동은 나중**: 코드를 짤 때 애니메이션 파라미터가 유니티 에디터상에서 제대로 틱틱 돌아가는지 눈으로 먼저 확인한 뒤에 물리 이동 코드를 얹으세요. 두 개를 한 번에 짜면 캐릭터가 안 움직일 때 물리 문제인지 애니메이터 문제인지 찾기 힘듭니다.
* **조작감은 에디터에서**: "조작이 너무 답답해요!"라는 피드백이 오면 코드를 뜯기 전에 Animator 화살표의 `Has Exit Time`과 `Transition Duration`부터 0으로 줄여보세요. 90%는 여기서 해결됩니다.
