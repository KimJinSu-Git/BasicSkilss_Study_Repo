# [Fundamentals] 11. Collider2D, Rigidbody2D

## 1. Collider2D, Rigidbody2D 란?

> **자동차의 차체와 엔진**
> * **`Collider2D` (차체)** : 어디까지가 내 몸통인지, 다른 차와 언제 부딪히는지를 판정하는 **껍데기(경계)** 입니다.
> * **`Rigidbody2D` (엔진)** : 그 몸통을 중력에 떨어지게 하고, 마찰력과 충격량에 반응하게 만드는 **물리적 심장**입니다.

**왜 이 둘을 쪼개 놨을까?**\
게임 내 모든 물체가 중력을 받을 필요는 없기 때문입니다.\
가만히 서 있는 돌담(벽)은 껍데기(`Collider2D`)만 있으면 남을 막을 수 있습니다. 여기다가 굳이 무거운 물리 엔진(`Rigidbody2D`)을 달아줄 필요가 없습니다. 기능의 낭비를 막기 위해 철저히 부품을 쪼개놓은 유니티의 철학입니다.

---

## 2. 핵심 요약

| 컴포넌트 | 맡는 일 | 빼면 어떻게 되는가? |
| :--- | :--- | :--- |
| **`Collider2D`** | 부딪히는 **모양(경계)** 정의 | 서로 겹쳐도 쑥 통과하고 아무 일도 안 일어남 |
| **`Rigidbody2D`**| 중력과 힘을 계산하는 **물리 연산** | 허공에 떠서 중력을 안 받고, 충돌해도 튕겨나가지 않음 |

* 두 오브젝트가 튕겨 나가려면 **양쪽에 `Collider2D`**, 그리고 **최소 한쪽에는 `Rigidbody2D`** 가 있어야 합니다.
* 유니티 2D에서는 절대 `transform.position`으로 물리 객체를 억지로 이동시키지 마세요. 무조건 `Rigidbody2D`가 제공하는 힘(`Force`)이나 `Velocity`를 통해 움직여야 물리 법칙이 깨지지 않습니다.

## 3. 세부 개념 및 원리

### 3.1 `Collider2D` : 부딪히는 경계선
2D 게임 오브젝트의 물리적 형태를 정의합니다. 인스펙터에서 `Edit Collider` 버튼을 누르면 초록색 선으로 형태를 시각적으로 편집할 수 있습니다.

| 종류 | 특징 및 주로 쓰는 곳 |
| :--- | :--- |
| **BoxCollider2D** | 사각형 (발판, 벽, 네모난 상자) |
| **CircleCollider2D** | 원형 (공, 구르는 아이템) ➔ 굴림이 제일 자연스럽고 연산이 **가장 쌉니다.** |
| **CapsuleCollider2D**| 알약 모양 (사람형 캐릭터) ➔ 모서리에 걸리지 않아 점프 게임에 필수 |
| **PolygonCollider2D**| 스프라이트 모양대로 자동 생성 ➔ 무겁고 요철에 걸리므로 가급적 쓰지 마세요. |

> **[팁] 벽 타기 버그 방지 (`PhysicsMaterial2D`)**\
> 2D 플랫포머에서 플레이어가 점프해서 벽으로 직진하면, 중력을 무시하고 스파이더맨처럼 벽에 찰싹 붙어있는 버그가 발생합니다.\
> ➔ **원인**: 콜라이더 간의 기본 마찰력(Friction) 때문입니다.\
> ➔ **해결**: 프로젝트 창에서 우클릭 ➔ `Create ➔ 2D ➔ Physics Material 2D` 생성 ➔ `Friction`을 **0**으로 설정 ➔ 캐릭터 콜라이더의 `Material` 슬롯에 쏙 넣어주면 완벽히 미끄러져 내려옵니다

### 3.2 `Rigidbody2D` : 물리 엔진의 심장
이 녀석을 달아주면 오브젝트가 유니티 물리 엔진(PhysX 2D)의 완벽한 지배를 받게 됩니다.\
가장 중요한 설정은 3가지로 나뉘는 **`Body Type`** 입니다.

| Body Type | 중력/외력의 영향 | 움직이는 주체 | 실무 쓰임새 |
| :--- | :--- | :--- | :--- |
| **Dynamic** (동적) | **전부 다 받음** | 힘(`Force`)을 가해서 | 주인공, 몬스터, 굴러가는 돌 |
| **Kinematic** (운동학적) | **안 받음** | 스크립트로 직접 조작 | 움직이는 엘리베이터 발판 |
| **Static** (정적) | **전혀 안 받음** | 절대 움직이지 않음 | 가만히 있는 땅, 건물 |

> **Kinematic의 무서움 (`MovePosition`의 위력)**\
> `Kinematic`은 지진이 나도 절대 밀리지 않는 줏대 있는 녀석이지만, 자기가 움직일 땐 남(Dynamic)을 무자비하게 밀어버립니다.\
> 만약 엘리베이터(`Kinematic`) 위에 플레이어(`Dynamic`)가 올라탔을 때, 엘리베이터를 `transform.position += ...` 로 움직이면 플레이어가 미끄러져 떨어집니다. 하지만 물리 엔진 함수인 **`rb.MovePosition(...)`** 으로 움직이면 위에 탄 플레이어를 마찰력으로 붙잡고 같이 데리고 올라갑니다

### 3.3 인스펙터의 핵심 속성들
* **Gravity Scale**: 중력의 세기. (보통 점프 게임 캐릭터는 3~5배 정도로 높여서 떨어지는 속도를 빠릿빠릿하게 만듭니다.)
* **Linear Damping**: 이동 저항(공기 마찰). 높을수록 빙판길이 아니라 진흙탕처럼 꾹꾹 멈춥니다.
* **Constraints ➔ Freeze Rotation Z**: **캐릭터가 돌부리에 걸려 데굴데굴 구르거나 드러눕는 것을 막는 생명줄입니다.** 사람 형태 캐릭터면 무조건 체크하세요.

## 4. 코드로 보는 치명적인 이동 버그

### 잘못된 물리 이동 (순간이동 버그)
```csharp
public class TransformPusher : MonoBehaviour
{
    private void Update()
    {
        // 최악: 차에 엔진(Rigidbody)을 달아놓고 손(Transform)으로 차를 밀고 감.
        // 벽을 만나도 뚫고 나가버리거나 덜덜 떨리는 물리 버그 발생
        transform.position += Vector3.right * moveSpeed * Time.deltaTime;
    }
}
```

### 정석 물리 이동 (엔진 구동)
```csharp
[RequireComponent(typeof(Rigidbody2D))] // 스크립트 붙일 때 리지드바디도 강제 자동 장착
public class RigidbodyPusher : MonoBehaviour
{
    private Rigidbody2D _rb;

    private void Awake() => _rb = GetComponent<Rigidbody2D>();

    // 물리 연산은 Update가 아니라 무조건 FixedUpdate(고정 프레임) 안에서 처리합니다.
    private void FixedUpdate()
    {
        // 속도(Velocity)를 덮어씌움. (y축 속도는 기존 중력값을 그대로 살림)
        _rb.linearVelocity = new Vector2(moveSpeed, _rb.linearVelocity.y);
    }
}
```

## 5. 실전 활용 예시 (2D 플랫포머 점프 로직)

충돌 콜백(`OnCollisionEnter2D`)으로 바닥을 판정하면 벽에 비빌 때도 '땅에 닿았다'고 판정되어 무한 점프가 가능해집니다. 이를 막는 완벽한 바닥 판정 기법입니다.

```csharp
[RequireComponent(typeof(Rigidbody2D))]
public class Platformer2D : MonoBehaviour
{
    [SerializeField] private float jumpForce = 10f;
    [SerializeField] private Transform groundCheck; // 캐릭터 발밑에 둔 빈 오브젝트
    [SerializeField] private LayerMask groundLayer; // 바닥으로 취급할 레이어

    private Rigidbody2D _rb;
    private bool _isGrounded;
    private bool _wantsToJump;

    private void Awake() => _rb = GetComponent<Rigidbody2D>();

    private void Update()
    {
        // 1. 발밑에 아주 작은 가상의 원(0.15f)을 그려서 바닥 레이어와 닿았는지 묻기
        _isGrounded = Physics2D.OverlapCircle(groundCheck.position, 0.15f, groundLayer) != null;

        // 2. 키보드 입력은 누락을 막기 위해 무조건 Update에서 받아서 플래그만 켭니다.
        if (_isGrounded && Input.GetKeyDown(KeyCode.Space))
        {
            _wantsToJump = true;
        }
    }

    private void FixedUpdate()
    {
        // 3. 실제 물리 점프 실행은 FixedUpdate에서 안전하게 처리합니다.
        if (_wantsToJump)
        {
            // y축에 점프력을 통째로 때려 박습니다.
            _rb.linearVelocity = new Vector2(_rb.linearVelocity.x, jumpForce);
            _wantsToJump = false;
        }
    }
}
```

## 6. Unity 최적화 팁

### 6.1 `velocity` 를 직접 수정할 것인가, 힘(`AddForce`)을 줄 것인가?
* **`linearVelocity` 덮어쓰기**: 정확히 5m/s 속도로 움직여야 하는 **이동 조작, 점프**에 씁니다. 조작감이 빠릿빠릿해집니다.
* **`AddForce(힘)` 밀어내기**: 폭탄을 맞고 튕겨 날아가는 **넉백(Knockback)** 이나 얼음판 미끄러짐에 씁니다. 질량(`Mass`)의 영향을 받아 사실적으로 밀려납니다.

### 6.2 콜라이더 경계 상자 (`bounds`)의 활용
캐릭터가 낭떠러지 화면 아래로 완전히 떨어졌을 때 파괴(`Destroy`)하는 로직입니다.\
`transform.position.y`로 검사하면 캐릭터 몸통 중심점 기준이라 머리통이 아직 보일 때 잘려나갈 수 있습니다.
```csharp
// 콜라이더의 찐 '머리 꼭대기(max.y)'가 기준선 아래로 내려갈 때만 판정
if (_collider.bounds.max.y < killHeight)
{
    Destroy(gameObject); 
}
```

### 6.3 상태를 뒤집을 때는 세트로 조작하라 (매달린 공 떨어뜨리기)
공이 무언가에 매달려 있을 때는 `Kinematic`으로 물리를 꺼둡니다. 그러다 떨어뜨릴 때는 3가지를 콤보로 갈아끼워야 관성 버그가 안 생깁니다.
```csharp
public void Drop()
{
    _rb.bodyType = RigidbodyType2D.Dynamic; // 1. 물리 영향 켬
    _rb.gravityScale = 1f;                  // 2. 중력 복구
    _rb.linearVelocity = Vector2.zero;      // 3. Kinematic 시절 매달려 흔들리던 관성(속도) 잔여물 삭제
}
```

## 7. 실습 문제 및 복습

**Q1. `Kinematic` 모드인 엘리베이터 발판 위에 `Dynamic` 모드인 상자를 올려두었습니다. 발판 스크립트에서 `transform.position`으로 발판을 옆으로 쓱 옮겼더니 상자가 미끄러져 바닥으로 추락했습니다. 어떻게 고쳐야 상자를 데리고 갈 수 있나요?**
> `Update` 문 안의 `transform.position += ...` 이동 로직을 지우고, 물리 엔진과 통신하는 `FixedUpdate` 안에서 **`rb.MovePosition(rb.position + 방향)`** 을 사용해야 합니다. 물리 엔진이 위치 이동을 텔레포트가 아니라 물리적 궤적으로 인식하여 마찰력을 통해 위의 상자를 데리고 갑니다.

**Q2. 캐릭터가 점프 게임에서 공중을 날아다니다가 벽의 모서리에 닿으면, 중력이 있는데도 떨어지지 않고 벽에 찰싹 붙어있습니다. 코드의 문제가 아니라면 어떤 에셋 세팅이 빠진 것인가요?**
> 캐릭터 콜라이더나 벽 콜라이더 간의 기본 마찰력(Friction)이 작용하기 때문입니다. `Physics Material 2D` 에셋을 하나 새로 만들고 **Friction(마찰력) 값을 0**으로 세팅한 뒤, 캐릭터 콜라이더의 Material 슬롯에 장착해주면 모서리에서 부드럽게 미끄러져 떨어집니다.

**Q3. 총알 오브젝트의 Rigidbody 속성 중 `Collision Detection` 모드가 기본값인 `Discrete`일 때 생길 수 있는 치명적 버그는 무엇이며, 어떻게 해결하나요?**
> 총알이 너무 빠르면, 다음 물리 연산 스텝을 계산하기 전에 이미 얇은 벽을 뚫고 지나가 버려 충돌 판정이 통째로 씹히는 **터널링(Tunneling)** 버그가 발생합니다.\
> ➔ **해결책**: 총알 리지드바디의 `Collision Detection`을 경로 사이사이의 여백 공간까지 정밀하게 검사해 주는 **`Continuous`** 로 바꿔야 합니다. (단, 벽이나 느린 몹은 연산 폭주를 막기 위해 무조건 `Discrete`로 둬야 함)

## 8. 주의사항 및 안전 습관

* **물리 코드는 무조건 `FixedUpdate`**: `Update`에서 리지드바디 속도를 건드리면, 기기 성능에 따라 프레임이 널뛰며 물리 연산이 기괴하게 망가집니다.
* **`Freeze Rotation Z` 확인**: 2D 사람형 캐릭터를 만들 때 이 체크박스 안 켜고 테스트 시작했다가 캐릭터 자빠지는 건 하루에 한 번씩 꼭 하는 실수입니다.
* **리지드바디 없는 트리거의 분노**: 콜라이더에 `Is Trigger`를 켜두고 "왜 아이템을 못 먹지?" 한다면, 나와 아이템 둘 중 하나라도 리지드바디가 있는지 확인하세요. 둘 다 껍데기만 있으면 유령처럼 스쳐 지나갈 뿐 콜백은 영원히 오지 않습니다.
