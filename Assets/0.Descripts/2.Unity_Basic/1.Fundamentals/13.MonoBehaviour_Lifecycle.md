# [Fundamentals] 13. MonoBehaviour 라이프사이클 (Lifecycle)

## 1. MonoBehaviour 라이프사이클 이란?
> **연극 배우의 하루 일과표**
> * **`Awake`** : 무대에 오르기 전, 대기실에서 나 홀로 화장하고 의상을 입으며 준비하는 시간.
> * **`OnEnable`** : 내 차례가 되어 무대 조명을 받고 등장하는 순간 (퇴장했다가 다시 등장할 때마다 불림)
> * **`Start`** : 첫 대사를 치기 직전, 주변에 다른 동료 배우들이 잘 서 있는지 확인하는 시간.
> * **`Update`** : 연극이 진행되는 동안 쉴 새 없이 움직이고 대사를 치는 실시간 연기.
> * **`OnDisable`** : 내 씬이 끝나서 무대 뒤로 잠시 퇴장하는 순간.
> * **`OnDestroy`** : 연극이 완전히 끝나서 극장 밖으로 퇴근(파괴)하는 순간.

C# 콘솔 프로그램은 내가 짠 `Main()` 함수부터 주도적으로 흐르지만, 유니티는 엔진(감독)이 전체 흐름을 쥐고 있습니다.\
**내 스크립트(배우)는 유니티 엔진이 정해진 시점마다 찔러서 불러주는 '이벤트 함수' 안에 코드를 채워 넣는 방식으로 동작합니다.** 이 정해진 실행 순서표를 **라이프사이클(Lifecycle)** 이라고 부릅니다.

---

## 2. 핵심 요약

| 단계 | 이벤트 함수 | 무엇을 두는 자리인가 |
| :--- | :--- | :--- |
| **초기화** | `Awake` ➔ `OnEnable` ➔ `Start` | **내 부품 찾기 (`Awake`) ➔ 이벤트 구독 (`OnEnable`) ➔ 남의 부품 찾기 (`Start`)** |
| **매 프레임**| `FixedUpdate` ➔ `Update` ➔ `LateUpdate` | 물리 엔진 적용 ➔ 유저 입력 및 로직 ➔ 후처리 및 카메라 추적 |
| **해제** | `OnDisable` ➔ `OnDestroy` | 구독 해제 및 마무리 ➔ 오브젝트 메모리 삭제 |

> **원칙**
> 1. **"내 것은 `Awake`, 남의 것은 `Start`"**: 이 규칙만 지켜도 지옥의 `NullReferenceException` 90%를 막습니다.
> 2. `Update`끼리의 실행 순서는 완전 랜덤(운빨)입니다. 순서가 보장되어야 하는 로직은 **`LateUpdate`** 로 빼세요.
> 3. **`Destroy()`는 즉시 처형이 아니라 암살 예약입니다.** 코드를 부른 그 순간에는 안 지워지고 프레임 끝에 지워집니다.

## 3. 세부 개념 및 원리

### 3.1 초기화 단계 (Initialization)
게임 시작 시 딱 한 번(또는 켜질 때마다) 불리는 3형제입니다.

#### 1.  `Awake()` : 태어나는 순간
* 스크립트가 메모리에 로드될 때 단 한 번 불립니다.
* 자기 자신(내 게임오브젝트)에 붙은 컴포넌트를 `GetComponent`로 캐싱하는 자리입니다.
* 인스펙터에서 스크립트 체크박스(Enabled)를 끄고 시작해도 `Awake`는 무조건 불립니다 (단, 게임오브젝트 자체가 꺼져있으면 안 불림)

#### 2. `OnEnable()` : 켜질 때마다
* `Awake` 직후에 한 번 불리고, 이후 오브젝트가 꺼졌다 켜질 때마다 계속 불립니다.
* 이벤트(`Action`, `delegate`)를 구독(`+=`)하기 가장 좋은 자리입니다. (풀링 시스템의 실질적인 초기화 자리)

#### 3. `Start()` : 첫 `Update` 직전
* 모든 오브젝트의 `Awake`가 싹 다 끝났다는 것이 유니티에 의해 보장된 시점입니다.
* 따라서 **"다른 오브젝트(남)를 검색하거나 남의 값을 읽어올 때"** 절대 에러가 나지 않는 안전한 자리입니다.
* 스크립트 체크박스가 꺼져있으면 대기하다가, 나중에 켜지는 순간 그제야 한 번 불립니다.

### 3.2 매 프레임 단계 (가장 많이 하는 실수)
게임이 도는 동안 계속 불리는 핵심 로직 구역입니다.

#### 1. `Update()` : 매 프레임 (유저 입력)
* 모니터 화면이 한 번 깜빡일 때마다 불립니다. 프레임률(FPS)에 따라 호출 간격이 들쭉날쭉합니다.
* 마우스/키보드 입력 처리, 타이머 계산 등 물리와 무관한 로직을 둡니다.

#### 2. `FixedUpdate()` : 고정 간격 (물리 연산)
* 프레임률과 상관없이 무조건 고정된 간격(기본 0.02초)마다 불립니다. `Rigidbody`에 힘을 가하는 등 **물리 연산 전용 구역**입니다.
* **[함정] `Input.GetKeyDown`을 절대 이곳에 쓰지 마세요**
    * `FixedUpdate`는 화면 렉이 걸리면 한 프레임에 여러 번 돌거나 0번 돌기도 합니다. 이때 짧게 누른 스페이스바(점프) 입력을 씹어먹는 버그가 발생합니다.
    * **정석**: 입력은 `Update`에서 받아서 `bool` 플래그만 켜고, 힘은 `FixedUpdate`에서 플래그를 보고 가해야 합니다

#### 3. `LateUpdate()` : 모든 `Update`가 끝난 후 (후처리)
* 맵에 있는 100마리 몬스터와 플레이어의 `Update`가 전부 끝난 뒤 마지막으로 불립니다.
* 주인공이 이동을 다 끝낸 것을 확인한 후, **카메라가 부드럽게 쫓아가게 할 때(`Camera Follow`)** 씁니다.

### 3.3 해제 단계 (Decommissioning)

#### 1. `OnDisable()` : 꺼질 때마다
* `OnEnable`의 완벽한 짝꿍입니다. 여기서 구독을 해제(`-=`)해야 메모리 누수와 좀비 콜백을 막습니다.

#### 2. `OnDestroy()` : 죽기 직전
* 오브젝트가 완전히 파괴되거나, 씬이 넘어갈 때 마지막 유언을 남기는 곳입니다.

## 4. 코드로 보는 위력 (입력과 물리의 완벽한 분리)

`FixedUpdate`에서 점프를 처리할 때, 입력을 놓치지 않는 실무 100% 정석 코드입니다.

```csharp
[RequireComponent(typeof(Rigidbody2D))]
public class PlayerJump : MonoBehaviour
{
    [SerializeField] private float jumpForce = 6f;
    private Rigidbody2D _rb;
    private bool _isJumpQueued; // 점프 대기 플래그

    private void Awake()
    {
        // 내 몸의 부품을 찾는 건 Awake
        _rb = GetComponent<Rigidbody2D>();
    }

    private void Update()
    {
        // 1. 빛처럼 지나가는 1프레임짜리 단발성 입력(Down)은 무조건 Update에서 낚아챕니다
        if (Input.GetKeyDown(KeyCode.Space))
        {
            _isJumpQueued = true; // "점프 예약" 깃발만 꼽음
        }
    }

    private void FixedUpdate()
    {
        // 2. 물리 턴(0.02초)이 돌아오면, 깃발을 확인하고 힘을 줍니다.
        if (_isJumpQueued)
        {
            _rb.linearVelocity = new Vector2(_rb.linearVelocity.x, jumpForce);
            _isJumpQueued = false; // 힘을 줬으니 깃발을 내림
        }
    }
}
```

## 5. 실전 활용 예시

내가 가진 부품과 남이 가진 부품을 가져올 때, 에러를 막는 분업화 코드입니다.

```csharp
public class EnemyAI : MonoBehaviour
{
    private Animator _myAnim;       // 내 부품
    private Transform _playerTrans; // 남의 부품

    private void Awake()
    {
        // 내 부품은 내가 태어나자마자 무조건 세팅
        _myAnim = GetComponent<Animator>();
        Debug.Log("[Enemy] 내 애니메이터 장착 완료");
    }

    private void Start()
    {
        // 모든 애들이 태어난(Awake) 1프레임 뒤 시점.
        // 이때 남(Player)을 찾으면, 그 녀석도 자기 세팅을 다 끝냈을 테니 안전함
        GameObject playerObj = GameObject.FindWithTag("Player");
        if (playerObj != null)
        {
            _playerTrans = playerObj.transform;
        }
    }
}
```

## 6. 엔진 내부의 1프레임 훔쳐보기 (의사 코드)

유니티 엔진 내부에서는 대략 아래와 같은 순서로 1프레임이 굴러갑니다.
(이 흐름을 이해하면 버그의 90%를 머릿속에서 잡을 수 있습니다.)

```csharp
// 엔진의 무한 루프 (1프레임)
while (GameIsRunning)
{
    // 1. 방금 태어난 놈들 깨우기
    foreach (var obj in spawnedObjects) obj.Awake();
    
    // 2. 켜진 놈들 조명 비추기
    foreach (var obj in enabledObjects) obj.OnEnable();
    
    // 3. 첫 프레임 도는 놈들 대사 맞추기 (이래서 Awake가 Start보다 무조건 먼저 돕니다)
    foreach (var obj in unstartedObjects) obj.Start();

    // 4. 물리 연산 (렉 걸리면 여러 번 돌 수 있음)
    while (PhysicsTime >= 0.02f) {
        foreach (var obj in activeObjects) obj.FixedUpdate();
    }

    // 5. 일반 로직 (입력 처리)
    foreach (var obj in activeObjects) obj.Update();

    // 6. 후처리 (카메라 이동)
    foreach (var obj in activeObjects) obj.LateUpdate();

    // 7. 암살 명단(Destroy 예약) 처리 
    // Update가 다 끝나고 나서야 지워지기 때문에, 삭제를 부른 순간엔 안 지워지는 겁니다
    foreach (var obj in deathQueue) 
    {
        obj.OnDisable();
        obj.OnDestroy();
        RemoveFromMemory(obj);
    }
    
    RenderCamera(); // 화면 그리기 끝
}
```

## 7. 실습 문제 및 복습

**Q1. 스크립트에서 `GameObject.Find("Player")`를 썼습니다. 이 코드를 `Update()` 안에 넣으면 안 되는 이유와, 가장 적절하게 옮겨야 할 이벤트 함수는 어디인가요?**
> `GameObject.Find`는 씬 전체의 엑스트라들을 다 뒤져보는 엄청나게 무거운 탐색 함수입니다. 이를 매 프레임 불리는 `Update`에 넣으면 1초에 60번씩 씬 전체를 뒤지며 게임 프레임이 박살 납니다. **`Start()`** 함수 안에서 게임 시작 시 딱 한 번만 찾아서 멤버 변수(필드)에 저장(Cache)해 두고 써야 합니다.

**Q2. 두 명의 프로그래머가 게임을 만듭니다. A는 `Player` 스크립트의 `Update`에서 카메라를 움직이고, B는 `CameraFollow` 스크립트의 `Update`에서 카메라를 플레이어 위치로 덮어씌웁니다. 게임을 켜보니 카메라가 덜덜 떨리며 멀미가 납니다. 원인과 해결책은?**
> **원인**: 유니티는 같은 `Update` 함수끼리의 실행 순서를 보장하지 않습니다 (운빨). 어떤 프레임엔 카메라가 먼저 따라가고 플레이어가 움직여서 떨림이 발생합니다.\
> **해결책**: 카메라 이동 코드를 무조건 모든 `Update`가 끝난 뒤에 불리는 **`LateUpdate()`** 로 옮겨야 합니다.

**Q3. `void Updata()` 라고 함수 이름을 틀리게 적었습니다. 콘솔에 빨간 에러 메시지가 뜰까요? 안 뜬다면 유니티는 이 코드를 어떻게 취급하나요?**
> **빨간 에러는 절대 뜨지 않습니다.** 유니티의 이벤트 함수는 오버라이드(Override) 방식이 아니라, 문자열 리플렉션을 통해 정해진 이름(`Update`)을 찾는 방식입니다. 따라서 스펠링을 틀리면 컴파일러는 그냥 "아, 유저가 직접 만든 잡동사니 함수구나" 하고 무시해 버리며, 영원히 실행되지 않는 유령 코드가 됩니다.

## 8. 주의사항 및 안전 습관

* **빈 `Update` 함수는 렉의 주범이다**: 유니티 스크립트를 처음 만들면 비어있는 `Start`와 `Update`가 기본으로 적혀있습니다. 내용이 없다면 1초에 60번씩 헛스윙을 하므로 **무조건 지워버리세요.**
* **`Time.deltaTime`의 위치**: `Update` 안에서 움직일 때는 `Time.deltaTime`을 곱하지만, `FixedUpdate` 안에서 움직일 때는 `Time.fixedDeltaTime`을 곱해야 합니다. (리지드바디의 `AddForce`는 엔진이 알아서 시간 보정을 해주므로 곱할 필요가 없습니다)
* **구독과 해제는 찰떡궁합 짝꿍**: `OnEnable`에서 이벤트에 `+=`를 했다면, 무조건 `OnDisable`에서 `-=` 코드를 바로 짜두는 습관을 들이세요. 나중에 까먹으면 씬 전환 시 에러가 쏟아집니다.
