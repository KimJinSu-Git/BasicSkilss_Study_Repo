# [Fundamentals] 3. Scene · Hierarchy · Inspector

## 1. 세 창의 앙상블 (Scene, Hierarchy, Inspector)
Unity Editor에서 수많은 창이 있지만, 게임 콘텐츠를 만드는 동안 개발자의 눈과 손이 거의 떠나지 않는 핵심 창은 이 3개입니다. 이 셋은 서로를 실시간으로 갱신하며 완벽하게 맞물려 돌아가기 때문에, 떼어놓고 외우면 오히려 흐름을 놓치게 됩니다.

> **요리 작업장**
> * **Hierarchy (재료 목록)** : 지금 도마 위에 당근, 양파, 고기가 몇 개 올라와 있는지 보여주는 '리스트'입니다.
> * **Scene (도마와 작업대)** : 실제로 눈으로 보면서 재료를 썰고, 굽고, 물리적으로 조립하는 '3D/2D 캔버스 공간'입니다.
> * **Inspector (양념 계기판)** : 선택한 재료 하나(예: 고기)에 소금을 얼마나 칠지, 온도는 몇 도로 할지 '상세 설정'을 조절하는 패널입니다.

**왜 이 셋을 묶어서 알아야 할까요?**
1. **작업 속도**: "아까 만든 투명한 벽이 어디 갔지?" 할 때, 씬(Scene)에서 클릭이 안 되면 하이어라키(Hierarchy)에서 이름을 검색해 찾고, 그 투명도를 인스펙터(Inspector)에서 고치는 흐름이 몸에 배어야 합니다.
2. **디버깅의 본질**: 유니티에서 게임의 상태는 'C# 코드' 안에만 있지 않습니다. 씬 파일에 저장된 인스펙터 값, 체크박스의 켜짐/꺼짐 상태 자체가 모두 게임 로직의 일부입니다. 코드를 열 번 읽어도 안 보이는 버그는 이 세 창 어딘가에 숨어있습니다.

## 2. 핵심 요약

| 창 (Window) | 역할 | 여기서 주로 하는 일 |
| :--- | :--- | :--- |
| **Scene** | 게임 월드의 시각적 뷰 | 오브젝트 **배치, 이동, 회전, 크기 조절** |
| **Hierarchy** | 현재 씬에 존재하는 것의 목록 | 오브젝트 **생성, 삭제, 부모-자식 관계(트리) 묶기** |
| **Inspector** | 선택한 오브젝트 하나의 상태 | **컴포넌트 추가/제거, 스크립트 변수값 수정, 체크박스 끄기** |

* 세 창은 항상 100% 동기화됩니다. 하이어라키에서 고르면 씬 뷰와 인스펙터도 동시에 그 녀석을 쳐다봅니다.
* 인스펙터에 노출된 값은 유니티 씬 파일(`.unity`)에 저장되며, 게임이 실행될 때 **C# 코드에 적어둔 선언 초기값을 덮어써 버립니다.**

## 3. 세부 개념 및 원리

### 3.1 Scene 창 — 시각 편집의 작업대
좌상단 툴바의 도구 단축키는 왼손이 키보드 **[Q, W, E, R, T, Y]**에 올라가 있어야 합니다.

| 도구 (Tool) | 단축키 | 하는 일                                |
| :--- | :--- |:------------------------------------|
| **Hand** | `Q` | 씬 화면의 시점을 옮깁니다.                     |
| **Move** | `W` | 오브젝트의 위치를 X, Y, Z축 화살표를 잡아 옮깁니다.    |
| **Rotate** | `E` | 둥근 띠를 잡아 오브젝트를 회전시킵니다.              |
| **Scale** | `R` | 오브젝트를 찌그러트리거나 크기를 뻥튀기합니다.           |
| **Rect Transform**| `T` | 사각형 핸들을 잡고 드래그합니다 (주로 2D UI 작업 전용). |

> **[팁] Global vs Local 좌표계의 함정**\
> 씬 뷰 상단에 보면 **[Global / Local]** 토글 버튼이 있습니다.\
> 대각선으로 누워있는 미사일을 선택하고 `W` 키를 눌렀을 때, 화살표가 우주의 절대 축(위/아래)을 향한다면 **Global**, 미사일의 머리 방향(대각선)을 향한다면 **Local**입니다. 미사일을 뾰족한 앞 방향으로 움직이려면 반드시 `Local` 상태에서 파란색(Z) 화살표를 잡고 당겨야 합니다

### 3.2 Hierarchy 창 — 부모와 자식의 관계 (Transform 트리)
이 씬에 무엇이 존재하는가에 대한 유일한 정답지입니다.\
오브젝트를 다른 오브젝트 위로 드래그 앤 드롭 하면 **'부모-자식'** 계층 구조가 생깁니다.

```text
Car (부모)                 ← 얘를 움직이거나 회전시키면 아래 자식들도 똑같이 움직입니다.
  ├── Wheel_FL (자식)
  ├── Wheel_FR (자식)
  └── Door (자식)
      └── Window (손자)    ← 문(Door)이 열리며 회전하면, 창문(Window)도 같이 회전합니다.
```
자식의 좌표는 부모를 중심(0,0,0)으로 삼는 **상대 좌표(Local Position)** 가 됩니다. 부모인 자동차가 100km를 달려가도, 바퀴의 상대 좌표는 영원히 제자리입니다.

### 3.3 Inspector 창 — 체크박스의 무서움
선택한 객체의 모든 컴포넌트(부품)가 레고 블록 단위로 쌓여 있습니다.\
여기서 가장 무서운 것은 두 종류의 **체크박스(끄고 켜기)** 입니다.

1. **오브젝트 전체 끄기 (이름 옆 체크박스)** : 이 녀석이 통째로 우주에서 사라진 취급을 받습니다. 하이어라키에서 이름이 회색으로 흐려집니다.
2. **컴포넌트 하나만 끄기 (컴포넌트 헤더 체크박스)** : **발생하면 찾기 힘든 버그입니다.** 오브젝트는 멀쩡히 화면에 보이고 하이어라키에서도 활성화되어 있는데, 그 안에 붙어있는 `Collider(충돌체)` 하나만 조용히 꺼져 있으면 "왜 총알이 그냥 통과하지?" 하면서 코드를 백날 뒤져도 원인을 찾을 수 없습니다.

## 4. 코드로 보는 에디터 연동

### 4.1 Inspector를 아름답게 꾸미는 애트리뷰트(Attribute)
C# 스크립트의 변수들을 인스펙터에 어떻게 보여줄지 기획자를 위해 화장(디자인)을 해줍니다.

```csharp
using UnityEngine;

public class Player : MonoBehaviour
{
    // [Header]: 인스펙터에 보기 좋게 굵은 제목을 달아줍니다.
    [Header("전투 설정")]
    [SerializeField] private int maxHealth = 100;

    // [Space]: 변수들 사이에 여백을 주어 섹션을 구분해 줍니다.
    [Space(10)] 
    
    // [Range]: 숫자를 직접 치지 못하게 슬라이더 바(Bar)를 만들어 줍니다.
    [Range(0f, 1f)]
    [SerializeField] private float moveSpeed = 0.5f;

    // [Tooltip]: 기획자가 변수 이름에 마우스를 올리면 이 설명이 말풍선으로 뜹니다.
    [Tooltip("캐릭터가 점프할 때 위로 솟구치는 힘의 크기입니다.")]
    [SerializeField] private float jumpPower = 10f;
}
```

### 4.2 부모-자식 트리 구조의 위력
무기가 항상 플레이어의 손을 따라다녀야 한다고 칩시다. 코드로 해결하려 하면 참사가 벌어집니다.

```csharp
// 상황 (Before): 코드로 매 프레임 위치를 억지로 동기화하려 함
private void Update()
{
    // 캐릭터가 회전하거나 크기가 커지면 이 코드는 다 박살 납니다. 코드가 걷잡을 수 없이 길어집니다.
    weapon.transform.position = character.transform.position + new Vector3(0.5f, 0f, 0f);
}
```

```csharp
// 적용 (After): 하이어라키에서 무기를 캐릭터의 '자식'으로 끌어다 놓음
private void Update()
{
    // 아무 코드도 필요 없습니다
    // 엔진이 매 프레임 자식을 부모에게 완벽하게 종속시켜 움직여줍니다.
}
```

## 5. 실전 활용 예시 (코드에 없는 버그 심어보기)

```csharp
using UnityEngine;

public class Coin : MonoBehaviour
{
    [SerializeField] private ScoreBoard board;   // 인스펙터에서 ScoreBoard 를 끌어 놓는다

    private void OnTriggerEnter2D(Collider2D other)
    {
        if (!other.CompareTag("Player")) return;

        if (board == null)
        {
            // 연결을 빼먹었으면 조용히 넘어가지 않고 즉시 알린다
            Debug.LogError($"{name}: ScoreBoard 를 인스펙터에서 연결하지 않았다", this);
            return;
        }

        Debug.Log($"{name} 획득");
        board.ReportPickup(name);

        gameObject.SetActive(false);
    }
}
```
```csharp
using UnityEngine;

public class ScoreBoard : MonoBehaviour
{
    [SerializeField] private int requiredCoins = 3;   // 씬에 둔 코인 개수와 같아야 한다

    private int pickedCount;

    public void ReportPickup(string coinName)
    {
        pickedCount++;

        // 남은 개수를 '목표치 - 모은 수' 로 계산한다 — 목표치가 틀리면 이 로그도 함께 틀린다
        Debug.Log($"{coinName} 수집 — 남은 코인 {requiredCoins - pickedCount}개");

        if (pickedCount < requiredCoins) return;

        Debug.Log("모두 수집했습니다");
    }
}
```

**[상황]**
"코인을 3개 다 먹었는데 게임 클리어가 안 떠요" / "두 번째 코인은 먹어지지도 않아요"\
코드를 보면 분명히 `requiredCoins = 3`이고 충돌 처리도 멀쩡합니다.

**[원인 분석: 코드 밖의 세계]**
1. **Coin_B가 안 먹어지는 이유**: 인스펙터에서 실수로 `Circle Collider 2D` 컴포넌트의 **체크박스를 꺼버렸습니다.** 충돌체가 없으니 트리거 이벤트가 아예 호출되지 않은 것입니다.
2. **목표치가 이상한 이유**: 코드에는 `requiredCoins = 3`이라 적혀있지만, 씬에 배치된 ScoreBoard의 인스펙터 창에서는 예전에 누군가 **`2`로 값을 덮어써 둔 상태**였습니다. 게임이 켜질 때 인스펙터의 `2`가 코드의 `3`을 덮어써 버리므로 클리어 로직이 박살 난 것입니다.

> **한 줄 회고**: 이 실습에서 얻는 것은 지식이 아니라 '버그를 찾는 순서'입니다. 증상이 코드와 맞지 않으면 **코드를 째려보지 말고 씬의 인스펙터를 먼저 보세요.**

## 6. 디버깅 체크리스트 5단계

같은 스크립트를 쓰는 적들 중 한 마리만 버그가 난다면, 100% 코드 밖(에디터)의 문제입니다.
**[스크립트를 열기 전에 반드시 확인할 5단계]**
1. **오브젝트가 켜져 있는가?** (Hierarchy 이름이 회색인지 확인)
2. **컴포넌트가 켜져 있는가?** (Inspector 컴포넌트 헤더 체크박스 확인)
3. **값이 코드와 같은가?** (코드의 초기값이 인스펙터 값에 의해 덮어씌워져 있는지 확인)
4. **파란 막대가 붙어 있는가?** (프리팹 원본과 값이 달라졌다는 Overrides 표시를 의심할 것)
5. **연결 칸(`Reference`)이 비어(None) 있지 않은가?** (오브젝트 할당을 까먹었는지 확인)

## 7. 실습 문제 및 복습

**Q1. 스크립트 안에 `public int hp = 100;` 이라고 선언해 두었는데, Play를 누르고 보니 50부터 시작합니다. 대체 왜 이런 일이 벌어지는 것인가요?**
> 과거에 에디터 인스펙터 창에서 누군가 이 값을 `50`으로 수정해 두었기 때문입니다. **인스펙터에 텍스트로 노출된 값은 씬 파일에 찰칵 저장되며, 게임 시작 시 코드에 적힌 선언 초기값(`100`)을 덮어써버립니다.** 원래대로 되돌리려면 인스펙터 값을 수동으로 100으로 고치거나, 컴포넌트 우상단 메뉴에서 `Reset`을 눌러야 합니다.

**Q2. 카메라(Camera) 오브젝트를 캐릭터의 자식(Child)으로 끌어다 넣으면 어떤 일이 발생하나요?**
> 캐릭터가 앞으로 걸어가면 카메라도 정확히 그 거리만큼 쫓아가고, 캐릭터가 오른쪽으로 고개를 돌리면 카메라도 똑같이 우회전합니다 (1인칭 시점 완성). 부모-자식 계층이 되면 자식의 트랜스폼(위치, 회전, 크기)이 부모에게 완벽하게 종속되기 때문입니다.

**Q3. "버그가 생기면 예외 처리(`try-catch`나 `if(null)`) 방어 코드를 떡칠해서 무조건 막아야 한다"는 주장의 위험성은?**
> 아군 타워를 연결해야 할 인스펙터 변수 칸이 비어있는(`None`) 것은 기획자의 단순한 드래그 앤 드롭 실수입니다. 이걸 코드로 억지로 예외 처리해서 에러를 안 나게 덮어버리면, 타워가 작동하지 않는데 콘솔에는 에러조차 찍히지 않는 '침묵의 버그'가 됩니다. **개발 중인 에디터 단계에서는 비어있으면 당당하게 `Debug.LogError`를 뿜거나 크래시가 나도록 터트리는 것(Fail-Fast)이 원인을 찾는 가장 빠른 길입니다.**

## 8. 주의사항 및 안전 습관

* **Play 모드의 환상**: Play 중에 만진 인스펙터 수치는 멈추면 **전부 롤백**됩니다. 제발 좋은 수치를 찾았다면 멈추기 전에 `Copy Component` 하세요.
* **Ctrl + S는 살 길이다**: 씬(Scene) 저장과 코드(Script) 저장은 완전히 별개입니다. 코드를 아무리 잘 짰어도 씬에 배치한 노력이 유니티 크래시로 날아가면 눈물 납니다.
* **None의 공포**: 인스펙터에 슬롯을 파두고 오브젝트 연결을 빼먹으면, 코드가 그 슬롯을 부르는 순간 `NullReferenceException` 폭탄이 터집니다.
* **파란색 세로줄(Override)을 주목하라**: 인스펙터 변수 이름 왼쪽에 파란색 세로줄이 생겼다면, "원본 프리팹과 설정값이 달라졌다!"는 유니티의 강력한 경고이자 단서입니다. 버그가 났을 때 이 파란 줄부터 의심하세요.
