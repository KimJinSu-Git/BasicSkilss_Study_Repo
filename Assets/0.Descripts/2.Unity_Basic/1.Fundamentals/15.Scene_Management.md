# [Fundamentals] 15. 씬 관리 (Scene Management)

## 1. 씬 관리(Scene Management) 란?
Unity에서 **씬(Scene)** 은 게임의 한 장면을 담는 독립적인 공간(파일)입니다. 메인 메뉴, 튜토리얼, 보스 스테이지처럼 완전히 성격이 다른 장면들을 각각 별개의 `.unity` 파일로 만들어 관리합니다.

> **한 권의 책과 책갈피**
> * 각 **씬(Scene)** 은 책의 '챕터(장)'입니다 — '1장: 프롤로그', '2장: 마을', '3장: 전투'.
> * **씬 관리**는 이 페이지를 매끄럽게 넘기는 기술입니다.
> * 그리고 페이지를 넘길 때 손에 쥐고 다음 장으로 가져가야 하는 것(예: 플레이어의 레벨, 소지품)이 있습니다. 이것이 씬을 넘나드는 **책갈피(데이터 유지)** 입니다.

**왜 필요한가?**\
오픈월드조차도 게임 전체를 단 하나의 씬으로 만들지 않습니다. 처음 켤 때 모든 리소스를 한꺼번에 램(RAM)에 올려야 하니 로딩이 끔찍하게 길어지고, 메모리가 터져버립니다.\
씬 단위로 나누면 **필요한 부분만 메모리에 올릴 수 있고(최적화)**, 여러 명의 개발자가 각자 다른 씬 파일을 맡아 동시에 작업할 수 있어 **협업 충돌(Git Merge)** 을 막을 수 있습니다.

대신 규칙이 있습니다. **"씬이 바뀌면, 이전 씬에 있던 모든 오브젝트는 파괴(Destroy)된다"** 는 것입니다. 살아남아야 할 매니저와 데이터를 어떻게 옮길 것인가가 이 챕터의 핵심입니다.

## 2. 핵심 요약

| 개념 | 한 줄 설명 |
| :--- | :--- |
| **`SceneManager`** | 씬을 불러오고 현재 씬 정보를 얻는 핵심 정적(static) 클래스 |
| **빌드 목록 (Build Settings)**| `File ➔ Build Profiles` 목록에 씬을 등록해야만 코드로 부를 수 있습니다. |
| **`LoadScene()`** | 다음 씬을 다 읽을 때까지 화면이 **멈춥니다 (동기 로드)**. |
| **`LoadSceneAsync()`** | 게임이 멈추지 않고 백그라운드에서 씬을 불러옵니다 **(비동기 로드)**. |
| **`LoadSceneMode.Additive`**| 기존 씬을 파괴하지 않고, 그 위에 새 씬을 투명한 셀로판지처럼 **겹쳐 올립니다.** |
| **`DontDestroyOnLoad()`** | 이 함수를 거친 오브젝트는 씬이 전환되어도 파괴되지 않고 살아남습니다. |

## 3. 세부 개념 및 원리

### 3.1 가장 흔한 에러: 씬 목록에 등록하기
아무리 코드를 완벽하게 짜도, 유니티는 목록에 등록되지 않은 씬은 세상에 없는 것으로 취급합니다.
* `File ➔ Build Profiles (또는 Build Settings)`를 엽니다.
* `Scene List (Scenes in Build)` 항목에 Project 창의 씬 파일(`.unity`)을 드래그 앤 드롭합니다.
* 등록된 씬은 맨 위부터 **빌드 인덱스(0, 1, 2...)** 를 부여받습니다.

### 3.2 동기 씬 로딩 (가벼운 씬 전환)
가장 단순하지만, 로딩이 끝날 때까지 게임이 완전히 '프리즈(멈춤)' 상태가 됩니다.
```csharp
using UnityEngine;
using UnityEngine.SceneManagement; // 씬 관리를 위한 필수 네임스페이스

public class MainMenu : MonoBehaviour
{
    public void StartGame()
    {
        SceneManager.LoadScene("Level_01"); // 씬 이름으로 전환
    }
}
```

### 3.3 비동기 씬 로딩과 진행률 표시 `(LoadSceneAsync)`
'로딩 화면'을 띄우고 싶다면 무조건 비동기`(Async)`를 써야 합니다. 진행 상황을 코루틴으로 감시합니다.
```csharp
using System.Collections;
using UnityEngine;
using UnityEngine.SceneManagement;
using UnityEngine.UI;

public class LoadingManager : MonoBehaviour
{
    [SerializeField] private Slider _loadingBar;

    public void LoadGameScene() => StartCoroutine(LoadSceneProcess("Level_01"));

    private IEnumerator LoadSceneProcess(string sceneName)
    {
        // 백그라운드에서 씬을 조용히 읽어오기 시작함
        AsyncOperation op = SceneManager.LoadSceneAsync(sceneName);
        op.allowSceneActivation = false; // 데이터를 다 읽어도 자동으로 씬을 넘기지 않게 막음

        while (!op.isDone)
        {
            // 유니티의 비동기 로딩은 0.9(90%) 까지만 진행되고 멈춥니다. (나머지 0.1은 씬 활성화 몫)
            // 따라서 0.9로 나누어 주어야 로딩바가 100%까지 예쁘게 찹니다.
            _loadingBar.value = Mathf.Clamp01(op.progress / 0.9f);

            if (op.progress >= 0.9f)
            {
                _loadingBar.value = 1f; // 로딩바 100%
                yield return new WaitForSeconds(0.5f); // 100%를 유저에게 보여주기 위한 찰나의 대기
                op.allowSceneActivation = true; // 잠금 해제 씬 전환 실행
            }
            yield return null;
        }
    }
}
```

### 3.4 씬을 넘어 살아남기 — `DontDestroyOnLoad` 와 `싱글톤(Singleton)`
씬이 전환되면 모든 오브젝트가 폭파되지만, `GameManager`나 `SoundManager`는 살아남아야 합니다.\
이때 "이 오브젝트는 부수지 마라"라고 엔진에 명령하는 것이 `DontDestroyOnLoad`입니다.
```csharp
public class GameManager : MonoBehaviour
{
    // 누구나 쉽게 접근할 수 있는 static(전역) 변수
    public static GameManager Instance { get; private set; }

    public int playerScore = 0; // 씬을 넘어가도 유지되어야 할 책갈피 데이터

    private void Awake()
    {
        // 1. 내가 첫 번째 매니저라면? (왕좌가 비어있다면)
        if (Instance == null)
        {
            Instance = this;
            DontDestroyOnLoad(gameObject); // 씬이 넘어가도 나를 죽이지 마라
        }
        // 2. 씬을 다시 로드해서 내가 또 생겨났다면? (왕좌에 이미 누군가 있다면)
        else
        {
            Destroy(gameObject); // 가짜(복제본)인 나는 스스로 목숨을 끊는다.
            return; // 삭제 예약 후, 아래의 초기화 로직이 불리지 않도록 반드시 return
        }
        
        Initialize(); // 이 매니저 고유의 준비는 따로 뺍니다.
    }
    
    private void Initialize()
    {
        // 고유 초기화 로직
    }
}
```
> 주의사항: `DontDestroyOnLoad`는 반드시 하이어라키의 최상위 루트(Root) 오브젝트에만 작동합니다. 다른 오브젝트의 자식으로 들어가 있으면 무시당하고 씬과 함께 파괴됩니다.

## 4. 실전 활용: `Additive` 로 UI 겹치기
RPG 게임에서 인벤토리 창이나 일시정지(Pause) 창을 띄울 때, 무거운 UI를 매번 씬마다 복사해 둘 필요가 없습니다. UI 전용 씬을 하나 만들고 `Additive` 모드로 현재 씬 위에 투명하게 겹쳐 올리면 됩니다.
```csharp
// 1. 일시정지 키를 누르면, 기존 게임 씬 위에 "PauseUI" 씬을 투명하게 겹쳐서 올린다
if (Input.GetKeyDown(KeyCode.Escape))
{
    // 이미 열려있지 않을 때만 로드 (안 막으면 씬이 여러 겹 쌓임)
    if (!SceneManager.GetSceneByName("PauseUI").isLoaded)
    {
        SceneManager.LoadScene("PauseUI", LoadSceneMode.Additive);
        Time.timeScale = 0f; // 겹쳐진 뒤쪽의 본 게임은 시간을 멈춰둔다.
    }
}

// 2. 일시정지 창의 "닫기" 버튼을 누르면 그 UI 씬만 깔끔하게 내린다
public void ResumeGame()
{
    Time.timeScale = 1f; // 시간 복구
    SceneManager.UnloadSceneAsync("PauseUI"); // 겹쳐놓은 씬만 조용히 내린다.
}
```

## 5. Unity 최적화 팁
### 5.1 매직 스트링(Magic String)의 공포 피하기
`SceneManager.LoadScene("Level_01");` 처럼 문자열을 직접 치는 것은 좋지 않습니다. 기획자가 씬 이름을 Level01로 바꾸면 에러도 없이 게임이 멈춰버리기 때문입니다.

#### [정석: 씬 이름 상수화 클래스 만들기]
```csharp
// 씬 이름만 전문적으로 모아두는 클래스
public static class SceneNames
{
    public const string MainMenu = "MainMenuScene";
    public const string Level1 = "Level_01";
    public const string BossRoom = "Boss_Stage";
}

// 사용할 때 (오타 발생 확률 0%, 자동완성 지원)
SceneManager.LoadScene(SceneNames.Level1);
```

### 5.2 씬을 다시 로드해도 `static` 변수는 죽지 않는다
플레이어가 죽어서 현재 씬을 재시작`(LoadScene(GetActiveScene().name))`했습니다.\
그런데 `static int totalScore = 30;` 같은 전역 변수가 있다면, 씬이 재시작되어도 이 변수는 0으로 돌아가지 않고 30으로 남아있습니다. (static은 오브젝트가 아니라 클래스 소속이기 때문입니다.)
* **해결책**: 재시작하는 시점이나 매니저의 Start에서 명시적으로 값을 초기화`(totalScore = 0;)`해주는 리셋 코드를 반드시 짜야 합니다.

### 5.3 `인덱스(BuildIndex)` 사용의 양면성
`SceneManager.LoadScene(1);` 처럼 인덱스로 로드하면 코드는 짧아집니다.\
하지만 빌드 세팅 창에서 누군가 씬의 순서를 위아래로 섞어버리면, 보스전으로 가야 할 포탈이 튜토리얼 씬으로 유저를 던져버립니다.\
실전에서는 현재 씬 재시작`(SceneManager.GetActiveScene().buildIndex)`을 제외하고는, 무조건 이름(상수)으로 로드하는 것이 가장 안전합니다.

## 6. 실습 문제 및 복습
**Q1. `LoadScene`을 불렀더니 콘솔 창에 `Scene 'BossRoom' couldn't be loaded because it has not been added to the build settings` 라는 빨간 에러가 떴습니다. 어떻게 해결해야 하나요?**
> 상단 메뉴의 `File ➔ Build Profiles` 창을 열고, Project 창에 있는 `BossRoom.unity` 씬 파일을 드래그해서 `Scenes in Build` 목록에 등록해주어야 엔진이 씬의 존재를 인식합니다.

**Q2. `DontDestroyOnLoad(gameObject);` 를 썼는데도 씬 전환 시 오브젝트가 파괴되고, 콘솔에 `DontDestroyOnLoad only works for root GameObjects` 라는 노란색 경고가 떴습니다. 원인은 무엇인가요?**
> 해당 스크립트가 붙은 오브젝트가 하이어라키(Hierarchy) 상에서 다른 오브젝트의 '자식(Child)'으로 들어가 있기 때문입니다. 씬을 넘어가는 방주 기능은 무조건 계층 구조의 최상단(Root)에 있는 오브젝트에게만 작동하므로, 부모 밖으로 빼내 최상위 오브젝트로 만들어야 합니다.

**Q3. 현재 진행 중인 씬을 재시작(리로드)하는 코드를 작성해보세요. (이름을 직접 치지 마세요)**
> `SceneManager.LoadScene(SceneManager.GetActiveScene().buildIndex);`\
> (현재 활성화된 씬의 정보를 가져와서, 그 씬이 가진 고유 빌드 인덱스 번호를 다시 로드하라고 명령하는 범용적인 재시작 코드입니다.)

## 7. 주의사항 및 안전 습관
* **전환 직후의 코드 작성 금지**: `SceneManager.LoadScene("Level2");` 라고 적은 바로 아랫줄에 `GameObject.Find("Boss");` 를 적지 마세요. 씬 전환은 프레임이 다 끝나야 일어나므로, 그 아랫줄이 실행될 때는 아직 이전 씬에 머물러 있어 100% `NullReferenceException`이 터집니다. 새 씬의 로직은 새 씬에 있는 스크립트의 Start에 맡기세요. 
* **Additive 씬은 쓴 뒤에 반드시 분리수거하라**: UI 씬을 `LoadSceneMode.Additive`로 겹쳐 올렸다면, 닫을 때 단순히 UI 캔버스를 끄는 게 아니라 반드시 `UnloadSceneAsync`를 통해 메모리에서 완벽히 씬을 지워주어야 합니다. 안 그러면 백그라운드에 UI 씬이 10겹씩 쌓이게 됩니다.
