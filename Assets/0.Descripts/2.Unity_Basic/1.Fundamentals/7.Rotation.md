# [Fundamentals] 7. Rotation (회전)

## 1. 회전(Rotation)이란?
> **종이 위에 꽂은 압정**
> * 종이에 그린 2D 그림 한 장을 책상에 놓고, 가운데에 **압정**을 꽂아 고정해 봅시다.
> * 그림은 그 압정을 중심으로 빙글빙글 돌기만 할 뿐입니다. (평면 위의 회전에는 각도 하나면 충분합니다.)
> * 유니티 2D 게임에서 그 압정이 꽂힌 방향이 바로 화면을 뚫고 들어가는 **Z축**입니다.

**왜 필요한가?**\
Vector3 챕터에서 오브젝트를 옮기는(이동) 법을 익혔습니다. 그런데 이동만 하면 화면이 이상해지는 순간이 옵니다.
* 오른쪽을 보고 있는 화살이 위로 날아가는데 여전히 오른쪽을 봅니다.
* 포탑이 적을 향해 총알은 쏘는데, 포탑의 포신은 가만히 있습니다.
* 캐릭터가 넘어졌는데 몸이 꼿꼿하게 서 있습니다.

이 모든 것을 해결하기 위해 **매 프레임 조금씩 더하는 회전(Spin)** 과, **목표를 향해 단번에 각도를 맞추는 조준(Look)** 을 완벽하게 다룰 줄 알아야 합니다.

---

## 2. 핵심 요약

| 개념 | 2D 게임에서의 의미와 활용                                                |
| :--- |:---------------------------------------------------------------|
| **회전축 (Z축)** | 2D에서 물체가 도는 기준 축. 인스펙터의 `Rotation Z` 값만 만집니다.                  |
| **`Vector3.forward`** | 값이 `(0, 0, 1)`. 2D 회전 코드에서는 "앞쪽"이 아니라 **"Z축으로 돌려라"** 는 뜻.      |
| **증분 회전 (Spin)** | `transform.Rotate(...)` ➔ 매 프레임 선풍기나 코인처럼 **계속 빙글빙글 돌 때** 사용.  |
| **각도 대입 (Look)** | `transform.rotation = ...` ➔ 목표물을 향해 포신을 **단번에 꺾어서 조준할 때** 사용. |
| **`Time.deltaTime`** | 이걸 안 곱하면 똥컴과 좋은 컴에서 회전 속도가 다르게 미쳐 날뜁니다.                        |
| **`Mathf.Atan2`** | X, Y 방향 벡터를 360도 각도로 변환해 주는 수학 공식.                             |

## 3. 세부 개념 및 원리

### 3.1 2D의 회전축은 오직 Z뿐입니다
2D 스프라이트(그림)를 X축이나 Y축으로 돌리면 종이(그림)가 화면 안쪽으로 눕게 되어 납작해지다가 아예 안 보이게 됩니다. 따라서 2D에서는 인스펙터의 **Rotation Z** 값만 조작합니다.

```csharp
// 주의: Vector3.forward는 "앞으로 가라"가 아니라 "(0, 0, 1) 즉 Z축" 이라는 뜻입니다
transform.Rotate(Vector3.forward * 60f * Time.deltaTime);

// 헷갈린다면 차라리 아래처럼 명시적으로 Z축 칸에 숫자를 넣는 것이 읽기 좋습니다.
transform.Rotate(0f, 0f, 60f * Time.deltaTime);
```

### 3.2 증분 회전 — 매 프레임 빙글빙글 돌기 (`Rotate`)
현재 각도에 조금씩 값을 누적하여 더하는 방식입니다. (코인, 톱니바퀴, 로딩 스피너)
```csharp
public class SpinCoin : MonoBehaviour
{
    [SerializeField] private float speed = 180f; // 초당 180도 (2초면 1바퀴)

    private void Update()
    {
        // 팁: 각도가 양수(+)면 반시계 방향, 음수(-)면 시계 방향으로 돕니다.
        transform.Rotate(0f, 0f, speed * Time.deltaTime);
    }
}
```

### 3.3 목표 각도로 맞추기 — 조준하기 (`rotation`)
"저쪽을 쳐다보게 하라"는 미션은 `Rotate`로 계속 더하는 방식으로는 절대 풀리지 않습니다.\
각도를 수학적으로 딱 구한 다음, 쿼터니언(Quaternion)이라는 캡슐에 담아 `transform.rotation`에 통째로 덮어씌워야 합니다.

**[정석 방법: 수학 공식 `Mathf.Atan2` 사용]**
```csharp
// 1. 적을 향하는 방향 벡터 구하기 (목표 - 내 위치)
Vector3 dir = target.position - transform.position;

// 2. 방향 벡터를 라디안 각도로 바꾼 후, 유니티 360도(Degree) 각도로 변환
float angle = Mathf.Atan2(dir.y, dir.x) * Mathf.Rad2Deg;

// 3. Z축 각도만 돌리도록 쿼터니언 캡슐에 담아서 덮어씌우기
transform.rotation = Quaternion.Euler(0f, 0f, angle);
```

> **치명적인 90도 함정**\
> 유니티의 `Mathf.Atan2`는 **'오른쪽(+X)'을 바라보는 것을 0도(정면)** 로 간주합니다.\
> 만약 디자이너가 우주선을 '위쪽(+Y)'을 바라보게 그렸다면, 조준했을 때 항상 90도가 엇나가게 됩니다.\
> ➔ **해결책**: 그림을 무조건 오른쪽을 보게 다시 그리게 하거나, 코드에서 `angle - 90f`로 강제 보정해야 합니다.

### 3.4 복잡한 수학 없이 유니티 엔진에 맡기기
위의 복잡한 삼각함수 수학 공식 없이도, 유니티가 제공하는 변수 하나면 조준이 끝납니다.

```csharp
Vector3 dir = target.position - transform.position;

// 꼼수 1: 내 우주선의 "오른쪽 화살표(right)"가 적(dir)을 향하게 꺾어라 (2D 전용 초고속 꼼수)
// 만약 우주선이 위를 보고 그려져 있다면 transform.up = dir; 로 쓰면 됩니다.
transform.right = dir.normalized;

// 꼼수 2: 3D/2D 겸용 쿼터니언 마법
// "이 방향(dir)을 쳐다보는 쿼터니언 각도를 너가 계산해서 만들어줘"
transform.rotation = Quaternion.LookRotation(Vector3.forward, dir); // 2D 평면 조준
```

## 4. 코드로 보는 치명적인 실수들

### 4.1 2D에서 Y축으로 돌리면 마술처럼 사라집니다
```csharp
// 3D 예제를 복붙해서 생긴 대참사
// 팽이처럼 Y축을 중심으로 돌리면, 종이(스프라이트)가 화면 안으로 눕다가 투명하게 사라짐
transform.Rotate(Vector3.up * speed * Time.deltaTime); 

// 2D는 무조건 Z축(forward)이다
transform.Rotate(Vector3.forward * speed * Time.deltaTime); 
```

### 4.2 오일러 각(Euler)은 믿을 게 못 된다 (짐벌 락)
유니티 인스펙터에 보이는 (0, 0, 90) 같은 직관적인 각도는 사람이 보기 좋게 유니티가 가짜로 보여주는 '오일러 각'입니다. 실제 엔진 내부의 `transform.rotation`은 X,Y,Z,W 4차원 복소수라는 기괴한 구조로 돌아가는 **쿼터니언(Quaternion)** 입니다.

그래서 아래와 같은 행동을 하면 안 됩니다.
```csharp
// 버그: 인스펙터 각도를 단순히 빼기로 비교하려 함
float angleDiff = targetAngle - transform.eulerAngles.z; 
// 유니티 내부에선 350도와 10도가 20도 차이라는 걸 인지하지 못하고 340도 차이라고 계산해 버림

// 정답: 유니티가 제공하는 각도 전용 함수를 쓴다
float angleDiff = Mathf.DeltaAngle(current, targetAngle); // -180 ~ 180 사이의 완벽한 찐 차이값 반환
```

## 5. 실전 활용 예시 (천천히 따라 도는 포탑)

`Atan2`로 목표 각도를 구하고, `MoveTowardsAngle`을 써서 부드럽게 총구가 돌아가는 실무 코드입니다.

```csharp
using UnityEngine;

public class Turret2D : MonoBehaviour
{
    [SerializeField] private Transform target;
    [SerializeField] private float turnSpeed = 180f; // 초당 180도 회전 성능

    private void Update()
    {
        if (target == null) return;

        // 1. 방향 구하기
        Vector3 dir = target.position - transform.position;
        if (dir.sqrMagnitude < 0.0001f) return; // 완벽히 겹쳤을 때의 에러 방지

        // 2. 목표 각도(Goal) 계산
        float goalAngle = Mathf.Atan2(dir.y, dir.x) * Mathf.Rad2Deg;

        // 3. 내 현재 각도
        float currentAngle = transform.eulerAngles.z;

        // 4. 유니티 함수: 현재 각도에서 목표 각도까지 최단 거리로 '속도'만큼만 조금 꺾기
        float nextAngle = Mathf.MoveTowardsAngle(currentAngle, goalAngle, turnSpeed * Time.deltaTime);

        // 5. 꺾인 각도를 장전
        transform.rotation = Quaternion.Euler(0f, 0f, nextAngle);
    }
}
```

## 6. Unity 최적화 및 물리 엔진(`Rigidbody`)과의 충돌

### 물리가 적용된 캐릭터의 회전
캐릭터에 `Rigidbody2D`가 달려있는데 스크립트로 `transform.rotation`을 억지로 비틀면, 유니티 물리 엔진(PhysX)이 충돌 버그나 떨림 현상을 유발합니다.

1. **안 넘어지게 하기**: 캐릭터가 적에게 부딪혀서 데굴데굴 구르는 걸 막으려면 코드를 짜지 말고, 인스펙터 `Rigidbody2D`의 `Constraints ➔ Freeze Rotation Z` 체크박스를 켜세요
2. **물리적인 회전력 주기**: 코드로 회전을 강제하지 말고 물리 엔진에 맞게 회전 속력을 줍니다.
```csharp
// Update가 아니라 FixedUpdate에서 처리해야 부드럽습니다.
_rigidbody2D.angularVelocity = 180f; // 초당 180도로 물리적으로 팽이처럼 회전시킴
```
3. **물리적인 방향 조준**: `transform.rotation = ...` 대신 `_rigidbody2D.MoveRotation(목표각도)`를 쓰세요.

## 7. 실습 문제 및 복습

**Q1. `transform.Rotate(Vector3.forward * speed * Time.deltaTime)` 코드에서 스프라이트를 시계 방향(오른쪽)으로 돌리고 싶다면 어떻게 수정해야 하나요?**
> 각도 앞에 마이너스 부호를 붙이거나, `Vector3.back`을 사용합니다.\
> 예: `transform.Rotate(Vector3.back * speed * Time.deltaTime);` (유니티 2D 공간에서 Z축 회전의 양수(+)는 무조건 반시계 방향이기 때문입니다.)

**Q2. 인스펙터에서 포탑이 목표물을 향해 90도 어긋난 채로 조준합니다. 원인은 무엇이며 코드를 어떻게 수정해야 하나요?**
> 원인은 포탑의 원본 그림(스프라이트)이 '오른쪽'을 바라보지 않고 '위쪽'을 바라보게 그려져 있기 때문입니다. (`Mathf.Atan2`는 오른쪽을 0도로 봅니다.)\
> 수정 방법: 계산된 `angle` 변수에서 그림이 틀어진 만큼 각도를 뺍니다. `transform.rotation = Quaternion.Euler(0, 0, angle - 90f);`

**Q3. 현재 각도 350도에서 목표 각도 10도로 부드럽게 회전시키려 합니다. `10 - 350`을 단순히 빼면 -340도가 되어 포탑이 한 바퀴를 거꾸로 헛돌게 됩니다. 유니티에서 이 최단 거리를 똑똑하게 구해주는 함수는 무엇인가요?**
> **`Mathf.MoveTowardsAngle(현재각도, 목표각도, 최대회전속도)`** 입니다. 또는 각도의 단순 차이값만 필요하다면 **`Mathf.DeltaAngle(현재, 목표)`** 를 쓰면 완벽하게 최단 경로(20도)를 찾아줍니다.

## 8. 주의사항 및 안전 습관

* **`transform.eulerAngles` 맹신 금지**: 이 변수는 유니티가 임의로 0~360도로 변환해서 보여주는 가짜 각도입니다. 여기다가 `+=` 로 계속 각도를 더하거나 빼면 360도를 넘어서는 순간 온갖 기괴한 버그가 터집니다. 각도를 누적할 거면 무조건 내가 별도의 `float myAngle;` 변수를 파서 계산한 뒤 `Quaternion.Euler`로 덮어씌우세요.
* **스프라이트는 무조건 오른쪽을 보게 그려라**: 팀 기획자나 디자이너에게 리소스를 받을 때, 무기나 캐릭터의 정면이 무조건 "오른쪽"을 향하도록 잘라서 달라고 강력하게 주장하세요. 코드마다 `- 90f`, `+ 90f` 예외 처리를 넣기 시작하면 지옥이 열립니다.
* **타겟과 완벽히 겹쳤을 때의 에러**: `Mathf.Atan2(0, 0)`이 되는 순간 회전 각도가 0도(오른쪽)로 리셋되어버립니다. 적과 겹치면 포탑이 갑자기 오른쪽을 쳐다보고 굳어버리니, 거리가 0에 가까우면 `return;`으로 회전 로직을 스킵하는 안전장치를 꼭 넣으세요.
