# [Game Math] 7. 베지어 곡선 (Bezier Curve)

## 1. 베지어 곡선(Bezier Curve)이란?
**베지어 곡선(Bezier Curve)** 은 소수의 **제어점(Control Point)** 만으로 부드러운 곡선을 정의하는 매개변수 곡선입니다.\
포토샵 펜 도구, 트루타입 폰트, 게임의 유도 투사체 궤적, 시네마틱 카메라 경로, UI 트윈 이징(Easing)까지 거의 모든 부드러운 곡선의 기반이 됩니다.

> **베지어 곡선은 '자석에 끌리는 고무줄'입니다.**
> * 양 끝의 **앵커(Anchor)** 에 고무줄을 고정합니다.
> * 중간의 **제어점(Control Point)** 들이 자석처럼 고무줄을 자기 쪽으로 끌어당깁니다.
> * 자석의 위치와 거리가 곡선의 휘어짐과 탄력을 결정합니다.

---

## 2. 핵심 요약

| 차수 | 제어점 수 | 공식 ($0 \le t \le 1$) | 주요 용도 |
| :--- | :--- | :--- | :--- |
| **Linear (1차)** | 2개 ($P_0, P_1$) | $P(t) = (1-t)P_0 + tP_1$ | 직선 보간 (`Vector3.Lerp`) |
| **Quadratic (2차)** | 3개 ($P_0, P_1, P_2$) | $P(t) = (1-t)^2 P_0 + 2(1-t)t P_1 + t^2 P_2$ | 포물선 화살, 아치형 투사체 |
| **Cubic (3차)** | 4개 ($P_0, P_1, P_2, P_3$) | $P(t) = (1-t)^3 P_0 + 3(1-t)^2 t P_1 + 3(1-t)t^2 P_2 + t^3 P_3$ | S자 곡선, 카메라 레일, UI 이징 (표준) |

* **$t$의 의미:** $0 \sim 1$ 사이의 **매개변수(진행도)**. $t = 0$이면 시작점($P_0$), $t = 1$이면 끝점($P_n$)에 정확히 위치합니다.
* **핵심 성질 1 (통과 여부):** 곡선은 시작점과 끝점만 통과하며, 중간 제어점은 통과하지 않습니다.
* **핵심 성질 2 (비등속):** $t$를 일정한 간격으로 증가시켜도 곡선 위 점들 사이의 실제 거리는 일정하지 않습니다. 등속 이동에는 **호 길이 재매개변수화(LUT)** 가 필요합니다.

## 3. 세부 개념

### 3.1 De Casteljau 알고리즘 (재귀적 선형 보간)
전개 공식(번스타인 다항식)을 외우지 않고도, **`Lerp`를 단계적으로 반복**해 베지어 곡선 위의 점을 구하는 기하학적 알고리즘입니다.
* 3차 베지어(점 4개): `4개 → Lerp 3회 → 3개 → Lerp 2회 → 2개 → Lerp 1회 → 최종 1개`
* **장점:** 기하학적 직관이 뛰어나고, 마지막 2개 점(`d → e`)을 잇는 선분이 곧 그 지점의 **접선(Tangent)** 이 됩니다.

### 3.2 접선 벡터 (Tangent / 1차 미분)
화살·미사일·카메라가 곡선의 **진행 방향을 바라보게** 하려면 곡선 위 위치 $P(t)$의 1차 미분(속도 벡터) $P'(t)$를 구합니다.

```text
3차 베지어 1차 미분 (속도/접선 벡터):
P'(t) = 3(1-t)²(P1 - P0) + 6(1-t)t(P2 - P1) + 3t²(P3 - P2)
```

* **`P'(t).normalized`:** 해당 시점의 순수한 진행 방향 (`Quaternion.LookRotation`에 전달)
* **`P'(t).magnitude`:** 해당 시점의 순간 속도 크기 — 이 값이 $t$에 따라 변하기 때문에 곡선이 등속이 되지 않습니다.

### 3.3 호 길이 재매개변수화 (Arc-Length LUT)
3차 베지어의 정확한 호 길이는 단순한 공식으로 풀 수 없으므로, 실무에서는 **누적 거리 룩업 테이블(LUT)** 방식을 사용합니다.
1. 곡선을 $N$개(보통 30~100개) 구간으로 샘플링하여 점 배열 `points[]`와 누적 거리 배열 `cumulativeLengths[]`를 미리 구축합니다.
2. 원하는 이동 거리 `targetDist = progress * totalLength`가 속한 구간 `[i, i+1]`을 찾습니다.
3. 해당 구간 안의 비율로 `points[i]`와 `points[i+1]`을 선형 보간(`Lerp`)하여 부드러운 등속 좌표를 얻습니다.

### 3.4 여러 곡선 이어 붙이기와 연속성 (Spline 기초)
두 3차 베지어 곡선 $(P_0, P_1, P_2, P_3)$과 $(Q_0, Q_1, Q_2, Q_3)$을 연결할 때 이음매의 매끄러움은 다음 3단계로 구분됩니다.

| 연속성 | 조건 | 시각적/물리적 특징 |
| :--- | :--- | :--- |
| **$C^0$ (위치 연속)** | $P_3 = Q_0$ | 선이 끊어지진 않으나 이음매가 뾰족하게 꺾임 |
| **$G^1$ (접선 방향 연속)** | $P_2 \to P_3$ 방향과 $Q_0 \to Q_1$ 방향이 일직선 | 모양은 매끄럽지만 이음매에서 속도가 튈 수 있음 |
| **$C^1$ (속도 연속)** | $Q_1 = 2P_3 - P_2$ (방향과 길이 모두 대칭) | 카메라·오브젝트가 통과해도 가속/감속 튐 없음 |

## 4. 코드로 보기

### 4.1 재사용 가능한 정적 유틸리티 (`BezierUtility`)
여러 스크립트에 곡선 함수를 복사해 두지 않고, 정적 유틸리티 클래스로 분리해 사용합니다.

```csharp
using System;
using UnityEngine;

public static class BezierUtility
{
    /// <summary>
    /// 2차 베지어 곡선 위치 (전개 공식 — 핫 루프 권장)
    /// </summary>
    public static Vector3 Quadratic(Vector3 p0, Vector3 p1, Vector3 p2, float t)
    {
        t = Mathf.Clamp01(t);
        float u = 1f - t;
        return (u * u * p0) + (2f * u * t * p1) + (t * t * p2);
    }

    /// <summary>
    /// 3차 베지어 곡선 위치 (전개 공식 — Clamp 1회 + 연산 최소화로 가장 빠름)
    /// </summary>
    public static Vector3 Cubic(Vector3 p0, Vector3 p1, Vector3 p2, Vector3 p3, float t)
    {
        t = Mathf.Clamp01(t);
        float u = 1f - t;
        float uu = u * u;
        float tt = t * t;

        return (uu * u * p0)
             + (3f * uu * t * p1)
             + (3f * u * tt * p2)
             + (tt * t * p3);
    }

    /// <summary>
    /// 3차 베지어 곡선 위치 (De Casteljau 방식 — 원리 학습 및 직관적 이해용)
    /// </summary>
    public static Vector3 CubicDeCasteljau(Vector3 p0, Vector3 p1, Vector3 p2, Vector3 p3, float t)
    {
        t = Mathf.Clamp01(t); // 앞에서 한 번만 클램프하고 내부는 LerpUnclamped 사용

        Vector3 a = Vector3.LerpUnclamped(p0, p1, t);
        Vector3 b = Vector3.LerpUnclamped(p1, p2, t);
        Vector3 c = Vector3.LerpUnclamped(p2, p3, t);

        Vector3 d = Vector3.LerpUnclamped(a, b, t);
        Vector3 e = Vector3.LerpUnclamped(b, c, t);

        return Vector3.LerpUnclamped(d, e, t);
    }

    /// <summary>
    /// 3차 베지어 1차 미분 (진행 방향 및 순간 속도 벡터)
    /// </summary>
    public static Vector3 CubicVelocity(Vector3 p0, Vector3 p1, Vector3 p2, Vector3 p3, float t)
    {
        t = Mathf.Clamp01(t);
        float u = 1f - t;

        return 3f * u * u * (p1 - p0)
             + 6f * u * t * (p2 - p1)
             + 3f * t * t * (p3 - p2);
    }

    /// <summary>
    /// 3차 베지어 정규화 접선 벡터 (진행 방향을 바라보는 회전 계산용)
    /// </summary>
    public static Vector3 CubicTangent(Vector3 p0, Vector3 p1, Vector3 p2, Vector3 p3, float t)
    {
        Vector3 velocity = CubicVelocity(p0, p1, p2, p3, t);
        return velocity.sqrMagnitude > 0.0001f ? velocity.normalized : Vector3.forward;
    }

    /// <summary>
    /// 등속 이동용 누적 호 길이 테이블(LUT) 생성
    /// </summary>
    public static void BuildArcLengthLut(
        Vector3 p0, Vector3 p1, Vector3 p2, Vector3 p3,
        Vector3[] outPoints, float[] outCumulativeLengths)
    {
        int count = outPoints.Length;
        outPoints[0] = p0;
        outCumulativeLengths[0] = 0f;

        float total = 0f;
        for (int i = 1; i < count; i++)
        {
            float t = i / (float)(count - 1); // 정수 나눗셈 방지
            outPoints[i] = Cubic(p0, p1, p2, p3, t);
            total += Vector3.Distance(outPoints[i - 1], outPoints[i]);
            outCumulativeLengths[i] = total;
        }
    }

    /// <summary>
    /// 누적 호 길이 테이블에서 등속 비율(0~1)에 해당하는 부드러운 위치 샘플링
    /// </summary>
    public static Vector3 SampleUniformByDistance(
        Vector3[] points, float[] cumulativeLengths, float normalizedDist)
    {
        int lastIdx = points.Length - 1;
        normalizedDist = Mathf.Clamp01(normalizedDist);

        float totalLength = cumulativeLengths[lastIdx];
        if (totalLength < 0.0001f) return points[0];

        float targetDist = normalizedDist * totalLength;
        int idx = Array.BinarySearch(cumulativeLengths, targetDist);

        if (idx >= 0) return points[idx];

        // BinarySearch가 음수를 반환하면 ~idx가 targetDist보다 큰 첫 번째 인덱스
        int nextIdx = Mathf.Clamp(~idx, 1, lastIdx);
        int prevIdx = nextIdx - 1;

        float segLen = cumulativeLengths[nextIdx] - cumulativeLengths[prevIdx];
        float localT = segLen > 0.0001f
            ? (targetDist - cumulativeLengths[prevIdx]) / segLen
            : 0f;

        return Vector3.LerpUnclamped(points[prevIdx], points[nextIdx], localT);
    }
}
```

## 5. 활용 예시 (게임 도메인: 시네마틱 카메라 & 유도 발사체)
> 카메라는 베지어 곡선을 따라 이동하며, 타겟이 지정되어 있으면 타겟을 주시하고, 없으면 **접선 방향(진행 방향)** 을 자연스럽게 바라봅니다.

```csharp
using UnityEngine;

public class BezierCameraPath : MonoBehaviour
{
    [Header("Control Points")]
    [SerializeField] private Transform p0;
    [SerializeField] private Transform p1;
    [SerializeField] private Transform p2;
    [SerializeField] private Transform p3;

    [Header("Motion Settings")]
    [SerializeField][Min(0.01f)] private float duration = 5f;
    [SerializeField] private Transform lookAtTarget;
    [SerializeField] private bool lookAlongPath = true;

    private float _elapsed;
    private bool _isFinished;

    private void Update()
    {
        if (_isFinished || !HasValidPoints()) return;

        _elapsed += Time.deltaTime;
        float t = Mathf.Clamp01(_elapsed / duration);

        transform.position = BezierUtility.Cubic(
            p0.position, p1.position, p2.position, p3.position, t);

        if (lookAtTarget != null)
        {
            transform.LookAt(lookAtTarget);
        }
        else if (lookAlongPath)
        {
            Vector3 tangent = BezierUtility.CubicTangent(
                p0.position, p1.position, p2.position, p3.position, t);
            transform.rotation = Quaternion.LookRotation(tangent);
        }

        if (t >= 1f) _isFinished = true;
    }

    private bool HasValidPoints()
    {
        return p0 != null && p1 != null && p2 != null && p3 != null;
    }

    private void OnDrawGizmos()
    {
        if (!HasValidPoints()) return;

        Gizmos.color = Color.yellow;
        const int segments = 30;
        Vector3 prev = p0.position;

        for (int i = 1; i <= segments; i++)
        {
            float t = i / (float)segments;
            Vector3 cur = BezierUtility.Cubic(
                p0.position, p1.position, p2.position, p3.position, t);
            Gizmos.DrawLine(prev, cur);
            prev = cur;
        }
    }
}
```

## 6. 실전에서는?

### 곡선이 필요할 때 무엇을 고르는가
| 상황 | 추천 도구 | 이유 |
| :--- | :--- | :--- |
| 값 1개의 시간 변화 (알파, 볼륨, 이징) | `AnimationCurve` | 인스펙터에서 직관적 편집, 코드 불필요 |
| 간단한 3D 공간 경로·투사체 궤적 | 직접 구현한 `BezierUtility` | 가볍고 런타임 동적 생성(유도탄 등)에 최적 |
| 긴 트랙·도로·다중 구간 레일 편집 | **Unity Splines** 패키지 | $C^1/G^1$ 핸들 편집, 등속 평가, 메시 압출 기본 제공 |
| 지정된 경유지를 반드시 통과해야 함 | Catmull-Rom Spline | 베지어 중간 제어점은 곡선 위에 놓이지 않음 |
| 지형·장애물을 회피하며 이동 | `NavMesh` | 수학 곡선 자체는 충돌·지형을 인식하지 못함 |
| 단순 A → B 직선 이동 | `Lerp` / `SmoothStep` | 제어점 4개는 과설계 |

### 제어점을 누가 만지는가 — 에디터 vs 코드
* **기획자·연출가용 경로:** 씬에 빈 `GameObject`를 두고 아래 `BezierCurveViewer` 같은 기즈모 미리보기 도구를 반드시 붙여 시각화합니다.
* **코드 동적 생성 경로(투사체·유도 미사일):** `Vector3`로 제어점을 절차적으로 계산합니다. 보통 `(start + end) * 0.5f + Vector3.up * arcHeight`처럼 규칙을 세웁니다.

### 씬 뷰 전용 곡선 미리보기 도구 (`BezierCurveViewer`)
핸들 Transform의 길이는 버리고 **방향만 취해 `curvature` 하나로 균형 잡힌 곡률을 조절**할 수 있는 에디터 친화형 뷰어입니다.

```csharp
using UnityEngine;

public class BezierCurveViewer : MonoBehaviour
{
    [Header("Anchor Points")]
    [SerializeField] private Transform startPoint;
    [SerializeField] private Transform endPoint;

    [Header("Control Direction Handles")]
    [SerializeField] private Transform startHandle;
    [SerializeField] private Transform endHandle;

    [Header("Curve Settings")]
    [SerializeField] private float curvature = 1f;
    [SerializeField][Range(0f, 1f)] private float progress;

    [Header("Gizmo Display")]
    [SerializeField][Range(10, 100)] private int segmentCount = 50;
    [SerializeField] private Color curveColor = Color.green;
    [SerializeField] private Color lineColor = Color.gray;
    [SerializeField] private Color markerColor = Color.cyan;
    [SerializeField] private float gizmoRadius = 0.12f;

    private void OnDrawGizmos()
    {
        if (startPoint == null || endPoint == null || startHandle == null || endHandle == null)
            return;

        Vector3 p0 = startPoint.position;
        Vector3 p3 = endPoint.position;

        Vector3 p1 = p0 + (startHandle.position - p0).normalized * curvature;
        Vector3 p2 = p3 + (endHandle.position - p3).normalized * curvature;

        DrawControlLines(p0, p1, p2, p3);
        DrawCurve(p0, p1, p2, p3);
        DrawPoints(p0, p1, p2, p3);
        DrawProgressMarker(p0, p1, p2, p3);
    }

    private void DrawControlLines(Vector3 p0, Vector3 p1, Vector3 p2, Vector3 p3)
    {
        Gizmos.color = lineColor;
        Gizmos.DrawLine(p0, p1);
        Gizmos.DrawLine(p3, p2);
    }

    private void DrawCurve(Vector3 p0, Vector3 p1, Vector3 p2, Vector3 p3)
    {
        Gizmos.color = curveColor;
        Vector3 previous = p0;

        for (int i = 1; i <= segmentCount; i++)
        {
            float t = i / (float)segmentCount;
            Vector3 current = BezierUtility.Cubic(p0, p1, p2, p3, t);
            Gizmos.DrawLine(previous, current);
            previous = current;
        }
    }

    private void DrawPoints(Vector3 p0, Vector3 p1, Vector3 p2, Vector3 p3)
    {
        Gizmos.color = Color.red;
        Gizmos.DrawSphere(p0, gizmoRadius);
        Gizmos.DrawSphere(p3, gizmoRadius);

        Gizmos.color = Color.yellow;
        Gizmos.DrawSphere(p1, gizmoRadius * 0.6f);
        Gizmos.DrawSphere(p2, gizmoRadius * 0.6f);
    }

    private void DrawProgressMarker(Vector3 p0, Vector3 p1, Vector3 p2, Vector3 p3)
    {
        Vector3 pos = BezierUtility.Cubic(p0, p1, p2, p3, progress);
        Vector3 tangent = BezierUtility.CubicTangent(p0, p1, p2, p3, progress);

        Gizmos.color = markerColor;
        Gizmos.DrawSphere(pos, gizmoRadius);
        Gizmos.DrawRay(pos, tangent * (gizmoRadius * 4f)); // 진행 방향(접선) 시각화
    }
}
```

> **주의: 기즈모는 에디터 전용입니다.**\
> `OnDrawGizmos` / `OnDrawGizmosSelected`는 빌드된 게임에서 실행되지 않습니다. 실제 플레이어에게 선을 보여주려면 `LineRenderer` 컴포넌트를 사용하세요.

### 성능·정확도의 경계
1. **실시간 평가 vs LUT:** 단일 컷신 카메라나 투사체 몇 개는 매 프레임 `BezierUtility.Cubic`을 직접 호출하는 것이 메모리도 안 쓰고 충분히 빠릅니다.
2. **등속이 눈에 보이는가:** 컷신 카메라는 자연스러운 가감속이 오히려 유리해 기본 `t`를 써도 무방합니다. 반면 레일 오브젝트·리듬 게임 노트·컨베이어 벨트에는 **호 길이 LUT(`SampleUniformByDistance`)** 가 필수입니다.
3. **샘플 분할 수:** 시각적 곡선이나 LUT는 보통 **30~50분할**이면 부드러움과 메모리 효율의 균형이 잘 맞습니다.

## 7. 실습 문제

1. Linear, Quadratic, Cubic 베지어의 제어점 개수는 각각 몇 개인가요?
2. $t = 0$과 $t = 1$에서 베지어 곡선은 어디에 위치하나요?
3. 2차 베지어 함수 `QuadraticBezier(p0, p1, p2, t)`를 De Casteljau 방식으로 작성하세요.
4. 베지어 곡선에서 $t$를 일정하게 증가시켜도 등속으로 이동하지 못하는 수학적 이유는 무엇인가요?
5. Cubic 베지어 1개 vs Quadratic 베지어 2개 연결 — 어느 쪽이 어떤 면에서 더 유리한가요?

<details>
<summary>정답 및 해설 보기</summary>

1. **Linear 2개, Quadratic 3개, Cubic 4개** (차수 $n$의 베지어 곡선은 항상 $n + 1$개의 제어점을 가집니다.)
2. **$t = 0$이면 시작점 $P_0$, $t = 1$이면 끝점 $P_n$** 에 정확히 위치합니다.
3. **2차 베지어 De Casteljau 구현:**
   ```csharp
   public static Vector3 QuadraticDeCasteljau(Vector3 p0, Vector3 p1, Vector3 p2, float t)
   {
       t = Mathf.Clamp01(t);
       Vector3 a = Vector3.LerpUnclamped(p0, p1, t);
       Vector3 b = Vector3.LerpUnclamped(p1, p2, t);
       return Vector3.LerpUnclamped(a, b, t);
   }
   ```
4. **곡선의 1차 미분 크기(순간 속도) $\vert{}P'(t)\vert{}$가 $t$에 따라 변하기 때문입니다.** \
제어점이 앵커 가까이 몰린 구간에서는 $t$가 변해도 이동 거리가 짧아 느려지고, 제어점이 멀리 떨어진 구간에서는 빠르게 이동합니다. 즉, $t$는 이동 거리가 아니라 가중치 비율일 뿐입니다.
5. **Cubic 베지어 1개는 S자 변곡점과 3D 공간 비틀림(비평면 곡선)을 단일 수식으로 매끄럽게($C^\infty$) 표현**할 수 있어 카메라·디자인 툴의 표준입니다. \
반면 **Quadratic 2개 연결**은 차수가 낮아 연산·충돌 판정이 단순하고(폰트 렌더링 TrueType 등에 사용), 연결 지점을 직접 통과하도록 제어할 수 있지만 이음매에서 $C^1$ 연속성을 맞추려면 제어점 위치에 제약이 생깁니다.

</details>

## 8. 이것만은 기억하자

* **`Mathf.Clamp01(t)`를 습관화하라:** 전개 공식과 `LerpUnclamped`에 범위 밖 `t`가 들어가면 곡선 밖으로 폭주합니다.
* **정수 나눗셈 함정 조심:** 루프에서 `i / segments` 대신 반드시 `i / (float)segments`를 쓰세요.
* **진행 방향 회전은 1차 미분(접선)으로:** `CubicTangent`를 구해 `Quaternion.LookRotation`에 넘기면 어떤 위치에서도 매끄럽게 앞을 바라봅니다.
* **등속 이동엔 호 길이 LUT + 구간 보간:** `t` 균일 샘플링만으로는 등속이 되지 않으며, 배열 인덱스 스냅 대신 구간 사이를 `Lerp`해야 끊기지 않습니다.
* **빌드용 선 렌더링은 `LineRenderer`, 긴 다중 경로는 `Unity Splines`:** 기즈모는 에디터 전용임을 잊지 마세요.
