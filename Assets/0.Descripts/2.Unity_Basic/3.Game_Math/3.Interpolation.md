# [Game Math] 3. 부드러운 움직임의 예술, 보간 (Interpolation)

## 1. 보간(Interpolation) 이란?
> **애니메이터의 키프레임(Keyframe)과 인비트윈(In-between)**
> * 애니메이터는 캐릭터의 '시작 자세'와 '끝 자세'처럼 가장 중요한 장면(Keyframe)만 직접 그립니다.
> * 그 사이의 수많은 중간 동작(In-between)은 어시스턴트나 컴퓨터가 채워 넣습니다.
> * 정해진 두 지점 사이의 **중간 과정을 계산해 만들어 내는 일** — 그것이 바로 **보간(Interpolation)** 입니다.

정의하자면 보간은 주어진 시작값과 목표값 사이의 중간값을 계산해 부드러운 변화를 만드는 기술입니다. 위치, 회전, 색상, 크기, 사운드 볼륨처럼 **수치로 표현할 수 있는 모든 것**에 적용할 수 있습니다.

**왜 필요한가?**\
게임은 1초에 수십 번 화면을 새로 그립니다. 보간 없이 오브젝트를 A에서 B로 옮기면, 한 프레임에 A에 있다가 다음 프레임에 B로 **순간이동**해 버립니다. 움직임이 뚝뚝 끊겨 보이고, 플레이어는 무슨 일이 일어났는지 인지조차 못 합니다.

이전 챕터(비율과 비례)에서 만든 `현재값 / 최대값`이 여기서 그대로 **`t`(진행도, 0.0 ~ 1.0)** 라는 이름으로 다시 등장합니다. 비율을 구할 줄 안다면, 보간은 그 비율을 두 값 사이에 대입하는 한 줄이 더 붙은 것뿐입니다.

## 2. 핵심 요약

보간 코드는 언제나 아래 **네 가지**를 결정하는 일로 분해됩니다.

| 정할 것 | 무엇을 결정하는가 | 대표 표현 |
| :--- | :--- | :--- |
| **섞을 두 값** | 무엇과 무엇 사이를 오갈 것인가 | `Vector3.Lerp(start, end, t)` |
| **진행도 `t`** | 지금 얼마나 왔는가 (`0.0 ~ 1.0`) | `t = elapsed / duration` |
| **`t`의 곡선** | 등속인가, 가감속(Easing)인가 | `Mathf.SmoothStep(0f, 1f, t)`, `curve.Evaluate(t)` |
| **끝에 닿은 뒤** | 멈추는가, 되돌아가는가 | 튜플 스왑, 방향 플래그, `Mathf.PingPong` |

> **[원칙]**
> 1. **핵심 공식**: `결과 = 시작값 + (끝값 - 시작값) * t`. Unity의 `Lerp` 계열은 이 계산과 `t`의 0~1 클램핑을 대신해 줍니다.
> 2. **방식 선택**: 도착 시간이 정해진 연출은 **시간 누적(`elapsed / duration`)**, 끝없이 따라다니는 추적은 **지수 감쇠(`1 - Exp`)** 나 `SmoothDamp`를 씁니다.
> 3. **물리 바디 이동**: `Rigidbody` / `Rigidbody2D`가 붙은 오브젝트를 보간으로 옮길 때는 `Update + transform.position`이 아니라 **`FixedUpdate + MovePosition`** 을 써야 충돌이 깨지지 않습니다.

## 3. 세부 개념 및 원리

### 3.1 선형 보간 (Linear Interpolation · Lerp)
가장 기본이 되는 보간입니다. '선형(Linear)'이라는 이름처럼 변화 속도가 일정한 **등속 운동**을 만듭니다.

* **공식**: `결과 = 시작값 + (끝값 - 시작값) * t`
* `t = 0`이면 시작값, `t = 1`이면 끝값, `t = 0.5`면 정확히 중간값이 나옵니다.

```csharp
using UnityEngine;

public class TimedMover : MonoBehaviour
{
    [SerializeField] private Transform _startMarker;
    [SerializeField] private Transform _endMarker;
    [SerializeField] private float _duration = 2.0f; // 도착까지 걸리는 시간(초)

    private float _elapsedTime;

    private void Update()
    {
        _elapsedTime += Time.deltaTime;

        // duration이 0이면 나눗셈 결과가 Infinity가 되어 t가 곧바로 1로 튄다 (0 나누기 방어)
        float t = Mathf.Clamp01(_elapsedTime / Mathf.Max(_duration, 0.0001f));

        // 공식 : 시작값 + (끝값 - 시작값) * t
        // Vector3 current = _startMarker.position + (_endMarker.position - _startMarker.position) * t;

        // Unity 내장 Lerp — 성분(x, y, z)별 계산 + t의 0~1 자동 클램핑 포함
        transform.position = Vector3.Lerp(_startMarker.position, _endMarker.position, t);
    }
}
```
> **참고 (`Lerp` vs `LerpUnclamped`)**: `Lerp`는 `t`를 0~1로 가둡니다. `t = 1.5`를 넣어도 끝값에서 멈춥니다. 반대로 끝값을 지나쳐 바깥으로 뻗어 나가는 외삽(예: 탄성 오버슈트 연출)이 필요하다면 **`LerpUnclamped`** 를 씁니다.

### 3.2 `t`를 만드는 두 가지 방식

`Lerp`의 첫 번째 인자에 **'고정된 시작점'** 을 넣느냐, **'매 프레임 바뀌는 현재 위치'** 를 넣느냐에 따라 움직임의 성격이 완전히 달라집니다.

#### ① 정해진 시간 동안의 보간 (Timed Interpolation)
경과 시간을 전체 시간으로 나누어 `t`를 0에서 1로 밀어 올립니다. 프레임률이 흔들려도 "2초는 정확히 2초"가 보장됩니다. (문 열림, UI 팝업, 스킬 캐스팅 연출)

```csharp
using System.Collections;
using UnityEngine;

public class DoorOpener : MonoBehaviour
{
    [SerializeField] private Transform _door;
    [SerializeField] private float _openYAngle = 90f;
    [SerializeField] private float _duration = 2.0f;

    public void OpenDoor() => StartCoroutine(RotateDoorRoutine(_openYAngle));

    private IEnumerator RotateDoorRoutine(float targetYAngle)
    {
        float elapsedTime = 0f;
        float startYAngle = _door.eulerAngles.y;
        float safeDuration = Mathf.Max(_duration, 0.0001f);

        while (elapsedTime < safeDuration)
        {
            elapsedTime += Time.deltaTime;
            float t = Mathf.Clamp01(elapsedTime / safeDuration);

            // LerpAngle은 350도 -> 10도 구간을 최단 경로(20도)로 돌린다
            float currentAngle = Mathf.LerpAngle(startYAngle, targetYAngle, t);
            _door.eulerAngles = new Vector3(0f, currentAngle, 0f);

            yield return null;
        }

        // 루프 종료 후 오차 없이 목표값을 정확히 못 박아 둔다
        _door.eulerAngles = new Vector3(0f, targetYAngle, 0f);
    }
}
```

#### ② 지수적 감속 보간 (Exponential Easing) & 프레임 독립 보정
매 프레임 '현재 위치'에서 '목표 위치'까지 남은 거리의 일정 비율만큼 다가갑니다. 가까워질수록 이동량이 줄어들어 스르륵 멈추는 느낌을 줍니다. (카메라 추적, 커서를 쫓는 조준선)

```csharp
using UnityEngine;

public class SmoothFollowCamera : MonoBehaviour
{
    [SerializeField] private Transform _player;
    [SerializeField] private Vector3 _offset = new Vector3(0f, 0f, -10f);
    [SerializeField] private float _decaySpeed = 8.0f; // 클수록 빠르게 따라붙음 (보통 1 ~ 25)

    // 플레이어 이동이 Update에서 끝난 뒤 카메라를 옮겨야 떨리지 않는다
    private void LateUpdate()
    {
        if (_player == null) return;

        Vector3 desiredPosition = _player.position + _offset;

        // 단순 방식: Time.deltaTime * speed는 FPS마다 속도가 미묘하게 달라지고, 렉(스파이크) 시 1을 넘어 순간이동할 수 있다.
        // float t = Time.deltaTime * _decaySpeed;

        // 정석 (프레임 독립 지수 감쇠): 어떤 FPS에서도 수렴 속도가 100% 동일하며 절대 1을 넘지 않는다
        float t = 1f - Mathf.Exp(-_decaySpeed * Time.deltaTime);

        transform.position = Vector3.Lerp(transform.position, desiredPosition, t);
    }
}
```

### 3.3 다양한 데이터 타입의 보간
Unity는 자료형마다 전용 `Lerp` 함수를 제공합니다. 내부 원리는 모두 같습니다.

```csharp
float t = 0.5f;

float alpha = Mathf.Lerp(0f, 1f, t);                    // 단일 실수 — 투명도, 볼륨
float angle = Mathf.LerpAngle(350f, 10f, t);            // 단일 각도 — 360도 경계 최단 회전
Vector3 pos = Vector3.Lerp(startPos, endPos, t);        // 3D 위치, 크기
Vector2 uiPos = Vector2.Lerp(startUi, endUi, t);        // 2D 좌표, RectTransform
Color tint = Color.Lerp(Color.white, Color.red, t);     // 색상 (RGBA)
Quaternion turn = Quaternion.Slerp(fromRot, toRot, t);  // 3D 회전 — 구면 선형 보간 (등속, 자연스러움)
Quaternion quick = Quaternion.Lerp(fromRot, toRot, t);  // 3D 회전 — 더 가볍지만 각도가 크면 속도 불균일
```
> **회전 보간 원칙**: 3D 회전을 `Vector3.Lerp(eulerA, eulerB, t)`로 섞으면 0°/360° 경계에서 반대로 뺑 돌고 짐벌 락(Gimbal Lock)에 걸립니다. 단일 축은 `Mathf.LerpAngle`, 3D 회전은 무조건 **`Quaternion.Slerp`** 를 씁니다.

### 3.4 비선형 보간 (Non-Linear Interpolation · Easing)
등속 직선 이동은 기계적입니다. `Lerp`에 넘기기 전에 **`t`(0~1)를 곡선으로 한 번 구부려 주면** 생동감 있는 가감속이 탄생합니다.

```csharp
// 1. 가장 가벼운 수식 Easing (t는 0~1)
float easeIn  = t * t;                     // 서서히 빨라짐 (출발 가속)
float easeOut = 1f - (1f - t) * (1f - t);  // 빠르게 나가다 스르륵 멈춤 (UI 팝업, 착지)

// 2. Unity 내장 S자 곡선 (시작과 끝이 모두 느림)
float smooth = Mathf.SmoothStep(0f, 1f, t);

// 3. 인스펙터에서 직접 그리는 커스텀 곡선 (AnimationCurve)
float custom = _bounceCurve.Evaluate(t);
```

```csharp
using UnityEngine;

public class BounceMover : MonoBehaviour
{
    [SerializeField] private AnimationCurve _bounceCurve = AnimationCurve.EaseInOut(0f, 0f, 1f, 1f);
    [SerializeField] private float _duration = 2f;
    [SerializeField] private float _height = 3f;

    private Vector3 _startPosition;
    private float _elapsedTime;

    private void Start() => _startPosition = transform.position;

    private void Update()
    {
        _elapsedTime += Time.deltaTime;
        float t = Mathf.Clamp01(_elapsedTime / Mathf.Max(_duration, 0.0001f));

        // 인스펙터에서 그린 그래프 모양대로 통통 튀는 움직임을 코드 수정 없이 구현
        float curveValue = _bounceCurve.Evaluate(t);
        transform.position = _startPosition + Vector3.up * (curveValue * _height);
    }
}
```

### 3.5 끝에 닿은 뒤 — 왕복시키는 세 가지 방법
`t`가 1에 닿은 뒤 다시 되돌아오게 하는 대표 패턴입니다.

1. **시작과 끝을 맞바꾸기 (최신 C# 튜플 스왑)**
```csharp
if (_currentTime >= safeDuration)
{
    _currentTime = 0f;
    (_startPosition, _goalPosition) = (_goalPosition, _startPosition); // temp 변수 없이 깔끔하게 스왑
}
```

2. **방향 플래그로 `t`를 되돌리기**
```csharp
_elapsedTime += _isForward ? Time.deltaTime : -Time.deltaTime;
_elapsedTime = Mathf.Clamp(_elapsedTime, 0f, safeDuration);

if (_isForward && _elapsedTime >= safeDuration) _isForward = false;
else if (!_isForward && _elapsedTime <= 0f) _isForward = true;
```

3. **`Mathf.PingPong` 한 줄로 맡기기**
```csharp
// 0과 1 사이를 자동으로 왕복하는 등속 삼각파 생성
float t = Mathf.PingPong(Time.time / Mathf.Max(_duration, 0.0001f), 1f);
```

### 4.1 왕복 보간 리팩토링 (Before vs After)

#### 잘못된 코드 (0 나누기 무방비 + 콘솔 도배)
```csharp
public class BadPositionPingPong : MonoBehaviour
{
    public float lerpTime = 1.0f; // public 노출 위험
    public Transform Start_PositionLerp;
    public Transform Current_PositionLerp;
    public Transform End_PositionLerp;

    private float currentTime = 0.0f;
    private bool isPositive = true;

    void Update()
    {
        currentTime += isPositive ? Time.deltaTime : -Time.deltaTime;
        float ratio = currentTime / lerpTime; // lerpTime이 0이면 Infinity 발생 -> 양 끝을 미친 듯이 깜빡임

        Current_PositionLerp.position = Vector3.Lerp(
            Start_PositionLerp.position, End_PositionLerp.position, ratio);

        Debug.Log($"{ratio}"); // 매 프레임 콘솔 출력 (심각한 성능 저하)

        if (isPositive && currentTime >= lerpTime) { currentTime = lerpTime; isPositive = false; }
        else if (!isPositive && currentTime <= 0) { currentTime = 0f; isPositive = true; }
    }
}
```

#### 정리된 코드 (안전한 방어 + 깔끔한 컨벤션)
```csharp
using UnityEngine;

public class PositionPingPong : MonoBehaviour
{
    [SerializeField] private float _lerpDuration = 1.0f;

    [Header("위치 마커")]
    [SerializeField] private Transform _startMarker;
    [SerializeField] private Transform _endMarker;
    [SerializeField] private Transform _movingTarget;

    private float _elapsedTime;
    private bool _isForward = true;

    private void Update()
    {
        float safeDuration = Mathf.Max(_lerpDuration, 0.0001f); // 0 나누기 원천 차단

        _elapsedTime += _isForward ? Time.deltaTime : -Time.deltaTime;
        _elapsedTime = Mathf.Clamp(_elapsedTime, 0f, safeDuration);

        float t = Mathf.Clamp01(_elapsedTime / safeDuration);

        _movingTarget.position = Vector3.Lerp(_startMarker.position, _endMarker.position, t);

        if (_isForward && t >= 1f) _isForward = false;
        else if (!_isForward && t <= 0f) _isForward = true;
    }
}
```

### 4.2 같은 `t` 하나로 위치 · 회전 · 크기를 동시에 굴리기
보간은 타입마다 다른 기술이 아니라, **하나의 `t`를 여러 성분에 동시에 적용하는 기술**임을 한눈에 보여주는 예제입니다.

```csharp
using UnityEngine;

public class InterpolationStage : MonoBehaviour
{
    [SerializeField] private float _lerpDuration = 1.0f;

    [Header("위치 — 시작 · 현재 · 끝")]
    [SerializeField] private Transform _positionStart;
    [SerializeField] private Transform _positionCurrent;
    [SerializeField] private Transform _positionEnd;

    [Header("회전 — 시작 · 현재 · 끝")]
    [SerializeField] private Transform _rotationStart;
    [SerializeField] private Transform _rotationCurrent;
    [SerializeField] private Transform _rotationEnd;

    [Header("크기 — 시작 · 현재 · 끝")]
    [SerializeField] private Transform _scaleStart;
    [SerializeField] private Transform _scaleCurrent;
    [SerializeField] private Transform _scaleEnd;

    private void Update()
    {
        float t = Mathf.PingPong(Time.time / Mathf.Max(_lerpDuration, 0.0001f), 1f);

        // t 하나가 위치, 회전, 크기를 동시에 제어한다
        _positionCurrent.position = Vector3.Lerp(_positionStart.position, _positionEnd.position, t);
        _rotationCurrent.rotation = Quaternion.Slerp(_rotationStart.rotation, _rotationEnd.rotation, t);
        _scaleCurrent.localScale  = Vector3.Lerp(_scaleStart.localScale, _scaleEnd.localScale, t);
    }
}
```

## 5. 활용 예시 (게임 도메인)

### 시나리오 1: 피격 시 빨갛게 점멸하는 데미지 플래시 (풀링 안전판)
시작과 끝이 명확한 일회성 연출이므로 코루틴을 씁니다. 특히 **연출 도중 비활성화(오브젝트 풀 반납)되더라도 색상이 붉게 굳지 않도록 `OnDisable`에서 원복**하는 것이 핵심입니다.

```csharp
using System.Collections;
using UnityEngine;

[RequireComponent(typeof(SpriteRenderer))]
public class DamageFlash : MonoBehaviour
{
    [SerializeField] private Color _flashColor = Color.red;
    [SerializeField] private float _duration = 0.5f;

    private SpriteRenderer _spriteRenderer;
    private Color _originalColor;
    private Coroutine _flashRoutine;

    private void Awake()
    {
        _spriteRenderer = GetComponent<SpriteRenderer>();
        _originalColor = _spriteRenderer.color;
    }

    // 실무 방어: 피격 플래시 도중 오브젝트가 꺼져도(풀링 반납/사망) 원래 색을 복구한다
    private void OnDisable()
    {
        if (_flashRoutine != null)
        {
            StopCoroutine(_flashRoutine);
            _flashRoutine = null;
        }
        _spriteRenderer.color = _originalColor;
    }

    public void TakeDamage()
    {
        // 연달아 맞아도 색 연출이 겹치지 않게 이전 코루틴을 먼저 끊는다
        if (_flashRoutine != null) StopCoroutine(_flashRoutine);
        _flashRoutine = StartCoroutine(FlashRoutine());
    }

    private IEnumerator FlashRoutine()
    {
        float elapsedTime = 0f;
        float safeDuration = Mathf.Max(_duration, 0.0001f);

        while (elapsedTime < safeDuration)
        {
            elapsedTime += Time.deltaTime;
            float t = Mathf.Clamp01(elapsedTime / safeDuration);

            _spriteRenderer.color = Color.Lerp(_flashColor, _originalColor, t);
            yield return null;
        }

        _spriteRenderer.color = _originalColor;
        _flashRoutine = null;
    }
}
```

### 시나리오 2: 움직이는 발판 (`FixedUpdate` + `MovePosition`)
`Rigidbody2D`가 붙은 물리 발판을 보간으로 왕복시킵니다. 물리 바디는 **`FixedUpdate`** 에서 **`Time.fixedDeltaTime`** 과 **`MovePosition`** 을 써야 충돌과 보간이 어긋나지 않습니다.

```csharp
using UnityEngine;

[RequireComponent(typeof(Rigidbody2D))]
public class PlatformMover : MonoBehaviour
{
    [SerializeField] private Vector2 _moveOffset = new Vector2(4f, 0f);
    [SerializeField] private float _goalTime = 2.0f;

    private Rigidbody2D _rb;
    private Vector2 _startPosition;
    private Vector2 _goalPosition;
    private float _currentTime;

    private void Awake()
    {
        _rb = GetComponent<Rigidbody2D>();
        _rb.bodyType = RigidbodyType2D.Kinematic; // 코드로 운동을 직접 제어

        _startPosition = _rb.position;
        _goalPosition = _startPosition + _moveOffset;
    }

    private void FixedUpdate()
    {
        float safeGoalTime = Mathf.Max(_goalTime, 0.0001f);

        _currentTime += Time.fixedDeltaTime;
        float t = Mathf.Clamp01(_currentTime / safeGoalTime);

        Vector2 nextPosition = Vector2.Lerp(_startPosition, _goalPosition, t);

        // transform.position 대신 MovePosition을 써야 물리 엔진이 이동 경로와 충돌을 인지한다
        _rb.MovePosition(nextPosition);

        if (_currentTime >= safeGoalTime)
        {
            _currentTime = 0f;
            (_startPosition, _goalPosition) = (_goalPosition, _startPosition);
        }
    }
}
```
> **참고**: `MovePosition`은 발판 자체의 물리 충돌을 매끄럽게 맞춰 줍니다. 다만 2D에서 Kinematic 발판 위의 플레이어가 수평 이동 시 미끄러지지 않고 같이 따라가게 하려면, 발판의 이번 프레임 이동량(`deltaPosition`)을 탑승자에게 더해 주는 별도 처리가 필요합니다.

## 6. 실전에서는?

### 6.1 상황별 보간 방식 선택 기준
* **도착 시각이 기획으로 고정됨**: 경과 시간 누적 (`elapsed / duration`) — 문 열림, 캐스팅 게이지, 컷신.
* **움직이는 대상을 계속 추적**: 지수 감쇠 (`1 - Mathf.Exp(-decay * dt)`) 또는 `SmoothDamp` — 카메라 팔로우, 조준선.
* **3D 회전**: `Quaternion.Slerp` (단일 축 각도는 `Mathf.LerpAngle`).
* **디자이너/기획자가 감각을 직접 튜닝해야 함**: `AnimationCurve`.

### 6.2 왕복 방식 4종 비교

| 방법 | 어울리는 곳 | 트레이드오프 (주의점) |
| :--- | :--- | :--- |
| **시작·끝 튜플 스왑** | 두 지점 사이를 정확히 오가는 발판 | 실행 중 시작/끝 필드의 의미가 뒤바뀜 |
| **방향 플래그** | 진행도(`t`)를 직접 제어·표시해야 할 때 | 코드가 가장 길어짐 |
| **`Mathf.PingPong`** | 끝없이 등속 왕복하는 단순 장식 | 시작 위상 제어와 중간 정지가 번거로움 |
| **사인파 (`Mathf.Sin`)** | 끝에서 부드럽게 감속하는 두둥실 진동 | 등속이 아니므로 정속 발판에는 부적합 |

```csharp
// 사인파를 이용한 부드러운 진동 발판 (조건문 없이 한 줄로 왕복)
private void FixedUpdate()
{
    _timer += Time.fixedDeltaTime;
    Vector2 targetPos = _startPosition + _amplitude * Mathf.Sin(2f * Mathf.PI * _timer / _period);
    _rb.MovePosition(targetPos);
}
```

### 6.3 Update · LateUpdate · FixedUpdate · 코루틴 배치 기준
* **코루틴**: 시작과 끝이 분명한 일회성 연출 (페이드, 피격 플래시, 문 열림).
* **Update / LateUpdate**: 상시 작동하는 추적 (카메라는 반드시 `LateUpdate`).
* **FixedUpdate**: `Rigidbody` / `Rigidbody2D`가 붙은 물리 바디 이동.

### 6.4 직접 짜지 않고 도구로 넘어갈 시점
보간 코드에 *"이동 끝나면 0.2초 쉬고, 크기를 키운 뒤 콜백 실행"* 같은 **시퀀스(연쇄 연출)** 가 붙기 시작하면 손으로 짠 코루틴은 금세 스파게티가 됩니다. 이때가 **트윈 라이브러리(DOTween, PrimeTween)** 나 **Animator / Timeline**으로 넘어갈 신호입니다.

## 7. 실습 문제
1. `Mathf.Lerp(10f, 20f, 0.2f)`의 결과값은 얼마인가요? 공식에 대입해 계산해 보고, `Mathf.Lerp(10f, 20f, 1.5f)`의 결과도 함께 답해 보세요.
> * **`Mathf.Lerp(10f, 20f, 0.2f)` = `12f`**
>   * 선형 보간 공식 `시작값 + (끝값 - 시작값) * t`에 대입하면 `10 + (20 - 10) * 0.2 = 10 + 2 = 12f`가 됩니다.
> * **`Mathf.Lerp(10f, 20f, 1.5f)` = `20f`**
>   * Unity의 `Mathf.Lerp`는 내부적으로 `t`를 자동으로 `0 ~ 1` 범위로 클램핑(`Clamp01`)합니다. 따라서 `1.5f`는 `1f`로 고정되어 끝값인 `20f`를 반환합니다.
>   * *(참고: `t`를 가두지 않고 바깥으로 뻗게 하려면 `Mathf.LerpUnclamped(10f, 20f, 1.5f)`를 써야 하며, 이때 결과는 `25f`가 됩니다.)*

2. 3D 모델을 부드럽게 회전시킬 때 `Vector3.Lerp`로 `eulerAngles`를 섞는 대신 `Quaternion.Slerp`를 쓰는 이유를 두 가지 적어 보세요.
> 1. **최단 경로 회전 보장 (0° / 360° 경계 문제 해결)**
>    * 오일러 각을 단순 선형 보간하면 `350도 → 10도`로 갈 때 가까운 `20도`가 아니라 반대쪽으로 `340도`를 빙 돌아버립니다. 반면 `Quaternion.Slerp`는 항상 두 회전 사이의 최단 경로를 따라 회전합니다.
> 2. **짐벌 락(Gimbal Lock) 방지 및 일정한 회전 속도**
>    * 오일러 각을 보간하면 특정 각도에서 회전축이 겹쳐 자유도를 잃는 짐벌 락 현상이 생기고, 회전 경로가 뒤틀리거나 속도가 불균일해집니다. `Quaternion.Slerp`는 구면 선형 보간(Spherical Linear Interpolation)을 수행해 짐벌 락 없이 일정한 각속도로 매끄럽게 회전합니다.

3. Z 키를 누르면 `Light` 컴포넌트의 색이 3초에 걸쳐 파란색에서 노란색으로 변하는 스크립트를 작성하세요. `duration`을 인스펙터에서 조절할 수 있고, 0을 넣어도 깨지지 않아야 합니다.
> * `Mathf.Max(_duration, 0.0001f)`로 0 나누기(`Infinity`/`NaN`)를 방어하고, 코루틴 핸들을 관리해 Z 키를 연타해도 연출이 겹치지 않게 처리합니다.
>
> ```csharp
> using System.Collections;
> using UnityEngine;
> using UnityEngine.InputSystem;
>
> [RequireComponent(typeof(Light))]
> public class LightColorChanger : MonoBehaviour
> {
>     [SerializeField] private Color _startColor = Color.blue;
>     [SerializeField] private Color _endColor = Color.yellow;
>     [SerializeField] private float _duration = 3f;
>
>     private Light _targetLight;
>     private Coroutine _colorRoutine;
>
>     private void Awake()
>     {
>         _targetLight = GetComponent<Light>();
>     }
>
>     private void OnDisable()
>     {
>         if (_colorRoutine != null)
>         {
>             StopCoroutine(_colorRoutine);
>             _colorRoutine = null;
>         }
>     }
>
>     private void Update()
>     {
>         Keyboard keyboard = Keyboard.current;
>         if (keyboard == null) return;
>
>         if (keyboard.zKey.wasPressedThisFrame)
>         {
>             // 연타 시 기존 연출을 끊고 처음부터 다시 시작
>             if (_colorRoutine != null) StopCoroutine(_colorRoutine);
>             _colorRoutine = StartCoroutine(ChangeColorRoutine());
>         }
>     }
>
>     private IEnumerator ChangeColorRoutine()
>     {
>         float elapsedTime = 0f;
>         float safeDuration = Mathf.Max(_duration, 0.0001f); // 0 나누기 원천 차단
>
>         _targetLight.color = _startColor;
>
>         while (elapsedTime < safeDuration)
>         {
>             elapsedTime += Time.deltaTime;
>             float t = Mathf.Clamp01(elapsedTime / safeDuration);
>
>             _targetLight.color = Color.Lerp(_startColor, _endColor, t);
>             yield return null;
>         }
>
>         _targetLight.color = _endColor; // 최종 목표 색상 보장
>         _colorRoutine = null;
>     }
> }
> ```

4. `Vector3.Lerp(transform.position, target.position, 0.5f)`를 `Update`에 넣으면 오브젝트가 어떻게 움직일까요? 세 번째 인자를 `Time.deltaTime * 5f`로 바꿀 때와 `1f - Mathf.Exp(-5f * Time.deltaTime)`로 바꿀 때의 차이도 함께 설명하세요.
> * **`0.5f` 고정 시 (프레임률 완전 종속)**
>   * 매 프레임 현재 위치에서 목표까지 남은 거리의 절반(50%)씩 이동하는 **지수 감속 운동**을 합니다. 처음엔 빠르게 움직이다가 목표에 가까워질수록 스르륵 느려지며, 수학적으로는 영원히 목표에 도달하지 못합니다.
>   * 시간(`deltaTime`) 개념이 없으므로 120FPS 환경에서는 60FPS 환경보다 **2배 빠르게** 따라붙는 심각한 기기별 속도 차이가 생깁니다.
> * **`Time.deltaTime * 5f`로 바꿀 때 (근사 보정, 스파이크 취약)**
>   * 프레임 간격을 곱해 기기별 속도 차이를 완화하지만 수학적으로 완벽한 프레임 독립은 아닙니다(30FPS와 144FPS에서 수렴 속도가 미묘하게 다름).
>   * 또한 프레임 드랍(렉)으로 `Time.deltaTime`이 `0.2초` 이상 튀면 `t >= 1f`가 되어 오브젝트가 목표 위치로 **순간이동(Snap)**해 버립니다.
> * **`1f - Mathf.Exp(-5f * Time.deltaTime)`로 바꿀 때 (완벽한 프레임 독립 지수 감쇠)**
>   * 어떤 FPS 환경에서도 1초 뒤에 남는 거리의 비율이 100% 동일하게 유지됩니다.
>   * `Time.deltaTime`이 아무리 크게 튀어도 결과값 `t`가 절대로 `1`을 넘지 않아 스파이크에도 안전합니다.

5. `Rigidbody2D`를 붙인 발판이 시작 위치에서 오른쪽으로 4칸 갔다가 되돌아오기를 반복하게 만드세요. 한쪽 끝까지 2초가 걸려야 하며, 물리 충돌과 어긋나지 않아야 합니다.
> * 물리 바디이므로 `RigidbodyType2D.Kinematic`으로 설정하고, `Update + transform.position`이 아니라 **`FixedUpdate` + `Time.fixedDeltaTime` + `MovePosition`** 을 사용해야 충돌이 깨지거나 떨리지 않습니다.
>
> ```csharp
> using UnityEngine;
>
> [RequireComponent(typeof(Rigidbody2D))]
> public class MovingPlatform2D : MonoBehaviour
> {
>     [SerializeField] private Vector2 _moveOffset = new Vector2(4f, 0f); // 오른쪽으로 4칸
>     [SerializeField] private float _duration = 2f;                      // 한쪽 끝까지 2초
>
>     private Rigidbody2D _rb;
>     private Vector2 _startPosition;
>     private Vector2 _endPosition;
>     private float _elapsedTime;
>
>     private void Awake()
>     {
>         _rb = GetComponent<Rigidbody2D>();
>         _rb.bodyType = RigidbodyType2D.Kinematic; // 코드로 이동을 직접 제어
>
>         _startPosition = _rb.position;
>         _endPosition = _startPosition + _moveOffset;
>     }
>
>     private void FixedUpdate()
>     {
>         float safeDuration = Mathf.Max(_duration, 0.0001f);
>
>         _elapsedTime += Time.fixedDeltaTime;
>         float t = Mathf.Clamp01(_elapsedTime / safeDuration);
>
>         Vector2 nextPosition = Vector2.Lerp(_startPosition, _endPosition, t);
>
>         // 물리 엔진이 이동 경로를 인지하도록 반드시 MovePosition을 사용한다
>         _rb.MovePosition(nextPosition);
>
>         if (_elapsedTime >= safeDuration)
>         {
>             _elapsedTime = 0f;
>             (_startPosition, _endPosition) = (_endPosition, _startPosition); // 튜플 스왑으로 왕복
>         }
>     }
> }
> ```

## 8. 주의사항 및 안전 습관

### 흔한 실수
* **분모에 0이 들어간다**: `elapsed / duration`에서 `duration`이 0이면 `Infinity`(또는 0/0으로 `NaN`)가 발생해 연출이 순간이동하거나 에러가 납니다. 무조건 `Mathf.Max(duration, 0.0001f)`로 방어하세요.
* **오일러 각을 `Vector3.Lerp`로 섞는다**: 359° → 1° 경계에서 반대로 한 바퀴 돌고, 3D에서는 짐벌 락이 발생합니다.
* **코루틴 중단 시 상태가 중간값에 굳는다**: `StopCoroutine`이나 `SetActive(false)`로 연출이 끊기면 루프 뒤의 마무리 코드가 실행되지 않습니다. `OnDisable`에서 원래 값으로 원복하는 습관이 필수입니다.
* **물리 바디를 `transform.position`으로 옮긴다**: 물리 엔진이 모르는 순간이동이 되어 캐릭터가 끼거나 뚫립니다. `FixedUpdate` + `MovePosition`을 씁니다.
* **직렬화 필드를 `Awake`에서 덮어쓴다**: `goalPosition = transform.position + goalPosition;`처럼 쓰면 인스펙터 값의 의미가 바뀌어 혼란을 줍니다. `_moveOffset`처럼 이름과 필드를 명확히 구분하세요.

### 안전 습관
* **`t`는 만든 자리에서 바로 `Mathf.Clamp01`로 가둡니다.**
* **인스펙터 노출은 `[SerializeField] private`**로 통일하고, 시작/끝 지점은 씬의 마커(`Transform`)로 잡으면 눈으로 보며 튜닝하기 쉽습니다.
* **일회성 코루틴은 반드시 핸들(`Coroutine`)을 변수에 들고 시작**해 중복 실행과 상태 꼬임을 막습니다.
* **외삽(1을 넘는 `t`)이 필요하면 `LerpUnclamped`**를 명시적으로 사용합니다.
