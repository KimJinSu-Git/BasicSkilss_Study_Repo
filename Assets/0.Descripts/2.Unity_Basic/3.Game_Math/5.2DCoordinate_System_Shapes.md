# [Game Math] 5. 2D 좌표계와 도형 (2D Coordinate System & Shapes)

## 1. 2D 좌표계와 도형 이란?
> **거대한 모눈종이와 그 위에 그린 도형**
> * **2D 좌표계**는 끝없이 펼쳐진 한 장의 **모눈종이**입니다. 모든 캐릭터와 아이템은 이 모눈종이 위의 특정 위치에 놓이며, 그 주소가 바로 **좌표 `(x, y)`** 입니다.
> * **도형(Shape)** 은 캐릭터의 몸통, 칼의 공격 범위, 아이템 획득 반경처럼 모눈종이 위에 그려 넣은 **영역**입니다.

**왜 필요한가?**\
게임이 매 프레임 던지는 질문은 대개 세 가지로 압축됩니다.
1. *"지금 어디에 있는가?"* ➔ **좌표계 (`Vector2`, `Vector2Int`)**
2. *"목표까지 얼마나 먼가?"* ➔ **거리 (피타고라스 정리)**
3. *"범위 안에 들어왔는가?"* ➔ **도형 겹침 판정 (부등식 한 줄)**

삼각함수에서 각도를 좌표로 바꾸는 법을 다뤘다면, 이 문서는 그렇게 얻은 좌표를 **읽고, 재고, 겹침을 판정하는 방법**을 다룹니다.

## 2. 핵심 요약

| 개념 | 무엇인가 | Unity 대표 표현 |
| :--- | :--- | :--- |
| **2D 데카르트 좌표계** | 직교하는 X·Y축으로 평면 위치를 `(x, y)`로 표기 | 오른쪽이 `+X`, 위쪽이 `+Y` |
| **좌표계 3종** | 같은 점이라도 기준에 따라 숫자가 완전히 다름 | World / Screen(픽셀) / Viewport(`0~1`) |
| **거리 (Distance)** | 두 점 사이의 최단 길이 (피타고라스 정리) | `Vector2.Distance(a, b)`, `sqrMagnitude` |
| **도형 겹침 판정** | 두 도형이 겹치는지 묻는 수학적 부등식 | 원, AABB(`Rect`), 원 vs AABB |
| **격자 좌표 (Cell)** | 연속된 월드 좌표를 정수 칸 번호로 접은 것 | `Vector2Int`, `Mathf.FloorToInt`, `Grid` |

> **[원칙]**
> 1. **겹침 판정의 본체는 부등식 한 줄**입니다. 물리 엔진(`Collider2D`)은 이 수학 계산을 자동화해 주는 도구일 뿐입니다.
> 2. **단순 거리 비교에는 제곱근(`Sqrt`)을 쓰지 마세요.** `(b - a).sqrMagnitude <= r * r`로 양변을 제곱해 비교합니다.
> 3. **좌표계를 절대 섞지 마세요.** 월드 좌표, 스크린 좌표(픽셀), 뷰포트 좌표(`0~1`)를 변수 이름에 명시(`mouseScreenPos`, `clickWorldPos`)해 사고를 예방합니다.

## 3. 세부 개념 및 원리

### 3.1 Unity의 2D 좌표계 3총사 — 월드 · 스크린 · 뷰포트
같은 화면 위의 한 점이라도 어떤 좌표계로 읽느냐에 따라 숫자가 완전히 달라집니다.

| 좌표계 | 원점 `(0, 0)`과 단위 | 우상단 끝값 | 대표 사용처 |
| :--- | :--- | :--- | :--- |
| **World Space (월드)** | 씬 중심 `(0, 0)`, 게임 유닛(m) | 무한대 | `transform.position`, 게임 로직 전체 |
| **Screen Space (스크린)** | 화면 좌하단, 픽셀(px) | `(Screen.width, Screen.height)` | `Mouse.current.position`, 픽셀 UI |
| **Viewport Space (뷰포트)** | 화면 좌하단, 정규화 비율(`0~1`) | `(1, 1)` | 카메라 화면 안/밖 판정, 해상도 독립 배치 |

> **뷰포트 좌표가 편리한 이유**: 해상도가 `1920×1080`이든 `2560×1440`이든 화면 안쪽은 항상 `0 <= x <= 1 && 0 <= y <= 1`입니다. 적이 화면 안에 들어왔는지 검사할 때 해상도를 신경 쓸 필요가 없습니다.

### 3.2 두 점 사이의 거리 (피타고라스 정리)
두 점 $A(x_1, y_1)$과 $B(x_2, y_2)$ 사이의 거리는 직각삼각형의 빗변 공식에서 바로 나옵니다.

* **공식**: $\text{거리} = \sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2}$

```csharp
Vector2 pointA = new Vector2(1f, 1f);
Vector2 pointB = new Vector2(4f, 5f);

// 직접 계산: √((4 - 1)² + (5 - 1)²) = √(9 + 16) = 5
// float dx = pointB.x - pointA.x;
// float dy = pointB.y - pointA.y;
// float dist = Mathf.Sqrt(dx * dx + dy * dy);

// Unity 내장 Distance — 위 공식과 동일
float distance = Vector2.Distance(pointA, pointB); // 5f (3 : 4 : 5 직각삼각형으로 검산 가능)
```

### 3.3 실전 2D 도형 겹침 판정 5종 세트
게임에서 가장 많이 쓰이는 5가지 겹침 판정입니다. 단순 비교에는 모두 제곱근 없는 **`sqrMagnitude`** 를 사용합니다.

#### ① 점 vs 원 (Point vs Circle)
점과 중심 사이의 거리가 반지름 이하이면 원 안쪽입니다.
```csharp
bool IsPointInCircle(Vector2 point, Vector2 center, float radius)
{
    return (point - center).sqrMagnitude <= radius * radius;
}
```

#### ② 점 vs 축 정렬 사각형 (Point vs AABB)
회전하지 않은 사각형(Axis-Aligned Bounding Box)은 X 구간과 Y 구간을 따로 확인합니다.
```csharp
bool IsPointInAABB(Vector2 point, Vector2 min, Vector2 max)
{
    return point.x >= min.x && point.x <= max.x
        && point.y >= min.y && point.y <= max.y;
}

// Unity 내장 Rect: (x, y)는 중심이 아니라 '좌하단 모서리'임에 주의
Rect area = new Rect(0f, 0f, 100f, 50f);
bool inside = area.Contains(new Vector2(20f, 30f));

// 중심(center) 기준으로 Rect를 만들고 싶을 때:
Rect centeredRect = new Rect(center - size * 0.5f, size);
```

#### ③ 원 vs 원 (Circle vs Circle)
두 중심 사이의 거리가 두 반지름의 합 이하이면 겹칩니다. **회전에 영향을 받지 않아** 캐릭터·투사체·코인 판정에 가장 널리 쓰입니다.
```csharp
bool IsCircleOverlapping(Vector2 c1, float r1, Vector2 c2, float r2)
{
    float radiusSum = r1 + r2;
    return (c1 - c2).sqrMagnitude <= radiusSum * radiusSum;
}
```

#### ④ 사각형 vs 사각형 (AABB vs AABB)
두 사각형의 X 구간이 겹치고, 동시에 Y 구간도 겹치면 충돌입니다.
```csharp
bool IsAABBOverlapping(Rect a, Rect b)
{
    return a.xMin <= b.xMax && a.xMax >= b.xMin
        && a.yMin <= b.yMax && a.yMax >= b.yMin;
    // Unity 내장 함수: return a.Overlaps(b); (단, Overlaps는 경계선만 스친 경우 false)
}
```

#### ⑤ 원 vs 사각형 (Circle vs AABB) — 벽돌 깨기·장애물 충돌의 핵심!
사각형 위에서 **원의 중심과 가장 가까운 점**을 `Mathf.Clamp`로 찾아낸 뒤, 그 점과 원의 중심 거리를 비교합니다.
```csharp
bool IsCircleOverlappingAABB(Vector2 circleCenter, float radius, Rect rect)
{
    // 1. 사각형 내부(또는 테두리)에서 원의 중심과 가장 가까운 점을 구한다
    float closestX = Mathf.Clamp(circleCenter.x, rect.xMin, rect.xMax);
    float closestY = Mathf.Clamp(circleCenter.y, rect.yMin, rect.yMax);
    Vector2 closestPoint = new Vector2(closestX, closestY);

    // 2. 그 최단점과 원의 중심 거리가 반지름 이하이면 겹친다
    return (circleCenter - closestPoint).sqrMagnitude <= radius * radius;
}
```

### 3.4 격자 좌표 — 연속 좌표를 정수 칸 번호로 (`Vector2Int`)
타일맵·퍼즐·디펜스 배치처럼 칸으로 이루어진 세계에서는 연속된 월드 좌표 `(2.7, -0.4)`를 정수 칸 번호 `(2, -1)`로 접어 씁니다.

* **월드 ➔ 칸 번호**: $\text{Cell} = \lfloor (\text{World} - \text{Origin}) / \text{CellSize} \rfloor$
* **칸 번호 ➔ 칸 중심**: $\text{WorldCenter} = \text{Origin} + (\text{Cell} + 0.5) \times \text{CellSize}$

```csharp
using UnityEngine;

public class GridCoordinateHelper : MonoBehaviour
{
    [SerializeField] private Vector2 _gridOrigin = Vector2.zero; // 격자의 좌하단 시작점
    [SerializeField] private float _cellSize = 1f;               // 한 칸의 길이
    [SerializeField] private int _columns = 10;
    [SerializeField] private int _rows = 10;

    private void OnValidate()
    {
        if (_cellSize <= 0f) _cellSize = 0.1f; // 0 나누기 및 음수 크기 방어
    }

    public Vector2Int WorldToCell(Vector2 worldPos)
    {
        float safeSize = Mathf.Max(_cellSize, 0.0001f);
        Vector2 local = (worldPos - _gridOrigin) / safeSize;

        // 🚨 반드시 FloorToInt 사용! (int) 캐스팅은 -0.4f를 -1이 아닌 0으로 잘라버린다.
        return new Vector2Int(Mathf.FloorToInt(local.x), Mathf.FloorToInt(local.y));
    }

    public Vector2 CellToWorldCenter(Vector2Int cell)
    {
        // 칸 번호는 좌하단 모서리를 가리키므로, 반 칸(0.5)을 더해 중심 좌표를 얻는다
        return _gridOrigin + ((Vector2)cell + Vector2.one * 0.5f) * _cellSize;
    }

    public bool IsInsideGrid(Vector2Int cell)
    {
        return cell.x >= 0 && cell.x < _columns
            && cell.y >= 0 && cell.y < _rows;
    }
}
```
> **참고**: Unity의 `Grid` 컴포넌트도 동일한 공식을 `WorldToCell`, `GetCellCenterWorld` 메서드로 내장 제공합니다. 또한 격자에서는 이웃 칸 탐색이 `(1,0), (-1,0), (0,1), (0,-1)` 정수 덧셈만으로 끝나므로 거리 계산이 전혀 들지 않습니다.

### 3.5 스크립트에서 자주 쓰는 멤버 요약

```csharp
Camera cam = Camera.main; // Awake에서 1회 캐싱 필수

Vector2 a = new Vector2(3f, 4f);
Vector2 b = new Vector2(6f, 8f);
Vector2Int cell = new Vector2Int(2, -1); // 정수 칸 번호 / 배열 인덱스

float dist = Vector2.Distance(a, b);     // 실제 거리 (Sqrt 포함)
float sqr  = (b - a).sqrMagnitude;       // 거리의 제곱 (Sqrt 없음, 비교용)

// 좌표계 3총사 변환
Vector3 worldPos    = cam.ScreenToWorldPoint(mouseScreenPos);    // 스크린 -> 월드
Vector3 screenPos   = cam.WorldToScreenPoint(transform.position);// 월드 -> 스크린 (머리 위 UI)
Vector3 viewportPos = cam.WorldToViewportPoint(transform.position); // 월드 -> 뷰포트 (0~1)
```

## 4. 코드로 보기 (흔한 실수: `ScreenToWorldPoint`의 Z 함정)

### 잘못된 코드 (오브젝트가 화면에서 증발함)
```csharp
private void Update()
{
    if (Mouse.current != null && Mouse.current.leftButton.wasPressedThisFrame)
    {
        Vector2 mouseScreenPos = Mouse.current.position.ReadValue();

        // Input 마우스 좌표는 z = 0이므로, 직교 카메라(z = -10)에서는 world.z가 -10이 된다
        // 오브젝트가 카메라와 정확히 같은 z 평면에 놓여 클리핑(사라짐)된다.
        Vector3 clickWorldPos = Camera.main.ScreenToWorldPoint(mouseScreenPos);
        transform.position = clickWorldPos;
    }
}
```

### 수정된 코드 (카메라 캐싱 + Z 평면 정리)
```csharp
private Camera _mainCamera;

private void Awake() => _mainCamera = Camera.main;

private void Update()
{
    Mouse mouse = Mouse.current;
    if (mouse == null || _mainCamera == null) return;

    if (mouse.leftButton.wasPressedThisFrame)
    {
        Vector2 mouseScreenPos = mouse.position.ReadValue();

        // 원근 카메라에서도 안전하게 동작하도록 카메라~작업평면(z=0) 거리를 z로 넘긴다
        float depth = -_mainCamera.transform.position.z;
        Vector3 clickWorldPos = _mainCamera.ScreenToWorldPoint(
            new Vector3(mouseScreenPos.x, mouseScreenPos.y, depth));

        clickWorldPos.z = 0f; // 2D 작업 평면 z = 0 고정
        transform.position = clickWorldPos;
    }
}
```

## 5. 활용 예시 (게임 도메인)

### 시나리오: 마우스 클릭 지점의 원형 광역 스킬 (GC-Free 물리 질의 vs 직접 거리 판정)
마우스를 클릭한 월드 좌표에 반지름 `_skillRadius`의 광역 스킬을 터뜨립니다. 실무에서는 `FindGameObjectsWithTag` 전수 검사 대신, 미리 확보한 `List<Collider2D>` 버퍼와 `ContactFilter2D`를 사용해 **가비지(GC) 할당 없이** 범위 내 적을 뽑아냅니다.

```csharp
using System.Collections.Generic;
using UnityEngine;
using UnityEngine.InputSystem;

public class AreaSkill2D : MonoBehaviour
{
    [SerializeField] private float _skillRadius = 3f;
    [SerializeField] private int _skillDamage = 10;
    [SerializeField] private LayerMask _enemyLayer; // 적 레이어만 필터링

    private Camera _mainCamera;
    private ContactFilter2D _enemyFilter;
    private readonly List<Collider2D> _hitResults = new List<Collider2D>(32); // GC 없는 재사용 버퍼
    private Vector2 _lastCastWorldPos;

    private void Awake()
    {
        _mainCamera = Camera.main;

        _enemyFilter = new ContactFilter2D
        {
            useLayerMask = true,
            layerMask = _enemyLayer,
            useTriggers = true
        };
    }

    private void Update()
    {
        Mouse mouse = Mouse.current;
        if (mouse == null || _mainCamera == null) return;

        if (!mouse.leftButton.wasPressedThisFrame) return;

        // 1. 스크린 좌표 -> 2D 월드 좌표 변환 (Vector2로 받아 z 자동 제거)
        Vector2 mouseScreenPos = mouse.position.ReadValue();
        float depth = -_mainCamera.transform.position.z;
        _lastCastWorldPos = _mainCamera.ScreenToWorldPoint(
            new Vector3(mouseScreenPos.x, mouseScreenPos.y, depth));

        // 2. 가비지 할당 없이 범위 내 적 콜라이더만 수집 (내부 공간 분할 활용)
        _hitResults.Clear();
        int hitCount = Physics2D.OverlapCircle(_lastCastWorldPos, _skillRadius, _enemyFilter, _hitResults);

        for (int i = 0; i < hitCount; i++)
        {
            Debug.Log($"{_hitResults[i].name} 이(가) {_skillDamage} 피해를 입었습니다.");
            // 실무에서는 여기서 TryGetComponent(out IDamageable target) 호출
        }
    }

    // 마지막으로 시전한 스킬 범위를 씬 뷰에 시각화
    private void OnDrawGizmosSelected()
    {
        Gizmos.color = Color.cyan;
        Gizmos.DrawWireSphere(_lastCastWorldPos, _skillRadius);
    }
}
```
> **직접 수학 판정이 더 나은 경우**: 적이 10~20마리 이하로 적고 `EnemyManager`가 이미 `List<Enemy>`를 들고 있다면, 콜라이더 없이 `foreach`로 `(enemyPos - skillWorldPos).sqrMagnitude <= _skillRadius * _skillRadius`만 검사하는 편이 훨씬 가볍고 단순합니다.

## 6. 실전에서는?

### 6.1 직접 수학 계산 vs 물리 엔진 선택 기준
| 상황 | 권장 방식 | 이유 |
| :--- | :--- | :--- |
| **스킬 범위, 감지 반경, 소수 대상** | 직접 수학 (`sqrMagnitude`) | 부등식 한 줄로 끝나며 콜라이더/레이어 관리 비용이 없습니다 |
| **다수의 적 대상 원형/사각 탐색** | `Physics2D.OverlapCircle` (List 버퍼) | 엔진 내부 공간 분할을 활용해 $O(N^2)$를 피하고 GC도 0입니다 |
| **벽 막힘, 밀려남, 반발·마찰** | `Collider2D` + `Rigidbody2D` | 겹침 해소와 물리 반응은 엔진에 맡기는 것이 정석입니다 |
| **타일맵·퍼즐·그리드 배치** | 논리 격자 배열 (`map[x, y]`) | 거리 계산 없이 $O(1)$ 배열 인덱싱으로 즉시 조회합니다 |

### 6.2 성능의 벽: $O(N^2)$ 전수 검사를 피하는 3단계
1. **검사 주기 늘리기**: 적의 시야·감지 판정은 매 프레임 대신 `0.1초` 간격으로 검사해도 플레이어는 차이를 못 느낍니다.
2. **엔진 공간 분할 활용**: 대상이 수백 개를 넘어가면 전수 `for`문 대신 `Physics2D.OverlapCircle` 계열이나 공간 해시(Spatial Hash Grid)를 씁니다.
3. **격자 구조 활용**: 이미 격자 기반 게임이라면 `WorldToCell`로 내 주변 3×3 칸만 조회해 검사 횟수를 상수 시간으로 묶습니다.

### 6.3 UI와 마우스 영역 판정 주의
`Canvas`가 `Screen Space - Overlay`라면 스크린 좌표와 대략 맞지만, `Screen Space - Camera`나 `World Space`에서는 좌표가 어긋납니다. \
UI 영역 판정은 직접 `Rect`를 계산하지 말고 **`RectTransformUtility.ScreenPointToLocalPointInRectangle`** 을 쓰는 것이 안전합니다.

### 6.4 반지름은 아트가 아니라 기획 수치
탄막 슈팅에서 플레이어의 피격 판정(Hitbox)을 스프라이트보다 훨씬 작게 잡는 것처럼, 겉보기 그림과 판정 도형은 별개입니다. \
판정 반지름은 반드시 `[SerializeField]`로 노출하고 **`OnDrawGizmosSelected`** 로 씬 뷰에 그려 주어 기획자와 눈으로 보며 밸런스를 맞춰야 합니다.

> **해답**
> * 두 중심 사이의 거리가 `0.5f + 0.2f = 0.7f` 이하가 되는 순간 겹침으로 판정합니다.

>

### Q4. Q3의 판정을 `Vector2.Distance` 없이 제곱 거리(`sqrMagnitude`)로 최적화하고, 이 방식을 쓸 수 있는 경우와 쓸 수 없는 경우를 각각 설명하세요.
> **해답**
> * **최적화 코드**:
>   ```csharp
>   Vector2 diff = (Vector2)_coin.position - (Vector2)transform.position;
>   float radiusSum = _playerRadius + _coinRadius;
>
>   if (diff.sqrMagnitude <= radiusSum * radiusSum)
>   {
>       Debug.Log("코인 획득");
>       Destroy(_coin.gameObject);
>   }
>   ```
> * **쓸 수 있는 경우**: *"범위 안에 들어왔는가?"*, *"가장 가까운 적은 누구인가?"*처럼 **대소 비교(순서·범위 판정)** 만 필요할 때. 음수가 아닌 값에서는 제곱해도 대소 관계가 변하지 않습니다.
> * **쓸 수 없는 경우**: *"목표까지 남은 거리: 12.4m"* 처럼 **실제 거리 수치를 UI에 표시**하거나, 거리에 비례해 **폭발 피해량을 선형으로 감쇠**시키는 계산처럼 정확한 길이 값 자체가 필요할 때.

### Q5. 칸 크기 `1`, 원점 `(0, 0)`인 `10×10` 격자에서 마우스 클릭 위치의 칸 중심에 프리팹을 생성하세요. 격자 밖 클릭은 무시하며, 음수 좌표에서 `FloorToInt`와 `(int)` 캐스트의 차이를 적으세요.
> **해답**
> * **음수 좌표에서의 차이**: 예를 들어 월드 좌표 `(-0.3, 0.2)`를 클릭했을 때:
>   * `Mathf.FloorToInt(-0.3f)` = **`-1`** ➔ 격자 밖(음수 칸)으로 정확히 판정되어 무시됩니다.
>   * `(int)(-0.3f)` = **`0`** ➔ 소수점을 0 쪽으로 잘라버려, 격자 밖을 클릭했는데도 `(0, 0)` 칸에 잘못 생성되는 버그가 발생합니다!
>
> ```csharp
> using UnityEngine;
> using UnityEngine.InputSystem;
>
> public class GridClickSpawner : MonoBehaviour
> {
>     [SerializeField] private GameObject _tilePrefab;
>     [SerializeField] private Vector2 _gridOrigin = Vector2.zero;
>     [SerializeField] private float _cellSize = 1f;
>     [SerializeField] private int _columns = 10;
>     [SerializeField] private int _rows = 10;
>
>     private Camera _mainCamera;
>
>     private void Awake() => _mainCamera = Camera.main;
>
>     private void Update()
>     {
>         Mouse mouse = Mouse.current;
>         if (mouse == null || _mainCamera == null || _tilePrefab == null) return;
>         if (!mouse.leftButton.wasPressedThisFrame) return;
>
>         Vector2 mouseScreenPos = mouse.position.ReadValue();
>         float depth = -_mainCamera.transform.position.z;
>         Vector2 clickWorldPos = _mainCamera.ScreenToWorldPoint(
>             new Vector3(mouseScreenPos.x, mouseScreenPos.y, depth));
>
>         Vector2 local = (clickWorldPos - _gridOrigin) / Mathf.Max(_cellSize, 0.0001f);
>         Vector2Int cell = new Vector2Int(Mathf.FloorToInt(local.x), Mathf.FloorToInt(local.y));
>
>         // 격자 밖(음수 포함)이면 무시
>         if (cell.x < 0 || cell.x >= _columns || cell.y < 0 || cell.y >= _rows)
>             return;
>
>         // 칸 모서리가 아닌 중심(+0.5)에 프리팹 생성
>         Vector2 centerPos = _gridOrigin + ((Vector2)cell + Vector2.one * 0.5f) * _cellSize;
>         Instantiate(_tilePrefab, centerPos, Quaternion.identity);
>     }
> }
> ```

## 8. 주의사항 및 안전 습관

### 흔한 실수
* **좌표계 혼용**: 월드 좌표(`transform.position`)와 스크린 좌표(`mousePosition`)를 변환 없이 빼면 수백~수천 단위로 어긋납니다.
* **`ScreenToWorldPoint`의 `z` 방치**: 2D에서 `z`를 `0f`로 정리하지 않거나 `Vector2`로 받지 않으면, 오브젝트가 카메라와 같은 깊이에 놓여 화면에서 사라집니다.
* **`Rect`의 `(x, y)`를 중심으로 착각**: Unity `Rect(x, y, w, h)`의 `(x, y)`는 중심이 아니라 **좌하단 모서리**입니다.
* **회전하는 오브젝트에 AABB 억지 적용**: AABB는 축에 고정되어 있어 회전 시 빈 공간이 커집니다. 회전이 필요하면 원(Circle) 근사나 `Collider2D`(OBB/SAT)를 씁니다.
* **격자 변환에 `(int)` 캐스팅 사용**: 음수 좌표에서 0 쪽으로 잘려 원점 주변 두 칸이 겹칩니다. 무조건 `Mathf.FloorToInt`를 쓰세요.
* **칸 중심 `+ 0.5f` 누락**: 칸 번호는 모서리를 가리킵니다. 스프라이트를 배치할 때 반 칸을 안 더하면 맵 전체가 반 칸씩 밀립니다.

### 안전 습관
* **단순 거리 비교는 `sqrMagnitude` + `r * r`**: 제곱근 호출을 습관적으로 제거하세요.
* **변수 이름에 좌표계를 못 박기**: `mouseScreenPos`, `clickWorldPos`, `enemyViewportPos`처럼 접미사를 붙이면 좌표 혼용 버그가 코드 리뷰에서 바로 잡힙니다.
* **판정 도형은 기즈모로 눈으로 확인**: `[SerializeField]`로 반지름·크기를 노출하고 `OnDrawGizmosSelected`로 그려 두세요.
* **검산 가능한 숫자로 테스트**: `(3, 4)` 떨어진 두 점의 거리가 `5`인지, 음수 `(-0.3, -0.3)`의 칸 번호가 `(-1, -1)`인지 손으로 아는 값을 먼저 넣어 확인합니다.
