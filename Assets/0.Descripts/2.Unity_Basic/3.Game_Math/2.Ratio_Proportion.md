# [Game Math] 2. 비율과 비례 (Ratio and Proportion)

## 1. 비, 비례, 비율 이란?
> **케이크 레시피**
> * 케이크 레시피에 '밀가루 2컵, 설탕 1컵'이라고 적혀 있습니다. '밀가루와 설탕이 2 대 1'이라는 이 관계가 **비(Ratio)** 입니다.
> * 더 큰 케이크를 만들려고 밀가루를 4컵 쓰면 설탕은 2컵이 되어야 맛이 유지됩니다. 전체 양이 변해도 이 관계를 그대로 지키는 것, 이것이 **비례(Proportion)** 입니다.
> * 그리고 '설탕은 전체 3컵 중 1컵, 즉 0.33(33%)'처럼 전체 대비 부분의 크기로 바꿔 적은 값이 **비율(Rate)** 입니다.

세 낱말을 한 줄로 갈라 두면 뒤가 헷갈리지 않습니다.
1. **비 (Ratio)** : 두 수량 사이의 관계 ➔ (예: 모니터 화면비 16:9)
2. **비례 (Proportion)** : 그 관계를 유지한 채 크기만 바꾸는 것 ➔ (예: 16:9 비율을 지키며 창고 크기 키우기)
3. **비율 (Rate/Percentage)** : 전체에 대한 부분의 크기 ➔ (예: 체력 100 중 80이면 0.8)

**왜 필요한가? (만능 번역기)**\
게임 속 값들의 범위는 제각각입니다. 슬라임의 최대 체력은 30이고 보스는 5000이며, 월드 맵 크기는 1000유닛입니다. 이 값들을 UI나 다른 시스템에 쌩으로 넘기면 체력 바가 화면 밖으로 뚫고 나가거나 미니맵 아이콘이 우주로 날아갑니다.

이때 **'비율(0.0 ~ 1.0)'** 은 서로 다른 범위의 숫자들을 하나로 통일시키는 완벽한 통역사 역할을 합니다. \
실제 값이 30이든 5000이든 일단 0.0 ~ 1.0 사이의 값으로 **접어 두면(정규화, Normalize)** 그 뒤로는 체력 바(`fillAmount`), 로딩 진행률, 미니맵 좌표, 앵커(Anchor) 등 게임 내 상대적 값이 필요한 모든 곳에 동일한 방식으로 꽂아 넣을 수 있습니다.

## 2. 핵심 요약

| 개념 | 한 줄 정의 | 유니티 대표 활용 |
| :--- | :--- | :--- |
| **비 (Ratio)** | 두 수량 사이의 고정된 관계 | 화면비 (Aspect Ratio), 16:9 |
| **비례 (Proportion)**| 관계를 유지한 채 크기를 변환 | UI `RectTransform` 앵커(Anchor) 시스템 |
| **비율 (Rate)** | 전체에 대한 부분의 진행 정도 | 현재 체력 / 최대 체력 ➔ 0.8 (80%) |
| **정규화 (Normalize)**| 제각각인 임의 범위를 0.0 ~ 1.0으로 쫙 **접는** 것 | `Mathf.InverseLerp(최소, 최대, 현재값)` |
| **역변환 (Lerp)** | 0.0 ~ 1.0의 비율을 내가 원하는 실제 목표 범위로 다시 **펼치는** 것 | `Mathf.Lerp(최소, 최대, 비율)` |

> **[비율 계산 원칙]**\
> 비율(나눗셈)을 만들 때는 다음 3가지 방어막을 한 세트로 묶어야 시스템이 터지지 않습니다.
> 1. **정수 나눗셈 방지**: `int / int`는 소수점을 버리므로, 둘 중 하나를 무조건 `(float)`으로 캐스팅
> 2. **0 나누기(Divide by Zero) 방지**: 분모(최대값)가 0이 아닌지 반드시 `if`문이나 삼항 연산자로 확인
> 3. **범위 이탈 방지**: 결과값을 `Mathf.Clamp01()`로 감싸서 0~1 범위를 강제로 사수

## 3. 세부 개념 및 원리

### 3.1 비율의 마법: 미니맵 좌표 변환
월드가 가로 1000 · 세로 1000 유닛이고, 화면 구석의 미니맵 UI는 200 × 200 픽셀입니다. 플레이어가 월드 좌표 (X:800, Z:300) 에 있을 때 미니맵 UI의 어느 위치에 내 얼굴(점)을 찍어야 할까요?

1. **월드를 비율로 접기 (정규화)**: X축 비율 = 800 / 1000 = 0.8 (80%), Z축 비율 = 300 / 1000 = 0.3 (30%)
2. **비율을 미니맵으로 펼치기 (역변환)**: X 좌표 = 200 * 0.8 = 160, Y 좌표 = 200 * 0.3 = 60
3. **결과**: 미니맵 UI 상의 좌표 (160, 60) 위치에 점을 찍으면 완벽하게 일치합니다!

월드(3D 공간)와 미니맵(2D 픽셀)이라는 전혀 다른 두 세계를 이어주는 다리가 오직 **'비율(0~1)'** 하나라는 점이 이 마법의 핵심입니다.

### 3.2 비례식과 유니티 UI 앵커(Anchor)
버튼 너비가 모니터 크기와 상관없이 항상 "화면 너비의 20%"가 되게 만들고 싶다면?
* 버튼 너비 : 화면 너비 = 1 : 5 ➔ 버튼 너비 = 화면 너비 / 5

Unity UI의 `RectTransform` 앵커(`Anchor Min`, `Max`)가 완벽하게 이 비례 원리로 동작합니다. 앵커 값은 픽셀(절대값)이 아니라 부모 크기에 대한 **비율(0~1)** 이므로, 부모 창(해상도)이 커지거나 작아져도 자식 버튼은 그 비율을 완벽하게 유지하며 늘어납니다.

### 3.3 유니티 기능 속에 이미 숨어있는 비율들
우리가 흔히 쓰는 유니티 기능 상당수는 이미 0~1 비율(정규화된 값)을 받는 입구로 설계되어 있습니다.

```csharp
// 아래 값들은 모두 '0.0 ~ 1.0' 사이의 비율 값을 요구합니다
image.fillAmount = 0.5f;             // 이미지 절반 채우기
slider.normalizedValue = 0.5f;       // 슬라이더 핸들을 정중앙에 놓기 (value와 다름)
Mathf.Lerp(a, b, 0.5f);              // a와 b의 정확히 50% 중간 지점 찾기
animationCurve.Evaluate(0.5f);       // 0~1초 커브 그래프의 정중앙 값 가져오기
```

## 4. 코드로 보기 (비율 3단계 변환)

비율 계산은 "접고 ➔ 펼친다"라는 완벽한 2단계 파이프라인으로 구성됩니다. 이 2단계를 함수(`Remap`)까지 알아봅니다.

### 4.1 1단계: 값 ➔ 비율로 쫙 접기 (정규화, `InverseLerp`)
```csharp
// 하드코딩 방식: 공식 = (현재값 - 최소값) / (최대값 - 최소값)
// float ratio = (current - min) / (max - min);

// 유니티 내장 함수: 범위를 벗어난 값(초과 회복 등)이 들어와도 알아서 0~1로 잘라(Clamp) 줍니다
float ratio = Mathf.InverseLerp(min, max, current); 
```

### 4.2 2단계: 비율 ➔ 원하는 새 범위로 펼치기 (역변환, `Lerp`)
```csharp
// 하드코딩 방식: 공식 = 시작값 + (끝값 - 시작값) * 비율
// float needleAngle = 0f + (180f - 0f) * ratio;

// 유니티 내장 함수
float needleAngle = Mathf.Lerp(0f, 180f, ratio); 
```

### 4.3 맵핑(`Remap`) 유틸리티 함수 만들기
"접고 펼치는" 2단계를 한 줄의 C# 확장 메서드(Extension Method)로 묶어두면 프로젝트 내내 두고두고 편하게 써먹을 수 있습니다.

```csharp
public static class MathExtensions 
{
    // 어떤 값(value)을 from1~to1 범위에서 from2~to2 범위로 비율을 유지한 채 변환해줍니다
    public static float Remap(this float value, float from1, float to1, float from2, float to2) 
    {
        // 1. 기존 범위(from1~to1)에서 비율(0~1)로 접기
        float ratio = Mathf.InverseLerp(from1, to1, value);
        
        // 2. 새 범위(from2~to2)로 펼치기
        return Mathf.Lerp(from2, to2, ratio);
    }
}

// 실전 사용법: 현재 내 체력(75)이 0~150 사이일 때, 이 비율을 UI 너비(0~300 픽셀)로 맵핑해라
// float uiWidth = currentHealth.Remap(0f, 150f, 0f, 300f); ➔ 결과: 150f
```

## 5. 실전 활용 예시: 비동기 씬 로딩 화면 구현

씬 로딩 API가 던져주는 값의 범위(0~0.9)와 UI 슬라이더가 원하는 값의 범위(0~1.0)가 다를 때, 이 둘을 이어주는 비율 정규화 코드입니다.

```csharp
using System.Collections;
using UnityEngine;
using UnityEngine.SceneManagement;
using UnityEngine.UI;

public class LoadingProgress : MonoBehaviour
{
    [SerializeField] private Slider _loadingSlider;
    [SerializeField] private float _minShowSeconds = 1f; // 로딩창 최소 유지 시간

    public void LoadScene(string sceneName) => StartCoroutine(LoadSceneRoutine(sceneName));

    private IEnumerator LoadSceneRoutine(string sceneName)
    {
        AsyncOperation op = SceneManager.LoadSceneAsync(sceneName);

        // 우리가 허락할 때까지 씬 활성화를 막는다 (progress가 0.9에서 더 이상 안 오르고 멈춤)
        op.allowSceneActivation = false;

        float elapsed = 0f;

        // 로딩이 0.9(완료 대기)에 도달 안 했거나, 최소 유지 시간(1초)이 안 지났다면 계속 반복
        while (op.progress < 0.9f || elapsed < _minShowSeconds)
        {
            elapsed += Time.deltaTime;

            // 0.0 ~ 0.9 사이에서 노는 progress 값을, 강제로 0.0 ~ 1.0(UI용) 범위로 쫙 접어준다
            _loadingSlider.normalizedValue = Mathf.InverseLerp(0f, 0.9f, op.progress);

            yield return null;
        }

        // 반복문 종료 = 로딩 데이터 다 읽었고, 1초도 지났음
        _loadingSlider.normalizedValue = 1f; // 바를 100% 가득 채움
        op.allowSceneActivation = true; // 잠금 해제 (씬 전환)
    }
}
```

## 6. Unity 최적화 팁

### 6.1 에러 발생: 정수 나눗셈과 0 나누기 방어
비율을 계산할 때 초보자들이 99.9% 밟는 2가지 지뢰입니다.

```csharp
int currentHp = 80;
int maxHp = 100;

// 대참사 1: int끼리 나누면 소수점을 버리므로 무조건 0이 나옵니다 (체력바 항상 비어있음)
float ratio = currentHp / maxHp; 

// 대참사 2: 만약 몬스터가 죽어서 maxHp가 0이 되었다면? DivideByZero 에러로 UI 전체가 터짐
float progress = score / target;

// 정석 코드
// 1. (float)으로 하나를 캐스팅해서 실수 연산으로 만듦
// 2. 최대값(max)이 0 초과인지 반드시 확인 (삼항 연산자)
// 3. 초과 회복으로 값이 1(100%)을 넘지 않게 Clamp01로 가둠
float safeRatio = maxHp > 0 ? Mathf.Clamp01((float)currentHp / maxHp) : 0f;
```
이 3중 방어막(float 캐스팅, 0 체크, Clamp01) 코드를 습관처럼 한 세트로 묶어서 짜야 합니다.

### 6.2 데이터 설계: 비율을 열쇠(Key)로 쓰는 지층 시스템
비율은 UI 그리기에서 안 끝납니다. 어떤 값을 0~1로 접어두면 기획 데이터를 맵핑하기 엄청나게 쉬워집니다.

* **(요구사항)**: 무한히 깊어지는 광산 게임에서, 맵 깊이에 따라 나오는 광물을 다르게 해주세요
* **(하드코딩)**: `if (depth < 500m) 흙; else if (depth < 1500m) 돌;` ➔ 나중에 최대 깊이가 10000m로 밸런스 패치되면 코드를 다 뜯어고쳐야 합니다.
* **(비율 활용)**: 현재 깊이를 무조건 비율(0~1)로 변환한 뒤, 기획자에게 `0.0~0.2 구간은 흙, 0.2~0.6 구간은 돌` 표(테이블)를 작성하게 만듭니다. 맵 전체 크기가 아무리 바뀌어도 코드는 단 한 줄도 수정할 필요가 없습니다. (크기와 규칙의 완벽한 분리)

### 6.3 정규화 지점을 한 곳으로 모아 캡슐화하기
체력 게이지를 그리는 수많은 UI 스크립트마다 나눗셈과 3중 방어 코드를 흩뿌려놓으면 관리 지옥이 열립니다. 데이터 원본(`Health` 클래스) 쪽에서 아예 비율 값을 안전하게 말아서 프로퍼티로 던져주세요.

```csharp
public class Health : MonoBehaviour
{
    [SerializeField] private float _max = 100f;
    private float _current = 75f;

    // 비율 계산 방어 로직을 이 한 줄(프로퍼티)로 모조리 캡슐화
    // 외부 UI 스크립트들은 골치 아프게 계산할 필요 없이 이 속성만 달달 가져다 쓰면 끝
    public float Ratio => _max > 0f ? Mathf.Clamp01(_current / _max) : 0f;
}
```

## 7. 실습 문제 및 복습

**Q1. `int currentExp = 300;` 이고 `int maxExp = 500;` 입니다. UI 경험치 바를 채우기 위해 `float fill = currentExp / maxExp;` 라고 코드를 짰는데, 경험치 바가 텅 비어서 차오르지 않습니다. 이유가 무엇인가요?**
> C#에서 정수(`int`)끼리의 나눗셈은 소수점 이하를 반올림 없이 무조건 쳐내버립니다(Truncate). \
> 따라서 300 / 500은 0.6이 아니라 `0`이 반환되고, 뒤늦게 그걸 `float` 변수에 담아봤자 이미 소수점은 잘려 나간 뒤라 무조건 0.0f가 됩니다. \
> 해결하려면 `(float)currentExp / maxExp;` 처럼 연산자 중 하나를 명시적으로 실수 형변환(Casting) 해주어야 합니다.

**Q2. 슬라이더(Slider) UI 컴포넌트에는 현재 값을 설정하는 두 가지 프로퍼티인 `value`와 `normalizedValue`가 있습니다. 인스펙터에 슬라이더의 Min/Max 값이 0 ~ 200 으로 설정되어 있을 때, 핸들을 슬라이더 정중앙(50%)에 위치시키려면 각각의 프로퍼티에 어떤 숫자를 대입해야 하나요?**
> `slider.value`를 사용한다면 현재 Min/Max 범위 내의 실제 절대값을 넣어야 하므로 **100**을 대입해야 정중앙에 옵니다. \
> 반면 `slider.normalizedValue`를 사용한다면 Min/Max 범위와 전혀 상관없이 무조건 0~1 사이의 비율 값을 꽂아 넣어야 하므로 **0.5f**를 대입해야 정중앙에 옵니다.

**Q3. 유니티 UI에서 버튼의 `Anchor Min`을 `(0.2, 0)`으로, `Anchor Max`를 `(0.4, 1)`로 설정했습니다. 이 버튼은 부모 창(Canvas)이 이리저리 늘어나거나 줄어들 때 어떻게 반응하여 크기와 위치를 잡게 되나요? (비례와 비율 관점에서)**
> 앵커(Anchor) 값은 부모 패널의 가로/세로 길이를 1(100%)로 보았을 때의 '비율' 위치입니다. \
> 따라서 이 버튼은 해상도나 부모 창 크기가 어떻게 변하든 상관없이, 무조건 **부모 창 가로폭의 20% 지점부터 40% 지점 사이의 공간(가로 폭 20%)을 꽉 채우며**, 세로로는 **부모 창 높이 0% 바닥부터 100% 천장까지 꽉 채우는(Stretch) 비례 형태**로 유연하게 늘어나고 줄어듭니다.

## 8. 주의사항 및 안전 습관

* **API가 주는 값의 최대 범위를 맹신하지 마세요**: 유니티 씬 로딩의 `progress` 값은 0~1이 아니라 0~0.9에서 멈추고, `AudioSource.volume`은 0~1이지만 실제 사람 귀에 들리는 데시벨 스케일과 달라서 그냥 `Lerp`를 먹이면 소리가 이상하게 줄어듭니다. 외부 API에서 던져주는 숫자의 '실제 최대/최소 범위'를 도큐먼트에서 무조건 확인한 뒤에 정규화(`InverseLerp`)를 시작하세요.
* **비율 변수 이름에 힌트를 남기세요**: 아무 변수나 `float hp`로 적지 마세요. 0~1 사이의 비율을 담은 변수는 무조건 **`hpRatio`, `progressNormalized`** 처럼 뒤에 꼬리표를 붙이는 네이밍 컨벤션을 지켜야 다른 팀원이 실수로 절대값을 더하거나 빼는 대참사를 막을 수 있습니다.
* **과다 회복 시 UI 뚫림 주의**: 체력이나 마나가 버프로 인해 최대치(Max)를 초과 회복했을 때, 나눗셈 결과 비율이 1.2, 1.5처럼 1(100%)을 넘어가 버리게 됩니다. 이를 `Image.fillAmount`가 아닌 특정 오브젝트의 크기 조절(`Scale`)이나 각도 회전(`EulerAngles`)에 비율로 사용하게 되면 UI가 박스 밖으로 미친 듯이 뚫고 나가는 버그가 납니다. 비율 역변환 계산 전에는 무조건 `Mathf.Clamp01()`로 비율을 0~1 사이에 가둬버리는 습관을 들이세요.
