# [Game Math] 8. 공간 좌표계 (Spatial Coordinate Systems)

## 1. 공간 좌표계란?
게임에서 어떤 점의 위치나 방향을 숫자로 표현할 때, **누구의 관점(기준점과 축)에서 바라보는지**에 따라 같은 점도 완전히 다른 좌표로 표현됩니다. \
게임 엔진 안에는 여러 좌표계가 동시에 공존하며, 상황에 맞게 좌표계를 변환하는 것이 게임 수학의 핵심입니다.

> **좌표계는 '지도의 종류'입니다.**
> * **세계 지도 (World Space):** 씬 전체 기준의 절대 좌표
> * **국가/건물 내부 지도 (Local / Object Space):** 부모 또는 자기 자신 기준의 상대 좌표
> * **카메라 파인더 격자 (Viewport Space):** 화면을 `0~1` 비율로 나눈 좌표
> * **모니터 픽셀 지도 (Screen Space):** 실제 화면 해상도 픽셀 좌표

### Unity의 좌표축 규칙: 왼손 좌표계 (Y-Up)
Unity는 **왼손 좌표계(Left-Handed Coordinate System)** 를 사용합니다.
* **`+X` (빨강, Right):** 오른쪽
* **`+Y` (초록, Up):** 위쪽
* **`+Z` (파랑, Forward):** 앞쪽 (화면 안쪽 방향)

## 2. 핵심 요약

| 좌표계 | 원점 및 기준 | 대표 Unity API |
| :--- | :--- | :--- |
| **World Space** | 씬 전체의 절대 원점 `(0, 0, 0)` | `transform.position`, `transform.rotation` |
| **Local Space** | 부모 오브젝트 기준 상대 좌표 (부모 없으면 World와 동일) | `transform.localPosition`, `transform.localRotation`, `transform.localScale` |
| **Object (Self) Space** | 오브젝트 자기 자신의 피벗과 로컬 축 기준 | `Space.Self`, `transform.TransformPoint()` |
| **Viewport Space** | 카메라 화면 비율 좌하단 `(0, 0)` ~ 우상단 `(1, 1)` | `cam.WorldToViewportPoint()` |
| **Screen Space** | 화면 픽셀 좌하단 `(0, 0)` ~ 우상단 `(pixelWidth, pixelHeight)` | `cam.WorldToScreenPoint()`, `Mouse.current.position` / `Input.mousePosition` |

> **헷갈리기 쉬운 포인트:** `transform.forward`, `transform.right`, `transform.up`은 오브젝트의 로컬 Z/X/Y 축이 **World 공간에서 어느 방향을 가리키는지** 반환하는 **World 기준 단위 벡터**입니다.

# 3. 세부 개념

### 3.1 World vs Local — 부모-자식 계층과 TRS 변환
```text
Scene Root
└── Car (World Position = (10, 0, 5), Rotation = (0, 0, 0), Scale = (1, 1, 1))
    └── SteeringWheel (Local Position = (0, 1, 0.5))  ← Car 기준 상대 좌표
```
* Car의 회전이 `(0, 0, 0)`, 스케일이 `(1, 1, 1)`일 때만 `SteeringWheel`의 월드 좌표가 단순 덧셈인 `(10, 1, 5.5)`가 됩니다.
* Car가 Y축으로 90° 회전하면 운전대의 `localPosition`은 `(0, 1, 0.5)`로 유지되지만, 실제 **World 좌표는 부모의 이동·회전·스케일(TRS) 행렬이 적용되어 `(10.5, 1, 5)`로 바뀝니다.**
* `transform.lossyScale`: 부모들의 스케일이 누적된 대략적인 월드 스케일(읽기 전용). 부모에 비균일 스케일(예: `(2, 1, 1)`)이 있으면 회전한 자식이 찌그러지므로(Shear) 가급적 부모 스케일은 `(1, 1, 1)`을 유지합니다.

### 3.2 Local ↔ World 변환 3총사 (`Transform` 메서드)
게임 로직에서 가장 자주 쓰는 변환 메서드입니다. **위치냐 방향이냐**에 따라 반드시 구분해 사용합니다.

| 메서드 (역변환: `Inverse...`) | 위치(T) | 회전(R) | 스케일(S) | 대표 활용처 |
| :--- | :---: | :---: | :---: | :--- |
| **`TransformPoint(v)`** | O | O | O | 총구 오프셋, 캐릭터 기준 앞 2m 스폰 위치 계산 |
| **`TransformDirection(v)`** | X | O | X | 로컬 이동 벡터를 월드 방향으로 변환 (크기 유지) |
| **`TransformVector(v)`** | X | O | O | 스케일이 반영된 변위·속도 벡터 변환 |

```csharp
// 캐릭터 로컬 기준 "앞으로 2m, 위로 1m" 지점의 월드 좌표
Vector3 spawnWorldPos = transform.TransformPoint(new Vector3(0f, 1f, 2f));

// 월드 좌표의 적이 "내 기준 앞/뒤(z), 좌/우(x) 어디에 있는가?" 한 줄 판정
Vector3 enemyLocalPos = transform.InverseTransformPoint(enemy.position);
bool isEnemyInFront = enemyLocalPos.z > 0f;
bool isEnemyOnRight = enemyLocalPos.x > 0f;
```

### 3.3 Screen 좌표 & Viewport 좌표
* **Screen Space (픽셀):** 좌하단 `(0, 0)`, 우상단 `(cam.pixelWidth, cam.pixelHeight)`. `Z` 값은 카메라 전방으로부터의 월드 거리(미터).
* **Viewport Space (비율):** 해상도와 무관하게 좌하단 `(0, 0)`, 정중앙 `(0.5, 0.5)`, 우상단 `(1, 1)`. 화면 안/밖 판정 및 멀티 카메라 분할 화면(`Camera.rect`)에 필수적입니다.

### 3.4 Camera 기반 World ↔ Screen / Viewport 변환
```csharp
Vector3 screenPos = cam.WorldToScreenPoint(worldPos);    // World -> Screen 픽셀 (z = 카메라 거리)
Vector3 worldPos1 = cam.ScreenToWorldPoint(screenWithZ); // Screen -> World (z에 카메라 거리 필수)
Vector3 viewPos   = cam.WorldToViewportPoint(worldPos);  // World -> Viewport 비율 (0~1)
Vector3 worldPos2 = cam.ViewportToWorldPoint(viewWithZ); // Viewport -> World (z 필수)
Ray ray           = cam.ScreenPointToRay(screenPos);     // Screen 지점에서 World로 쏘는 광선
```

## 4. 코드로 보기

### 4.1 마우스 클릭 위치로 캐릭터 이동 (Raycast 활용)
> *Legacy Input(`Input.mousePosition`)과 New Input System(`Mouse.current.position.ReadValue()`) 모두 동일한 Screen 픽셀 좌표를 반환합니다.*

```csharp
using UnityEngine;
// New Input System 사용 시: using UnityEngine.InputSystem;

public class ClickToMove : MonoBehaviour
{
    [SerializeField] private Camera mainCam;
    [SerializeField] private LayerMask groundLayer;
    [SerializeField] private float maxRayDistance = 100f;

    private void Awake()
    {
        if (mainCam == null) mainCam = Camera.main;
    }

    private void Update()
    {
        // New Input System: if (Mouse.current != null && Mouse.current.leftButton.wasPressedThisFrame)
        if (Input.GetMouseButtonDown(0))
        {
            // New Input System: Vector2 mousePos = Mouse.current.position.ReadValue();
            Vector3 mousePos = Input.mousePosition;

            // Screen 좌표 -> World 공간 광선(Ray) 변환
            Ray ray = mainCam.ScreenPointToRay(mousePos);

            if (Physics.Raycast(ray, out RaycastHit hit, maxRayDistance, groundLayer))
            {
                transform.position = hit.point; // World 좌표 히트 지점으로 이동
            }
        }
    }
}
```

### 4.2 잘못된 코드 vs 안전한 코드 (Before / After)

```csharp
// [Before] 실수 4가지

// 실수 1: 자식 오브젝트에 World position 직접 대입 -> 씬 원점 근처로 워프
steeringWheel.transform.position = new Vector3(0f, 1f, 0.5f);

// 실수 2: ScreenToWorldPoint에 z = 0 그대로 전달
// - 3D Perspective 카메라: 항상 카메라 자신의 위치(cam.transform.position) 반환
// - 2D Orthographic 카메라: XY는 맞지만 Z가 카메라 평면(-10)에 놓여 화면에 안 보임
Vector3 wrongWorld = mainCam.ScreenToWorldPoint(Input.mousePosition);

// 실수 3: Translate(기본 Space.Self)에 World 방향(transform.forward)을 넣어 이중 회전 버그
transform.Translate(transform.forward * (speed * Time.deltaTime));

// 실수 4: position += 에 World 축(Vector3.forward)을 더해 자기 정면이 아닌 월드 Z로 이동
transform.position += Vector3.forward * (speed * Time.deltaTime);
```

```csharp
// [After] 버그 없는 표준 패턴

// 1) 부모 기준 부착은 localPosition 사용
steeringWheel.transform.SetParent(car.transform, worldPositionStays: false);
steeringWheel.transform.localPosition = new Vector3(0f, 1f, 0.5f);

// 2) ScreenToWorldPoint는 카메라로부터의 거리(Z) 명시
//    (3D는 원하는 거리 또는 카메라~대상 평면 거리, 2D는 -mainCam.transform.position.z)
Vector3 screenPos = Input.mousePosition;
screenPos.z = 10f;
Vector3 targetWorldPos = mainCam.ScreenToWorldPoint(screenPos);

// 3) 자기 정면 이동 — 아래 세 가지는 모두 동일하게 '자기 정면'으로 이동 (1번 권장)
transform.position += transform.forward * (speed * Time.deltaTime);                  // 가장 명확
transform.Translate(Vector3.forward * (speed * Time.deltaTime), Space.Self);         // 로컬 +Z
transform.Translate(transform.forward * (speed * Time.deltaTime), Space.World);      // 월드 방향
```

## 5. 활용 예시 (게임 도메인: 해상도·Canvas 모드 무관 Screen Space 체력바)
> 적 머리 위의 World 좌표를 **Screen Space UI**로 변환해 추적합니다.\
> *(중복 투영 제거, 카메라 등 뒤 판정, `LateUpdate` 떨림 방지, `RectTransformUtility` 대응)*

```csharp
using UnityEngine;

public class EnemyHealthBarUI : MonoBehaviour
{
    [SerializeField] private Transform enemy;
    [SerializeField] private Camera mainCam;
    [SerializeField] private Canvas parentCanvas;
    [SerializeField] private RectTransform healthBarRect;
    [SerializeField] private Vector3 worldOffset = new Vector3(0f, 2f, 0f);

    private RectTransform _canvasRect;
    private Camera _uiCam;

    private void Awake()
    {
        if (mainCam == null) mainCam = Camera.main;
        if (parentCanvas != null)
        {
            _canvasRect = parentCanvas.GetComponent<RectTransform>();
            // Screen Space - Overlay 모드에서는 UI 카메라로 null을 전달해야 함
            _uiCam = parentCanvas.renderMode == RenderMode.ScreenSpaceOverlay
                ? null
                : parentCanvas.worldCamera;
        }
    }

    // 캐릭터·카메라 이동(Update)이 모두 끝난 뒤 UI 좌표를 갱신해 떨림 방지
    private void LateUpdate()
    {
        if (enemy == null || mainCam == null || healthBarRect == null) return;

        Vector3 worldPos = enemy.position + worldOffset;

        // 1) 투영 변환은 1회만 수행 (World -> Viewport)
        Vector3 vp = mainCam.WorldToViewportPoint(worldPos);

        // 2) 카메라 앞(z > 0)이면서 화면(0~1) 안에 있는지 검사
        bool isVisible = vp.z > 0f
                      && vp.x >= 0f && vp.x <= 1f
                      && vp.y >= 0f && vp.y <= 1f;

        if (healthBarRect.gameObject.activeSelf != isVisible)
            healthBarRect.gameObject.SetActive(isVisible);

        if (!isVisible) return;

        // 3) Viewport -> Screen 픽셀 환산 (중복 WorldToScreenPoint 호출 생략)
        Vector2 screenPoint = new Vector2(vp.x * mainCam.pixelWidth, vp.y * mainCam.pixelHeight);

        // 4) Canvas 렌더 모드(Overlay / Camera)와 CanvasScaler에 상관없이 정확한 로컬 UI 좌표 계산
        if (_canvasRect != null &&
            RectTransformUtility.ScreenPointToLocalPointInRectangle(
                _canvasRect, screenPoint, _uiCam, out Vector2 localPoint))
        {
            healthBarRect.anchoredPosition = localPoint;
        }
    }
}
```

## 6. 실전에서는?

### 월드 오브젝트에 UI를 붙이는 두 가지 방식
| 방식 | 구현 방법 | 유리한 상황 |
| :--- | :--- | :--- |
| **Screen Space UI + 좌표 변환** | `LateUpdate`에서 `WorldToViewportPoint` + `RectTransformUtility`로 갱신 | 거리가 멀어져도 글자·체력바 크기가 일정하게 읽혀야 할 때 (HP바, 닉네임, 데미지 팝업) |
| **World Space Canvas** | `Canvas`를 대상의 자식으로 배치 | 게임 세계 안의 간판, 홀로그램, VR UI처럼 원근감과 가림이 자연스러워야 할 때 |

> **판단 한 줄:** *"멀어지면 작아져야 하는가?"* → 작아져야 하면 **World Space**, 언제나 선명하게 읽혀야 하면 **Screen Space**.

### 반드시 챙겨야 할 체크리스트
1. **카메라 뒤(`z <= 0`) 검사 필수:** `WorldToScreenPoint` / `WorldToViewportPoint`는 카메라 등 뒤에 있는 오브젝트도 화면 좌표를 반환합니다. `z > 0f`를 확인하지 않으면 등 뒤 적의 UI가 화면에 뒤집혀 나타납니다.
2. **UI 추적은 반드시 `LateUpdate()`:** 카메라와 캐릭터가 `Update()`에서 이동한 뒤 좌표를 변환해야 1프레임 밀림(떨림) 현상이 사라집니다.
3. **`SetParent(parent, worldPositionStays)` 올바르게 고르기:**
    * **`true` (기본값):** 현재 눈으로 보이는 월드/화면 위치를 그대로 유지한 채 부모만 교체할 때 (예: 바닥의 무기를 손에 쥐기, 드래그 중인 UI 아이콘을 최상위 레이어로 옮기기).
    * **`false`:** 부모의 로컬 좌표·회전·스케일 기준으로 맞추고 싶을 때 (예: **UGUI 프리팹을 `Canvas`나 `LayoutGroup` 자식으로 생성할 때** — `true`로 두면 `CanvasScaler` 배율 때문에 스케일이 틀어짐).
4. **대량 객체 변환 최적화:** 수백 마리의 몬스터가 있다면 화면 밖 대상을 먼저 컬링(`Renderer.isVisible` 또는 거리·프러스텀 체크)하고, 화면에 보이는 대상만 UI를 풀링해 좌표를 갱신하세요.

## 7. 실습 문제

1. Unity Screen 좌표의 원점 `(0, 0)`은 화면의 어느 모서리인가요?
2. `transform.position`과 `transform.localPosition`의 차이를 설명하고, 부모가 회전했을 때 자식의 월드 좌표가 어떻게 달라지는지 설명하세요.
3. 화면 정중앙 `(0.5, 0.5)`에서 카메라 앞 `10m` 지점의 World 좌표를 구하는 코드를 작성하세요.
4. `transform.Translate(transform.forward * speed * Time.deltaTime)` 코드가 왜 의도와 다르게 동작할까요? 올바르게 고쳐 보세요.
5. 멀티 카메라 게임(예: 2인 로컬 분할 화면, 미니맵)에서 Viewport 좌표가 유용한 이유는?

<details>
<summary>정답 및 해설 보기</summary>

1. **좌하단(Bottom-Left)** 입니다. 우상단이 `(cam.pixelWidth, cam.pixelHeight)`입니다. *(참고: 일부 GUI/웹 브라우저는 좌상단이 원점이므로 혼동에 주의!)*
2. `position`은 씬 전체(World) 기준 절대 좌표이고, `localPosition`은 부모 오브젝트 기준 상대 좌표입니다. \
부모가 회전하거나 스케일이 변하면 자식의 `localPosition` 숫자는 변하지 않지만, 부모의 TRS 행렬이 곱해져 자식의 실제 `position`(World)은 함께 회전·이동합니다.
3. **Viewport → World 변환 코드:**
   ```csharp
   Vector3 worldCenter = mainCam.ViewportToWorldPoint(new Vector3(0.5f, 0.5f, 10f));
   ```
4. `transform.Translate`의 두 번째 인자 기본값이 **`Space.Self`** 이기 때문입니다. 이미 World 기준인 `transform.forward`에 오브젝트의 회전이 **한 번 더 곱해지는 이중 회전 버그**가 발생합니다. \
`transform.position += transform.forward * (speed * Time.deltaTime);` 또는 `transform.Translate(Vector3.forward * (speed * Time.deltaTime), Space.Self);`로 고쳐야 합니다.
5. Viewport는 실제 픽셀 해상도(1920×1080, 2560×1440 등)와 무관하게 항상 **`0~1` 정규화 비율**을 쓰기 때문입니다. \
`Camera.rect`에 좌측 절반 `(0, 0, 0.5, 1)`과 우측 절반 `(0.5, 0, 0.5, 1)`만 지정하면 어떤 모니터 해상도에서도 자동으로 정확히 반으로 분할됩니다.

## 8. 이것만은 기억하자

* **`Translate` 함정 탈출:** 자기 정면 이동은 `transform.position += transform.forward * speed * Time.deltaTime`이 가장 직관적이고 실수가 없습니다.
* **위치 변환은 `TransformPoint`, 방향 변환은 `TransformDirection`:** 부모-자식 및 로컬-월드 변환의 핵심 API입니다.
* **`ScreenToWorldPoint`엔 `z` 필수, `WorldToViewportPoint`엔 `z > 0` 검사 필수.**
* **UI 프리팹 생성엔 `SetParent(parent, false)`, 월드 위치 보존엔 `SetParent(parent, true)`.**
* **Screen Space UI 추적은 `LateUpdate` + `RectTransformUtility` 조합이 실무 정석입니다.**
