# [Game Math] 1. 게임 수학의 만능 도구, Mathf

## 1. Mathf (Math for float) 란?

> **눈금이 새겨진 만능 도구 상자**
> * 게임을 만드는 일을 요리라고 치면, 화려한 연출에는 아주 정밀한 계량이 필요합니다.
> * `Mathf`는 눈금이 새겨진 계량컵·온도계·타이머가 한꺼번에 들어 있는 유니티 전용 도구 상자입니다.
> * "두 지점의 중간 구하기", "값을 범위 안에 가두기", "방향을 각도로 되돌리기" 등을 매번 직접 구현하지 않고 상자에서 쓱 꺼내 씁니다.

**왜 필요한가?**\
게임의 모든 움직임과 변화는 결국 숫자 몇 개의 계산으로 환원됩니다. 체력이 0 아래로 내려가지 않게 막는 일, 카메라가 부드럽게 따라가는 일 등이 모두 그렇습니다. \
이때 계산식 자체보다 **경계 예외 처리**(범위 이탈, 각도가 한 바퀴 넘음 등)가 코드를 더 길게 만듭니다. `Mathf`는 그 피곤한 경계 처리와 수학적 예외들을 유니티 엔진 개발자들이 미리 안전망을 쳐둔(감싸둔) 함수들의 묶음입니다.

*(참고: 이름 끝의 `f`는 모든 입출력이 `float` 실수형이라는 것을 의미합니다.)*

## 2. 핵심 요약

| 분류 (서랍) | 대표 멤버 함수 | 언제 꺼내 쓰나요? |
| :--- | :--- | :--- |
| **기본 상수** | `PI`, `Deg2Rad`, `Rad2Deg` | 3.14가 필요하거나, 각도(Degree)와 라디안(Radian)을 오갈 때 |
| **범위 가두기** | `Clamp`, `Clamp01`, `Min`, `Max` | 체력이나 스탯이 한계치를 돌파하지 못하게 벽을 칠 때 |
| **정수 반올림** | `RoundToInt`, `FloorToInt`, `CeilToInt`| 소수점 좌표를 딱 떨어지는 타일맵 칸 번호(인덱스)로 바꿀 때 |
| **보간(부드러움)**| `Lerp`, `MoveTowards`, `SmoothDamp` | 값을 등속으로 밀거나, 부드럽게 늦추며 목표에 도달시킬 때 |
| **각도 안전 처리**| `DeltaAngle`, `LerpAngle` | 359도에서 1도로 넘어갈 때 반대로 358도를 뺑 돌지 않게 할 때 |
| **삼각 함수** | `Sin`, `Cos`, `Atan2` | 주기적인 파도 움직임이나, 목표물 방향으로 총구를 돌릴 때 |

> **[원칙]**
> 1. `Mathf`는 정적(Static) 클래스이므로 `new Mathf()`로 찍어내지 않고, `Mathf.Clamp()`처럼 바로 갖다 씁니다.
> 2. `Mathf`의 삼각함수(`Sin`, `Cos` 등)는 무조건 **라디안(Radian)** 단위만 알아먹습니다. 우리가 아는 90도는 반드시 `Mathf.Deg2Rad`를 곱해서 먹여야 합니다.
> 3. 각도는 일반 숫자처럼 그냥 빼면 안 됩니다. 무조건 **`Mathf.DeltaAngle`** 을 써야 360도 경계 버그가 안 터집니다.

## 3. 세부 개념 및 원리

### 3.1 변환 상수 (도 ➔ 라디안)
우리는 "90도 회전해"라고 도(Degree)로 생각하고 인스펙터에도 그렇게 적혀 있지만, 수학 함수들은 라디안으로만 말합니다. 두 세계를 잇는 통역사 상수입니다.

```csharp
float degree = 90f;

// 90도에 'Deg2Rad(도➔라디안 변환 상수)'를 곱해주면 안전하게 라디안 값이 됩니다.
float radian = degree * Mathf.Deg2Rad;

float height = Mathf.Sin(radian); // 1 (90도의 사인 값)
float backToDegree = radian * Mathf.Rad2Deg; // 다시 90으로 돌아옴
```

### 3.2 가장 많이 쓰는 `Clamp` (범위 가두기)
`if`문 2개로 짤 코드를 1줄로 압축해 줍니다.
```csharp
currentHealth -= damage;

// 원시적인 if문 방식
// if (currentHealth < 0f) currentHealth = 0f;
// else if (currentHealth > maxHealth) currentHealth = maxHealth;

// 최신 방식 (0과 maxHealth 사이로 강제로 욱여넣음)
currentHealth = Mathf.Clamp(currentHealth, 0f, maxHealth);
```
> **주의사항**: `Clamp`의 인자 순서를 실수로 `Clamp(값, 최대치, 최소치)`로 뒤집어 넣으면 코드가 값을 통과시키지 못하고 꽉 막히는 조용한 버그가 납니다. 순서는 무조건 **(값, 최소, 최대)** 입니다

### 3.3 `(int)` 캐스팅과 `FloorToInt`의 치명적 차이
소수점을 정수로 만들 때, 단순히 `(int)`를 씌우면 양수에서는 내림과 같지만 음수에서는 0을 향해 소수점을 무자비하게 잘라버립니다(Truncate).
```csharp
float pos = -2.7f;

// (int) 캐스팅: 0 쪽으로 잘라버림 ➔ 결과: -2
int tileX1 = (int)pos; 

// FloorToInt: 수학적으로 '내림(바닥)' ➔ 결과: -3
int tileX2 = Mathf.FloorToInt(pos); 
```
타일맵 좌표계를 짤 때 `(int)`를 쓰면 원점(0) 부근에서 두 칸이 겹치는 인덱스 버그가 터지므로, 반드시 `FloorToInt`를 써야 합니다.

### 3.4 부드러운 움직임의 마법 (보간 함수들)
* **`Mathf.Lerp(시작, 끝, 비율)`**: 남은 거리의 비율(%)만큼 좁힙니다. 처음엔 빠르고 목표에 갈수록 스르륵 느려집니다. (카메라 추적 등에 쓰임)
* **`Mathf.MoveTowards(시작, 끝, 고정스피드)`**: 한 번에 정해진 속도만큼 무식하고 정직하게 직진합니다. (장애물 등속 이동 등에 쓰임)
* **`Mathf.SmoothDamp()`**: 내부적으로 가속도를 기억하며 스프링처럼 가장 부드럽고 물리적으로 도달합니다. (흔들림 없는 카메라에 필수)

### 3.5 각도 계산의 구원자 (`DeltaAngle`)
포탑이 359도를 보고 있는데, 오른쪽 1도 방향에 나타난 적을 쏘고 싶습니다.
그냥 뺄셈(`1 - 359`)을 해버리면 "-358도 회전해"라고 명령이 들어가 포탑이 빙구처럼 왼쪽으로 358도를 미친 듯이 뺑 돕니다.

```csharp
// DeltaAngle은 두 각도 사이의 '최단 거리'를 기가 막히게 뽑아줍니다.
float diff = Mathf.DeltaAngle(359f, 1f); // ➔ 2도 (오른쪽으로 살짝만 돔)
```

## 4. 코드로 보기 (포탑 조준 시스템)

`Mathf` 상자에서 꺼낸 3가지 도구(Atan2, Clamp, MoveTowardsAngle)를 조합해 완벽한 포탑 AI를 구현합니다.

```csharp
public class TurretAim : MonoBehaviour
{
    [SerializeField] private Transform _target;
    [SerializeField] private float _limitAngle = 45f; // 포탑이 돌아가는 좌우 한계각
    [SerializeField] private float _turnSpeed = 120f; // 초당 120도 회전 (등속)
    
    private float _currentAngle; 

    private void Update()
    {
        if (_target == null) return;

        // 1. 타겟을 향한 방향 벡터
        Vector2 direction = _target.position - transform.position;

        // 2. Atan2로 방향을 각도로 번역 (결과가 라디안이므로 꼭 Rad2Deg를 곱해 도로 바꿈)
        float targetDegree = Mathf.Atan2(direction.y, direction.x) * Mathf.Rad2Deg;

        // 3. 포탑이 너무 꺾이지 않게 사각(Limit) 안으로 각도를 가둠
        float desiredAngle = Mathf.Clamp(targetAngle, -_limitAngle, _limitAngle); 

        // 4. 현재 각도에서 목표 각도까지 등속(MoveTowards)으로 안전하게 회전시킴
        _currentAngle = Mathf.MoveTowardsAngle(_currentAngle, desiredAngle, _turnSpeed * Time.deltaTime);

        // 5. 최종 각도 적용
        transform.rotation = Quaternion.Euler(0f, 0f, _currentAngle);

        // 6. 조준 완료 판정 (단순 뺄셈 금지. DeltaAngle로 최단 차이값 확인)
        if (Mathf.Abs(Mathf.DeltaAngle(_currentAngle, desiredAngle)) < 1f)
            Fire();
    }

    private void Fire() { /* 빵야 */ }
}
```

## 5. 실전 활용 예시: 핑퐁(PingPong) 숨쉬기 연출

UI나 함정 톱니바퀴가 두 지점 사이를 영원히 왕복하게 만드는 방법입니다.

```csharp
public class BreathingUI : MonoBehaviour
{
    [SerializeField] private float _scaleSize = 0.2f; // 커질 크기
    [SerializeField] private float _speed = 2f; // 깜빡이는 속도

    private Vector3 _originalScale;

    private void Awake() => _originalScale = transform.localScale;

    private void Update()
    {
        // PingPong(증가하는 시간, 최고점) ➔ 0에서 최고점 사이를 삼각파로 예쁘게 왕복합니다
        // 0 -> 1 -> 0 -> 1 ... 무한 반복
        float bounce = Mathf.PingPong(Time.time * _speed, 1f);

        // 원래 크기에서 추가 크기(bounce * scaleSize)를 더해줌
        transform.localScale = _originalScale + Vector3.one * (bounce * _scaleSize);
    }
}
```

## 6. Unity 최적화 팁

### 6.1 실수를 `==`로 비교하면 터지는 이유 (`Approximately`)
컴퓨터 메모리는 소수점 실수를 완벽하게 저장하지 못하고 근사치로 저장(부동소수점 오차)합니다.
```csharp
float sum = 0.1f + 0.2f; // 컴퓨터는 이걸 0.300000000004 정도로 인식함

// 실수: 눈으론 0.3 같아 보이지만 컴퓨터는 다르다고 뱉음 (무조건 false 됨)
if (sum == 0.3f) { /* 영원히 실행 안 됨 */ }

// 정석: "대충 눈감아줄 정도로 아주 근사하게 비슷해?" 라고 물어봄 (true 반환)
if (Mathf.Approximately(sum, 0.3f)) { /* 성공 */ }
```

### 6.2 틱(Tick) 단위 최적화
수천 개의 타일이나 파티클이 매 프레임 `Mathf.Sin`이나 `Mathf.Cos`를 호출하면 CPU가 비명을 지릅니다.\
수학 삼각 함수 연산은 꽤 무거운 편이므로, 고정된 패턴이 필요하다면 미리 시작할 때 배열이나 곡선(`AnimationCurve`)에 계산값을 다 캐싱(저장)해 두고 배열 인덱스만 뽑아다 쓰는 룩업 테이블(Look-Up Table) 방식을 써야 합니다.

## 7. 실습 문제 및 복습

**Q1. `Mathf.Clamp(50f, 100f, 0f)` 코드를 실행하면 어떤 값이 튀어나오고, 이 코드가 지닌 치명적인 논리적 함정은 무엇인가요?**
> **100f가 튀어나옵니다.** `Clamp` 함수의 내부 논리는 "값이 최소값보다 작으면 최소값을 뱉고, 아니면 최대값을 뱉는다"는 순서로 동작합니다. \
> 따라서 인자 순서를 `(값, 최대, 최소)`로 실수로 뒤집어 넣으면, 유니티는 에러를 안 띄워주는 대신 50f가 최소값인 100f보다 작으므로 무조건 100f만 영원히 뱉어내는 조용한 버그를 유발합니다. 반드시 `(값, 최소, 최대)` 순서를 지켜야 합니다.

**Q2. `Mathf.Round(2.5f)`와 `Mathf.Round(3.5f)`를 호출했을 때 각각 어떤 결과가 나오나요?**
> 둘 다 똑같이 **3이 나오지 않고, 2와 4가 나옵니다.** C#의 `Mathf.Round`는 소수점이 정확히 `.5`일 때 은행원 반올림(Banker's Rounding) 규칙을 따라 가장 가까운 **'짝수'** 쪽으로 끌려갑니다.\
> 만약 항상 수학적으로 익숙한 위로 올림(0.5 이상 올림)을 하고 싶다면 `Mathf.Floor(값 + 0.5f)` 공식을 써야 합니다.

**Q3. 캐릭터의 3D 공간 위치(`Vector3`)를 목표물 위치까지 부드럽게 이동시키려 합니다. `transform.position = Mathf.Lerp(transform.position, target.position, 0.1f);` 라고 코드를 짰더니 컴파일 에러가 터졌습니다. 이유가 무엇인가요?**
> `Mathf` 클래스 안에 있는 모든 함수는 순수하게 `float`형 스칼라(단일 실수) 값 하나만 받고 뱉을 수 있습니다. \
> 3차원 좌표인 `Vector3`를 통째로 `Mathf.Lerp`에 밀어 넣으려 했기 때문에 자료형 불일치로 에러가 난 것입니다. \
> 3D 좌표 보간은 유니티가 3축(X,Y,Z)을 알아서 한 방에 계산해 주는 별도 전용 함수인 **`Vector3.Lerp`** 를 사용해야 합니다.

## 8. 주의사항 및 안전 습관

* **자료형에 맞는 전용 Lerp 쓰기**: 투명도, 체력 같은 숫자(float)는 `Mathf.Lerp`를 쓰지만, 공간 위치 보간은 `Vector3.Lerp`, 3D 회전 보간은 각도 꼬임을 방지해 주는 `Quaternion.Lerp`나 `Slerp`, 색상 보간은 `Color.Lerp`를 써야 합니다.
* **`Atan2`의 Y, X 함정 주의**: 수학의 탄젠트 공식 특성상 `Mathf.Atan2`의 괄호 안 인자 순서는 무조건 **`(Y, X)`** 입니다. 본능적으로 (X, Y)로 적었다가 포탑이 대각선 기준으로 미러링되어 뒤집혀 도는 버그를 찾느라 밤을 새울 수 있습니다.
* **`System.Math` 쓰지 말기**: 가끔 구글링 코드를 복붙하다가 순수 C#의 `Math.Abs()`가 섞여 들어오는 경우가 있습니다. 순수 `Math` 클래스는 `double`형(64비트)을 반환하므로, 유니티의 32비트 `float` 생태계와 섞이면 잦은 형 변환(Casting)이 일어나 성능이 떨어집니다. 유니티 안에선 무조건 뒤에 'f'가 붙은 `Mathf`로 통일하세요
