# [Game Math] 4. 주기적인 움직임과 방향의 언어, 삼각함수

## 1. 삼각함수(Trigonometry) 란?
> **각도와 좌표를 오가는 '마법의 번역기'**
> * 번역기에 **"동쪽으로 30도 방향"** 이라는 **각도**를 넣으면 ➔ **"오른쪽으로 0.86칸, 위쪽으로 0.5칸"** 이라는 **좌표(방향 벡터)** 로 번역해 줍니다. (`Cos`, `Sin`)
> * 반대로 **"오른쪽으로 3칸, 위쪽으로 4칸"** 이라는 **좌표**를 넣으면 ➔ **"약 53.1도 방향"** 이라는 **각도**로 되돌려 줍니다. (`Atan2`)

본래 삼각함수는 직각삼각형의 변과 각도 사이의 관계를 다루는 수학이지만, 게임 개발에서는 **회전, 공전, 파도 같은 주기적 움직임, 부채꼴 탄막 배치, 목표 조준 각도 계산**을 담당하는 필수 언어입니다.

**왜 필요한가?**\
포탑이 마우스를 향해 회전하고, 위성이 캐릭터 주위를 공전하며, 드롭 아이템이 공중에서 두둥실 떠다니는 모든 연출은 결국 **각도와 좌표 사이의 변환**으로 이루어집니다. 삼각함수를 이해하면 복잡한 움직임을 애니메이션 클립 없이도 수학 식 몇 줄로 깔끔하게 구현할 수 있습니다.

## 2. 핵심 요약

| 핵심 도구 | 역할 | 입력 ➔ 출력 | 주 사용처 |
| :--- | :--- | :--- | :--- |
| **`Mathf.Cos(rad)`** | 단위 원 위의 **X 좌표** | 라디안 ➔ `-1 ~ 1` | 원형 배치, 공전(X), 시야각 임계값 |
| **`Mathf.Sin(rad)`** | 단위 원 위의 **Y 좌표** | 라디안 ➔ `-1 ~ 1` | 상하 진동, 공전(Y), 파도 움직임 |
| **`Mathf.Atan2(y, x)`**| 방향 벡터의 **각도** 계산 | `(y, x)` ➔ `-π ~ π` 라디안 | 2D 포탑 조준, 캐릭터 시선 회전 |
| **`Deg2Rad` / `Rad2Deg`**| 각도(°) ↔ 라디안 변환 상수 | 단위 변환 | `Transform` 회전과 삼각함수 연결 |

> **[원칙]**
> 1. **단위 원 공식**: 반지름 1인 원 위의 점 좌표는 항상 **`(Cos θ, Sin θ)`**입니다. (`X = Cos`, `Y = Sin`)
> 2. **단위는 무조건 라디안(Radian)**: Unity의 `Sin`, `Cos`, `Atan2`는 모두 라디안만 알아듣습니다. 인스펙터의 도(Degree)와 섞을 땐 반드시 `Mathf.Deg2Rad` / `Mathf.Rad2Deg`를 곱하세요.
> 3. **`Atan2`의 인자 순서는 `(y, x)`**: 일반 좌표 `(x, y)`와 반대입니다. 또한 `(0, 0)` 근처 벡터를 넘기면 0도로 튈 수 있으니 거리 방어를 걸어야 합니다.

## 3. 세부 개념 및 원리

### 3.1 단위 원(The Unit Circle) — 게임 개발자의 관점
원점 `(0, 0)`을 중심으로 반지름이 `1`인 원을 **단위 원**이라고 합니다. 이 원 위를 도는 점 $P$의 위치는 각도 $\theta$ 하나만으로 결정됩니다.

* 점 $P$의 X 좌표 = $\cos(\theta)$
* 점 $P$의 Y 좌표 = $\sin(\theta)$
* 반지름이 $r$인 원이라면 그대로 $r$만 곱합니다: **`(Cos(θ) * r, Sin(θ) * r)`**

각도 $\theta$가 $0^\circ \to 360^\circ$로 계속 커지면, `Cos`와 `Sin` 값은 `-1`과 `1` 사이를 부드러운 파도 모양(Sine Wave)으로 끝없이 왕복합니다.

### 3.2 주기적인 움직임: `Sin`, `Cos`, 그리고 `2π`의 비밀
`Time.time`처럼 계속 증가하는 시간을 `Sin`에 넣으면 부드러운 왕복 운동이 만들어집니다. 이때 주의할 점은 **`Sin`의 한 주기는 `1`이 아니라 `2π` (약 6.28초)** 라는 사실입니다.

* `Mathf.Sin(Time.time * 1f)` ➔ 한 바퀴 왕복에 **약 6.28초** 걸림 (각속도 기준)
* `Mathf.Sin(Time.time * frequency * Mathf.PI * 2f)` ➔ `frequency = 1`일 때 **정확히 1초에 1회 왕복 (1 Hz)**

#### ① 상하 진동 (아이템 두둥실 효과 + 위상 오프셋)
여러 아이템을 필드에 뿌릴 때 랜덤한 **위상 오프셋(`_phaseOffset`)** 을 주면, 모든 아이템이 똑같은 박자로 움직이는 기계적인 느낌을 없앨 수 있습니다.

```csharp
using UnityEngine;

public class FloatingItem : MonoBehaviour
{
    [SerializeField] private float _amplitude = 0.25f; // 위아래 진폭 (m)
    [SerializeField] private float _frequency = 1.0f;  // 초당 왕복 횟수 (Hz)
    [SerializeField] private bool _useRandomPhase = true;

    private Vector3 _startPos;
    private float _phaseOffset;

    private void Start()
    {
        _startPos = transform.position;
        // 0 ~ 2π 사이의 무작위 시작 위상으로 군집 움직임을 자연스럽게 만든다
        _phaseOffset = _useRandomPhase ? Random.Range(0f, Mathf.PI * 2f) : 0f;
    }

    private void Update()
    {
        // 2π를 곱해 frequency(Hz)가 직관적으로 "초당 왕복 횟수"가 되게 맞춘다
        float radian = (Time.time * _frequency * Mathf.PI * 2f) + _phaseOffset;
        float yOffset = Mathf.Sin(radian) * _amplitude;

        transform.position = _startPos + new Vector3(0f, yOffset, 0f);
    }
}
```

#### ② 원형 공전 운동 (위성/보호막 회전)
X에 `Cos`, Y에 `Sin`을 조합하면 완벽한 원 궤도가 만들어집니다.

```csharp
using UnityEngine;

public class OrbitSatellite : MonoBehaviour
{
    [SerializeField] private Transform _center;
    [SerializeField] private float _radius = 2f;
    [SerializeField] private float _angularSpeedDeg = 180f; // 초당 회전 각도 (도)

    private float _currentAngleDeg;

    private void Update()
    {
        if (_center == null) return;

        // 각도를 누적하고 360도로 접어 부동소수점 정밀도 저하를 막는다
        _currentAngleDeg = Mathf.Repeat(_currentAngleDeg + _angularSpeedDeg * Time.deltaTime, 360f);

        float rad = _currentAngleDeg * Mathf.Deg2Rad;
        float x = Mathf.Cos(rad) * _radius;
        float y = Mathf.Sin(rad) * _radius;

        transform.position = _center.position + new Vector3(x, y, 0f);
    }
}
```

### 3.3 방향으로부터 각도 구하기: `Atan2`
`Atan(y / x)`는 `x = 0`일 때 0 나누기가 터지고 사분면(180° 차이)을 구분하지 못합니다. 반면 **`Mathf.Atan2(y, x)`** 는 `x`와 `y`의 부호를 모두 보고 **360도 전 방향(`-π ~ π`)** 을 정확하게 반환합니다.

```csharp
using UnityEngine;
using UnityEngine.InputSystem;

public class TurretMouseAim2D : MonoBehaviour
{
    // 스프라이트가 오른쪽(+X)을 보고 그려졌다면 0, 위쪽(+Y)을 보고 그려졌다면 -90
    [SerializeField] private float _spriteAngleOffset = -90f;

    private Camera _mainCamera;

    private void Awake()
    {
        _mainCamera = Camera.main; // 매 프레임 태그 탐색 방지를 위해 캐싱
    }

    private void Update()
    {
        Mouse mouse = Mouse.current;
        if (mouse == null || _mainCamera == null) return;

        // 1. 마우스 화면 좌표를 2D 월드 좌표로 변환
        Vector2 screenPos = mouse.position.ReadValue();
        Vector3 worldPos = _mainCamera.ScreenToWorldPoint(new Vector3(screenPos.x, screenPos.y, -_mainCamera.transform.position.z));

        // 2. 포탑 -> 마우스 방향 벡터 계산
        Vector2 direction = (Vector2)worldPos - (Vector2)transform.position;

        // 3. 커서가 포탑 정중앙과 겹칠 때 Atan2(0, 0) = 0으로 튀는 현상 방어
        if (direction.sqrMagnitude < 0.0001f) return;

        // 4. Atan2(y, x)로 라디안 각도를 구하고 도(Degree)로 변환
        float angleDeg = Mathf.Atan2(direction.y, direction.x) * Mathf.Rad2Deg;
        transform.rotation = Quaternion.Euler(0f, 0f, angleDeg + _spriteAngleOffset);
    }
}
```

### 3.4 주요 관련 함수 및 상수 한눈에 보기

## 5. 활용 예시 (게임 도메인)

### 시나리오 1: 적 AI의 부채꼴 시야각(FOV) 감지 + 씬 뷰 기즈모 시각화
적이 자신의 전방 `120도` 시야각과 `10m` 반경 안에 플레이어가 들어왔을 때만 감지합니다. 거리 검사는 `Sqrt` 연산이 없는 **`sqrMagnitude`** 로 가볍게 먼저 걸러내고, 에디터에서 시야각을 눈으로 확인할 수 있도록 삼각함수로 부채꼴 경계선을 그려 줍니다.

```csharp
using UnityEngine;

public class EnemyFieldOfView : MonoBehaviour
{
    [SerializeField] private Transform _target;
    [SerializeField] private float _viewRadius = 10f;
    [SerializeField, Range(0f, 360f)] private float _viewAngle = 120f;

    public bool IsTargetInSight()
    {
        if (_target == null) return false;

        Vector3 toTarget = _target.position - transform.position;
        toTarget.y = 0f; // 3D 평면(XZ) 기준 판정

        // 1. 거리 검사: Vector3.Distance 대신 sqrMagnitude로 제곱근(Sqrt) 연산 절약
        if (toTarget.sqrMagnitude > _viewRadius * _viewRadius)
            return false;

        // 2. 각도 검사: 정면과 타겟 방향의 사이각이 시야각 절반 이내인지 확인
        // (※ 적이 수백 마리라면 Vector3.Angle 대신 내적(Dot)과 Cos(halfAngle) 비교로 최적화)
        float angleToTarget = Vector3.Angle(transform.forward, toTarget);
        return angleToTarget <= _viewAngle * 0.5f;
    }

    // 씬 뷰에서 시야각 부채꼴을 눈으로 확인하기 위한 기즈모
    private void OnDrawGizmosSelected()
    {
        Gizmos.color = IsTargetInSight() ? Color.red : Color.yellow;
        Gizmos.DrawWireSphere(transform.position, _viewRadius);

        float halfAngle = _viewAngle * 0.5f;
        Vector3 leftDir = DirectionFromAngle(-halfAngle);
        Vector3 rightDir = DirectionFromAngle(halfAngle);

        Gizmos.DrawLine(transform.position, transform.position + leftDir * _viewRadius);
        Gizmos.DrawLine(transform.position, transform.position + rightDir * _viewRadius);
    }

    // 3D XZ 평면에서 Y축 회전 각도를 방향 벡터로 변환 (Unity 3D는 +Z가 0도, 시계 방향이 +)
    private Vector3 DirectionFromAngle(float angleOffsetDeg)
    {
        float rad = (transform.eulerAngles.y + angleOffsetDeg) * Mathf.Deg2Rad;
        return new Vector3(Mathf.Sin(rad), 0f, Mathf.Cos(rad));
    }
}
```

### 시나리오 2: 보스 부채꼴(Spread) 탄막 발사 패턴
슈팅/RPG 보스가 플레이어를 향해 부채꼴 형태로 탄환 여러 발을 균등하게 쏘는 패턴입니다.

```csharp
using UnityEngine;

public class SpreadBulletEmitter : MonoBehaviour
{
    [SerializeField] private Rigidbody2D _bulletPrefab;
    [SerializeField] private int _bulletCount = 5;
    [SerializeField] private float _spreadAngle = 60f; // 전체 부채꼴 각도
    [SerializeField] private float _bulletSpeed = 8f;

    public void FireSpread(Vector2 aimDirection)
    {
        if (_bulletPrefab == null || _bulletCount <= 0) return;

        // 중심 조준 각도 계산
        float centerAngle = Mathf.Atan2(aimDirection.y, aimDirection.x) * Mathf.Rad2Deg;

        // 1발일 때 0 나누기를 막기 위해 분기 처리
        float startAngle = _bulletCount == 1 ? centerAngle : centerAngle - (_spreadAngle * 0.5f);
        float angleStep = _bulletCount == 1 ? 0f : _spreadAngle / (_bulletCount - 1);

        for (int i = 0; i < _bulletCount; i++)
        {
            float currentDeg = startAngle + (angleStep * i);
            float rad = currentDeg * Mathf.Deg2Rad;

            // 각도 -> 단위 방향 벡터 변환
            Vector2 shootDir = new Vector2(Mathf.Cos(rad), Mathf.Sin(rad));

            Rigidbody2D bullet = Instantiate(_bulletPrefab, transform.position, Quaternion.Euler(0f, 0f, currentDeg));
            bullet.linearVelocity = shootDir * _bulletSpeed;
        }
    }
}
```

## 6. 실전에서는?

### 6.1 엔진에 맡길 때 vs 직접 계산할 때
| 상황 | 권장 방식 | 이유 |
| :--- | :--- | :--- |
| **3D에서 목표 바라보기** | `transform.LookAt` / `Quaternion.LookRotation` | 3축 회전에서 `Atan2`를 직접 조합하면 축 순서와 짐벌 락이 꼬입니다 |
| **두 방향 사이 각도** | `Vector3.Angle` 또는 내적(`Dot`) | 정규화와 역삼각함수 예외 처리를 엔진이 대신합니다 |
| **오브젝트의 현재 정면** | `transform.up` / `transform.forward` | 이미 회전 행렬에서 계산된 단위 벡터라 `Cos`/`Sin`을 또 부를 필요가 없습니다 |
| **2D Z축 회전 조준** | `Mathf.Atan2` + `Quaternion.Euler(0, 0, deg)` | 가장 짧고 직관적이며 예측 가능합니다 |
| **원형·부채꼴 배치/탄막** | `Mathf.Cos` / `Mathf.Sin` | 각도를 등분해 좌표를 뽑는 작업은 삼각함수가 정석입니다 |
| **무한 반복 미세 연출** | `Mathf.Sin(Time.time * ...)` | 애니메이션 클립 없이 둥실거림·점멸을 가볍게 구현합니다 |

### 6.2 대량 AI 시야 판정 최적화 (각도 대신 내적)
`Vector3.Angle`은 내부에서 비용이 비싼 역삼각함수(`Mathf.Acos`)를 호출합니다. 적이 수백 마리 등장하는 게임이라면, \
`Awake`에서 기준값 `float cosHalfFov = Mathf.Cos(_viewAngle * 0.5f * Mathf.Deg2Rad);`를 미리 한 번만 구해 두고, 매 프레임 **`Vector3.Dot(transform.forward, dirToTarget) >= cosHalfFov`** 로 비교하는 편이 훨씬 빠릅니다.

### 6.3 팀 협업 규칙: 스프라이트 기본 정면 방향 합의
`angleDeg - 90f`처럼 보정값이 코드에 들어가는 이유는 "스프라이트가 위쪽(+Y)을 보고 그려져 있기 때문"입니다. \
아트 팀과 **"모든 2D 캐릭터/투사체 스프라이트는 오른쪽(+X)을 정면으로 그린다"** 처럼 기준 방향을 초기에 합의하면, 모든 조준 코드에서 `-90f` 같은 매직 넘버가 깔끔하게 사라집니다.

## 7. 실습 문제 및 해답

### Q1. 단위 원(Unit Circle)에서 0도의 `Cos`값과 `Sin`값은 각각 얼마일까요? 90도의 `Cos`, `Sin` 값은 얼마일까요?
> **해답**
> * **0도** (오른쪽 끝 점 `(1, 0)`): `Cos(0°) = 1`, `Sin(0°) = 0`
> * **90도** (위쪽 끝 점 `(0, 1)`): `Cos(90°) = 0`, `Sin(90°) = 1`

### Q2. `Mathf.Sin(Time.time)`을 사용하면 오브젝트가 위아래로 움직입니다. 만약 `Mathf.Cos(Time.time)`을 사용하면 어떻게 움직일까요? 그 이유는 무엇인가요?
> **해답**
> * **움직임의 모양과 주기는 완전히 동일하지만, '시작 위치(위상)'만 다릅니다.**
> * `Sin(0) = 0`이므로 시작 시 **중앙(0)** 에서 출발해 위로 올라가며 왕복하지만, `Cos(0) = 1`이므로 시작 시 **가장 높은 꼭대기(+amplitude)** 에서 출발해 아래로 내려오며 왕복합니다.
> * 수학적으로 `Cos`는 `Sin` 그래프를 왼쪽으로 90도($\pi/2$) 밀어 놓은 동일한 파형이기 때문입니다.

### Q4. 2D 탑다운 슈팅 게임에서, 플레이어가 바라보는 방향으로 총알을 발사하려고 합니다. 플레이어의 `transform.up` 벡터(`Vector2`)를 사용하여 총알의 속도(`linearVelocity`)를 설정하는 한 줄의 코드를 작성해 보세요. 삼각함수가 이 과정 어디에 숨어 있을까요?
> **해답**

> * **삼각함수가 숨어 있는 곳**: `transform.up` 프로퍼티를 읽는 순간, Unity 엔진 내부에서 오브젝트의 회전(`Quaternion` / 회전 행렬)을 계산할 때 이미 `Cos`와 `Sin` 연산이 적용되어 길이 1짜리 단위 방향 벡터가 만들어집니다. 따라서 개발자가 `eulerAngles.z`를 꺼내 다시 `Cos`/`Sin`을 계산할 필요가 없습니다.

### Q5. 오브젝트가 사인파(Sine Wave)를 그리며 오른쪽으로 계속 이동하는 움직임을 만들어 보세요. X축 위치는 `Time.deltaTime`을 이용해 계속 증가시키고, Y축 위치는 `Mathf.Sin`을 이용해 주기적으로 변화시킵니다.
> **해답**
> * X축은 등속 전진시키고, Y축은 시작 높이(`_startY`)를 기준으로 사인파 오프셋을 더해 줍니다.
>
> ```csharp
> using UnityEngine;
>
> public class SineWaveMover : MonoBehaviour
> {
>     [SerializeField] private float _moveSpeed = 3f;  // 오른쪽 이동 속도
>     [SerializeField] private float _amplitude = 1f;  // 파도의 높이 (진폭)
>     [SerializeField] private float _frequency = 1f;  // 초당 출렁임 횟수 (Hz)
>
>     private float _startY;
>     private float _elapsedTime;
>
>     private void Start()
>     {
>         _startY = transform.position.y;
>     }
>
>     private void Update()
>     {
>         _elapsedTime += Time.deltaTime;
>
>         float nextX = transform.position.x + (_moveSpeed * Time.deltaTime);
>         float nextY = _startY + Mathf.Sin(_elapsedTime * _frequency * Mathf.PI * 2f) * _amplitude;
>
>         transform.position = new Vector3(nextX, nextY, transform.position.z);
>     }
> }
> ```

## 8. 주의사항 및 안전 습관

### 흔한 실수
* **단위 혼동 (라디안 vs 도)**: `Mathf.Sin(90f)`는 `90도`가 아니라 `90 라디안`입니다. 반드시 `90f * Mathf.Deg2Rad`로 변환하세요.
* **`Atan2(x, y)` 순서 뒤바뀜**: 반드시 **`Mathf.Atan2(y, x)`**입니다. 반대로 넣으면 회전이 대각선(y=x) 기준으로 뒤집혀 기괴하게 움직입니다.
* **`Sin(Time.time * frequency)`에 `2π` 누락**: `2π`를 안 곱하면 1초에 1번이 아니라 약 6.28초에 1번 왕복합니다. 주파수(Hz) 개념으로 쓰고 싶다면 `Mathf.PI * 2f`를 곱하세요.
* **`Atan2(0, 0)` 튐 현상 방치**: 타겟과 내 위치가 겹치는 순간 각도가 0으로 튑니다. `sqrMagnitude`로 최소 거리 가드를 세우세요.
* **모든 오브젝트가 같은 위상으로 움직임**: 코인 20개가 똑같은 타이밍에 오르내리면 어색합니다. 시작 시 랜덤 위상 오프셋을 더하세요.

### 안전 습관
* **각도 ↔ 좌표 변환은 한 번만**: 이미 `transform.up` / `transform.forward`가 있다면 굳이 각도를 뽑아 다시 `Cos`/`Sin`을 돌리지 않습니다.
* **성능 민감 구간에서는 역삼각함수 회피**: 대량 AI의 시야 판정에서는 `Vector3.Angle`(`Acos`) 대신 미리 캐싱한 `Cos(halfAngle)`과 `Vector3.Dot` 비교를 검토합니다.
* **`Camera.main`은 `Awake`에서 캐싱**: 마우스 조준처럼 `Update`마다 좌표 변환이 필요한 스크립트는 카메라 참조를 필드에 저장해 둡니다.
* **기준 방향 합의 및 오프셋 노출**: 스프라이트 회전 보정값(`0f`, `-90f`)은 코드에 숨기지 말고 `[SerializeField]`로 빼두거나 아트 파이프라인 규칙으로 통일합니다.
