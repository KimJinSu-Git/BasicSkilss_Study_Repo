# [Game Math] 6. 벡터 (Vector)

## 1. 벡터(Vector)란?
**벡터(Vector)** 는 **크기(Magnitude)** 와 **방향(Direction)** 을 동시에 가지는 수학적 양입니다. \
캐릭터 이동, 시선 처리, 충돌 반사, 카메라 셰이크, 물리력 등 게임에서 **"어디로 얼마나"** 를 표현하는 거의 모든 연산이 벡터 위에 서 있습니다.

> **벡터는 '화살표'입니다.**
> * **화살표의 길이(= 크기):** 얼마나 강한지, 얼마나 먼지
> * **화살촉이 가리키는 쪽(= 방향):** 어디로 향하는지
> * **위치 무관(자유 벡터):** 같은 길이와 방향을 가진 화살표는 공간의 어디에 그려도 같은 벡터

### Unity의 `Vector3`와 위치 vs 방향 벡터
Unity의 `Vector3`는 이 챕터의 개념을 구현한 **값 타입(`struct`)** 입니다. 힙(Heap) 메모리 할당이 발생하지 않아 GC(가비지 컬렉션) 부담 없이 매 프레임 수많은 연산을 수행할 수 있습니다.

주의할 점은 Unity가 **점(위치)** 과 **벡터(방향/변위)** 를 모두 `Vector3` 하나로 표현한다는 것입니다.
* **위치 벡터(Position):** 원점 `(0, 0, 0)`에서 특정 지점을 가리키는 좌표 (`transform.position`)
* **방향/변위 벡터(Direction):** 위치와 무관하게 방향이나 이동량만을 표현 (`transform.forward`, `target - self`)

> *이 구분은 추후 행렬(Matrix) 변환과 `TransformPoint` vs `TransformDirection`의 차이를 이해하는 핵심 기초가 됩니다.*

## 2. 핵심 요약

| 개념 | 한 줄 설명 | 핵심 수식 / Unity API |
| :--- | :--- | :--- |
| **크기 (Magnitude)** | 벡터의 길이 | $\Vert{}v\Vert{} = \sqrt{x^2 + y^2 + z^2}$ / `v.magnitude` |
| **단위 벡터 (Normalized)** | 크기가 1인 순수 방향 벡터 | $\hat{v} = v / \Vert{}v\Vert{}$ / `v.normalized` |
| **덧셈** | 두 벡터를 꼬리에 꼬리를 물어 이어 붙임 | $\vec{A} + \vec{B}$ |
| **뺄셈** | **목적지 - 출발지** 방향 및 거리 벡터 | $\vec{B} - \vec{A}$ (A에서 B로 향하는 벡터) |
| **스칼라 곱** | 크기 조절 (양수: 방향 유지, **음수: 반대 방향**, 0: 영벡터) | $k \cdot \vec{A}$ |
| **내적 (Dot)** | 두 벡터의 방향 유사도 및 투영 길이 (결과는 **스칼라**) | $\vec{A} \cdot \vec{B} = \Vert{}\vec{A}\Vert{}\Vert{}\vec{B}\Vert{}\cos\theta$ |
| **외적 (Cross)** | 두 벡터 모두에 수직인 벡터 (결과는 **벡터**) | $\vec{A} \times \vec{B}$ (순서 바뀌면 방향 반대) |

## 3. 세부 개념

### 3.1 크기 (Magnitude)와 제곱 크기 (sqrMagnitude)
피타고라스 정리의 확장입니다.

| 차원 | 공식 | Unity API |
| :--- | :--- | :--- |
| 2D | $\Vert{}v\Vert{} = \sqrt{x^2 + y^2}$ | `v.magnitude` / `v.sqrMagnitude` |
| 3D | $\Vert{}v\Vert{} = \sqrt{x^2 + y^2 + z^2}$ | `v.magnitude` / `v.sqrMagnitude` |

* **`magnitude`:** 제곱근(`Mathf.Sqrt`)을 계산해 실제 길이를 반환합니다.
* **`sqrMagnitude`:** 제곱근을 생략한 길이의 제곱값($x^2 + y^2 + z^2$)입니다. 단순 거리 비교나 정렬에 사용합니다.

### 3.2 단위 벡터 (Normalized)
벡터의 크기를 1로 정규화(Normalize)해 순수한 **방향**만 추출할 때 사용합니다.

```csharp
Vector3 toTarget = target - self;

// 1) 프로퍼티: 원본(toTarget)은 유지하고 정규화된 새 복사본 반환
Vector3 dir = toTarget.normalized;

// 2) 메서드: 원본(toTarget) 자체를 길이 1로 직접 수정 (in-place)
toTarget.Normalize();
```

### 3.3 덧셈 · 뺄셈 · 스칼라 곱
| 연산 | 기하학적 의미 | 실전 활용 |
| :--- | :--- | :--- |
| `A + B` | A 끝에서 B만큼 이어 이동 | 현재 위치 + 이동 변위, 힘(Force) 합산 |
| `B - A` | **A(출발지)에서 B(목적지)로** 가는 벡터 | 적을 향한 방향 및 거리 계산 (`target - self`) |
| `A * k` | `k > 0`: 같은 방향 `k`배 / `k < 0`: 반대 방향 `\|k\|`배 | 속도 조절, 넉백 반전(`-forward * power`) |

### 3.4 내적 (Dot Product)
두 벡터를 곱해 하나의 **실수(스칼라)** 를 얻는 연산입니다.

```text
A · B = |A| × |B| × cos θ
      = (A.x × B.x) + (A.y × B.y) + (A.z × B.z)
```

두 벡터가 **단위 벡터(길이 1)** 일 때 내적 값은 곧 `cos θ`(-1 ~ 1)가 됩니다.

| 내적 결과 | 각도 관계 | 기하학적 의미 |
| :--- | :--- | :--- |
| **양수 (`> 0`)** | 예각 (90° 미만) | 같은 방향을 바라봄 (전방) |
| **0 (`== 0`)** | 직각 (90°) | 서로 수직 |
| **음수 (`< 0`)** | 둔각 (90° 초과) | 반대 방향을 바라봄 (후방) |

* **심화 — 투영(Projection):** 임의의 벡터 `A`와 단위 벡터 `B`를 내적하면 **"A를 B 축에 내린 그림자의 길이"** 가 됩니다. 경사면 미끄러짐(`Vector3.ProjectOnPlane`)이나 벽면 슬라이딩 계산의 핵심 원리입니다.
* **주요 활용:** AI 시야 판정, 셰이더 랑베르(Lambert) 조명 계산, 경사면 이동 보정.

### 3.5 외적 (Cross Product)
3D 공간에서 두 벡터 `A`, `B` 모두에 **수직인 새로운 벡터**를 생성합니다.

```text
|A × B| = |A| × |B| × sin θ   (크기 = 두 벡터가 만드는 평행사변형의 넓이)
A × B   = -(B × A)            (교환법칙 불성립: 순서가 바뀌면 방향이 정반대!)
```

* **왼손 법칙 (Unity 기준):** Unity는 **왼손 좌표계**를 사용합니다. 왼손 손가락을 첫 번째 인자 `A`에서 두 번째 인자 `B` 방향으로 감아 쥘 때, 엄지가 가리키는 방향이 결과 벡터의 방향입니다.
* **주요 활용:** 3D 메시 면의 법선(Normal) 벡터 계산, 대상이 내 왼쪽/오른쪽 어디에 있는지 판정, 직교 좌표축 생성.

## 4. 코드로 보기

### 4.1 Unity `Vector3` 기본 연산
```csharp
using UnityEngine;

public class VectorBasicsExample : MonoBehaviour
{
    [SerializeField] private Transform target;
    [SerializeField] private float moveSpeed = 5f;
    [SerializeField] private float fullFovDegrees = 120f;

    private void Update()
    {
        if (target == null) return;

        // 1) 목적지 - 출발지: 방향과 거리를 동시에 담은 변위 벡터
        Vector3 toTarget = target.position - transform.position;

        // 2) 거리(크기)와 방향(단위 벡터)
        // 공식: Mathf.Sqrt(x*x + y*y + z*z)
        float distance = toTarget.magnitude;

        // 공식: toTarget / distance (Unity 내장 normalized는 영벡터일 때 안전하게 Vector3.zero 반환)
        Vector3 direction = toTarget.normalized;

        // 3) 적을 향해 초속 moveSpeed(m/s)로 이동
        transform.position += direction * (moveSpeed * Time.deltaTime);

        // 4) 내적을 활용한 시야 판정 (전체 시야각 120도 -> 정면 기준 좌우 각 60도 이내)
        float dot = Vector3.Dot(transform.forward, direction);
        float cosHalfFov = Mathf.Cos(fullFovDegrees * 0.5f * Mathf.Deg2Rad);
        bool isInView = dot >= cosHalfFov;
    }
}
```

### 4.2 잘못된 코드 vs 안전한 코드 (Before / After)

```csharp
// [Before] 흔한 실수 4가지

// 실수 1: 수동 정규화 시 영벡터(거리 0) 나누기 -> NaN 발생
Vector3 manualDir = toTarget / toTarget.magnitude;

// 실수 2: 단순 거리 비교에 매 프레임 제곱근(magnitude) 호출
if ((a - b).magnitude < 10f) { /* ... */ }

// 실수 3: Dot 결과(-1 ~ 1)를 각도(도)로 착각
float dot = Vector3.Dot(a, b);
if (dot > 60f) { /* 절대 true가 될 수 없음 */ }

// 실수 4: 부동소수점 오차(1.0000001f 등)를 방어하지 않은 Acos -> NaN 위험
float rawDot = Vector3.Dot(a.normalized, b.normalized);
float unsafeAngle = Mathf.Acos(rawDot) * Mathf.Rad2Deg;
```

```csharp
// [After] 실무 표준 패턴

// 1) 영벡터 방어 후 정규화 (LookRotation 등에 Vector3.zero가 넘어가는 것도 차단)
Vector3 toTarget = target.position - transform.position;
Vector3 dir = toTarget.sqrMagnitude > 0.0001f ? toTarget.normalized : transform.forward;

// 2) sqrMagnitude로 제곱근 없이 빠른 거리 비교
const float range = 10f;
if ((a - b).sqrMagnitude < range * range) { /* ... */ }

// 3) 정확한 각도가 필요할 때는 Clamp로 NaN 방지 (또는 Vector3.Angle 사용)
float clampedDot = Mathf.Clamp(Vector3.Dot(a.normalized, b.normalized), -1f, 1f);
float safeAngleDeg = Mathf.Acos(clampedDot) * Mathf.Rad2Deg;

// 4) 대각선 이동 속도(1.414배) 방지 + 아날로그 조이스틱 세밀함 유지
Vector3 moveInput = new Vector3(Input.GetAxis("Horizontal"), 0f, Input.GetAxis("Vertical"));
Vector3 clampedMove = Vector3.ClampMagnitude(moveInput, 1f); // 크기 1 초과는 자르고, 1 이하는 유지
```

> **`Vector3.zero.normalized`는 정말 `NaN`이 나올까?**\
> Unity의 `Vector3.normalized`는 내부적으로 크기가 `1E-05f` 이하이면 `Vector3.zero`를 반환하도록 방어되어 있어 직접 `NaN`을 뱉지는 않습니다.\
> **진짜 위험한 지점**은 ① 수동 나눗셈(`v / v.magnitude`)으로 `0 / 0 = NaN`이 발생하는 경우와, ② `(0, 0, 0)`을 유효한 방향 벡터로 착각하고 `Quaternion.LookRotation(dir)` 등에 넘겨 경고/회전 오류를 일으키는 경우입니다.

## 5. 활용 예시 (게임 도메인: 실무형 EnemyAI)
> 적이 플레이어를 **수평 시야(120°)** 와 **10m 사거리** 안에서 감지하면 추격합니다.\
> *(성능 캐싱, `out`을 통한 중복 연산 제거, 3D 높이차 보정 반영)*

```csharp
using UnityEngine;

public class EnemyAI : MonoBehaviour
{
    [SerializeField] private Transform player;
    [SerializeField] private float fovDegrees = 120f;
    [SerializeField] private float sightRange = 10f;
    [SerializeField] private float moveSpeed = 3f;

    // 매 프레임 삼각함수·곱셈을 반복하지 않도록 미리 캐싱
    private float _cosHalfFov;
    private float _sqrSightRange;

    private void Awake()
    {
        CacheDetectionValues();
    }

    // Inspector에서 값을 바꿀 때도 즉시 캐시 갱신 (에디터 편의성)
    private void OnValidate()
    {
        CacheDetectionValues();
    }

    private void CacheDetectionValues()
    {
        _cosHalfFov = Mathf.Cos(fovDegrees * 0.5f * Mathf.Deg2Rad);
        _sqrSightRange = sightRange * sightRange;
    }

    private void Update()
    {
        if (TryGetDirectionToVisiblePlayer(out Vector3 moveDir))
        {
            transform.position += moveDir * (moveSpeed * Time.deltaTime);
        }
    }

    private bool TryGetDirectionToVisiblePlayer(out Vector3 dirToPlayer)
    {
        dirToPlayer = Vector3.zero;
        if (player == null) return false;

        Vector3 toPlayer = player.position - transform.position;
        toPlayer.y = 0f; // 3D 지형 높이 차이로 인한 수평 시야 왜곡 방지

        // 1단계(가장 쌈): 거리 체크 (sqrMagnitude + 영벡터 방어)
        float sqrDist = toPlayer.sqrMagnitude;
        if (sqrDist > _sqrSightRange || sqrDist < 0.0001f)
            return false;

        // 2단계: 시야각 체크 (Dot + 캐싱된 cos 값)
        dirToPlayer = toPlayer / Mathf.Sqrt(sqrDist); // sqrDist를 재활용해 중복 연산 절약
        Vector3 flatForward = new Vector3(transform.forward.x, 0f, transform.forward.z).normalized;

        float dot = Vector3.Dot(flatForward, dirToPlayer);
        return dot >= _cosHalfFov;
    }
}
```

## 6. 실전에서는?

### 상황별 Unity API 선택 치트시트
| 알고 싶은 것 | 추천 API / 패턴 | 이유 |
| :--- | :--- | :--- |
| 시야 안/밖 판정 (`bool`) | `Vector3.Dot` + 캐싱된 `cos` 비교 | `Acos` 없이 곱셈·덧셈만 수행 (가장 저렴) |
| 두 벡터 사이의 실제 각도 (`0°~180°`) | `Vector3.Angle(a, b)` | 내부적으로 정규화 및 `Clamp` + `Acos` 안전 처리 |
| 좌/우 부호 포함 각도 (`-180°~180°`) | `Vector3.SignedAngle(a, b, Vector3.up)` | 회전 방향과 각도를 한 번에 안전하게 획득 |
| 단순 좌/우 판정 (`bool`) | `Vector3.Cross(fwd, dir).y` 부호 또는 `Dot(right, dir)` | `Dot(fwd, dir)` 하나만으로는 좌우 구분 불가 |
| 거리 비교 / 최단 거리 탐색 | `sqrMagnitude` | 제곱근(`Sqrt`) 생략 |
| UI 표시용 실제 거리 | `magnitude` / `Vector3.Distance` | 사람이 읽을 정확한 미터(m) 단위가 필요할 때 |
| 이동 입력 크기 제한 | `Vector3.ClampMagnitude(input, 1f)` | 대각선 가속 방지 + 조이스틱 미세 입력 유지 |

### 성능 최적화는 "무엇을 쓰나"보다 "몇 번 부르나"가 결정한다
* **적 10마리가 매 프레임 검사:** `magnitude`든 `sqrMagnitude`든 체감 차이가 없습니다. 가독성이 좋은 쪽을 택하세요.
* **적 수백 마리가 서로를 검사:** 호출이 수만~수십만 회를 넘어가면 `sqrMagnitude`와 **조기 반환(Early Return) 파이프라인**이 빛을 발합니다.
  > **추천 판정 순서:** `거리(sqrMagnitude)` → `시야각(Dot)` → `벽 가림 검사(Physics.Raycast)` *(싼 검사부터 배치)*
* **근본적 최적화:** 수식을 깎는 것보다 **검사 횟수 자체를 줄이는 전략**(감지 주기를 0.1~0.2초로 분산, 쿼드트리/그리드 공간 분할)이 훨씬 큰 효과를 냅니다.

### 실무에서 자주 발목 잡히는 3가지
1. **2D 게임에서 `Vector3` 혼용:** 물리·이동 계산은 `Vector2`로 고정해 Z축 오염을 원천 차단하고, `transform.position` 대입 경계에서만 변환하세요.
2. **3D 지형의 높이(Y축) 오염:** 탑다운·쿼터뷰·FPS 수평 시야나 이동에서 `y` 성분을 제거(`y = 0f`)하지 않으면 언덕 위 적을 감지 못하거나 땅으로 파고드는 버그가 생깁니다.
3. **float 동등 비교 금지:** `dir == Vector3.zero` 대신 `sqrMagnitude > 0.0001f`처럼 오차 허용치(Epsilon) 기반으로 판정하는 습관을 들이세요.

## 7. 실습문제

1. 2D 벡터 `(3, 4)`의 크기(Magnitude)는?
2. 점 `A`에서 점 `B`로 향하는 방향 벡터는 어떻게 구하나요?
3. 두 점 `A = (1, 2, 3)`, `B = (4, 6, 3)` 사이의 거리를 구하세요.
4. `Vector3.Dot(a.normalized, b.normalized) == 0.5f`일 때 두 벡터 사이의 각도는?
5. `magnitude`와 `sqrMagnitude`의 성능 차이를 설명하고, 각각 어떤 상황에 쓰는지 논하세요.

<details>
<summary>정답 및 해설 보기</summary>

1. **5** — $\sqrt{3^2 + 4^2} = \sqrt{9 + 16} = \sqrt{25} = 5$
2. **`B - A`** (목적지 - 출발지). 길이 1의 순수 방향만 필요하다면 `(B - A).normalized`를 사용합니다.
3. **5** — 변위 벡터 `B - A = (3, 4, 0)`이므로 거리는 $\sqrt{3^2 + 4^2 + 0^2} = 5$입니다.
4. **60°** — 두 벡터가 정규화되어 있으므로 내적 결과 `0.5`는 곧 $\cos\theta = 0.5$를 의미합니다. 따라서 $\theta = 60^\circ$입니다.
5. **`magnitude`는 제곱근(`Sqrt`) 연산을 포함하고, `sqrMagnitude`는 제곱합만 계산합니다.** 단순 거리 비교(공격 사거리 체크, 가장 가까운 적 탐색 등)에서는 제곱근을 생략한 `sqrMagnitude`가 유리하며, UI에 "남은 거리 12.5m"처럼 실제 거리 값을 표시하거나 정확한 길이로 벡터를 나눠야 할 때는 `magnitude`(`Vector3.Distance`)를 사용합니다.

</details>

## 8. 이것만은 기억하자

* **방향은 `목적지 - 출발지`, 비교 전엔 항상 정규화:** 단위 벡터(길이 1)로 맞춰야 내적과 이동 속도 계산이 왜곡되지 않습니다.
* **NaN 2대 원흉을 차단하라:** 수동 정규화 시 `0` 나누기 금지, `Mathf.Acos(dot)` 호출 전 `Mathf.Clamp(dot, -1f, 1f)` 필수
* **거리 비교는 `sqrMagnitude`, 시야 판정은 `Dot + cos(FOV/2)`, 좌우 구분은 `Cross` 또는 `SignedAngle`.**
* **대각선 이동엔 `ClampMagnitude`, 3D 수평 계산엔 `y = 0f` 평면화**를 습관으로 만드세요.
