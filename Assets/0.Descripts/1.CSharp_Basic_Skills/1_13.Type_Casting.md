# [C# 기초] 13. 형 변환 (Type Casting)

## 1. 형 변환이란? (Type Casting)
C#은 변수마다 담을 수 있는 타입이 엄격하게 정해져 있는 정적 형식(Statically-typed) 언어입니다. 성격이 다른 값을 한자리에 놓으려면 반드시 **'형 변환'** 이라는 과정이 끼어듭니다.

> **비유 : 다른 그릇에 물 옮겨 담기**
> * **암시적 변환** : 계량컵(`int`)의 물을 큰 비커(`double`)에 부으면 아무 일도 없이 넉넉하게 들어갑니다.
> * **명시적 변환** : 큰 비커(`double`)의 물을 작은 계량컵(`int`)에 부으면 물이 넘칩니다. **"넘치는 만큼 버리겠다!"** 라고 프로그래머가 서명(`(int)`)을 해야만 부을 수 있습니다.
> * **파싱(Parsing)** : 물이 든 컵에 "콜라"라고 라벨이 붙어있다고 콜라가 되진 않습니다. 문자열 `"10"`을 숫자 `10`이라 우기면 그릇째 바꾸는 게 아니라 **내용물을 아예 새로 만들어야(파싱)** 합니다.

**왜 자주 발생할까요?**
1. 체력 100의 35%는 실수(35.0)지만, 화면에는 정수(35)로 찍어야 할 때
2. 사용자 입력(`Console.ReadLine()`)은 무조건 문자열(`string`)로 들어올 때
3. 모든 것을 담을 수 있는 만능 상자(`object`)에서 본래 값을 다시 꺼낼 때

## 2. 핵심 요약

| 방식              | 문법 예시 | 언제 쓰나? | 실패하면? |
|:----------------| :--- | :--- | :--- |
| **암시적 변환**      | `double d = 10;` | 손실이 없는 방향 (작은 타입 ➔ 큰 타입) | 자동 처리 (실패 안 함) |
| **명시적 변환 (캐스트)**| `int n = (int)3.9;` | **손실을 감수하고** 좁은 타입으로 구겨 넣을 때 | 데이터가 잘리거나 오버플로우 |
| **문자열 파싱**      | `int.TryParse(s, out n)`| 글자로 적힌 숫자를 진짜 숫자로 만들 때 | `false` 반환 (안전함) |
| **Convert 클래스** | `Convert.ToInt32(x)`| 타입을 가리지 않고 숫자로 변환 (반올림 발생) | 형식이 안 맞으면 예외 발생 |
| **박싱 / 언박싱**    | `object o = 10; / (int)o` | 값 타입을 `object`에 넣거나 뺄 때 | 타입이 100% 일치 안 하면 예외 |
| **C# 패턴 매칭**    | `if (o is int n)` | `object` 안의 값을 안전하게 검사하고 꺼낼 때 | `false` 반환 (가장 안전) |

## 3. 세부 개념 및 실무 원리

### 3.1 암시적 변환 (손해 볼 것이 없을 때)
담을 그릇이 원래 그릇보다 크면 컴파일러가 알아서 옮겨 담습니다.
```csharp
int level = 7;
float ratio = level;       // int ➔ float : 7이 7.0f로 자연스럽게 승격됨
double precise = ratio;    // float ➔ double : 더 정밀한 상자로 이동
```
**정수 나눗셈의 함정**
```csharp
int currentHp = 7;
int maxHp = 10;

float badRatio = currentHp / maxHp;          // 결과: 0 (7/10이 정수 0으로 계산된 후 float에 담김)
float goodRatio = (float)currentHp / maxHp;  // 결과: 0.7 (한쪽을 float으로 캐스팅해야 실수 계산이 됨)
```

### 3.2 명시적 변환 (손실을 감수한다는 서명)
좁은 타입으로 가는 방향은 `(타입)` 기호를 값 앞에 직접 적어야 합니다.
**캐스트는 반올림이 아니라 '가차 없는 버림(0을 향해 자름)'입니다.**
* `(int)3.9` ➔ `3`
* `(int)-3.9` ➔ `-3` (내림을 해서 -4가 되는 것이 아님!)

### 3.3 문자열은 캐스트로 바뀌지 않습니다 (파싱)
메모리에 놓인 형태가 아예 다르기 때문에 `(int)"10"`은 컴파일 오류가 납니다.\
글자를 읽어서 숫자를 새로 그리는 **파싱(Parsing)** 이 필요합니다. 사용자 입력을 받을 때는 묻지도 따지지도 않고 **`TryParse`** 가 정답입니다.
```csharp
// int.Parse("abc") -> FormatException 예외 뿜고 게임 크래시
if (int.TryParse("25", out int age)) 
{
    Console.WriteLine($"성공: {age}");
}
```

> **`Convert.ToInt32()`의 반올림 주의 (Banker's Rounding)**\
> 캐스트(`(int)3.7`)는 소수점을 버리지만, `Convert.ToInt32(3.7)`은 `4`로 반올림합니다.\
> 특이한 점은 **정확히 0.5일 때는 가장 가까운 짝수로 간다**는 것입니다.
> * `Convert.ToInt32(2.5)` ➔ `2` (3이 아님)
> * `Convert.ToInt32(3.5)` ➔ `4`

### 3.4 무엇이든 담는 `object`, 그리고 박싱/언박싱
`object`는 C#의 모든 타입이 물려받는 뿌리(최상위 부모)입니다. 무엇이든 다 들어갑니다.
* **박싱 (Boxing)**: 값 타입(`int` 등)을 `object`에 넣는 일 (자동이지만 힙 메모리 할당 발생 ➔ 성능 저하)
* **언박싱 (Unboxing)**: `object`에서 값 타입을 꺼내는 일 (명시적 캐스팅 필수)
```csharp
object boxed = 10;           // int가 힙 메모리로 박싱됨
long wrong = (long)boxed;    // InvalidCastException / int로 넣었으면 무조건 int로만 꺼내야 함
long right = (int)boxed;     // int로 먼저 언박싱한 뒤, long으로 암시적 변환됨
```

### 3.5 타입 패턴 매칭 (is 변수명) 
과거에는 `as`를 쓰고 `null`을 체크하거나, `is`로 묻고 다시 `(int)`로 캐스팅하는 두 번의 수고를 겪었습니다. 최근 C#에서는 이 모든 것을 한 줄로 끝냅니다.

```csharp
object value = "홍길동";

// [C# 표준] 검사와 동시에 꺼내기 (값 타입, 참조 타입 모두 가능)
if (value is string text) 
{
    // value가 string이 맞다면, text 변수에 예쁘게 담아준다
    Console.WriteLine($"이름: {text.ToUpper()}"); 
}
else
{
    Console.WriteLine("문자열이 아닙니다.");
}
```
> **팁**: `as` 연산자는 값 타입(`int` 등)에 쓸 수 없고 실수로 `null` 체크를 빼먹을 위험이 크므로, C#에서는 **`is 변수명` 형태의 패턴 매칭을 기본으로 사용**하는 것을 권장합니다.

## 4. 활용 예시 (게임 도메인)

### 4.1 체력 바와 데미지 계산 (정수와 실수의 만남)
```csharp
int maxHp = 250;
int currentHp = 173;

// 1. 표시용 비율: 나누기 전에 반드시 한쪽을 실수(float)로 캐스팅
float hpRatio = (float)currentHp / maxHp; 
int hpPercent = Mathf.RoundToInt(hpRatio * 100); // Unity 방식 반올림

// 2. 데미지 계산: 배율은 실수, 실제 깎이는 값은 정수
int baseDamage = 37;
float critMultiplier = 1.75f;

// baseDamage가 float으로 승격(Promotion)되어 계산됨
float rawDamage = baseDamage * critMultiplier; 
int finalDamage = (int)rawDamage; // 소수점 버림 (게임 기획에 따라 Round를 쓸지 결정)
```

### 4.2 타입이 섞인 저장 데이터 안전하게 읽기
```csharp
object[] saveData = { "용사", 42, 0.75f, true, null };

foreach (object field in saveData)
{
    // C# 패턴 매칭
    if (field is string name)       Console.WriteLine($"[이름] {name}");
    else if (field is int level)    Console.WriteLine($"[레벨] {level}");
    else if (field is float ratio)  Console.WriteLine($"[비율] {ratio * 100}%");
    else if (field is bool isAlive) Console.WriteLine($"[상태] {isAlive}");
    else Console.WriteLine($"[알 수 없음 또는 null] {field}"); 
}
```

## 5. Unity 최적화 꿀팁

### 5.1 실수를 정수로 바꿀 때의 무기들
Unity에서는 좌표나 남은 쿨타임을 정수로 보여줄 일이 많습니다.

| Unity 메서드 | 2.7f | -2.7f | 어울리는 곳 |
| :--- | :--- | :--- | :--- |
| `(int)` 캐스트 | 2 | -2 | 값이 절대적으로 양수일 때만 |
| `Mathf.FloorToInt` | 2 | **-3** | **타일맵/그리드 좌표 계산 (음수 원점 처리용)** |
| `Mathf.CeilToInt` | 3 | -2 | 남은 쿨타임 초 표시 (0.1초 남아도 1초로 표시) |
| `Mathf.RoundToInt` | 3 | -3 | 최종 점수나 퍼센트 UI 표시 (0.5는 짝수 쪽으로 감) |

### 5.2 `Update()` 안의 `Debug.Log`
`Debug.Log(object message)`는 매개변수로 `object`를 받습니다.
```csharp
int score = 1200;

// score(int)가 object로 변환되면서 '박싱(Boxing)' 발생 -> 힙 메모리에 쓰레기 생성
Debug.Log(score); 
Debug.Log($"점수 {score}"); // Unity 6 (C# 9) 환경에서도 string.Format을 거치며 박싱 발생
```
한두 번은 괜찮지만, `Update()` 안에서 매 프레임 초당 60번씩 박싱이 일어나면 가비지 컬렉터(GC)가 작동하여 **게임 프레임이 뚝뚝 끊깁니다(스파이크).**\
➔ **해법**: 매 프레임 도는 로그는 배포 전 반드시 지우고, UI 텍스트 갱신이 빈번하다면 `StringBuilder`를 사용하세요.

## 6. 실습 문제 및 복습

**Q1. 아래 4줄 중 컴파일 오류가 나는 줄을 고르고 고쳐보세요.**
```csharp
long a = 100;
int b = 3.14;
float c = 2.5;
double d = 7;
```
> **오류 1**: `int b = 3.14;` (double ➔ int는 데이터 손실이 있으므로 명시적 캐스팅 필요. `int b = (int)3.14;`)\
> **오류 2**: `float c = 2.5;` (C#에서 소수점의 기본 타입은 double입니다. `float c = 2.5f;`로 접미사 f 필수)

**Q2. 아래 코드의 출력값을 예측하세요.**
```csharp
Console.WriteLine((int)3.9);               // 1번
Console.WriteLine((int)(-3.9));            // 2번
Console.WriteLine(Convert.ToInt32(3.9));   // 3번
Console.WriteLine(7 / 2);                  // 4번
```
> 1번: `3` (소수점 가차 없이 버림)\
> 2번: `-3` (0을 향해 버리므로 -4가 아님)\
> 3번: `4` (Convert는 반올림)\
> 4번: `3` (정수 나눗셈은 몫만 남음)

**Q3. `object` 변수에서 값을 꺼낼 때 캐스팅(`(int)obj`)을 바로 하지 않고 `is`를 사용하는 이유는?**
> 담겨 있는 타입과 정확히 100% 일치하지 않으면 `InvalidCastException` 예외가 발생하며 게임이 터지기 때문입니다. C#에서는 `if (obj is int number)` 형태로 안전하게 검사와 언박싱을 동시에 처리하는 것이 실무 표준입니다.

## 7. 주의사항 및 안전 습관

* **정수 나눗셈의 비극을 잊지 마라**: `float rate = a / b;`는 이미 0이 된 결과를 실수로 바꿀 뿐입니다. 반드시 `(float)a / b;` 처럼 나누기 **전**에 캐스팅하세요.
* **캐스트는 내림이 아니다**: 음수 `(int)-3.9`는 `-3`이 됩니다. 타일 좌표계처럼 정확한 내림이 필요하면 반드시 `Mathf.FloorToInt()`를 쓰세요.
* **입력값은 모두 적이다**: 사용자나 파일, 네트워크에서 들어오는 문자열은 무조건 `TryParse`로 방어하세요. `Parse`는 한 글자만 잘못 들어와도 게임을 강제 종료시킵니다.
* **박싱을 경계하라**: 값 타입(`int`, `struct`)을 굳이 `object`에 넣거나 인터페이스로 캐스팅하면 힙 메모리가 낭비됩니다. 반복문(Update) 안에서는 특히 조심하세요.
