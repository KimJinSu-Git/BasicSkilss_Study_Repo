# [C# 기초] 11. 참조 (Reference)와 값 전달

## 1. 참조(Reference)란?
메서드에 데이터를 전달할 때, C#은 두 가지 방식을 사용합니다. 하나는 **데이터의 알맹이(값)를 복사**해서 주는 것이고, 다른 하나는 원본 데이터가 있는 **위치(주소)를 알려주는 것**입니다.

> **비유 : 친구에게 요리 레시피를 공유하는 법**
> * **값에 의한 전달 (Pass by Value)** : 내 레시피를 종이에 **복사**해서 건네줍니다. 친구가 복사본에 낙서를 하거나 찢어버려도 **내 원본 레시피는 안전**합니다. (C#의 기본 방식)
> * **참조에 의한 전달 (Pass by Reference)** : 내 레시피북이 꽂혀 있는 **책장의 위치(주소)**를 알려줍니다. 친구가 그 위치로 가서 내용을 수정하면, **내 원본 레시피도 함께 변경**됩니다. (`ref`, `out` 키워드 사용 시)

**왜 필요한가?**\
이 차이를 완벽히 이해해야 메서드가 내 데이터를 마음대로 수정할 수 있는지(부작용)를 통제할 수 있습니다. 특히 게임 엔진(Unity)에서 `struct`(값 타입)와 `class`(참조 타입)가 메모리에서 다르게 동작하는 원리를 깨달아 치명적인 버그를 막을 수 있습니다.

## 2. 핵심 요약

| 구분 | 한 줄 설명                                                         |
| :--- |:---------------------------------------------------------------|
| **값 타입 (Value Type)** | 변수 자체가 스택(Stack) 메모리에 **실제 데이터**를 가짐 (`int`, `bool`, `struct`) |
| **참조 타입 (Reference Type)**| 변수는 힙(Heap) 메모리의 **주소(리모컨)** 만 가짐 (`class`, `array`, `string`) |
| **값에 의한 전달** | 기본 동작. 인자로 넘길 때 변수 안의 내용물(값 또는 주소값)이 **복사**됨                   |
| **`ref`** | 참조에 의한 전달. 호출 전 **반드시 초기화**해야 하며, 메서드 내에서 읽기/쓰기 가능             |
| **`out`** | 참조에 의한 전달. 초기화 불필요. 단, 메서드 종료 전 **반드시 값을 할당(쓰기)** 해야 함         |
| **`in` (C# 7.2+)** | 참조에 의한 전달. 원본 수정이 불가능한 **읽기 전용** (거대한 구조체 복사 비용 방지용)           |

## 3. 세부 개념 및 메모리 원리
### 3.1 값에 의한 전달 (Pass by Value) - C#의 기본
C#에서 매개변수를 넘길 때는 **무조건 변수 안의 내용물이 복사**됩니다. 단, 그 내용물이 '진짜 값'인지 '주소값'인지에 따라 결과가 다릅니다.

* **값 타입 전달 (`int`, `struct`)**: 숫자 자체가 통째로 복사됩니다. 메서드에서 매개변수를 아무리 바꿔도 **원본에는 영향이 없습니다.**
* **참조 타입 전달 (`class`, `array`)**: 변수가 들고 있던 **'주소값'이 복사**됩니다.
    * 복사된 주소를 타고 들어가 안쪽 데이터(`enemy.hp`)를 고치면 **원본도 바뀝니다.**
    * 하지만 매개변수 자체에 아예 새로운 객체를 할당(`enemy = new Enemy();`)하면, 복사된 리모컨의 주파수만 바뀔 뿐 **원본 리모컨이 가리키는 곳은 변하지 않습니다.**

### 3.2 `ref` - 원본 변수 자체를 통째로 넘김 (읽기/쓰기)
호출하는 쪽과 받는 쪽 모두 `ref`를 명시해야 합니다. **호출 전에 반드시 값이 초기화**되어 있어야 합니다.
* 대표 사용처: 두 변수의 값을 맞바꾸는 `Swap` 메서드

### 3.3 `out` - 결과를 받아올 빈 상자만 넘김 (쓰기 전용)
호출 전 초기화가 필요 없습니다. 대신 메서드는 종료되기 전에 **반드시 `out` 매개변수에 값을 채워 넣어야 합니다.**
* 대표 사용처: 성공 여부(`bool`)와 결과값(`int`)을 동시에 반환하는 `int.TryParse(input, out int result)`

### 3.4 `ref` vs `out` 요약 비교
| 항목 | `ref` | `out` |
| :--- | :--- | :--- |
| **호출 전 초기화** | 필수 | 불필요 |
| **메서드 내 값 할당**| 선택 (안 바꿔도 됨) | **필수 (무조건 채워야 함)** |
| **의도** | 원본을 읽고/쓰겠다 | 메서드의 결과값을 반환하겠다 |

## 4. 코드로 보는 참조와 전달

### 4.1 `ref`와 `out`의 기본 예시
```csharp
// 1. Swap 메서드 — ref 활용의 정석
void Swap(ref int a, ref int b)
{
    int temp = a;
    a = b;
    b = temp;
}

int num1 = 10, num2 = 20;
Swap(ref num1, ref num2); // 변수 자체를 통째로 넘김
Console.WriteLine($"num1={num1}, num2={num2}"); // num1=20, num2=10 (원본 바뀜)

// 2. 여러 값을 동시에 반환 — out 활용
bool TryGetMonsterStats(string id, out int hp, out int atk)
{
    if (id == "Orc") 
    { 
        hp = 120; atk = 15; // 메서드 종료 전 반드시 할당
        return true; 
    }
    
    hp = 0; atk = 0; // 실패 시에도 out 매개변수는 무조건 채워야 컴파일 통과
    return false;
}

// 최신 C#에서는 호출과 동시에 out 변수를 선언할 수 있습니다. (인라인 선언)
if (TryGetMonsterStats("Orc", out int orcHp, out int orcAtk))
{
    Console.WriteLine($"오크 발견! HP: {orcHp}, ATK: {orcAtk}");
}
```

### 4.2 참조 타입의 '값에 의한 전달' 함정
```csharp
public class Player { public int hp = 100; }

void ModifyPlayer(Player p) // 주소값이 '복사'되어 들어옴
{
    // 1. 주소를 타고 들어가 내부를 바꾸면 원본도 바뀜
    p.hp = 999; 

    // 2. 아예 새로운 주소를 덮어씌우면?
    p = new Player(); 
    p.hp = 50; // 복사된 리모컨(p)만 새 객체를 가리킬 뿐, 밖의 원본과는 연결이 끊어짐.
}

Player myPlayer = new Player();
ModifyPlayer(myPlayer);
Console.WriteLine(myPlayer.hp); // 결과는 999 (50이 아님)
```

## 5. Unity에서의 활용 및 주의점

Unity에서 `struct`와 `class`의 차이를 모르면 지옥 같은 디버깅을 겪게 됩니다.

```csharp
using UnityEngine;

public class UnityMemoryExample : MonoBehaviour
{
    void Start()
    {
        // 1. Vector3는 값 타입(struct)입니다.
        Vector3 pos = transform.position; 
        pos.x += 10f; // 복사본의 x값만 바뀝니다.
        // transform.position은 전혀 변하지 않음! (버그 발생의 주범)
        // 올바른 방법: transform.position = pos; (다시 덮어씌워야 함)

        // 2. GameObject, Transform, Component는 모두 참조 타입(class)입니다.
        Transform myTransform = transform; // 주소만 복사됨
        myTransform.position = new Vector3(0, 0, 0); // 원본(자신)의 위치가 0,0,0으로 이동함!
    }
}
```
> **핵심 팁**: Unity의 `Vector3`, `Quaternion`, `Color`는 모두 `struct`(값 타입)입니다. 메서드에 넘기거나 변수에 담을 때 통째로 복사되므로, 내부 변수를 수정한 뒤에는 반드시 원본에 다시 할당해 주어야 합니다.

## 6. 실습 문제 및 복습

**Q1. `ref`와 `out`의 가장 큰 차이는? (초기화 시점, 값 할당 의무 관점에서)**
> * `ref`: 호출 전 변수가 반드시 **초기화**되어 있어야 하고, 메서드 내부에서는 값을 읽거나 쓰거나 자유롭습니다. (의도: "이미 있는 변수를 조작하겠다")
> * `out`: 호출 전 초기화가 불필요합니다. 대신 메서드는 종료 전에 **반드시 값을 할당(채워 넣기)** 해야 합니다. (의도: "결과를 담아 돌려줄 빈 그릇이다")

**Q2. 아래 코드의 출력을 예측하고 그 이유를 설명하세요.**
```csharp
public struct Point { public int X, Y; } // 값 타입

Point p1 = new Point { X = 10, Y = 20 };
Point p2 = p1;
p2.X = 100;

int[] arr1 = { 1, 2, 3 }; // 참조 타입
int[] arr2 = arr1;
arr2[0] = 100;

Console.WriteLine($"p1.X = {p1.X}");
Console.WriteLine($"arr1[0] = {arr1[0]}");
```
> **출력**: `p1.X = 10`, `arr1[0] = 100`
> * **이유**: `Point`는 `struct`(값 타입)이므로 `p2 = p1`에서 내용물이 통째로 복사됩니다. 
> * 서로 독립적이므로 `p2`를 고쳐도 `p1`은 안전합니다. 반면 `int[]`는 배열(참조 타입)이므로 `arr2 = arr1`에서 메모리 주소만 복사됩니다. 
> * 두 변수가 같은 힙 메모리를 공유하므로 `arr2`를 고치면 `arr1`도 변합니다.

**Q3. 아래 코드의 `NullReferenceException` 원인을 찾고 안전하게 수정하세요.**
```csharp
public class Enemy { public string Name; }
Enemy enemy = null;
Console.WriteLine($"적의 이름: {enemy.Name}"); // 여기서 폭발
```
> **원인**: 참조 타입 변수가 `null`이라는 것은 가리키는 힙 메모리 객체가 없다는 뜻입니다. 비어있는 리모컨의 버튼(`.Name`)을 누르려 했기 때문에 예외가 발생합니다.
```csharp
안전한 수정 :

// 1. if문 가드
if (enemy != null) Console.WriteLine($"적의 이름: {enemy.Name}");

// 2. C# 널 조건부 연산자 (?.) 활용
Console.WriteLine($"적의 이름: {enemy?.Name ?? "이름 없는 적"}");
```

## 7. 주의사항 및 안전 습관

* **`ref`와 `out`은 신중하게 사용하라**: 메서드가 내 원본 변수를 몰래 바꿀 수 있다는 것은 가독성을 해칩니다. 가능하면 반환값(`return`)이나 튜플(`(int, int)`)을 사용해 명시적으로 결과를 돌려받는 것을 권장합니다.
* **`out` 변수 인라인 선언 적극 활용**: `int result; int.TryParse(..., out result);` 처럼 두 줄로 쓰지 말고, `if(int.TryParse(..., out int result))` 처럼 한 줄로 선언하는 것이 C#의 표준입니다.
* **무거운 구조체는 `in`으로 넘겨라**: 크기가 아주 큰 `struct`를 복사하면 성능이 떨어집니다. 수정할 계획이 없다면 `in` 키워드를 붙여 '읽기 전용 참조'로 넘겨 메모리와 성능을 모두 잡으세요.
