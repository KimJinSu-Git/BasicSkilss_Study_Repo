# [C# 기초] 12. 스코프·정적·상수 (Scope, static, const)

## 1. 스코프·정적·상수란?
코드를 짜다 보면 "이 변수는 어디까지 쓸 수 있지?", "모든 객체가 함께 공유하는 값은 어떻게 만들지?", "절대 바뀌면 안 되는 값은?" 같은 질문이 생깁니다. 이 질문들에 대한 답이 각각 **스코프(Scope)**, **정적(`static`)**, **상수(`const`/`readonly`)** 입니다.

> **비유 : 학교 생활**
> * **스코프 (Scope)** : 물건의 '활동 영역'입니다. 내 책상 위 지우개는 내 자리에서만(블록), 학급 비품은 교실 안에서만(클래스) 씁니다.
> * **`static` (정적)** : 교실 앞의 **'칠판'** 입니다. 모든 학생(객체)이 함께 보는 단 하나의 자원이며, 한 사람이 낙서를 지우면 모두에게서 지워집니다.
> * **`const` (상수)** : 학교 건물 대리석에 새겨진 **'교훈'** 입니다. 건물을 지을 때(컴파일) 새겨 넣었으므로 학기 중(실행 중)에는 절대 바꿀 수 없습니다.

**왜 필요한가?**
* **스코프**는 변수 이름이 부딪히는 것을 막고, 쓸모가 끝난 변수를 메모리에서 제때 치워 줍니다.
* **`static`** 은 객체를 일일이 만들지 않고도 공용 자원에 쉽게 접근하게 해줍니다.
* **`const` / `readonly`** 는 중요한 기획 데이터(최대 레벨 등)가 실수로 변경되는 대참사를 막아줍니다.

## 2. 핵심 요약

| 키워드 | 한 줄 설명 |
| :--- | :--- |
| **스코프 (Scope)** | 변수의 유효 생존 범위. `{ }`가 경계이며, **밖에서는 안이 보이지 않습니다.** |
| **`static`** | 인스턴스(객체)가 아니라 **클래스 자체에 소속**되는 공용 멤버. `클래스이름.멤버`로 접근합니다. |
| **`const`** | **컴파일 시점**에 값이 완전히 고정되는 불변 값. 선언과 동시에 반드시 값을 넣어야 합니다. |
| **`readonly`** | **실행 시점**에 값이 정해지는 불변 값. 선언 자리나 **생성자**에서 단 한 번만 할당 가능합니다. |

## 3. 세부 개념 및 원리

### 3.1 스코프 (Scope)의 규칙
스코프는 변수가 태어나서 죽을 때까지의 생명 주기입니다. 경계선은 항상 중괄호 `{ }` 입니다.

| 종류 | 위치 | 생존 기간 |
| :--- | :--- | :--- |
| **블록 스코프** | `if`, `for` 등의 `{ }` 안 | 블록이 끝나는 순간 메모리에서 소멸 |
| **메서드 스코프** | 메서드 본문의 지역 변수, 매개변수 | 메서드 호출이 끝나면 소멸 |
| **클래스 스코프** | 클래스의 멤버 변수 (필드) | 객체(인스턴스)가 살아 있는 동안 유지 |

**스코프의 단방향 원칙**: 안쪽에서는 바깥쪽 변수를 볼 수 있지만, 바깥쪽에서는 안쪽 변수를 절대 볼 수 없습니다. (예: `for`문 안에서 선언한 변수는 `for`문 밖에서 사용할 수 없음)

### 3.2 `static`: 클래스에 단 하나만 존재하는 공용 자원
일반적인 변수(인스턴스 멤버)는 객체를 `new`로 생성할 때마다 각자 따로 복사해서 가집니다. 하지만 `static`을 붙이면 **클래스 자체에 딱 하나만 생성**되어 모든 객체가 공유합니다.

* **정적 필드**: 인스턴스가 100개든 1000개든 메모리에 단 하나만 존재합니다.
* **정적 메서드**: `new` 없이 `클래스이름.메서드()`로 바로 호출합니다. (예: `Math.Max()`)
    * **주의**: `static` 메서드 안에서는 `this`를 쓸 수 없고, 일반 인스턴스 변수도 만질 수 없습니다. "누구의 변수인지" 알 수 없기 때문입니다.
* **정적 클래스**: 클래스 자체에 `static`을 붙인 것. 내부의 모든 멤버가 `static`이어야 하며, 절대 `new`로 생성할 수 없습니다.

### 3.3 불변의 두 얼굴: `const` vs `readonly`

| 항목 | `const` | `readonly` |
| :--- | :--- | :--- |
| **값이 정해지는 시점** | **컴파일 시점** (건물 지을 때) | **실행 시점** (입학할 때) |
| **초기화 시점** | 선언 시 반드시 값을 넣어야 함 | 생성자에서 동적으로 할당 가능 |
| **할당 가능 타입** | 내장 자료형 (`int`, `bool`, `string` 등) | 제한 없음 (클래스, `DateTime` 등 모두 가능) |
| **메모리 동작** | 자동으로 `static`처럼 동작 (클래스 단위) | 인스턴스마다 다른 불변 값을 가질 수 있음 |

> **팁: `static readonly`의 위력**\
> `const`는 컴파일할 때 값이 호출하는 쪽에 하드코딩(복사)되어 박힙니다. 나중에 값이 바뀌면 부르는 쪽도 다시 컴파일해야 합니다.\
> 따라서 값이 변경될 여지가 조금이라도 있거나, 유연한 타입이 필요할 때는 **`public static readonly`** 를 선언하는 편입니다.

## 4. 코드로 보는 개념

### 4.1 스코프와 생명주기
```csharp
public class Monster
{
    private int _health = 100; // 클래스 스코프 (객체와 운명을 함께함)

    public void Run()
    {
        int speed = 5; // 메서드 스코프

        for (int i = 0; i < 3; i++)
        {
            int boost = i * 2; // 블록 스코프
            speed += boost;    // 안쪽(for)에서 바깥쪽(speed)은 접근 가능
        }
        
        // Console.WriteLine(boost); -> 컴파일 오류! 블록을 벗어나면 boost는 소멸함
    }
}
```

### 4.2 `static`, `const`, `readonly` 종합 예시
```csharp
public class Player
{
    // 1. static (모두가 공유하는 칠판)
    public static int TotalPlayerCount = 0; 
    
    // 2. readonly (객체마다 다르지만, 한 번 정해지면 절대 안 바뀌는 고유 값)
    public readonly string PlayerId; 

    // 3. const (게임 전체에서 절대 변하지 않는 불변의 법칙)
    public const int MaxLevel = 99; 

    public Player(string name)
    {
        // 생성자 안에서 readonly 값을 세팅할 수 있는 마지막 기회
        PlayerId = $"USER_{name}_{DateTime.Now.Ticks}"; 
        
        TotalPlayerCount++; // 새 플레이어가 태어날 때마다 전체 공유 카운트 증가
    }
}
```

## 5. 실전 활용 예시 (Unity 도메인)

### 5.1 궁극의 공유 객체: 싱글턴 패턴 (Singleton Pattern)
Unity에서 `static`이 가장 찬란하게 쓰이는 곳은 단연 매니저(Manager) 클래스입니다.

```csharp
using UnityEngine;

public class GameManager : MonoBehaviour
{
    // 오직 나 자신만을 가리키는 static 변수 (클래스에 딱 하나)
    public static GameManager Instance { get; private set; }   
    
    public int currentScore = 0;

    void Awake()
    {
        // 이미 매니저가 존재한다면, 새로 생긴 녀석은 파괴(Destroy)한다.
        if (Instance != null && Instance != this)
        {
            Destroy(gameObject);
            return;
        }

        Instance = this;
        DontDestroyOnLoad(gameObject); // 씬(Scene)이 넘어가도 파괴되지 않게 보호
    }

    public void AddScore(int amount) { currentScore += amount; }
}

// 다른 스크립트에서의 사용 (FindObjectOfType 같은 무거운 탐색이 필요 없음)
public class Enemy : MonoBehaviour
{
    void OnDeath()
    {
        // static 덕분에 클래스 이름으로 전역 접근이 가능
        GameManager.Instance.AddScore(100); 
    }
}
```
> **Unity 싱글톤 주의사항**:\
> `static` 변수는 씬(Scene)이 재시작되거나 변경되어도 메모리에서 날아가지 않습니다. 따라서 게임 오버 후 재시작할 때 `currentScore = 0;`으로 직접 초기화해주지 않으면 이전 판의 점수가 그대로 남아있는 끔찍한 버그가 발생합니다.

### 5.2 C#: 확장 메서드 (Extension Method)
`static` 클래스와 `static` 메서드를 사용하면, Unity가 만들어둔 기존 클래스(`Transform` 등)에 **내 마음대로 커스텀 기능**을 끼워 넣을 수 있습니다.

```csharp
using UnityEngine;

// 1. 반드시 static 클래스로 만듭니다.
public static class TransformExtensions
{
    // 2. 반드시 static 메서드로 만들고, 첫 번째 매개변수 앞에 'this'를 붙입니다.
    public static void ResetPosition(this Transform transform)
    {
        transform.position = Vector3.zero;
        transform.rotation = Quaternion.identity;
        transform.localScale = Vector3.one;
    }
}

// ⚔사용 예시
public class PlayerMovement : MonoBehaviour
{
    void Respawn()
    {
        // 원래 Unity Transform에는 ResetPosition() 기능이 없지만,
        // 확장 메서드 덕분에 기본 기능처럼 호출할 수 있습니다!
        transform.ResetPosition(); 
    }
}
```

## 6. 실습 문제 및 복습

**Q1. `Math.Max(10, 20)`을 `new Math()`로 객체를 생성하지 않고도 부를 수 있는 이유는?**
> `Max`는 `static` 메서드이기 때문입니다. `Math` 클래스 자체가 정적 클래스라서 객체(인스턴스)를 만들 수 없고 오직 `클래스이름.메서드이름()`으로만 호출해야 합니다.\
> 상태(필드값)를 가지지 않는 단순 수학 계산은 `static` 메서드가 제격입니다.

**Q2. 아래 코드가 컴파일 에러를 내는 이유를 `static`과 `this`의 관점에서 설명하세요.**
```csharp
public class Monster
{
    public int Health = 100;

    public static void DropGold()
    {
        Console.WriteLine("10 골드 드랍!");
        this.Health = -1; // 컴파일 에러
    }
}
```
> **이유**: `DropGold`가 `static` 메서드이기 때문입니다. 정적 메서드는 클래스 자체에 소속되므로 객체를 가리키는 `this` 키워드가 존재하지 않습니다. 따라서 어떤 몬스터(객체)의 `Health`를 깎아야 하는지 알 수 없어 접근이 불가능합니다.

**Q3. 난이도(Easy, Normal, Hard)별 몬스터 체력 배율을 `const`와 `static readonly` 중 무엇으로 선언하는 것이 유리할까요?**
> **`static readonly`를 적극 권장합니다.**
> 기획 수치는 밸런스 패치에 따라 언젠가 바뀔 가능성이 높습니다.\
> `const`는 컴파일 시점에 다른 코드들에 값이 하드코딩으로 박혀버려 버전 관리 시 문제가 생길 수 있습니다.\
> 반면 `static readonly`는 실행 시점에 값을 가져오므로, 추후 외부 파일(JSON, CSV)에서 밸런스 데이터를 읽어와 초기화하도록 구조를 확장하기에도 훨씬 유리합니다.

## 7. 주의사항 및 안전 습관

* **`static`을 전역 변수처럼 남발하지 마라**: "어디서든 접근하기 편하다"는 이유로 `static`을 남용하면, 코드가 거미줄처럼 꼬여 값의 출처를 추적할 수 없는 스파게티 코드가 됩니다. 공용 자원(매니저, 유틸리티 함수)에만 제한적으로 사용하세요.
* **불변을 먼저 고려하라**: 변수를 만들 때 수정할 필요가 없다면 무조건 `readonly`나 `const`를 붙이는 습관을 들이세요. 버그 발생률이 기하급수적으로 낮아집니다.
* **스코프는 최대한 좁게 유지하라**: `for`문 안에서만 쓸 변수를 굳이 클래스 맨 위(필드)에 선언하지 마세요. 변수의 수명은 짧을수록 관리하기 쉽습니다.
