# [C# 기초] 7. 프로그램 흐름 제어 (Controlling Program Flow)

## 1. 흐름 제어란? (Program Flow Control)
프로그램 흐름 제어는 위에서 아래로만 흐르는 코드의 실행 순서를 원하는 대로 조종하는 기술입니다.\
조건에 따라 다른 길을 고르거나(분기), 같은 구간을 되풀이하게(반복) 만들어 상황에 맞게 동작하도록 만듭니다.

> **비유 1 : 요리 레시피**
> * **순차(Sequence)** : "재료를 씻는다 ➔ 썬다 ➔ 냄비에 넣는다" (순서대로)
> * **분기(Selection)** : "해산물이면 화이트 와인, 아니면 물을 넣는다" (조건별로)
> * **반복(Repetition)** : "소스가 졸 때까지 5분간 젓는다" (조건 만족까지)

> **비유 2 : 근무 중 자리를 뜨는 3가지 방식**
> * **`continue`** : "이 서류는 넘기고 다음 서류 주세요" (자리에는 그대로 있음 ➔ 다음 반복 진행)
> * **`break`** : "오늘 이 업무는 여기까지 합시다" (업무를 접음 ➔ 반복문 1개를 빠져나감)
> * **`return`** : "저 퇴근합니다!" (아예 회사를 나감 ➔ 메서드 자체를 통째로 끝냄)

**왜 필요한가?**
흐름 제어가 없으면 프로그램은 단 하나의 시나리오로만 동작합니다. 흐름 제어는 프로그램에 '판단력'을 부여해 입력, 상황, 데이터에 따라 다른 경로를 실행하게 만듭니다.

## 2. 핵심 요약

| 도구 | 무엇을 끝내는가? | 다음에 실행되는 곳 |
| :--- | :--- | :--- |
| **`break`** | 가장 가까운 **반복문 하나** (또는 `switch`) | 그 반복문이 끝난 바로 다음 줄 |
| **`continue`**| **이번 한 바퀴**의 남은 부분 | 같은 반복문의 증감식 ➔ 조건 검사 |
| **`return`** | **메서드 전체** | 이 메서드를 호출했던 원래 위치 |

* 세 키워드의 차이는 "무엇을 끝내는가"가 아니라 **"어디까지 빠져나오는가"** 입니다.
* `break`는 양파 껍질을 한 겹만 벗깁니다. 중첩 반복문 전체를 빠져나오려면 `return`이나 별도의 상태 변수(bool)가 필요합니다.
* `return`을 메서드 앞쪽에 배치해 비정상 상황을 미리 걸러내는 방식을 **가드 절(Guard Clause)** 이라고 합니다.

## 3. 세부 개념 및 실무 팁

### 3.1 `break`는 가장 가까운 반복문 "하나만" 끝냅니다.
```csharp
string[] inventory = { "낡은 검", "폭탄", "빨간 물약" };
string[] banned = { "폭탄", "독약" };

foreach (string item in inventory)
{
    foreach (string ban in banned)
    {
        if (item == ban)
        {
            Console.WriteLine($"{item} 은(는) 반입 금지 물품입니다!");
            break; // 안쪽 foreach만 끝남! 바깥 foreach는 다음 아이템("빨간 물약")으로 정상 진행됨.
        }
    }
}
```
만약 두 겹을 한 번에 빠져나오고 싶다면 `break` 두 번을 쓰는 게 아니라, **메서드로 빼내고 `return`** 하는 것이 가장 깔끔한 실무 해법입니다.

### 3.2 조기 반환(Early Return)과 가드 절(Guard Clause)
메서드 안에서 `if-else`를 깊게 쌓는 대신, 비정상 케이스를 앞쪽에서 `return`으로 잘라 내는 방식입니다. 잘라 내는 `if`문 한 줄 한 줄을 **가드 절**이라고 부릅니다.

```csharp
static int Divide(int a, int b)
{
    if (b == 0) return -1; //  가드: 나눌 수 없는 상황을 먼저 쳐낸다.

    return a / b;          // 여기 온 시점에 'b는 0이 아니다'라는 것이 100% 보장된다.
}
```
> **가드 절의 원칙**
> 1. **가드는 짧아야 한다**: 검사 1줄 + return 1줄. 가드 안에서 여러 처리를 하면 그건 본문입니다.
> 2. **가드는 위로 모은다**: 본문 중간에 흩어진 `return`은 가드가 아니라 숨겨진 '함정'이 됩니다.

### 3.3 화살표 반패턴 (Arrow Anti-Pattern) 피하기
`if` 안의 `if` 안의 `for` 안의 `if`... 들여쓰기가 깊어져 코드가 오른쪽으로 뾰족해지는 현상을 **화살표 반패턴**이라고 부릅니다.
* **비용**: 들여쓰기가 깊어 가독성이 떨어지고, 경우의 수가 곱연산으로 늘어나 디버깅이 지옥이 됩니다.
* **해결책**: 가드 절(조기 반환)로 쳐내기, 메서드로 분리하기, 논리 연산자(`&&`)로 조건 병합하기.

### 3.4 `while(true)` 안에서의 `continue` 주의점
```csharp
int number = 0;
while (true)
{
    number++; // 증감을 무조건 맨 위에 둔다!

    if (number > 10) break;
    if (number % 2 == 0) continue; 

    Console.WriteLine(number);
}
```
`while`문 안에서 `continue`를 쓸 때, 증감식(`number++`)이 `continue`보다 아래에 있으면 무한 루프에 빠집니다.\
**횟수를 제어하며 건너뛸 때는 `for`문을 쓰는 것이 가장 안전**합니다. (`for`문은 `continue`를 만나도 무조건 증감식으로 돌아가기 때문입니다.)

## 4. 코드로 보는 흐름 제어 (Before & After)

### Before: 화살표 반패턴 (최악의 코드)
```csharp
static bool ProcessOrder(Order order)
{
    if (order != null)
    {
        if (order.Items.Count > 0)
        {
            if (order.Customer != null)
            {
                if (order.Customer.IsActive)
                {
                    // 진짜 처리 로직...
                    return true;
                }
            }
        }
    }
    return false;
}
```

### After: 가드 절을 활용한 평탄화 (Flattening)
```csharp
static bool ProcessOrder(Order order)
{
    // 비정상 케이스를 입구에서 모두 쳐냅니다.
    if (order == null) return false;
    if (order.Items.Count == 0) return false;
    if (order.Customer == null) return false;
    if (!order.Customer.IsActive) return false;

    // 진짜 처리 로직 - 들여쓰기가 단 1단계! 코드가 편안해집니다.
    return true;
}
```

## 5. 활용 예시 (숫자 맞히기 게임)
순차, 분기, 반복, 흐름 제어(continue, break)가 한 화면에 모인 종합 선물 세트입니다.

```csharp
Random random = new Random();
int correct = random.Next(1, 101); // 1~100 정답
int attempts = 0;
int maxAttempts = 7;

Console.WriteLine("1~100 사이의 숫자를 맞혀 보세요. 기회는 7번입니다.");

while (true)
{
    Console.Write("추측: ");
    string input = Console.ReadLine();

    // 1. continue: 잘못된 입력은 기회를 깎지 않고 '무르기'
    if (!int.TryParse(input, out int guess))
    {
        Console.WriteLine("숫자만 입력해 주세요.");
        continue; 
    }

    attempts++;

    // 2. break (성공): 게임 종료 출구 1
    if (guess == correct)
    {
        Console.WriteLine($"정답! {attempts}번 만에 맞혔습니다.");
        break; 
    }

    Console.WriteLine(guess > correct ? "너무 큽니다!" : "너무 작습니다!");

    // 3. break (실패): 게임 종료 출구 2
    if (attempts >= maxAttempts)
    {
        Console.WriteLine($"기회를 모두 썼습니다. 정답은 {correct} 였습니다.");
        break; 
    }
}
```

## 6. Unity에서의 흐름 제어

### 6.1 `Update`의 맨 위는 가드 절의 VIP석
`Update()`는 1초에 60번씩 호출됩니다. 따라서 "지금 이 처리를 할 상황인가?"를 묻는 가드 절이 성능 낭비를 막아줍니다.
```csharp
private void Update()
{
    // 가드 — 죽었거나 일시정지 상태면 이번 프레임의 Update 처리는 여기서 끝!
    if (isDead || isPaused) return; 

    HandleMovement();
}
```
> ⚠**주의**: `Update()` 안의 `return`은 게임을 멈추는 게 아닙니다. 단지 **'이번 프레임'의 처리만 스킵**할 뿐, 1/60초 뒤 다음 프레임이 오면 Unity는 다시 `Update()`를 호출합니다.

### 6.2 Unity 흐름 제어 옵션 요약
| 제어 방식 | 효과 | 사용 상황 |
| :--- | :--- | :--- |
| **`return` (가드 절)** | 이번 프레임의 코드 실행만 스킵 (호출은 계속 됨) | 기절, 무적, 일시적 입력 차단 |
| **`enabled = false`** | 컴포넌트 자체를 끔 (Update 호출 자체가 멈춤) | 사망 후 리스폰 대기 등 장기적 중단 |
| **`Time.timeScale = 0f`**| **게임 전체의 시간 흐름을 멈춤** | 진짜 '일시 정지(Pause)' 버튼을 눌렀을 때 |
| **`yield break`** | **코루틴(Coroutine) 내부**를 완전히 종료시킴 | 코루틴 도중 조건이 안 맞아 취소할 때 |

### 6.3 목록을 훑을 때는 `continue`가 기본
게임 내 몬스터 목록 등을 훑을 때는 파괴된(`null`) 객체가 섞여 있기 마련입니다.
```csharp
private void DamageAllEnemies(Collider2D[] enemies, int damage)
{
    foreach (Collider2D enemy in enemies)
    {
        // 파괴된 대상이나 비활성화된 대상은 건너뛴다 (들여쓰기 방지)
        if (enemy == null || !enemy.gameObject.activeInHierarchy) continue; 

        enemy.GetComponent<Health>().TakeDamage(damage);
    }
}
```

## 7. 실습 문제 및 복습

**Q1. `break`, `continue`, `return`이 각각 어디까지 빠져나오는지 한 줄로 설명하세요.**
> * `break` : 가장 가까운 반복문(또는 switch) **하나**를 끝내고 밖으로 나갑니다.
> * `continue` : 반복문을 나가지 않고, **이번 바퀴의 남은 코드만 스킵**한 뒤 다음 바퀴로 넘어갑니다.
> * `return` : 반복문이 몇 겹이든 상관없이, **메서드 자체를 종료**하고 나갑니다.

**Q2. 아래 코드의 최종 출력값을 예측하고 이유를 설명하세요.**
```csharp
int total = 0;
for (int i = 1; i < 10; i++)
{
    if (i % 2 != 0) continue; // 홀수 스킵 (짝수만 통과)
    total += i;               // 2, 4, 6... 누적
    if (total > 10) break;    // 누적값이 10 초과면 탈출
}
Console.WriteLine(total);
```
> **출력값: `12`**
> * i=2 (통과) ➔ total = 2 (조건 미달)
> * i=4 (통과) ➔ total = 6 (조건 미달)
> * i=6 (통과) ➔ total = 12 ➔ `12 > 10` 이므로 `break` 발동!

**Q3. `if`문이 3~4단계 깊게 중첩된 코드(화살표 반패턴)의 문제점과 개선 방법은?**
> * **문제점**: 시각적으로 코드가 우측으로 쏠려 읽기 힘들고, 디버깅 시 경우의 수가 너무 많아 버그를 찾기 힘듭니다. 검사를 하나 추가할 때마다 코드가 더 망가집니다.
> * **개선 방법**:
> 1. **조기 반환 (가드 절)**: 비정상 케이스를 상단에서 `return`으로 차단해 들여쓰기를 없앱니다.
> 2. **메서드 분리**: 안쪽의 복잡한 로직을 따로 메서드로 빼내어 이름을 부여합니다.
> 3. **조건 병합**: 논리 연산자(`&&`)를 사용해 두 겹의 `if`를 한 줄로 합칩니다.

## 8. 주의사항 및 안전 습관

* **`goto`는 봉인하세요**: `switch` 문 내부에서 `goto case`를 쓰는 아주 특수한 상황을 제외하면, C#에서 `goto`는 스파게티 코드의 원흉이 되므로 절대 사용하지 않습니다.
* **`while(true)`를 쓸 때는 `break`부터 적어라**: 무한 루프의 출구를 먼저 만들어 두지 않으면, 본문을 작성하다가 까먹고 에디터를 멈추게(프리징) 만듭니다.
* **가드 절은 최상단에 모아라**: 본문 코드 중간중간에 뜬금없이 등장하는 `return`은 읽는 사람을 당황하게 만드는 지뢰입니다.
* **반복문 탈출 조건은 `==`보다 `>=`가 안전하다**: `if (score == 100) break;`로 해두면 버프를 받아 105점이 되었을 때 루프가 안 끝날 수 있습니다. `if (score >= 100)`으로 처리하는 것이 훨씬 안전합니다.
