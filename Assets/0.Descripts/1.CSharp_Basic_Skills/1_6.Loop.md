# [C# 기초] 6. 반복문 (Loop)

## 1. 반복문이란?
반복문(Loop)은 특정 조건을 만족하는 동안 정해진 코드 블록을 반복적으로 실행하는 제어 구조입니다.

> **직관적인 비유 : 자동화된 조립 라인**
> * **조립 라인 (반복문)** : `for`, `while`, `foreach`
> * **작업 지시서 (조건)** : "부품이 100개 쌓일 때까지", "불량품이 나올 때까지"
> * **반복 작업 (코드 블록)** : 부품을 조립하고 다음 단계로 넘기는 실제 작업

**왜 필요한가?** (코드 중복 제거)
1부터 10,000까지 더하는 코드를 손으로 쓴다면 1만 줄이 필요하지만, 반복문을 쓰면 단 4줄로 끝납니다.\
중복된 코드는 유지보수를 어렵게 하고 버그를 낳습니다. 반복문은 프로그래밍의 핵심 원칙인 **DRY(Don't Repeat Yourself)**를 실천하는 가장 강력한 무기입니다.

---

## 2. 핵심 요약

| 키워드 | 언제 사용하는가? |
| :--- | :--- |
| **`for`** | 반복 횟수가 명확할 때 (예: 10번 반복, 1~100 합산) |
| **`while`** | 조건이 참인 동안 반복 (횟수를 미리 알 수 없을 때) |
| **`do-while`** | `while`과 같지만, **무조건 최소 1회 실행**을 보장해야 할 때 |
| **`foreach`** | 배열/리스트의 모든 요소를 순회할 때 (인덱스 실수가 없어 가장 안전) |
| **`break`** | 조건을 무시하고 즉시 반복문을 **완전히 탈출**할 때 |
| **`continue`**| 이번 바퀴의 남은 코드를 건너뛰고 **다음 바퀴로 넘어갈 때** |

## 3. 세부 개념 및 비교

### 3.1 `for` - 횟수가 명확할 때
`for (초기화식; 조건식; 증감식)` 세 부분이 한 줄에 모여 있어 반복의 흐름을 한눈에 파악하기 좋습니다.
* **순서**: 초기화(1회) ➔ `조건 ➔ 본문 ➔ 증감` ➔ `조건 ➔ 본문 ➔ 증감` 반복

```csharp
// [정순] 1, 2, 3 ... 10
for (int i = 1; i <= 10; i++) { Console.WriteLine(i); }

// [역순] 10, 9, 8 ... 1
for (int i = 10; i > 0; i--) { Console.WriteLine(i); }
```

### 3.2 `while` - 조건이 중요할 때 (횟수 미상)
사용자가 언제 종료를 누를지, 몬스터가 몇 대를 맞아야 죽을지처럼 **횟수를 미리 알 수 없는 경우**에 사용합니다.
* **주의**: 루프 안에 조건식에 영향을 주는 변경(증감 등)이 없으면 영원히 도는 **무한 루프**에 빠집니다.

### 3.3 같은 결과, 다른 반복문 (1부터 n까지의 합)
세 반복문은 상황에 맞게 골라 써야 합니다. 억지로 바꿔 쓰면 코드를 읽는 사람에게 혼란을 줍니다.

```csharp
int n = 10;

// 1. for (횟수가 명확할 때 가장 직관적)
int sumFor = 0;
for (int i = 1; i <= n; i++) sumFor += i;

// 2. while (초기화와 증감이 흩어져 실수가 나오기 쉬움)
int sumWhile = 0;
int j = 1;
while (j <= n)
{
    sumWhile += j;
    j++; // 빠뜨리면 무한 루프!
}

// 3. do-while (최소 1회 실행 보장)
// n이 0이어도 무조건 1을 더해버리므로 이 상황엔 부적합! (입력 검증 등에 주로 쓰임)
int sumDo = 0;
int k = 1;
do
{
    sumDo += k;
    k++;
} while (k <= n);
```

### 3.4 중첩 반복문과 곱셈 (성능 주의!)
반복문 안에 반복문을 넣을 수 있습니다. 바깥이 한 칸 움직이는 동안 안쪽 루프는 처음부터 끝까지 다 돕니다.
> **실행 횟수는 더하기가 아니라 곱하기입니다**\
> 바깥 1,000번 × 안쪽 1,000번 = **1,000,000번 (100만 번)**\
> 이를 **시간 복잡도 $O(N^2)$**이라고 부르며, 데이터가 많아질수록 성능을 갉아먹는 주범이 되므로 남용을 조심해야 합니다. 변수 이름도 헷갈리지 않게 `i`, `j` 대신 명확한 이름을 쓰세요.

## 4. 코드로 보는 반복문 실전

### 4.1 짝수/홀수 판별과 음수 나머지 함정
```csharp
// ❌ 흔한 실수 (홀수 판별)
for (int n = -5; n <= 5; n++)
{
    // C#에서 -3 % 2 의 결과는 1이 아니라 -1입니다! 
    // 양수일 땐 정상 작동하다가 음수가 들어오는 순간 조용히 버그가 발생합니다.
    if (n % 2 == 1) Console.WriteLine(n); 
}

// ⭕ 안전한 코드
for (int n = -5; n <= 5; n++)
{
    // "2로 나누어 떨어지지 않으면 홀수"로 작성하면 음수/양수 모두 안전합니다.
    if (n % 2 != 0) Console.WriteLine(n);
}
```

### 4.2 안전한 입력 검증 (`do-while`)
> 게임 시작 전에 난이도를 1~10 중에서 고르게 합니다. 아무 값이나 받아서는 안 되고, 유효한 값이 들어올 때까지 다시 물어야 합니다.

입력을 받기도 전에 유효한지 검사할 순 없으므로, "일단 한 번 묻는" `do-while`이 찰떡궁합입니다.
```csharp
int level;
bool isValid;

do
{
    Console.Write("난이도를 고르세요 (1~10): ");
    string input = Console.ReadLine();

    // 변환에 성공(true)하고, 범위도 1~10 사이일 때만 isValid가 true가 됨
    isValid = int.TryParse(input, out level) && level >= 1 && level <= 10;

    if (!isValid)
        Console.WriteLine("숫자가 아니거나 범위를 벗어났습니다. 다시 입력하세요.\n");

} while (!isValid); // 유효하지 않으면 무한히 다시 묻는다.

Console.WriteLine($"난이도 {level} 로 시작합니다!");
```

## 5. Unity에서의 반복문

Unity에서 반복문을 쓸 때는 콘솔 환경과 **완전히 다른 패러다임**을 가져야 합니다.

```csharp
using UnityEngine;
using System.Collections.Generic;

public class GameManager : MonoBehaviour
{
    public List<Enemy> enemies = new List<Enemy>();

    // Update() 자체가 1초에 60번씩 도는 거대한 반복문입니다!
    void Update()
    {
        // 1. 모든 적 순회 (foreach가 가장 깔끔함)
        foreach (Enemy e in enemies)
        {
            e.UpdatePosition();
        }

        // 2. 순회하면서 요소를 삭제할 때는 무조건 '역방향 for'를 써야 합니다.
        // 정방향으로 지우면 뒤의 요소가 앞으로 당겨지면서 인덱스가 꼬이고 에러가 터집니다.
        for (int i = enemies.Count - 1; i >= 0; i--)
        {
            if (enemies[i].IsDead)
            {
                enemies.RemoveAt(i);
            }
        }
    }
}
```

> **Unity 최악의 실수: `Update` 안의 `while(true)`**\
> 콘솔에서 `while(true)`는 입력을 기다릴 때 유용하지만, Unity의 한 프레임(`Update`) 안에서 루프가 끝나지 않으면 **유니티 에디터 전체가 멈춰버립니다(프리징).**\
> "계속 돌면서 상태 갱신" ➔ `Update` 사용\
> "몇 초에 걸쳐 천천히 반복" ➔ `Coroutine(코루틴)` 사용

**[실무 팁] Unity 안전 카운터 (Fail-Safe)**\
어쩔 수 없이 `while`을 써야 한다면 안전장치를 꼭 넣으세요.
```csharp
int loopCount = 0;
while (isFindingTarget)
{
    // 타겟 찾는 로직...
    
    // 무한 루프 방지용 안전 카운터! 1만 번 넘게 돌면 강제로 탈출시켜 에디터 멈춤을 방지.
    if (++loopCount > 10000) { Debug.LogError("무한 루프 감지!"); break; }
}
```

## 6. 실습 문제 및 복습

**Q1. `for`와 `foreach`의 차이와 장단점은?**
> * **`foreach` 장점**: 인덱스 아웃 오브 레인지 에러가 없고 코드가 직관적입니다. 단순 순회할 때 최적입니다.
> * **`for` 장점**: 인덱스를 제어할 수 있어 '역방향 순회', '짝수 번째만 처리', '순회 중 요소 삭제'가 가능합니다.
> * **주의**: `foreach` 안에서는 반복 변수를 조작하거나 컬렉션의 요소를 추가/삭제(`Add`, `Remove`)할 수 없습니다.

**Q2. -50부터 50까지의 총합을 구하는 코드를 작성하세요.**
```csharp
int sum = 0;
for (int i = -50; i <= 50; i++)
{
    sum += i;
}
// 결과는 0입니다. 대칭 구간의 합은 부호가 서로 상쇄되어 0이 됩니다.
// 출력(WriteLine)은 반복문 안이 아니라 '다 끝난 뒤 밖에서 딱 1번만' 해야 합니다!
Console.WriteLine($"총합: {sum}"); 
```

**Q3. 무한 루프가 발생하는 이유와 자신만의 방지 규칙은?**
> **원인**: `while`문의 조건식에 영향을 주는 값(증감 연산 등)을 본문 안에서 변경해주지 않았기 때문입니다.
> **방지 규칙**:
> 1. 횟수가 명확하면 초기화, 조건, 증감이 한 줄에 있는 `for`를 쓴다.
> 2. `while`을 쓸 때는 '탈출 조건(증감 또는 break)'을 가장 먼저 본문 끝에 적어둔 뒤에 핵심 로직을 작성한다.
> 3. Unity 환경에서는 무조건 `loopCount` 같은 안전 카운터를 둔다.

## 7. 실무 주의사항 및 안전 습관

* **`foreach` 중 리스트 요소를 `Add/Remove` 하지 마라** : `InvalidOperationException` 에러가 즉시 터집니다. 삭제는 반드시 **역방향 `for`**로 하세요.
* **`switch` 안의 `break`에 속지 마라** : `while` 안의 `switch`에서 `break`를 호출하면 `switch`만 빠져나올 뿐 `while`은 계속 돕니다. `while`을 끝내려면 `bool isRunning = false;` 상태 변수를 활용하세요.
* **루프 밖에서 선언하기** : 루프 안에서 변수를 `int a = 0;`으로 계속 선언하고 버리는 행위는 메모리를 낭비(가비지 생성)합니다. 여러 번 쓰일 변수는 루프 밖에서 선언하세요.
* **조건 검사는 밖으로 빼기** : `for (int i = 0; i < myList.Count; i++)` 처럼 쓰면 매 바퀴마다 `Count`를 다시 계산합니다. 최적화가 필요할 땐 `int count = myList.Count;`로 밖에서 미리 구해두고 쓰면 좋습니다.
