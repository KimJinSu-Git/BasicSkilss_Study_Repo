# [메모리와 구조] 1. 클래스와 객체 (Class & Object)

## 1. 클래스(Class)란?
클래스(Class)는 객체 지향 프로그래밍(OOP)의 심장이자, **객체를 만들기 위한 설계도**입니다.\
특정 대상이 가져야 할 **데이터(상태)** 와 그 데이터로 수행할 수 있는 **행동(기능)** 을 하나의 캡슐 안에 예쁘게 묶어 정의합니다.

> **비유 : 붕어빵 틀과 붕어빵**
> * **붕어빵 틀 (클래스)** : `Player`, `Monster` 등을 만들기 위한 쇳물 주형 (설계도)
> * **팥, 밀가루 (필드)** : `name`, `hp`, `attackPower` 등 붕어빵의 속 재료 (상태 데이터)
> * **굽는 행위 (메서드)** : `Attack()`, `TakeDamage()` 등 붕어빵이 할 수 있는 동작 (기능)
> * **잘 구워진 붕어빵 (객체/인스턴스)** : `new` 키워드를 통해 메모리에 실제 구워져 나온 실체

**왜 필요한가?**\
클래스가 없다면 플레이어의 데이터(체력, 이름, 공격력)가 뿔뿔이 흩어진 변수로 존재하게 됩니다.\
적이 100마리면 변수 300개를 이름표(`monster1Hp`, `monster2Hp`...) 붙여가며 관리해야 합니다. 클래스는 이 데이터와 행동을 하나의 짝으로 묶어 코드에 질서를 부여합니다.

## 2. 핵심 요약

| 키워드 | 한 줄 설명                                              |
| :--- |:----------------------------------------------------|
| **클래스 (Class)** | 객체를 생성하기 위한 설계도 (데이터 + 행동의 묶음)                      |
| **객체 (Instance)** | `new` 키워드로 클래스에서 찍어내어 메모리(힙)에 올라간 실체                |
| **필드 (Field)** | 객체가 가지는 상태 데이터 (예: `int hp;`)                       |
| **메서드 (Method)** | 객체가 수행하는 행동/기능 (예: `void Attack() { }`)             |
| **생성자 (Constructor)** | `new`로 객체를 생성할 때 **단 한 번 자동 호출**되어 필드를 초기화하는 특수 메서드 |
| **`this`** | 클래스 내부에서 **객체 자기 자신(의 메모리 주소)** 을 가리키는 키워드          |
| **`.` (점 연산자)** | 객체 내부의 필드나 메서드에 접근할 때 사용 (예: `player.Attack()`)     |

## 3. 세부 개념 및 원리

### 3.1 클래스의 3대 구성 요소
`class` 키워드로 블록을 열면, 다음 3가지 요소로 목차를 구성합니다.
1. **필드 (Field)** : 무엇을 가지고 있는가?
2. **생성자 (Constructor)** : 어떻게 태어나는가? (초기 셋업)
3. **메서드 (Method)** : 무엇을 할 수 있는가?

### 3.2 객체 생성과 힙(Heap) 메모리
설계도(클래스)만 있다고 붕어빵이 먹어지는 것은 아닙니다. **`new` 키워드**를 사용해야 힙(Heap) 메모리에 실제 공간이 뚫리고 데이터가 올라갑니다. 이것을 **인스턴스화(Instantiation)** 라고 합니다.\
`new`를 부를 때마다 서로 완전히 독립된 메모리를 가진 객체들이 따로 태어납니다.

### 3.3 생성자 (Constructor)의 역할과 기본값
생성자는 객체가 태어날 때 초기 상태를 세팅해 줍니다.
* 이름은 반드시 클래스 이름과 똑같아야 합니다.
* 반환 타입(`void` 등)을 아예 적지 않습니다.
* 매개변수를 받아 필드에 값을 채워 넣습니다.

> **초기화를 빠뜨리면 어떻게 될까?**\
> C#에서 `new`로 힙 메모리를 할당할 때, 공간을 비워두지 않고 0으로 밀어버립니다.
> * 숫자형(`int`, `float`): `0`
> * 논리형(`bool`): `false`
> * 참조형(`string`, `class`): `null`
    > 만약 생성자에서 체력(`hp`) 세팅을 잊는다면, 체력이 0인 전사가 태어나서 스치자마자 죽게 됩니다.

### 3.4 `this` 키워드 (자기 자신 가리키기)
매개변수 이름과 필드 이름이 같을 때, 컴파일러는 어느 쪽이 매개변수인지 헷갈려합니다.
```csharp
public GameCharacter(string name, int maxHp)
{
    // 왼쪽의 this.name은 '내 필드', 오른쪽의 name은 '들어온 매개변수'
    this.name = name; 
    this.maxHp = maxHp;
}
```
`this.name = name;`을 안 쓰고 `name = name;`이라고 쓰면, 그냥 매개변수에 매개변수를 덮어쓰는 헛수고가 되며 실제 객체의 필드는 `null` 상태로 방치됩니다.

## 4. 객체 지향의 꽃 : 객체 간의 상호작용

메서드의 매개변수에는 `int`, `string` 뿐만 아니라 **클래스(객체)** 도 들어올 수 있습니다.
```csharp
public void Attack(GameCharacter target) 
{
    target.TakeDamage(this.attackPower);
}
```
이 한 줄이 클래스의 존재 이유를 증명합니다.\
전사가 슬라임을 때릴 때, 전사는 `target.hp -= this.attackPower;` 처럼 슬라임의 체력을 직접 깎지 않습니다. 대신 **"나 공격력 20으로 너 때렸어!"라는 메시지(`TakeDamage`)만 전달**합니다.\
체력을 깎고 죽을지 말지 판정하는 것은 **맞은 쪽(슬라임)이 스스로 자신의 메서드 안에서 처리**합니다. 이것이 객체 지향 프로그래밍입니다.

## 5. 실전 활용 예시 (콘솔 RPG 만들기)

데이터와 행동이 하나의 클래스에 완벽하게 묶여 상호작용하는 예제입니다.
> **캡슐화**: 아래 예제는 뼈대를 보기 위해 필드를 `public`으로 열었지만, 실전에서는 외부 조작을 막기 위해 필드를 `private`으로 숨깁니다.

```csharp
using System;

// 1. 클래스 정의 (설계도)
public class GameCharacter
{
    // 필드 (상태)
    public string name;
    public int hp;
    public int attackPower;

    // 생성자 (탄생)
    public GameCharacter(string name, int maxHp, int attackPower)
    {
        this.name = name;
        this.hp = maxHp; // 태어날 땐 최대 체력으로
        this.attackPower = attackPower;
    }

    // 메서드 1 (맞기)
    public void TakeDamage(int damage)
    {
        this.hp -= damage;
        if (this.hp <= 0)
        {
            this.hp = 0;
            Console.WriteLine($"{this.name}이(가) 쓰러졌습니다...");
            return;
        }
        Console.WriteLine($"{this.name} 피해 {damage} 입음 (남은 체력: {this.hp})");
    }

    // 메서드 2 (때리기) - 다른 객체를 넘겨받아 메시지를 전달한다
    public void Attack(GameCharacter target)
    {
        Console.WriteLine($"[{this.name}]이(가) [{target.name}]을(를) 공격합니다");
        target.TakeDamage(this.attackPower); 
    }
}

class Program
{
    // 2. 객체 생성 및 실행 (C# 9.0 미만 환경을 위한 진입점)
    static void Main()
    {
        // 실체화 (Instantiation)
        GameCharacter warrior = new GameCharacter("용사", 100, 25);
        GameCharacter slime = new GameCharacter("슬라임", 40, 8);

        // 객체 간의 상호작용
        warrior.Attack(slime);   // 슬라임 체력 40 -> 15
        slime.Attack(warrior);   // 용사 체력 100 -> 92
        warrior.Attack(slime);   // 슬라임 체력 15 -> 0 (사망)
    }
}
```

## 6. Unity에서의 클래스 활용

Unity에서 가장 헷갈리기 쉬운 부분이 바로 `new` 키워드입니다.

```csharp
using UnityEngine;

// MonoBehaviour를 상속받은 클래스는 씬(Scene)에 존재하는 부품(컴포넌트)이 됩니다.
public class PlayerController : MonoBehaviour
{
    [SerializeField] private string playerName = "Player";
    [SerializeField] private int health = 100;

    // Unity 엔진이 자동으로 호출해주는 생성자 대용 메서드
    void Start() 
    {
        Debug.Log($"{playerName} 게임 시작!");
    }

    public void TakeDamage(int damage) { health -= damage; }
}
```

**Unity 클래스 생성 주의점**
* `MonoBehaviour`를 상속받은 스크립트는 **절대 `new PlayerController()`로 생성하지 않습니다.** (에러 발생)
* 게임 오브젝트에 드래그 앤 드롭으로 붙이거나, 코드로 생성할 때는 `gameObject.AddComponent<PlayerController>()`를 사용해야 엔진이 메모리를 올바르게 관리합니다.
* 단, `MonoBehaviour`를 상속받지 않은 **순수 C# 데이터 클래스**(예: 스킬 정보, 인벤토리 아이템 모델 등)는 콘솔 C#처럼 마음껏 `new`를 사용해서 객체를 만듭니다.

## 7. 실습 문제 및 복습

**Q1. `Car` 클래스의 `SpeedUp` 메서드가 동작하지 않는 이유는?**
```csharp
public class Car
{
    public int Speed;
    public Car() { Speed = 0; }
    
    public void SpeedUp()
    {
        int speed = this.Speed; // 지역 변수에 값 복사
        speed += 10;            // 복사본만 증가함
    }
}
```
> **원인**: `this.Speed`의 값을 복사해 온 '지역 변수(`speed`)'만 증가시키고 끝났습니다. 지역 변수는 메서드가 끝나면 증발합니다.\
> **수정**: 객체 본연의 상태를 변경하려면 필드에 직접 접근해야 합니다. `public void SpeedUp() { this.Speed += 10; }`

**Q2. 생성자(`Constructor`)의 두 가지 문법적 특징은 무엇인가요?**
> 1. 메서드의 이름이 **클래스 이름과 완전히 동일**해야 합니다.
> 2. `void`, `int` 같은 **반환 타입(Return Type)을 아예 적지 않습니다.**

**Q3. 객체 간 상호작용에서, 공격자가 방어자의 `hp` 필드를 직접 빼는 대신 `TakeDamage()` 메서드를 호출하는 이유는?**
> 피해량 계산, 방어력 적용, 사망 처리 판정 등 복잡한 로직을 공격하는 쪽에서 일일이 신경 쓸 필요 없이 방어하는 객체에게 책임을 위임하기 위함입니다. 이를 통해 코드의 결합도가 낮아지고 유지보수가 훨씬 쉬워집니다.

## 8. 주의사항 및 안전 습관

* **필드는 `public`으로 열지 않는다**: 데이터를 아무나 밖에서 `player.hp = -99;` 로 건드릴 수 있게 방치하는 것은 폭탄을 안고 있는 것과 같습니다. 데이터는 `private`으로 숨기고(`은닉`), 메서드로만 소통하게 만드는 **캡슐화(Encapsulation)** 를 반드시 연습하세요.
* **생성자 초기화 누락 주의**: 매개변수로 받은 값을 `this.필드 = 매개변수;`로 연결하는 것을 잊지 마세요.
* **클래스 분리**: 하나의 `.cs` 파일에는 되도록 하나의 클래스만 작성하는 것이 협업과 유지보수의 기본 매너입니다.
* **네이밍 컨벤션**: 클래스 이름은 무조건 **PascalCase**(첫 글자 대문자)로 작성합니다. (`player` ➔ `Player`)
