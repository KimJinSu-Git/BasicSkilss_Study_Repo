# [메모리와 구조] 6. 정적·동적 할당 (Static & Dynamic Allocation)

## 1. 정적 할당 vs 동적 할당
여행 계획을 짤 때 두 가지 방법이 있습니다. 출발 전에 모든 숙소와 렌터카를 완벽하게 예약하는 것과, 현지에 도착해서 상황에 맞게 즉흥적으로 택시를 잡는 것입니다.

> **여행 계획 짜기**
> * **정적 할당 (Static Allocation)** : 여행 전 미리 크기와 일정을 확정하여 예약된 숙소. (컴파일 타임에 메모리 크기 확정)
> * **동적 할당 (Dynamic Allocation)** : 현지에서 필요할 때마다 즉석에서 잡는 택시. (런타임에 메모리를 유연하게 할당)

**왜 이 차이를 알아야 할까요?**\
이 두 방식을 이해하면 내가 짠 코드 한 줄이 컴퓨터의 **속도(성능)** 와 **유연성(메모리 활용)** 에 어떤 영향을 미치는지 완벽하게 통제할 수 있습니다.

---

## 2. 핵심 요약

| 구분 | 정적 할당 (Static Allocation) | 동적 할당 (Dynamic Allocation)        |
| :--- | :--- |:----------------------------------|
| **결정 시점** | **컴파일 타임** (코드 작성 시점에 크기 확정) | **런타임** (게임 실행 중에 크기 결정)          |
| **저장 위치** | **스택 (Stack)** 또는 정적 데이터 영역 | **힙 (Heap)**                      |
| **대상** | 값 타입 지역 변수, `static` 변수 | `new`로 만든 **참조 타입**(클래스, 배열, 문자열) |
| **할당 속도** | **매우 빠름** (포인터만 이동) | **상대적으로 느림** (빈 공간 탐색 필요)         |
| **데이터 크기**| 고정됨 (런타임에 크기 변경 불가) | **자유로움** (런타임에 원하는 만큼 할당)         |
| **메모리 해제**| 스코프 `{}` 종료 시 즉시 자동 소멸 | **가비지 컬렉터(GC)** 가 수거할 때까지 잔류      |

## 3. 세부 개념 및 원리

### 3.1 정적 할당: 빠르지만 융통성이 없다
컴파일러가 프로그램을 번역할 때 "이 메서드는 `int` 변수 2개가 필요하니까 8바이트를 미리 확보해둬!"라고 메모리 사용 계획을 확정 짓는 방식입니다.
* 빠르고 안전하며 메모리 낭비가 없습니다.
* 하지만 게임 중에 "유저가 10명 접속할지 100명 접속할지" 모르는 상황에서 미리 배열 크기를 고정해두어야 하는 답답함이 있습니다.

### 3.2 동적 할당: 자유롭지만 대가가 따른다
프로그램 실행(런타임) 중에 `new` 키워드를 만나면, 그제야 힙(Heap) 메모리에서 "빈 공간 좀 찾아주세요!" 하고 요청하여 메모리를 할당받습니다.
* 유저 수에 맞춰 배열 크기를 유동적으로 정할 수 있어 매우 유연합니다.
* 하지만 빈 공간을 찾는 시간, 그리고 버려진 메모리를 치우는 **가비지 컬렉터(GC) 비용**이라는 대가를 치러야 합니다.

### 3.3 C# `new` 키워드의 오해 (구조체의 예외)
"C#에서 `new`를 쓰면 무조건 힙에 동적 할당된다!" ➔ **절반만 맞는 말입니다.**
C#에서 `new`는 본래 "생성자를 호출하라"는 뜻입니다.
* `Player p = new Player();` (클래스): **힙에 동적 할당**됩니다.
* `Vector3 v = new Vector3();` (구조체): 값 타입이므로 힙이 아닌 **스택에 정적 할당**됩니다!

### 3.4 C#의 한계: 가변 길이 스택 배열 금지
C++에서는 런타임 변수(`count`)를 이용해 스택에 배열을 만들 수 있지만, C#은 안전을 위해 이를 엄격히 금지합니다.
```csharp
void CreateArray(int count)
{
    // ❌ 컴파일 에러 C#은 스택(정적)에 가변 크기를 허용하지 않음
    int arr[count]; 
    
    // ⭕ C#에서는 가변 크기가 필요하면 무조건 힙(동적)에 만들어야 함
    int[] arr = new int[count]; 
}
```

## 4. 코드로 보는 할당의 흐름

### 4.1 정적 할당과 동적 할당의 혼합
```csharp
// 1. 정적 데이터 영역 (프로그램 시작부터 끝까지 고정)
public class GameConfig
{
    public static readonly string Version = "1.0.2";
}

void StartGame()
{
    // 2. 스택 영역에 정적 할당 (메서드 끝나면 증발)
    int initialGold = 1000; 

    Console.Write("파티원 수 입력: ");
    int count = int.Parse(Console.ReadLine()); // 런타임에 유저가 5를 입력함

    // 3. 힙 영역에 동적 할당 (런타임 변수인 count만큼 유연하게 생성)
    Player[] party = new Player[count]; 
    
    for (int i = 0; i < count; i++)
    {
        // 4. 각 배열 칸에도 실제 Player 객체를 힙에 동적 할당
        party[i] = new Player(); 
    }
}
```

## 5. Unity 실무: 동적 할당의 저주와 오브젝트 풀링

Unity에서 매 프레임(1초에 60번) 동적 할당을 발생시키는 것은 성능을 깎아먹는 최악의 안티 패턴입니다.

### 최악의 코드: 매 프레임 동적 할당
```csharp
void Update()
{
    // 매 프레임마다 힙에 동적 할당을 하면, 가비지 컬렉터(GC)가 치울 쓰레기가 산더미처럼 쌓입니다.
    // 결국 GC가 청소를 시작하며 게임이 멈추는 프레임 드랍(Spike)이 발생합니다.
    if (Input.GetButton("Fire"))
    {
        Instantiate(bulletPrefab); // 힙에 동적 할당
    }
}
```

### 최고의 최적화: 오브젝트 풀링 (Object Pooling)
동적 할당의 유연함은 포기할 수 없고, 렉이 걸리는 건 싫다면 어떻게 할까요?\
**"로딩 화면(시작 시점)에 100개를 미리 동적 할당해 창고에 쑤셔 박아놓고, 전투 중에는 꺼내 쓰기만 하자!"** ➔ 이것이 실무의 표준입니다.

```csharp
public class BulletPool : MonoBehaviour
{
    public GameObject bulletPrefab;
    private Queue<GameObject> _pool = new Queue<GameObject>();

    void Start()
    {
        // 로딩 씬에서 100개를 미리 동적 할당 (렉이 걸려도 로딩 중이라 유저가 모름)
        for (int i = 0; i < 100; i++)
        {
            GameObject bullet = Instantiate(bulletPrefab);
            bullet.SetActive(false);
            _pool.Enqueue(bullet);
        }
    }

    public GameObject GetBullet()
    {
        // 전투 중에는 동적 할당(Instantiate)을 절대 하지 않고, 창고에서 꺼내 활성화만 시킴
        if (_pool.Count > 0)
        {
            GameObject bullet = _pool.Dequeue();
            bullet.SetActive(true);
            return bullet;
        }
        
        // 정 모자랄 때만 눈물을 머금고 동적 할당
        return Instantiate(bulletPrefab); 
    }
}
```

## 6. 실습 문제 및 복습

**Q1. 메모리 할당이 '런타임'에 이루어지면 정적 할당인가요, 동적 할당인가요? 주로 어느 메모리 영역을 사용하나요?**
> **동적 할당**입니다. 컴파일 타임에 크기를 알 수 없는 데이터를 실행 중(런타임)에 생성하므로, 유연하게 확장이 가능한 **힙(Heap)** 메모리 영역을 주로 사용합니다.

**Q2. 아래 코드의 `a`, `b`, `c`는 각각 어떤 방식으로 어디에 할당되나요?**
```csharp
class Test
{
    public static int a = 1;
    public string b = "hello";
    public void Run() { bool c = true; }
}
```
> * `a`: `static` 변수이므로 **정적 할당**되어 **정적 데이터 영역**에 저장됩니다. (프로그램 종료 시까지 생존)
> * `b`: `new Test()`로 객체가 생성될 때 함께 **동적 할당**되어 **힙**에 저장됩니다.
> * `c`: 메서드 내부의 지역 변수이므로 **정적 할당**되어 **스택**에 저장됩니다. (Run() 종료 시 즉시 소멸)

**Q3. 게임 프레임마다 계산되는 '물리 충돌 임시 변수'와, 게임 내 '모든 몬스터 목록'. 각각 어떤 할당 방식이 적합한지 이유와 함께 설명하세요.**
> * **물리 충돌 임시 변수**: **정적 할당 (스택)**
    >   메서드 안에서 찰나의 순간 사용되고 버려지므로, GC 부담이 전혀 없고 속도가 압도적으로 빠른 스택에 정적 할당하는 것이 완벽합니다. (그래서 Unity의 `Vector3`가 구조체인 것입니다.)
> * **모든 몬스터 목록**: **동적 할당 (힙)**
    >   게임 시작 시 몬스터가 10마리일지 100마리일지 알 수 없고, 게임 진행 내내 살아서 유지되어야 하므로 크기가 유연한 힙에 컬렉션(`List<T>`)으로 동적 할당하는 것이 필수입니다.

## 7. 주의사항 및 안전 습관

* **`Update` 내의 동적 할당을 색출하라**: `Update` 문 안에서 `new` 키워드나 `Instantiate`가 보인다면 무조건 '오브젝트 풀링'으로 리팩토링할 방법을 찾으세요.
* **구조체의 `new`에 쫄지 마라**: `new Vector3()`는 힙에 들어가는 무거운 동적 할당이 아니라 스택에 올라가는 가벼운 정적 할당입니다. 안심하고 팍팍 써도 프레임 드랍은 일어나지 않습니다.
* **초기화 비용은 로딩 화면에 떠넘기라**: 동적 할당이 많이 일어나는 무거운 객체나 거대한 배열은 게임 플레이 중이 아니라 `Start`나 `Awake` (또는 로딩 씬)에서 미리 할당해 두는 것이 클라이언트 최적화의 기본입니다.
