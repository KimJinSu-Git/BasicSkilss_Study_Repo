# [메모리와 구조] 2. 구조체 (Struct)

## 1. 구조체(Struct)란?
구조체(struct)는 클래스와 거의 같은 문법으로 데이터와 기능을 묶지만, **값 타입(Value Type)** 으로 동작하는 설계도입니다.\
클래스가 고유한 정체성을 가진 '객체'를 만들 때 쓰인다면, 구조체는 좌표(X,Y)나 색상(R,G,B)처럼 **그 자체로 하나의 값인 작은 데이터 덩어리**를 만들 때 씁니다.

> * **클래스 (참조 타입)** : 자동차. 정비소에 맡겨 부품을 갈면 그 차 자체가 바뀝니다. 친구에게 내 차의 '위치(주소)'를 알려주면, 친구가 내 차를 튜닝했을 때 내 차도 바뀝니다.
> * **구조체 (값 타입)** : (10, 20)이라는 좌표가 적힌 메모지. 친구에게 건넬 때는 메모지를 **복사해서 한 장 더** 적어줍니다. 친구가 자기 메모지에 낙서를 해도 내 메모지는 원래 상태 그대로 유지됩니다.

**왜 필요한가?**
1. **의미 단위의 묶음** : 한 학생의 국어, 영어, 수학 점수를 각각의 변수로 두면 관리가 복잡합니다. 이를 `Student`라는 구조체로 묶으면 코드가 깔끔해지고, 평균을 구하는 기능(메서드)도 함께 담을 수 있습니다.
2. **가비지 컬렉터(GC) 최적화** : 모든 것을 클래스로 만들면 힙(Heap) 메모리에 할당되어 무거워집니다. 구조체는 값 자체를 담아 **스택(Stack)** 에 올라가므로, 짧게 쓰고 버리는 데이터(파티클, 총알 좌표 등)를 대량으로 다룰 때 성능 부담이 크게 줄어듭니다.

## 2. 핵심 요약

| 구분 | `struct` (구조체) | `class` (클래스) |
| :--- | :--- | :--- |
| **타입** | **값 타입** (변수가 데이터 자체를 들고 있음) | **참조 타입** (변수가 힙 메모리의 주소를 들고 있음) |
| **대입 연산 (`=`)**| **데이터 전체가 통째로 복사됨** | 주소(참조)만 복사됨 |
| **메모리 위치** | 주로 스택 (Stack) | 힙 (Heap) |
| **상속** | 불가 (인터페이스 구현은 가능) | 가능 |
| **`null` 허용** | `Nullable<T>`로만 가능 (`Point?`) | 항상 가능 |
| **주요 용도** | 작고, 값 자체로 의미 있는 단순 데이터 묶음 | 정체성과 복잡한 생명주기를 가진 객체 |

> **판단 기준**: 잘 모르겠으면 `class`가 정답입니다. `struct`는 **(1) 16바이트 미만으로 작고**, **(2) 단일 값처럼 읽히며**, **(3) 한 번 만들면 거의 바뀌지 않을 때**만 고려하세요.

## 3. 세부 개념 및 실무 팁

### 3.1 언제 struct를 쓰면 좋은가?
1. **단일 값처럼 읽힌다**: `Point`, `Color`, `Vector3`처럼 묶음 자체가 하나의 값으로 느껴질 때.
2. **크기가 작다**: 16바이트 미만이 권장 기준입니다. (거대한 구조체는 복사 비용이 커서 오히려 느려집니다.)
3. **자주 만들어지고 사라진다**: 수백 개의 파티클 좌표처럼 대량으로 생성되고 즉시 소멸하는 데이터.

### 3.2 결정적 차이: 복사 동작과 사본(Copy)의 함정 
구조체는 대입(`=`)하거나 매개변수로 넘길 때, 데이터 전체가 통째로 복사되어 **완전히 독립적인 사본**이 됩니다.\
특히 **배열이나 `List<T>`에서 꺼낸 구조체 역시 '사본'** 이라는 사실을 잊으면 치명적인 논리 버그가 발생합니다.

```csharp
Student[] students = new Student[2];
students[0] = new Student("홍길동", 90, 85);

// ❌ 1. 꺼내서 고친다 (최악의 함정)
Student copy = students[0]; // 이 순간 통째로 '복사본'이 만들어짐
copy.KoreanScore = 50;      // 사본의 점수만 바뀜
Console.WriteLine(students[0].KoreanScore); // 여전히 90점 (원본은 무사함)

// ⭕ 2. 고친 값을 배열에 반영하려면 '되돌려 쓰기'를 해야 함
students[0] = copy; 

// ⭕ 3. 또는 배열 칸에 직접 접근하여 수정
students[0].KoreanScore = 100;
```

### 3.3 불변 구조체 (`readonly struct`) 
위와 같은 '사본 수정 버그'를 원천 차단하기 위해, 최신 C#에서는 구조체를 아예 **수정 불가능(Immutable)하게** 만듭니다.
```csharp
// readonly를 붙이면 생성자 외에는 값을 절대 바꿀 수 없습니다.
public readonly struct Point
{
    public readonly int X;
    public readonly int Y;

    public Point(int x, int y) { X = x; Y = y; }
    
    // 값을 바꾸고 싶다면? 아예 새로운 구조체를 찍어내서 반환합니다
    public Point WithX(int newX) => new Point(newX, this.Y);
}
```

### 3.4 제약 사항 (C# 최신 문법)
* 구조체는 다른 구조체나 클래스를 **상속할 수 없습니다.** (부모도 자식도 될 수 없음)
* 과거에는 매개변수 없는 생성자(`public Point() { }`)를 만들 수 없었으나, C# 10부터 가능해졌습니다.
* 과거에는 생성자 안에서 모든 필드를 초기화해야 했으나, **C# 11부터는 초기화하지 않은 필드는 자동으로 기본값(0, false)으로 셋팅되도록 규칙이 완화**되었습니다.

## 4. 코드로 보는 구조체 vs 클래스

같은 형태의 코드가 타입(`struct` vs `class`)에 따라 정반대로 동작합니다.

```csharp
// 1. [struct - 값 타입]
public struct ValuePoint { public int X, Y; }

ValuePoint p1 = new ValuePoint { X = 10, Y = 20 };
ValuePoint p2 = p1; // 데이터 통째로 복사
p2.X = 100;

Console.WriteLine($"p1.X={p1.X}, p2.X={p2.X}");
// 결과: p1.X=10, p2.X=100 (서로 완전히 독립적이다)


// 2. [class - 참조 타입]
public class RefPlayer { public string Name; }

RefPlayer player1 = new RefPlayer { Name = "전사" };
RefPlayer player2 = player1; // 주소(참조)만 복사
player2.Name = "도적";

Console.WriteLine($"p1={player1.Name}, p2={player2.Name}");
// 결과: p1=도적, p2=도적 (둘 다 같은 힙 메모리의 객체를 가리킨다)


// 3. 메서드 매개변수도 값 복사다
void ResetX(ValuePoint p) { p.X = 0; } // 매개변수 p는 사본임
ValuePoint original = new ValuePoint { X = 100, Y = 200 };
ResetX(original);

Console.WriteLine(original.X); // 결과: 100 (원본은 변하지 않음)
```

## 5. Unity에서의 활용 및 꿀팁

Unity에서 매일 숨 쉬듯이 사용하는 타입 중 상당수가 구조체입니다. `Vector3`, `Quaternion`, `Color`가 모두 `struct`입니다. 반면 `Transform`, `GameObject`, `Rigidbody` 등은 모두 `class`입니다.

### `transform.position.x = 5f;` 가 에러나는 이유
Unity 입문자가 100% 겪는 오류입니다.
```csharp
// ❌ 컴파일 오류 발생
transform.position.x = 5f;
```
> **이유**: `transform.position`은 필드가 아니라, 내부적으로 `Vector3`라는 구조체를 복사해서 던져주는 **프로퍼티(Property)** 입니다.\
> 돌려받은 `Vector3`는 이름조차 없는 '임시 사본'입니다. 이 사본의 `x` 값을 고쳐봐야 실제 게임 오브젝트의 위치에는 아무런 영향이 없기 때문에, C# 컴파일러가 사전에 에러를 띄워 막아주는 것입니다.

**해결책: 통째로 새 값을 만들어 대입해야 합니다.**
```csharp
// ⭕ 올바른 방법: 새로운 Vector3 구조체를 구워내서 통째로 덮어씌운다.
transform.position = new Vector3(5f, transform.position.y, transform.position.z);

// ⭕ 또는, 사본을 꺼내서 고친 뒤 '되돌려 쓴다'
Vector3 p = transform.position; // 사본 생성
p.x = 5f;                       // 사본 수정
transform.position = p;         // 사본을 통째로 덮어쓰기 (반영)
```

## 6. 실습 문제 및 복습

**Q1. 구조체와 클래스의 가장 큰 차이 두 가지를 메모리 할당 위치와 복사 방식으로 설명하세요.**
> * **메모리**: 구조체는 데이터 자체를 **스택(Stack)** 에 할당하고, 클래스는 객체를 **힙(Heap)** 에 생성한 뒤 스택에는 그 주소만 보관합니다.
> * **복사**: 구조체는 대입할 때 데이터가 통째로 복사되어 **독립적인 사본**이 되지만, 클래스는 주소만 복사되므로 **동일한 원본을 공유**하게 됩니다.

**Q2. 아래 점수판 코드는 같은 선수에게 50점, 30점을 더했으나 결과가 50점이 나옵니다. 원인을 설명하세요.**
```csharp
public struct ScoreEntry { public string Id; public int Score; }
ScoreEntry[] board = new ScoreEntry[10];
// ... 생략 ...
ScoreEntry entry = board[0]; // (1)
entry.Score += 30;           // (2)
```
> **원인**: (1)에서 배열의 요소를 `entry` 변수에 담는 순간, 구조체 특성상 **'값 복사'** 가 일어납니다.\
> (2)에서 올린 30점은 복사본(사본)의 점수일 뿐, 원본 배열(`board[0]`)에는 어떠한 영향도 미치지 않습니다. 해결하려면 `board[0] = entry;` 처럼 다시 배열에 덮어써야 합니다.

## 7. 주의사항 및 안전 습관

* **거대한 구조체를 피하라**: 필드가 수십 개인 데이터를 구조체로 만들면, 함수에 넘길 때마다 그 엄청난 용량이 스택 메모리에서 복사되므로 성능(CPU)이 크게 저하됩니다. 데이터가 크다면 `class`가 정답입니다.
* **불변성(Immutability)을 활용하라**: 구조체를 설계할 때는 되도록 `readonly struct`로 만들어, 값을 고치고 원본이 바뀌길 기대하는 초보적인 실수를 시스템적으로 차단하세요.
* **클래스 상속의 대안**: 구조체는 상속이 불가능합니다. 공통 기능이 필요하다면 상속(Inheritance) 대신 인터페이스(Interface)를 구현하거나 조립(Composition) 방식을 사용해야 합니다.
