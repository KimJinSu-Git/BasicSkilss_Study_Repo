# [객체 지향] 4. 다형성 (Polymorphism)

## 1. 다형성(Polymorphism)이란?
객체 지향 프로그래밍의 '꽃'이라 불리는 다형성은 '여러(Poly) 가지 형태(Morph)'라는 의미 그대로, **하나의 이름(부모의 메서드)으로 다양한 형태의 동작(자식들의 구현)을 수행하게 만드는 강력한 원칙**입니다.

> **만능 리모컨**
> * TV, 오디오, 에어컨을 각각의 전용 리모컨으로 조작할 수도 있지만, 하나의 **만능 리모컨(부모 타입)** 이 있다면 어떨까요?
> * 만능 리모컨의 **"전원 켜기"** 버튼은 딱 하나지만, 현재 가리키는 기기(실제 생성된 자식 객체)가 무엇이냐에 따라 TV가 켜지기도, 에어컨이 켜지기도 합니다.
> * 호출(버튼)은 하나지만, 결과(동작)는 객체에 따라 다양하게 나타납니다

**왜 필요한가?**\
게임에 새로운 직업(예: 도적)을 추가할 때마다 공격을 처리하는 `if~else` 코드를 찾아다니며 수정해야 한다면 유지보수는 지옥이 됩니다.\
다형성을 사용하면 부모 타입의 배열로 묶어서 `Attack()` 한 줄만 호출하면 끝납니다. **새로운 자식 클래스가 아무리 많이 추가돼도, 기존의 호출 코드는 단 한 글자도 수정할 필요가 없습니다.** (이것이 확장성의 본질입니다.)

## 2. 핵심 요약

| 구분 | 한 줄 설명 |
| :--- | :--- |
| **핵심 개념** | **하나의 인터페이스(명령), 다양한 구현** (One Interface, Multiple Implementations) |
| **구현 방법** | 메서드 오버라이딩 ➔ 부모는 **`virtual`**(허락), 자식은 **`override`**(덮어쓰기) |
| **전제 조건** | 반드시 **상속(is-a) 관계**가 맺어져 있어야 성립함 |
| **최대 장점** | 코드의 유연성과 확장성 극대화 (새로운 기능 추가 시 기존 코드 무수정) |
| **동작 시점** | 컴파일 시점이 아닌, 게임 **실행 중(런타임)에 객체의 진짜 타입(알맹이)을 보고 메서드를 결정**함 |

## 3. 세부 개념 및 원리

### 3.1 메서드 오버라이딩 (Overriding) ㅡ 기능의 완벽한 덮어쓰기
오버라이딩은 부모로부터 물려받은 메서드를 자식의 입맛에 맞게 **완전히 새롭게 재정의**하는 기술입니다.
* **부모 클래스**: `virtual` 키워드를 붙여 "이 메서드는 내 자식들이 맘대로 바꿔 써도 좋다"고 허락을 명시합니다.
* **자식 클래스**: `override` 키워드를 붙여 "부모의 낡은 기능 대신, 내 새로운 기능을 덮어쓰겠다"고 명시합니다.

### 3.2 오버라이딩(`override`) vs 메서드 숨기기(`new`)
자식 클래스에서 `override` 대신 `new` 키워드를 쓰면 어떻게 될까요?\
`new`는 부모 메서드를 덮어쓰는 게 아니라, 겉보기만 똑같은 새로운 함수를 하나 파서 **부모의 함수를 뒤로 숨겨버립니다.**\
이 경우, 부모의 리모컨으로 조작하면 숨겨져 있던 부모의 오리지널 함수가 튀어나오게 되어 **다형성이 완전히 박살 납니다.** 부모-자식 간에 다르게 동작하게 하려면 **무조건 `virtual` + `override` 조합**을 써야 합니다.

### 3.3 헷갈리지 말자: 오버라이딩 vs 오버로딩
| 구분 | 오버라이딩 (Overriding) | 오버로딩 (Overloading) |
| :--- | :--- | :--- |
| **의미** | 부모의 함수를 **재정의** (덮어쓰기) | 같은 이름의 함수를 매개변수만 바꿔 **다중 정의** |
| **관계** | 반드시 **상속 관계 (부모-자식)** 필수 | 상속 무관. **같은 클래스 내부**에서 발생 |
| **시그니처** | 부모와 이름, 매개변수, 반환 타입이 **100% 동일해야 함** | 함수 이름만 같고 **매개변수(개수/타입)가 달라야 함** |
| **키워드** | `virtual` / `override` | 키워드 필요 없음 |

## 4. 코드로 보는 다형성의 마법

### 잘못된 코드 (다형성이 깨진 `new`)
```csharp
public class Parent {
    public virtual void WhoAmI() => Console.WriteLine("나는 부모다");
}

public class ChildNew : Parent {
    // ❌ override 대신 new를 써서 부모 함수를 덮어쓰지 않고 숨겨버림
    public new void WhoAmI() => Console.WriteLine("나는 자식이다 (new)"); 
}

// 부모(Parent)라는 만능 리모컨에 자식(ChildNew) 알맹이를 끼워 넣음 (업캐스팅)
Parent p = new ChildNew(); 
p.WhoAmI(); // 출력: "나는 부모다" (다형성 작동 실패)
```

### 수정된 코드 (다형성이 작동하는 `override`)
```csharp
public class ChildOverride : Parent {
    // ⭕ override를 써서 부모의 함수를 완벽히 덮어씌움
    public override void WhoAmI() => Console.WriteLine("나는 자식이다 (override)");
}

Parent p = new ChildOverride();
p.WhoAmI(); // 출력: "나는 자식이다 (override)" (다형성 작동)
```

## 5. 실전 활용 예시 (게임 전투 파티 시스템)

`Character`라는 부모 타입의 리스트(배열) 하나에 전사, 마법사, 궁수를 몽땅 쑤셔 넣고 한 방에 관리하는 다형성의 궁극기입니다.

```csharp
using System;
using System.Collections.Generic;

// 1. 부모 클래스 (만능 리모컨 설계도)
public class Character
{
    public string Name { get; set; }
    public Character(string name) { Name = name; }

    // 자식들이 덮어쓸 수 있도록 virtual 허락
    public virtual void Attack(Character target) 
        => Console.WriteLine($"{Name} ➔ {target.Name} 맨손 공격");
}

// 2. 자식 클래스들 (각자의 개성 있는 구현)
public class Warrior : Character
{
    public Warrior(string name) : base(name) { }
    public override void Attack(Character target) 
        => Console.WriteLine($"{Name} ➔ {target.Name} 강하게 내려찍기");
}

public class Mage : Character
{
    public Mage(string name) : base(name) { }
    public override void Attack(Character target) 
        => Console.WriteLine($"{Name} ➔ {target.Name} 파이어볼 폭발");
        
    // 마법사만 가진 고유 스킬
    public void ChargeMana() => Console.WriteLine($"{Name}이(가) 마나를 집중합니다");
}
```

**[다형성의 축제: 파티 사냥 로직]**
```csharp
class Program
{
    static void Main()
    {
        Character boss = new Character("대악마");
        
        // 부모(Character) 타입의 리스트 하나에 온갖 자식들을 다 담아버림 (업캐스팅)
        List<Character> party = new List<Character>
        {
            new Warrior("강철주먹"),
            new Mage("불꽃술사"),
            new Character("지나가는 마을사람")
        };

        // 1. 다형성의 위력: 타입 검사 없이 Attack 한 줄로 각자의 공격이 알아서 나감
        foreach (Character member in party)
        {
            member.Attack(boss); 
        }

        Console.WriteLine("\n--- 다운캐스팅을 통한 고유 스킬 사용 ---");

        // 2. 다운캐스팅 (is 패턴 매칭): 리모컨으로는 마법사 전용 스킬을 못 누르니까, 진짜 알맹이를 확인
        foreach (Character member in party)
        {
            // "member야, 너 혹시 마법사(Mage) 맞니? 맞다면 mage라는 변수로 변신해줘"
            if (member is Mage mage)
            {
                mage.ChargeMana(); // 오직 불꽃술사만 마나를 채웁니다!
            }
        }
    }
}
```
**출력 결과:**
```text
강철주먹 ➔ 대악마 강하게 내려찍기
불꽃술사 ➔ 대악마 파이어볼 폭발
지나가는 마을사람 ➔ 대악마 맨손 공격

--- 다운캐스팅을 통한 고유 스킬 사용 ---
불꽃술사이(가) 마나를 집중합니다
```

> **설계의 승리**: 내일 `Archer(궁수)` 직업이 10개 더 추가되더라도, `foreach`를 돌며 `Attack()`을 부르는 게임 코드는 **단 한 줄도 수정할 필요가 없습니다.**

## 6. Unity 실무에서의 다형성

유니티 엔진 자체가 거대한 다형성 덩어리입니다.

```csharp
using UnityEngine;
using System.Collections.Generic;

// 1. 유니티의 최상위 컴포넌트인 MonoBehaviour 자체가 엄청나게 많은 virtual 메서드를 품고 있습니다.
public class MyGameComponent : MonoBehaviour
{
    // 우리가 밥 먹듯이 쓰는 Start, Update, OnTriggerEnter 등은 
    // 사실 부모의 보이지 않는 가상(virtual) 메서드를 유니티가 엔진단에서 다형성으로 쏴주는 것입니다
    void Update() { }
}

// 2. 패턴: 적(Enemy) 관리 매니저
public class GameManager : MonoBehaviour
{
    // Inspector 창에서 좀비, 오크, 보스 등 다양한 프리팹을 끌어다 넣을 수 있음
    public List<EnemyBase> activeEnemies; 

    public void OnPlayerSpotted()
    {
        // 리스트를 돌면서 공격 명령 하나만 딱 내려주면,
        // 좀비는 기어오고, 오크는 점프하고, 보스는 레이저를 쏘는 등 알아서 다형성으로 동작합니다.
        foreach (EnemyBase enemy in activeEnemies)
        {
            enemy.ChasePlayer(); 
        }
    }
}
```

## 7. 실습 문제 및 복습

**Q1. 부모 메서드를 자식이 덮어씌워서 다형성을 구현하려면 부모와 자식 메서드에 각각 어떤 키워드를 붙여야 하나요?**
> * 부모 클래스의 메서드: **`virtual`** (재정의를 허락함)
> * 자식 클래스의 메서드: **`override`** (재정의하여 덮어씀)

**Q2. 메서드 오버라이딩(Overriding)과 오버로딩(Overloading)의 차이는 무엇인가요?**
> * **오버라이딩 (Overriding)**: 상속 관계에서 부모의 메서드를 자식이 똑같은 이름/매개변수로 덮어쓰는 것. (수직적 관계)
> * **오버로딩 (Overloading)**: 같은 클래스 내에서 이름은 같지만 매개변수의 개수나 타입이 다른 메서드를 여러 개 만드는 것. (수평적 관계, 예: `Add(int a, int b)`와 `Add(float a, float b)`)

**Q3. 게임 내의 수많은 유닛(아군, 적군, 방어탑)을 `List<Unit>` 하나로 묶어서 관리하면 어떤 장점이 있나요? 다형성 관점에서 설명하세요.**
> * **렌더링과 로직의 압도적 단순화**: `foreach (Unit u in units) u.Draw();` 처럼 반복문 하나로 모든 객체의 화면 그리기와 업데이트를 처리할 수 있습니다.
> * **무한한 확장성**: 새로운 유닛(드래곤, 힐러)이 기획에서 수십 종이 추가되어도, 호출하는 매니저 쪽 코드(`foreach` 문)는 단 한 글자도 수정할 필요가 없습니다. (코드 유지보수성 극대화)
> * **`if-else` 지옥 탈출**: `if (u is Tank) ... else if (u is Healer) ...` 와 같은 지저분한 하드코딩 분기문을 싹 다 지울 수 있습니다.

## 8. 주의사항 및 안전 습관

* **`virtual`을 빼먹지 마라**: 부모 메서드에 `virtual`을 붙이지 않았는데 자식에서 `override`를 시도하면 컴파일 에러가 납니다.
* **`new` 키워드로 메서드를 덮어쓰지 마라**: 경고창을 없애겠다고 자식 메서드에 `new`를 붙이면, 부모 리모컨으로 조작할 때 다형성이 완전히 깨져버립니다. 다르게 동작하게 하려면 무조건 `override`입니다.
* **업캐스팅은 자동이지만 다운캐스팅은 신중하게**: 부모 배열에 자식을 넣는 건 자동으로 안전하게 됩니다(업캐스팅). 하지만 반대로 부모 타입 변수를 억지로 자식 타입으로 바꾸려 할 때(다운캐스팅), 실제 알맹이가 그 자식이 아니라면 프로그램이 터집니다. 반드시 **`if (obj is ChildClass child)`** 구문으로 타입 검사와 다운캐스팅을 동시에 안전하게 수행하세요.
