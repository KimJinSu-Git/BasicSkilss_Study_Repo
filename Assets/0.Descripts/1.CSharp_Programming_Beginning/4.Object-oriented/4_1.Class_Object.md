# [객체 지향] 1. 클래스와 객체 (Class & Object)

## 1. 클래스와 객체란?
객체 지향 프로그래밍(Object-Oriented Programming, OOP)의 첫걸음은 **클래스(Class)** 와 **객체(Object)** 의 관계를 완벽히 이해하는 것입니다.

> **붕어빵 틀과 붕어빵**
> * **클래스 (붕어빵 틀)** : 객체를 만들기 위한 **설계도**입니다. 틀 자체는 먹을 수 없듯, 클래스 자체는 메모리에 실체화되지 않으며 스스로 동작할 수도 없습니다.
> * **객체 (붕어빵)** : 틀에 반죽을 부어 구워낸 **실체(Instance)** 입니다. 힙(Heap) 메모리에 자신의 자리를 잡고, 자기만의 데이터(팥/슈크림)를 가지며, 행동할 수 있습니다.

**왜 필요한가?**\
게임에 등장하는 100마리의 몬스터 체력과 공격 함수를 모두 따로따로 변수로 만든다면 코드가 폭발해 버립니다. 하나의 `Monster` 클래스(설계도)를 잘 만들어 두고 거기서 `new`를 통해 100개의 객체를 찍어내면, 공통 로직은 단 한 번만 작성하면 됩니다. **OOP는 코드 재사용과 유지보수의 출발점입니다.**

## 2. 핵심 요약

| 키워드 | 한 줄 설명                                                |
| :--- |:------------------------------------------------------|
| **클래스 (Class)** | 객체를 만들기 위한 설계도. 객체가 가질 데이터(필드)와 기능(메서드)을 정의           |
| **객체 (Object / Instance)**| 클래스라는 설계도로부터 `new` 키워드를 통해 메모리에 실체화된 결과물              |
| **필드 (Field)** | 객체의 **상태(데이터)** 를 저장하는 클래스 내부의 변수                     |
| **메서드 (Method)** | 객체의 **행동(기능)** 을 정의하는 클래스 내부의 함수                      |
| **생성자 (Constructor)** | `new`로 객체를 생성할 때 **단 한 번 자동 호출**되는 초기화 전용 메서드         |
| **`this` 키워드** | 클래스 내부에서 **객체 자기 자신**을 가리키는 키워드 (주로 필드와 매개변수 구분 시 사용) |

## 3. 세부 개념 및 실무 원리

### 3.1 클래스 정의 ㅡ 나만의 데이터 타입 만들기
클래스를 정의한다는 것은 `int`, `string` 같은 내장 타입 외에, 내가 원하는 속성과 기능을 모두 가진 **나만의 복합 데이터 타입**을 만드는 과정입니다.
* `class` 키워드로 선언합니다.
* 클래스 이름은 무조건 **PascalCase**(첫 글자 대문자)로 작성합니다. (예: `Player`, `MonsterController`)

### 3.2 객체의 3요소: 필드, 생성자, 메서드
1. **필드 (Field)** : 자동차의 '색상', '최대 속도'처럼 객체가 가지는 고유한 상태 값입니다.
2. **생성자 (Constructor)** : 객체가 메모리에 태어나는 순간, 필드들의 초기값을 세팅해 줍니다. 반환 타입(`void` 등)이 아예 없으며 이름이 클래스 이름과 똑같습니다.
3. **메서드 (Method)** : 달린다, 멈춘다처럼 객체가 수행할 수 있는 행동입니다.

### 3.3 메모리 리마인드: 객체는 참조 타입(Reference Type)이다
```csharp
Player warrior = new Player();
```
여기서 `new Player()`를 하면 진짜 붕어빵(실체)은 거대한 **힙(Heap)** 메모리에 만들어집니다.\
그리고 `warrior`라는 변수는 스택(Stack) 메모리에서 그 붕어빵을 가리키는 **'주소(리모컨)'** 만 저장하고 있다는 사실을 명심해야 합니다.

## 4. 코드로 보는 클래스와 객체

### 4.1 기본 문법과 `this` 키워드 활용
```csharp
public class Player
{
    // 1. 필드 (객체의 데이터)
    public string name;       
    public int hp;            

    // 2. 생성자 (객체 생성 시 자동 호출)
    public Player(string name, int hp)
    {
        // this.name은 '나의 필드', 그냥 name은 '들어온 매개변수'
        this.name = name;
        this.hp = hp;
        Console.WriteLine($"[{this.name}] 생성 완료 (HP: {this.hp})");
    }

    // 3. 메서드 (객체의 행동)
    public void TakeDamage(int damage)
    {
        this.hp -= damage;
        Console.WriteLine($"{this.name}이(가) {damage} 피해를 입음 (남은 HP: {this.hp})");
    }
}

// 사용 예시
Player warrior = new Player("전사", 150); // new를 만나 생성자 호출
warrior.TakeDamage(30);
```

### 4.2 잘못된 코드와 흔한 실수
```csharp
class Monster
{
    public int health = 100;
    public void Attack() { Console.WriteLine("공격"); }
}

// ❌ [흔한 실수 1] 설계도(클래스) 자체에다 대고 명령을 내릴 수 없습니다
Monster.Attack();        // 컴파일 에러 "어떤 몬스터가 공격하라는 거지?"
int hp = Monster.health; // 컴파일 에러 "어떤 몬스터의 체력을 보려는 거지?"

// ⭕ [올바른 방법] 반드시 실체(객체)를 찍어낸 뒤, 그 실체에게 명령해야 합니다.
Monster goblin = new Monster(); 
goblin.Attack();
```
> 클래스 이름에 직접 점(`.`)을 찍고 호출하려면 멤버에 `static` 키워드가 붙어있어야 합니다. 하지만 각자 다른 체력을 가지는 일반적인 객체 지향 로직에서는 절대 그렇게 짜지 않습니다.

## 5. 실전 활용 예시 (RPG 상호작용)

객체 지향의 진정한 힘은 **"객체들이 서로의 메서드를 호출하며 상호작용(메시지 패싱)"** 할 때 나옵니다.

```csharp
public class Fighter
{
    public string Name;
    public int Hp;
    public int AttackPower;

    public Fighter(string name, int hp, int attackPower)
    {
        this.Name = name;
        this.Hp = hp;
        this.AttackPower = attackPower;
    }

    // 핵심: 공격 대상 자체(Fighter 객체)를 매개변수로 넘겨받음
    public void Attack(Fighter target)
    {
        Console.WriteLine($"\n🗡️ {this.Name} ➔ {target.Name} 공격");
        
        // 상대방의 피해 입는 메서드를 내가 직접 호출해준다 (메시지 전달)
        target.TakeDamage(this.AttackPower); 
    }

    public void TakeDamage(int damage)
    {
        this.Hp -= damage;
        string status = this.Hp <= 0 ? "쓰러짐" : $"남은 HP: {this.Hp}";
        Console.WriteLine($"   {this.Name} 피해 {damage} ({status})");
    }
}

// 사용
Fighter warrior = new Fighter("강철의 전사", 150, 20);
Fighter mage = new Fighter("화염의 마법사", 100, 35);

mage.Attack(warrior);   // 마법사가 전사를 때린다
warrior.Attack(mage);   // 전사가 마법사를 때린다
```

## 6. Unity에서의 클래스 활용

Unity 엔진에서 `class`를 다룰 때는 약간의 독특한 규칙이 있습니다.

```csharp
using UnityEngine;

// MonoBehaviour를 상속받은 클래스는 씬(Scene)의 부품(컴포넌트)이 됩니다.
public class PlayerController : MonoBehaviour   
{
    public string playerName;
    public int health = 100;

    // MonoBehaviour 클래스는 절대 new PlayerController()로 생성하지 않습니다
    // 하이어라키(Hierarchy)의 GameObject에 컴포넌트로 붙이는 순간, 
    // Unity 엔진 내부에서 알아서 인스턴스화(new)를 진행해 줍니다.

    // Start()가 사실상 Unity 컴포넌트의 '생성자' 역할을 대체합니다.
    void Start()
    {
        Debug.Log($"{playerName} 게임 참여 (HP={health})");
    }

    public void TakeDamage(int damage)
    {
        health -= damage;
    }
}
```
> **요약**: Unity에서 하이어라키 창에 존재하는 오브젝트에 붙일 클래스는 `MonoBehaviour`를 상속받고 `new`를 쓰지 않습니다. 반대로 데이터 보관용 순수 C# 클래스(아이템 정보, 스킬 트리 등)는 콘솔처럼 `new` 키워드로 생성해서 씁니다.

## 7. 실습 문제 및 복습

**Q1. 클래스와 객체의 관계를 "설계도"와 "건물"의 비유로 한 문장으로 설명하세요.**
> 클래스는 무형의 "건물 설계도"이고, 객체(인스턴스)는 그 설계도를 바탕으로 메모리 위에 실제로 지어진 "진짜 건물"입니다. 하나의 설계도로 여러 채의 똑같은 건물을 지을 수 있습니다.

**Q2. 강아지(`Dog`) 클래스를 설계하세요. `name`과 `age` 필드가 있고, 생성자에서 이를 `this` 키워드로 초기화하며, `Bark()` 메서드를 호출하면 이름과 함께 짖습니다.**
```csharp
public class Dog 
{ 
    public string name; 
    public int age;

    public Dog(string name, int age) 
    { 
        this.name = name; 
        this.age = age; 
    }
    
    public void Bark() 
    { 
        Console.WriteLine($"{this.name}이(가) 멍멍"); 
    }
}
```

**Q3. 아래 코드는 `Accelerate()`를 10번 호출해도 `speed`가 계속 10으로 출력됩니다. 어디가 잘못됐는지 찾고 올바르게 수정하세요.**
```csharp
for (int i = 0; i < 10; i++)
{
    Car myCar = new Car(); // 버그: 루프를 돌 때마다 새 차를 계속 뽑아내고 있음
    myCar.Accelerate();
    Console.WriteLine(myCar.speed);
}
```
> **수정안**: `new Car()`를 통해 객체를 생성하는 작업을 루프 밖으로 빼내야 합니다. 그래야 단 하나의 동일한 자동차(객체)에 속도가 계속 누적됩니다.
```csharp
Car myCar = new Car(); // 루프 밖에서 단 한 대만 생성
for (int i = 0; i < 10; i++)
{
    myCar.Accelerate();
    Console.WriteLine(myCar.speed); // 10, 20, 30... 정상 증가
}
```

## 8. 주의사항 및 안전 습관

* **생성자에 반환 타입을 적지 마라**: 실수로 `public void Player()` 라고 적는 경우가 많습니다. `void`가 붙는 순간 이것은 생성자가 아니라 일반 메서드로 취급되어 객체 생성 시 절대 호출되지 않습니다.
* **클래스는 단일 책임을 가져야 한다 (SRP 원칙)**: `Player` 클래스 안에 플레이어 체력도 관리하고, UI에 체력바도 그리고, 사운드도 재생하고, 네트워크 통신도 하게 묶어두면 스파게티 코드가 됩니다. 클래스는 하나의 명확한 역할만 수행하도록 작게 나누는 것이 핵심입니다.
* **명명 규칙 (Naming Convention)**:
    * 클래스 이름, 메서드 이름: `PascalCase` (첫 글자 대문자, 예: `AttackTarget`)
    * 매개변수, 지역 변수: `camelCase` (첫 글자 소문자, 예: `attackDamage`)
