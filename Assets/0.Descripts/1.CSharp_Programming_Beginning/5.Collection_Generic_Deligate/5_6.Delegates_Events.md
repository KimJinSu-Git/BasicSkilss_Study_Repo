# [컬렉션과 제네릭] 6. 델리게이트와 이벤트 (Delegate & Event)

## 1. 델리게이트와 이벤트란?
**델리게이트(Delegate)** 는 '대리자'라는 뜻으로, 값이 아니라 **'함수(메서드)' 자체를 담아두는 특별한 변수**입니다. 담아 두었다가 필요할 때 변수를 호출하면 담겨있던 함수들이 일제히 실행됩니다.\
**이벤트(Event)** 는 그 델리게이트에 **'자물쇠'** 를 하나 채운 것입니다. 외부에서는 구독과 해제만 가능하고, 발동(호출)은 오직 주인만 할 수 있게 캡슐화한 녀석입니다.

> **유튜브 채널 구독 알림**
> * **델리게이트** : 알림을 받을 사람들의 '연락처 명단'입니다. 이 명단에 이름을 더하거나 뺄 수 있습니다.
> * **이벤트** : 그 명단을 **채널 주인만 방송(호출)할 수 있게 잠가버린 것**입니다.
> * 구독자(다른 클래스)는 자기 이름을 명단에 넣고(`+=`) 뺄(`-=`) 수만 있습니다.
> * 남의 채널 명단을 통째로 지워버리거나(`=`), 남의 채널 알림을 내가 맘대로 울려버리는(`Invoke`) 짓을 완벽히 차단합니다.

**왜 필요한가? (느슨한 결합)**\
플레이어의 체력이 깎였을 때 UI 체력바를 줄이고, 피격 사운드를 내고, 카메라를 흔들어야 합니다. 플레이어 클래스 안에서 `ui.UpdateHp()`, `sound.Play()`, `camera.Shake()`를 일일이 부르면, 시스템이 추가될 때마다 플레이어 코드를 고쳐야 합니다 (강한 결합).\
이벤트를 쓰면 플레이어는 **"나 체력 깎였어!"라고 공중에 소리(알림)만 칩니다.** 듣고 싶은 쪽이 스스로 플레이어의 이벤트에 구독(`+=`)합니다. 알리는 쪽은 누가 듣는지 전혀 몰라도 되는 이 구조를 **느슨한 결합(Loose Coupling)** 이라고 부릅니다.

## 2. 핵심 요약

| 개념 | 한 줄 설명                                                          |
| :--- |:----------------------------------------------------------------|
| **델리게이트 (`delegate`)**| 함수를 가리키는 변수 (타입 안전한 함수 포인터)                                     |
| **`Action` / `Func`** | .NET이 미리 만들어둔 표준 제네릭 델리게이트 (반환 없음 `Action` / 반환 있음 `Func`)      |
| **멀티캐스트 (Multicast)** | `+=`, `-=` 연산자로 여러 개의 함수를 하나의 변수에 묶어서 한 방에 호출하는 기능              |
| **이벤트 (`event`)** | 밖에서는 `+=`, `-=` 만 허용하고, 덮어쓰기(`=`)와 호출(`Invoke`)은 막아버린 안전한 델리게이트 |
| **`?.Invoke()`** | 구독자가 0명이면 델리게이트는 `null`이 되므로, 에러 방지를 위해 널 조건부 연산자(`?.`)로 호출     |
| **구독과 해제의 짝** | `+=` 로 구독했다면 반드시 생명주기에 맞춰 `-=` 로 해제해야 메모리 누수가 안 생김              |

## 3. 세부 개념 및 실무 원리

### 3.1 델리게이트 — 함수를 담는 변수
변수는 보통 값을 담지만, 델리게이트는 시그니처(매개변수와 반환형)가 동일한 함수를 담습니다.
```csharp
using System;

public class Greeter
{
    // 1. 담을 대상이 될 평범한 메서드
    public static void SayHello(string name) => Console.WriteLine($"안녕, {name}");

    public static void Run()
    {
        // 2. Action<string>은 'string을 하나 받고 void를 반환하는 함수'를 담는 상자
        Action<string> handler = SayHello; // 괄호()를 안 붙임. 괄호를 붙이면 함수가 실행되어 버림.

        // 3. 변수를 메서드처럼 부른다. (이때 SayHello가 실행됨)
        handler("진수"); 
        // handler.Invoke("진수"); // 위와 완전히 똑같은 코드입니다.
    }
}
```

### 3.2 미리 만들어져 있는 델리게이트 — `Action`과 `Func`
옛날에는 `public delegate void MyDelegate(int a);` 처럼 일일이 타입을 선언했지만, 지금은 제네릭 덕분에 마이크로소프트가 다 만들어 두었습니다.

| 타입 | 매개변수 | 반환값 | 실무 쓰임새 |
| :--- | :--- | :--- | :--- |
| `Action` | 없음 | `void` | 버튼 클릭, 게임 시작, 사망 알림 등 |
| `Action<T>` | 1개 | `void` | 점수 변경 알림 `(int score)` 등 |
| `Action<T1, T2>` | 2개 | `void` | 체력 변경 알림 `(int hp, int maxHp)` 등 |
| `Func<TResult>` | 없음 | **있음** | 타이머 경과 시간 계산 등 |
| `Func<T, TResult>` | 1개 | **있음** | 특정 값을 받아 가공해서 돌려달라고 요청할 때 |

### 3.3 `event` 키워드의 철통 보안
델리게이트 필드를 그냥 `public Action`으로 열어두면 바깥에서 끔찍한 짓을 할 수 있습니다.

| 외부에서 하는 짓 | `public Action OnDied` | `public event Action OnDied` |
| :--- | :--- |:-----------------------------|
| **`+=` (구독)** | ⭕ 됨 | ⭕ 됨 (허용)                     |
| **`-=` (해제)** | ⭕ 됨 | ⭕ 됨 (허용)                     |
| **`=` (덮어쓰기)** | ❌ 됨 (기존 구독자 싹 다 날아감) | **⛔ 컴파일 에러**         |
| **`Invoke` (호출)** | ❌ 됨 (남이 맘대로 사망 발동시킴) | **⛔ 컴파일 에러**          |

```csharp
public class Player
{
    public event Action OnDied; // 밖에서는 구독/해제만 가능

    public void Die()
    {
        // 구독자가 아무도 없으면 OnDied는 null입니다. 
        // 그냥 Invoke()를 부르면 뻗어버리니 반드시 '?.'를 씁니다.
        OnDied?.Invoke(); 
    }
}
```

## 4. 코드로 보는 위력 (옵저버 패턴의 진화)

### 인터페이스로 통신할 때 (Before)
통지가 필요할 때마다 인터페이스를 만들고, 리스트를 만들고, 반복문을 돌리며 일일이 뿌려줘야 합니다.
```csharp
public interface IHpObserver { void OnHpChanged(int hp, int maxHp); }

public class Player
{
    private List<IHpObserver> _observers = new List<IHpObserver>();

    public void Subscribe(IHpObserver obs) => _observers.Add(obs);
    public void Notify() 
    {
        for (int i = 0; i < _observers.Count; i++) _observers[i].OnHpChanged(hp, maxHp);
    }
}
```

### `event`로 묶어버릴 때 (After)
위의 복잡한 5단계 구조가 **`event` 단 한 줄과 `?.Invoke()` 한 줄**로 깔끔하게 압축됩니다.
```csharp
public class Player
{
    public event Action<int, int> OnHpChanged; 

    public void TakeDamage(int damage)
    {
        // 데미지 로직...
        OnHpChanged?.Invoke(hp, maxHp); // 구독자가 알아서 다 받아감
    }
}

public class HpBar
{
    public void Refresh(int hp, int maxHp) { /* UI 갱신 */ }
}

// 메인 로직 (배선 작업)
player.OnHpChanged += hpBar.Refresh; // 인터페이스 상속 따위 필요 없음. 그냥 함수만 끼워 넣으면 끝
```

## 5. Unity에서의 이벤트
유니티에는 알림을 잇는 두 가지 길이 있습니다. 코드로 짜는 **C# `event`** 와 인스펙터 창에서 드래그 앤 드롭으로 연결하는 **`UnityEvent`** 입니다.

### 5.1 C# `event` vs `UnityEvent` 비교

| 항목 | C# `event` | `UnityEvent` |
| :--- | :--- | :--- |
| **연결 장소** | 코드 내부 (`+=`) | 유니티 인스펙터 창 |
| **성능** | **매우 빠름** (직접 호출) | **상대적으로 무거움** (리플렉션 기반) |
| **에러 발견** | 콤파일 시 에러 발생 (안전함) | 함수명/오브젝트가 바뀌면 **조용히 고장남** |
| **추천 용도** | 매 프레임 도는 시스템 간 알림 | UI 버튼 클릭 등 1회성 로직, 기획자 제어용 |

### 5.2 [팁] 구독과 해제의 생명주기 짝맞추기
유니티의 `MonoBehaviour` 객체들이 이벤트를 주고받을 때, **구독(`+=`)을 했으면 객체가 꺼질 때 반드시 해제(`-=`)를 해주어야 메모리 누수와 좀비 버그를 막을 수 있습니다.** 가장 완벽한 짝꿍은 `OnEnable`과 `OnDisable`입니다.

```csharp
public class UIManager : MonoBehaviour
{
    [SerializeField] private Player _player;

    // 컴포넌트가 켜질 때 구독
    private void OnEnable() 
    {
        _player.OnHpChanged += UpdateHpUI;
    }

    // 컴포넌트가 꺼지거나 파괴될 때 반드시 해제
    private void OnDisable() 
    {
        // 이걸 안 하면 UIManager 오브젝트가 파괴된 후에도 Player가 계속 이 UI를 부르려고 시도해서
        // MissingReferenceException이 발생합니다.
        _player.OnHpChanged -= UpdateHpUI; 
    }

    private void UpdateHpUI(int hp, int maxHp) { ... }
}
```
> **왜 `Start` / `OnDestroy` 짝을 안 쓰나요?**\
> `Start`는 컴포넌트가 태어날 때 딱 한 번만 불립니다. 만약 UI를 잠시 껐다(Disable)가 다시 켜면(Enable), `Start`는 다시 불리지 않으므로 영원히 구독이 끊어진 상태가 됩니다. 켜지고 꺼질 때마다 깔끔하게 뗐다 붙였다 하는 `OnEnable/OnDisable` 짝이 가장 안전합니다.

## 6. 실습 문제 및 복습

**Q1. `Action` 델리게이트 변수에 함수를 담을 때, `handler = MyMethod();` 라고 적으면 왜 에러가 나나요?**
> 이름 뒤에 괄호 `()`를 붙이면 **"그 함수를 지금 당장 실행하고 결과값을 가져와라"** 는 뜻이 됩니다. 델리게이트에는 실행된 결과가 아니라 '함수 그 자체(주소)'를 담아야 하므로 괄호를 뺀 이름만 적어야 합니다 (`handler = MyMethod;`).

**Q2. `public Action OnDied;` 대신 `public event Action OnDied;` 를 썼을 때 외부 클래스에서 차단되는 2가지 행동은 무엇인가요?**
> 1. **대입 연산(`=`) 차단**: 실수로 `player.OnDied = ShowGameOver;`를 해버려서 기존에 구독 중이던 사운드, 카메라, 업적 시스템 등의 알림을 싹 다 날려버리는 대참사를 막아줍니다. (오직 `+=`, `-=`만 허용)
> 2. **직접 호출(`Invoke()`) 차단**: 외부 클래스에서 멋대로 `player.OnDied?.Invoke();`를 실행하여 플레이어가 죽지도 않았는데 사망 이벤트를 터트리는 짓을 완벽히 막아줍니다.

**Q3. `GameManager.GameStarted` 라는 정적(Static) 이벤트에 적(Enemy) 생성자에서 구독(`+=`)만 하고 해제를 안 하면 어떤 일이 벌어지나요?**
> `static` 이벤트는 게임이 꺼질 때까지 메모리에 영원히 살아있습니다. 적(Enemy) 오브젝트가 게임 중에 죽어서 삭제(`Destroy`)되더라도, `GameManager`의 이벤트 명단에는 죽은 적의 멱살(참조)이 계속 잡혀 있습니다. 적이 스폰될 때마다 메모리 누수가 발생하고, 게임 시작 이벤트가 터지면 이미 죽은 수천 마리의 적 좀비들이 로직을 실행하며 게임이 멈춰버립니다.

## 7. 주의사항 및 안전 습관

* **이벤트 호출은 항상 `?.Invoke()`로**: 아무도 구독하지 않은 빈 이벤트는 `null`입니다. `if(OnDied != null)` 대신 `OnDied?.Invoke()` 한 줄로 에러를 방어하세요.
* **람다식 구독의 치명적 함정**: `OnDied += () => Debug.Log("죽음");` 처럼 이름 없는 익명 함수나 람다식을 이벤트에 집어넣으면, 나중에 `OnDisable`에서 `-=`로 떼어낼 방법이 없습니다. (이름이 없으니까요). 생명주기를 타는 유니티 이벤트에는 **무조건 이름이 있는 정식 메서드를 만들어서 등록하세요.**
* **이벤트 등록의 중복을 조심하라**: `+=` 연산자는 중복을 걸러주지 않습니다. `Update` 문 안에서 `+=`를 해버리면 1초에 60번씩 똑같은 함수가 명단에 등록되어, 알림이 한 번 터질 때 함수가 60번씩 실행되는 호러쇼가 벌어집니다. 등록은 1회성 타이밍에만 하세요.
