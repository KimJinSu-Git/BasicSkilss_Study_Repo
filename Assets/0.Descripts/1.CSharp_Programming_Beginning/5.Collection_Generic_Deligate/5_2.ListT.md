# [컬렉션과 제네릭] 2. List<T> (동적 배열)

## 1. List<T> 란? (동적 배열)
`List<T>`는 크기가 고정된 일반 배열(`[]`)의 한계를 극복하기 위해 만들어진, 타입이 정해진 마법의 쇼핑백입니다.

> **마법의 쇼핑백**
> * **크기가 자유자재** : 처음에는 비어 있지만 물건을 넣을수록 쇼핑백이 알아서 커집니다. 반대로 빼면 물건의 개수가 줄어듭니다. 처음에 크기를 고민할 필요가 없습니다.
> * **한 종류만 담는 규칙 (`<T>`)** : 과일만 담는 쇼핑백, 장난감만 담는 쇼핑백처럼 **어떤 종류를 담을지 미리 약속**합니다. 숫자를 담기로 한 곳에 문자를 넣으면 튕겨냅니다. 덕분에 꺼낼 때 이 물건이 무엇인지 헷갈릴 일이 없습니다.

**왜 필요한가?**\
"국어 점수가 80점 이상인 학생만 골라서 모아주세요."\
이 요구사항을 일반 배열(`Student[]`)로 풀려면, 몇 명인지 알 수 없으니 배열을 미리 만들 수가 없습니다. 그래서 1번 돌아서 개수를 세고, 그 개수만큼 새 배열을 만든 뒤, 다시 1번 더 돌면서 채워 넣는 비효율적인 짓을 해야 합니다.\
`List<T>`를 쓰면 이 모든 과정이 사라집니다. 그냥 빈 리스트를 만들고, 조건에 맞을 때마다 **`Add`** 만 하면 끝입니다. 적 몬스터 목록, 인벤토리, 대기열 등 게임의 핵심 데이터는 대부분 `List<T>`로 관리됩니다.

## 2. 핵심 요약

| 키워드 / 기능                   | 한 줄 설명 |
|:---------------------------| :--- |
| **`List<T>`**              | 실행 중에 크기가 늘고 주는 동적 배열. `<T>` 자리에 담을 타입을 적음 |
| **네임스페이스**                 | `using System.Collections.Generic;` 필수 |
| **생성 (`new`)**             | `List<int> numbers = new List<int>();` ➔ 생성 직후엔 **비어 있음** |
| **`Count`**                | 현재 들어있는 물건의 개수 (배열의 `Length`와 이름이 다름에 주의) |
| **`Add` / `Insert`**       | `Add`는 맨 뒤에 추가, `Insert`는 원하는 인덱스 번호에 억지로 끼워 넣음 |
| **`Remove` / `RemoveAt`**  | `Remove(값)`은 값을 찾아서 지우고, `RemoveAt(인덱스)`는 해당 자리의 물건을 지움 |
| **인덱스 당겨짐**              | 요소를 지우면, **뒤에 있던 요소들이 앞으로 한 칸씩 당겨지며 빈칸을 채움** |
| **`Contains` / `IndexOf`** | `Contains(값)`은 있는지 여부(`bool`), `IndexOf(값)`은 몇 번째(`int`)인지 반환 |

## 3. 세부 개념 및 원리

### 3.1 만들기 — 처음에는 비어 있습니다
```csharp
using System.Collections.Generic;

// "문자열을 담을 새 쇼핑백을 하나 주세요"
List<string> fruitsBasket = new List<string>();
Console.WriteLine(fruitsBasket.Count); // 0 (배열과 달리 빈칸조차 없습니다)

// C#의 축약 문법 (타입 추론)
List<string> basket = new(); 
List<string> fixedBasket = new() { "사과", "딸기" }; // 만들면서 바로 채우기
```

### 3.2 꺼내기와 인덱서 — 0번부터 받는 번호표
들어간 데이터는 순서대로 번호표(인덱스)를 받으며, 배열과 똑같이 0번부터 시작합니다.
```csharp
fruitsBasket.Add("사과");
fruitsBasket.Add("딸기");

Console.WriteLine(fruitsBasket[1]); // "딸기"
fruitsBasket[1] = "포도"; // 읽기뿐만 아니라 값을 덮어쓸 수도 있습니다.
```
> **인덱스 초과 예외**: 없는 번호표를 부르면 예외가 발생합니다.\
> 배열은 `IndexOutOfRangeException`을 뱉지만, `List<T>`는 **`ArgumentOutOfRangeException`** 을 뱉는다는 미세한 차이가 있습니다.

### 3.3 순회 — `for` 와 `foreach`
전부 꺼내 보려면 반복문을 씁니다. 배열의 `Length` 대신 **`Count`** 를 씁니다.
```csharp
// 1. 값만 필요할 때는 foreach가 더 짧고 안전합니다. (단, 도는 중에 원본 수정 불가)
foreach (string fruit in fruitsBasket) { Console.WriteLine(fruit); }

// 2. "몇 번째인지(인덱스)"가 필요하거나, 안에서 값을 덮어써야 한다면 for를 씁니다.
for (int i = 0; i < fruitsBasket.Count; i++) { fruitsBasket[i] = "다 먹음"; }
```

### 3.4 빼기 — 값으로 지우기와 자리로 지우기
```csharp
bool isRemoved = fruitsBasket.Remove("수박"); // 값으로 찾아서 지운다 (성공하면 true 반환)
fruitsBasket.RemoveAt(0); // 자리(인덱스)로 지운다 (0번 자리를 날려버림)
```

**[가장 중요한 성질: 지우면 당겨진다]**\
`["사과", "바나나", "딸기"]` 에서 `RemoveAt(0)` 을 하면 어떻게 될까요?\
"사과"가 있던 0번 칸이 영구히 비는 것이 아닙니다. 뒤에 있던 **"바나나"가 0번으로, "딸기"가 1번으로 당겨져 올라옵니다.**

### 3.5 참조 타입의 복사 함정
`List<T>`는 참조 타입(Reference Type)이므로, 힙(Heap) 메모리에 올라갑니다. 대입 연산자(`=`)를 쓰면 쇼핑백이 복사되는 게 아니라 **'주소(리모컨)'** 만 복사됩니다.
```csharp
List<string> a = new List<string> { "사과" };
List<string> b = a; // 주소만 복사됨 (같은 쇼핑백을 공유함)
b.Add("포도");
Console.WriteLine(a.Count); // 2 (a를 건드린 적 없지만 늘어남)

// 진짜 복사본(새 쇼핑백)이 필요하다면 이렇게 씁니다.
List<string> copy = new List<string>(a); 
```

## 4. 코드로 보는 `List<T>`의 위력

### 배열만으로 해결하려 할 때 (Before)
결과가 몇 개일지 모르므로, 개수를 먼저 세고 배열을 만든 뒤 다시 채워야 합니다.
```csharp
Student[] FindExcellentStudents(Student[] students, int threshold)
{
    // 1차 순회: 개수 세기
    int count = 0;
    for (int i = 0; i < students.Length; i++)
        if (students[i].Score >= threshold) count++;

    // 배열 생성 및 2차 순회: 채워 넣기
    Student[] result = new Student[count];
    int writeIndex = 0;
    for (int i = 0; i < students.Length; i++)
    {
        if (students[i].Score >= threshold)
            result[writeIndex++] = students[i];
    }
    return result;
}
```

### `List<T>`로 해결 (After)
크기를 정하지 않고 시작해서, 맞는 것을 만날 때마다 `Add`만 하면 알아서 늘어납니다.
```csharp
List<Student> FindExcellentStudents(Student[] students, int threshold)
{
    List<Student> result = new();
    
    for (int i = 0; i < students.Length; i++)
    {
        if (students[i].Score >= threshold)
            result.Add(students[i]); // 넣는 순간 크기가 알아서 늘어난다
    }
    return result;
}
```

> **[심화] LINQ 활용**\
> 사실 위 코드는 LINQ를 쓰면 `for`문조차 필요 없이 **단 한 줄**로 끝납니다.
> ```csharp
> using System.Linq;
> // "80점 이상인 애들만 걸러서(Where) 리스트로 만들어줘(ToList)"
> return students.Where(s => s.Score >= threshold).ToList();
> ```

## 5. 실전 활용 예시 (인벤토리 정리 버그)
인벤토리에서 개수가 0이 된 아이템 슬롯을 찾아 지우는 로직입니다. 얼핏 멀쩡해 보이지만 치명적인 버그가 숨어있습니다.

### 잘못된 코드 (앞에서부터 돌면서 지우기)
```csharp
public void Compact()
{
    for (int i = 0; i < slots.Count; i++)
    {
        if (slots[i].IsEmpty()) 
            slots.RemoveAt(i); // 버그 발생
    }
}
```
**[버그의 원인]**\
`[검 x0, 방패 x0, 물약 x3]` 상태일 때, `i=0`에서 '검'을 지우면 **'방패'가 0번 인덱스로 당겨져 옵니다.**\
하지만 `for`문은 다음 턴에 `i=1`로 넘어가 버리므로, 0번 칸에 새로 당겨져 온 '방패'는 검사조차 받지 못하고 살아남는 유령 슬롯이 됩니다.

### 올바른 해결책
```csharp
// 해결책 1: 뒤에서부터 앞으로 돈다 (당겨져 봐야 이미 검사가 끝난 뒷동네가 당겨지므로 안전함)
for (int i = slots.Count - 1; i >= 0; i--)
{
    if (slots[i].IsEmpty()) slots.RemoveAt(i);
}

// 해결책 2: C#의 람다식을 이용한 싹쓸이 (가장 권장됨)
slots.RemoveAll(slot => slot.IsEmpty());
```

## 6. Unity 최적화 팁

### 6.1 `Update` 문 안에서의 `new List` 금지
`Update` 안에서 매 프레임 `new List<int>()`를 하면 초당 60개의 쓰레기(가비지)가 생깁니다.\
목록을 클래스 필드로 하나만 빼두고, **`Clear()`로 비워서 재사용**하는 것이 기본 습관입니다.

### 6.2 `Clear()`와 메모리 다이어트 (`TrimExcess`)
`Clear()`를 호출하면 리스트 안의 내용물은 싹 지워지지만, **리스트 내부 배열이 이미 늘려놓은 최대 크기(Capacity) 자체는 줄어들지 않고 유지됩니다.** (재사용할 때 빠르기 때문)\
하지만 만약 100만 개를 담았던 리스트를 `Clear`하고 평소엔 10개만 담는다면 엄청난 메모리 낭비가 됩니다. 이때 쪼그라든 내용물 크기에 맞춰 쓸데없는 여유 공간을 잘라내는 메서드가 바로 **`TrimExcess()`** 입니다.
```csharp
myList.Clear();
myList.TrimExcess(); // 불필요하게 늘어난 메모리 공간을 다시 타이트하게 줄여줌
```

## 7. 실습 문제 및 복습

**Q1. `List<T>`에서 요소를 삭제하는 `Remove(값)` 메서드는 어떤 타입의 값을 반환하나요? 왜 이 반환값을 버리면 안 되나요?**
> `bool` 타입을 반환합니다. 삭제에 성공하면 `true`, 리스트 안에 해당 값이 없어서 실패하면 `false`를 반환합니다. 반환값을 `if`문 등으로 확인하지 않고 버리면, 오타가 나서 아무것도 안 지워졌는데도 프로그램이 조용히 통과하는 논리 버그가 발생합니다.

**Q2. `foreach` 문으로 리스트를 순회하는 도중에 `Add`나 `Remove`를 하면 어떻게 되나요?**
> **`InvalidOperationException`** 이 터지며 프로그램이 즉시 강제 종료됩니다. `foreach`는 리스트의 원본 구조가 유지될 것을 전제로 도는데, 도는 도중에 발밑의 징검다리를 빼거나 추가하면 어디까지 돌았는지 순서가 망가지기 때문입니다.

**Q3. 출석부 `attendanceBook` 리스트에서 "영희"가 포함되어 있는지 `Contains` 대신 `IndexOf`로 검색하면 무엇이 달라지며, 각각 어느 상황에 쓰는 것이 맞나요?**
> * `Contains("영희")`: "영희가 있는가?"라는 결과만 `bool(true/false)`로 알려줍니다. 단순히 포함 여부만 판단할 때 씁니다.
> * `IndexOf("영희")`: "영희가 몇 번째 칸에 있는가?"라는 정확한 **위치 인덱스(`int`)** 를 알려줍니다. (없으면 `-1` 반환). 영희를 찾아서 그 자리를 다른 이름으로 덮어쓰거나 지워야 할 때 씁니다.

## 8. 주의사항 및 안전 습관

* **`Length`가 아니라 `Count`다**: 배열(`Array`)은 `Length`를 쓰지만, 리스트(`List`)를 비롯한 모든 컬렉션은 개수를 물어볼 때 `Count`를 씁니다.
* **`RemoveAt`은 지우개가 아니라 블랙홀이다**: 칸의 내용물을 지우고 빈칸을 놔두는 게 아니라, 칸 자체를 찢어버리고 뒤의 것들을 전부 앞으로 한 칸씩 당겨(Shift)버립니다. 이 때문에 엄청난 성능 소모가 발생하므로, 수만 개의 요소를 뺄 때는 조심해야 합니다.
* **지우면서 순회할 때는 무조건 '역순(`for i--`)'으로 돌아라**: 앞에서부터 지우면 당겨져 온 요소를 건너뛰는 치명적 버그가 발생합니다. 혹은 깔끔하게 `RemoveAll(조건)`을 사용하세요.
* **함수 매개변수로 함부로 넘기지 마라**: 리스트는 참조 타입이므로, 넘겨받은 함수 안에서 `Add`나 `Clear`를 해버리면 원본이 통째로 바뀝니다. 읽기 전용으로만 넘기고 싶다면 `IReadOnlyList<T>` 같은 인터페이스로 포장해서 넘겨야 합니다.
