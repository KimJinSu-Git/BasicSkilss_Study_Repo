# [컬렉션과 제네릭] 5. 제네릭 프로그래밍 (Generic Programming)

## 1. 제네릭(Generic)이란?
제네릭은 클래스나 메서드를 설계할 때, 다룰 데이터의 **타입(Type)을 고정하지 않고 `<T>`라는 빈칸으로 비워 두었다가, 실제로 사용할 때 원하는 타입을 끼워 넣는 문법**입니다.

> **우체국 규격 택배 상자**
> * 우체국 상자는 안에 책이 들어가든 신발이 들어가든 상자의 모양(규격)은 똑같습니다.
> * 이 상자에 무엇을 담을지는 상자를 **만드는 사람**이 정하는 게 아니라, 짐을 **포장하는 사람(사용자)** 이 그때그때 정합니다.
> * 제네릭이 그 규격 상자이고, `<T>`는 "이번 상자에는 무엇을 담을지"를 적는 이름표 칸입니다. `List<int>`, `List<string>`이 전부 하나의 규격 상자에서 파생된 것입니다.

**왜 필요한가?**\
정수만 담는 스택, 문자열만 담는 스택, 몬스터만 담는 스택을 따로따로 클래스로 만들면 코드가 무한대로 폭발합니다. 반대로 모든 것을 담을 수 있는 `object` 타입으로 합쳐버리면 엉뚱한 물건이 들어가거나, 넣고 뺄 때마다 무거운 성능 저하(박싱/언박싱)가 발생합니다.\
제네릭은 **"코드 한 벌로 모든 타입을 처리하면서도, 성능 하락과 타입 꼬임 에러를 완벽하게 막아주는"** 현대 프로그래밍 문법입니다.

## 2. 핵심 요약

| 개념 | 한 줄 설명 |
| :--- | :--- |
| **제네릭 (Generic)** | 타입을 `<T>`라는 빈칸으로 받아 두는 문법 (예: `class Box<T>`) |
| **타입 매개변수 (`T`)** | 빈칸의 이름. 보통 `T`를 쓰며, 의미에 따라 `TKey`, `TValue`로 씀 |
| **이점 1: 코드 재사용** | `int`용, `string`용 클래스를 따로 만들지 않고 한 번만 짜면 됨 |
| **이점 2: 타입 안전성** | 엉뚱한 타입이 들어오는 것을 실행 도중이 아니라 **컴파일 타임에 차단함** |
| **이점 3: 성능 최적화** | 값 타입(`int`, `float`)을 담을 때 박싱(Boxing)이 일어나지 않아 초고속임 |
| **제약 조건 (`where`)** | `where T : MonoBehaviour` ➔ `<T>` 자리에 올 수 있는 자격을 좁히는 문법 |

## 3. 세부 개념 및 원리

### 3.1 타입 매개변수의 이름 규칙 (Naming Convention)
꺾쇠 안의 이름은 아무거나 적어도 문법상 동작하지만, 전 세계 개발자의 약속이 있습니다.

| 이름 | 쓰는 자리 | 예시 |
| :--- | :--- | :--- |
| **`T`** | 빈칸이 하나뿐일 때 (Type) | `List<T>`, `Stack<T>` |
| **`TKey`, `TValue`**| 역할이 두 개로 나뉠 때 | `Dictionary<TKey, TValue>` |
| **`TResult`** | 결괏값을 의미할 때 | `Func<T, TResult>` |

### 3.2 제약 조건(`where`) : T의 잠재력을 봉인 해제하다
`<T>`가 아무 타입이나 다 될 수 있다면, 역설적으로 `<T>` 안에서는 아무것도 할 수 없습니다. `T`가 숫자일지 몬스터일지 모르니 `T.Attack()`을 부를 수가 없기 때문입니다.\
이때 **"이런 타입만 허용한다"** 는 제약(`where`)을 걸어주면, 그 순간부터 해당 타입의 고유 기능들이 열립니다.

| 제약 문법 | 허용되는 타입 | 열어 주는 능력 |
| :--- | :--- | :--- |
| `where T : class` | 참조 형식만 가능 | `null` 대입 및 반환 기능이 열림 |
| `where T : new()` | 기본 생성자가 있는 타입만 | 클래스 안에서 `new T();` 로 객체 생성 가능 |
| `where T : Component` | 유니티 컴포넌트만 | `T.gameObject` 나 `T.transform` 사용 가능 |

### 3.3 제네릭 메서드와 `default(T)`
클래스 전체가 아니라 함수(메서드) 하나만 제네릭으로 뚫어버릴 수도 있습니다.
```csharp
// 두 변수의 값을 맞바꾸는 함수 (int든 string이든 다 됨)
public void Swap<T>(ref T a, ref T b)
{
    T temp = a;
    a = b;
    b = temp;
}

int x = 1, y = 2;
Swap(ref x, ref y); // 메서드를 부를 땐 <int>를 안 적어도 매개변수를 보고 알아서 추론합니다
```

만약 `<T>`의 빈값을 반환해야 한다면? 숫자면 `0`, 참조 타입이면 `null`이어야 하므로 헷갈립니다. 이때는 **`default`** 키워드를 씁니다.
```csharp
T empty = default(T); // T가 int면 0, class면 null로 알아서 변신함
```

## 4. 코드로 보는 제네릭의 진화 과정

똑같은 데이터를 담는 스택(Stack)을 만들 때 일어나는 3단 진화입니다.

### 1단계: 타입마다 일일이 복붙하기 (유지보수 지옥)
```csharp
public class IntStack { /* int 배열 처리 로직 */ }
public class StringStack { /* string 배열 처리 로직 */ }
// 몬스터 종류가 100개면 스택 클래스도 100개가 필요함...
```

### 2단계: `object`로 퉁치기 (성능 지옥 & 타입 붕괴)
```csharp
public class ObjectStack
{
    private object[] _items;
    public void Push(object v) { ... }
}

ObjectStack stack = new ObjectStack();
stack.Push(10);     // 박싱(Boxing) 발생. 성능 하락
stack.Push("용사"); // 숫자 스택에 문자열이 섞여도 에러가 안 남

int n = (int)stack.Pop(); // InvalidCastException. 실행 중에 게임이 터짐
```

### 3단계: 제네릭 `<T>` 도입 (완벽한 구원)
```csharp
public class SimpleStack<T>
{
    private T[] _items = new T[16];
    private int _count;

    public void Push(T v) => _items[_count++] = v;
    public T Pop() => _items[--_count];
}

// 1. 사용할 때 비로소 타입을 결정
SimpleStack<int> numbers = new SimpleStack<int>();

numbers.Push(10);
// numbers.Push("용사"); // 컴파일 에러. 애초에 들어가지도 못하게 편집기에서 빨간 줄이 그어짐.

int n = numbers.Pop(); // 빼낼 때 캐스팅(int)도 필요 없고, 박싱도 안 일어나서 초고속임.
```

## 5. 실전 활용 예시 (다목적 데이터 캐시)

유저 정보는 ID로 찾고, 아이템은 아이템 코드로 찾아야 합니다. 다루는 타입만 다를 뿐 딕셔너리로 보관하고 빼오는 로직은 똑같습니다.

```csharp
using System.Collections.Generic;

// T 자리에 무조건 참조 타입(class)만 들어오도록 제약을 겁니다.
public class DataCache<T> where T : class
{
    private Dictionary<string, T> _cache = new Dictionary<string, T>();

    public void Add(string key, T data)
    {
        _cache.TryAdd(key, data);
    }

    // where T : class 덕분에, 못 찾았을 때 당당하게 null을 돌려줄 수 있습니다
    public T Get(string key) => _cache.GetValueOrDefault(key, null);
}

// 사용 예시
DataCache<User> userCache = new DataCache<User>();
userCache.Add("u1", new User { Name = "Alice" });
User u = userCache.Get("u1"); // 형변환 없이 깔끔하게 User 객체가 튀어나옴
```

## 6. Unity 실무에서의 제네릭

### 6.1 우리는 이미 제네릭을 쓰고 있었다
```csharp
// 유니티의 가장 유명한 제네릭 삼대장
Rigidbody2D rb = GetComponent<Rigidbody2D>(); // T 타입으로 컴포넌트를 찾아 반환
Bullet b = Instantiate<Bullet>(bulletPrefab); // 복제 후 T 타입으로 형변환까지 알아서 해줌
GameManager gm = FindFirstObjectByType<GameManager>(); 
```

### 6.2 [패턴] 제네릭 싱글톤 (Generic Singleton)
유니티에서 `GameManager`, `SoundManager` 등을 만들 때 매번 싱글톤 코드를 복사 붙여넣기 하는 것은 끔찍한 일입니다.\
이때 제네릭 부모 클래스를 딱 하나만 만들어두면 평생 써먹을 수 있습니다.

```csharp
using UnityEngine;

// "나를 상속받는 자식 타입(T)은 무조건 MonoBehaviour여야 한다"
public abstract class Singleton<T> : MonoBehaviour where T : MonoBehaviour
{
    public static T Instance { get; private set; }

    protected virtual void Awake()
    {
        if (Instance == null) { Instance = this as T; }
        else { Destroy(gameObject); }
    }
}

// 자식들은 그저 상속 한 줄만 적으면 완벽한 싱글톤 매니저가 됩니다
public class GameManager : Singleton<GameManager> 
{
    public void StartGame() { ... }
}

public class SoundManager : Singleton<SoundManager> 
{
    public void PlayBGM() { ... }
}
```

## 7. 실습 문제 및 복습

**Q1. `List<int>`와 `ArrayList(object를 담는 구형 컬렉션)`의 차이를 '타입 안전성'과 '성능' 관점에서 비교하세요.**
> * **타입 안전성**: `List<int>`는 정수만 허용하여 엉뚱한 값이 들어오면 컴파일 에러를 내지만, `ArrayList`는 문자를 섞어 넣어도 컴파일러가 통과시키며 나중에 빼낼 때 크래시(런타임 에러)가 납니다.
> * **성능**: `List<int>`는 `int`를 순수하게 담아 초고속이지만, `ArrayList`는 값 타입을 힙 메모리에 올리는 박싱(Boxing)과 내리는 언박싱(Unboxing) 과정이 발생하여 심각한 성능 저하와 가비지(GC)를 유발합니다.

**Q2. 아래 제네릭 메서드가 컴파일되지 않는 이유와 필요한 `where` 제약 조건은 무엇인가요?**
```csharp
public T CreateNewInstance<T>() { return new T(); }
```
> **이유**: 컴파일러는 `<T>`로 들어올 타입에 '매개변수가 없는 기본 생성자'가 존재하는지 보장할 수 없기 때문에 냅다 에러를 냅니다.\
> **해결**: `public T CreateNewInstance<T>() where T : new()` 처럼 **`new()` 제약**을 걸어주면 깔끔하게 해결됩니다.

**Q3. 두 타입을 한 쌍으로 묶는 `Pair<T1, T2>` 클래스를 만들고, `Pair<int, string>`을 생성해 보세요.**
```csharp
public class Pair<TFirst, TSecond>
{
    public TFirst First { get; set; }
    public TSecond Second { get; set; }

    public Pair(TFirst first, TSecond second)
    {
        First = first; Second = second;
    }
}
// 사용
Pair<int, string> answer = new Pair<int, string>(42, "정답");
```

## 8. 주의사항 및 안전 습관

* **꺾쇠(`<T>`)가 3겹 이상 겹치면 리팩토링하라**: `Dictionary<int, List<Pair<string, T>>>` 처럼 제네릭이 미친 듯이 겹치기 시작하면 가독성이 박살 납니다. 이럴 때는 내부 자료구조를 묶는 별도의 `class`를 새로 만드세요.
* **`where` 제약은 꼭 필요한 것만 최소한으로 걸어라**: 불필요하게 `where T : MonoBehaviour`를 걸면 일반 순수 C# 클래스를 깎아 넣을 수 없게 됩니다. 필요한 권한만큼만 좁히세요.
* **제네릭 만능주의를 버려라**: 굳이 제네릭을 안 써도 상속(다형성)이나 인터페이스 하나로 깔끔하게 풀리는 문제가 많습니다. 클래스에 `<T>`가 붙는 순간 이 코드를 읽는 동료는 "여기에 뭐가 들어올까?"를 뇌에서 한 번 더 처리해야 하므로 코스트가 증가합니다
