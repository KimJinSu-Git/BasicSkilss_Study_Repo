# [컬렉션과 제네릭] 4. Dictionary 와 HashSet

## 1. Dictionary 와 HashSet 이란?
배열과 `List<T>`는 데이터를 '순서대로' 담는 그릇입니다. 순서(인덱스)를 알면 빠르지만, "김철수의 나이"처럼 특정 **이름**으로 찾아야 할 때는 처음부터 하나씩 다 뒤져봐야($O(N)$) 하는 치명적인 단점이 있습니다.\
이를 완벽하게 해결해 주는 마법의 그릇이 바로 `Dictionary`와 `HashSet`입니다.

> **사물함과 주머니**
> * **`Dictionary<TKey, TValue>` (이름표가 붙은 사물함)** : 칸마다 이름표(Key)가 하나씩 붙어 있습니다. 이름표만 알면 몇 번째 칸인지 세어 보지 않고 곧장 엽니다. 이름표는 서로 달라야(중복 불가) 하지만, 칸 안의 내용물(Value)은 똑같은 게 들어있어도 상관없습니다.
> * **`HashSet<T>` (중복 없는 마법 주머니)** : 값 하나만 툭툭 던져 넣습니다. 같은 물건을 두 번 넣을 수 없으며, 이미 있는 것을 또 넣으면 오류가 아니라 그냥 조용히 무시됩니다. 주머니 속 물건들은 특별한 순서 없이 섞여 있습니다.

**왜 필요한가?**
1. **압도적인 검색 속도**: 데이터가 10개든 10만 개든, 찾는 속도가 거의 일정하게 즉시($O(1)$) 나옵니다.
2. **중복 자동 차단**: `HashSet`은 데이터의 중복을 막기 위한 지저분한 `for`문과 `if`문을 싹 다 없애줍니다.

## 2. 핵심 요약

| 항목 | `Dictionary<TKey, TValue>` (사전) | `HashSet<T>` (해시셋) |
| :--- | :--- | :--- |
| **담는 것** | 키(Key)와 값(Value)의 쌍 | 고유한 값(Value) 하나 |
| **중복 규칙** | **키는 중복 불가**, 값은 중복 가능 | **중복 완벽 불가** |
| **순서** | 들어간 순서가 보장되지 않음 | 들어간 순서가 보장되지 않음 |
| **넣기** | `.Add(key, val)` (중복 시 에러) <br> `dict[key] = val` (중복 시 덮어씀) | `.Add(item)` (중복 시 조용히 무시, `false` 반환) |
| **찾기** | `.ContainsKey(key)` <br> `.TryGetValue()` | `.Contains(item)` |
| **지우기** | `.Remove(key)` | `.Remove(item)` |

## 3. 세부 개념 및 원리

### 3.1 `Dictionary` 만들고 넣기 (중복 처리의 3가지 태도)
만들 때 꺾쇠 안에 키의 타입과 값의 타입을 차례로 적습니다.

```csharp
using System.Collections.Generic;

// "문자열 이름(Key)으로 정수 나이(Value)를 담을 사물함"
Dictionary<string, int> studentAges = new Dictionary<string, int>();

// 1. .Add (엄격함): 키가 이미 있으면 ArgumentException 에러를 뿜으며 게임을 터트림
studentAges.Add("김철수", 20); 

// 2. 인덱서 대입 (유연함): 키가 없으면 새로 만들고, 있으면 조용히 값을 덮어씀 (가장 많이 씀)
studentAges["이영희"] = 22;
studentAges["김철수"] = 21; // 철수의 나이가 20에서 21로 수정됨

// 3. .TryAdd (무시함): 없으면 넣고(true), 이미 있으면 무시함(false 반환)
bool isAdded = studentAges.TryAdd("이영희", 99); // false 반환, 이영희 나이는 여전히 22
```

### 3.2 값 꺼내기 — `TryGetValue`와 `GetValueOrDefault`
이름표(Key)를 대괄호에 넣으면 값이 나옵니다. 단, **없는 이름표를 넣으면 프로그램이 죽습니다 (`KeyNotFoundException`).**\
그래서 실무에서는 대괄호를 바로 쓰기 전에 묻고 따지는 안전한 메서드를 씁니다.

```csharp
// 정석: 있는지 확인하면서 값까지 안전하게 빼오기
if (studentAges.TryGetValue("최수지", out int sujiAge))
{
    Console.WriteLine($"최수지의 나이: {sujiAge}");
}

// 꿀팁: "있으면 그거 주고, 없으면 에러 내지 말고 기본값 0 줘" (C# 7.0+)
int unknownAge = studentAges.GetValueOrDefault("존도우", 0); 
```

### 3.3 전부 돌아보기 (KeyValuePair)
`Dictionary`를 `foreach`로 돌리면 `KeyValuePair`라는 특별한 쌍으로 묶여서 나옵니다.
```csharp
foreach (KeyValuePair<string, int> entry in studentAges)
{
    Console.WriteLine($"이름: {entry.Key}, 나이: {entry.Value}");
}
// 주의: 출력 순서는 넣은 순서와 무관합니다. 순서가 중요하다면 List를 써야 합니다.
```

### 3.4 `HashSet` : 중복 없는 완벽한 주머니
실패를 에러로 터트리지 않고 깔끔하게 `bool(false)`로 알려주는 착한 컬렉션입니다.
```csharp
HashSet<string> uniqueColors = new HashSet<string>();

uniqueColors.Add("빨강");
uniqueColors.Add("파랑");

bool isAdded = uniqueColors.Add("빨강"); // 이미 있으므로 false를 반환하고 조용히 넘어감
Console.WriteLine(uniqueColors.Count);   // 여전히 2개
```

## 4. 코드로 보는 위력 (배열 vs 해시)

### 배열만으로 해결하려 할 때 (Before)
이름으로 나이를 찾고, 참가자 명단의 중복을 제거하는 최악의 시간복잡도 코드입니다.
```csharp
List<string> names = new List<string> { "김철수", "이영희", "박민수" };
List<int> ages = new List<int> { 20, 22, 21 };

// 1. 이름으로 나이 찾기 (앞에서부터 전부 훑어야 함)
for (int i = 0; i < names.Count; i++)
{
    if (names[i] == "이영희") Console.WriteLine(ages[i]);
}

// 2. 중복 없는 참가자 명단 (넣을 때마다 리스트 전체를 뒤져야 함)
string[] entries = { "김철수", "이영희", "김철수", "박민수" };
List<string> players = new List<string>();
foreach (string entry in entries)
{
    if (!players.Contains(entry)) players.Add(entry);
}
```

### Dictionary와 HashSet으로 해결 (After)
```csharp
// 1. 이름과 나이를 하나로 묶고, 0.0001초 만에 즉시 찾아냄
Dictionary<string, int> studentAges = new Dictionary<string, int>
{
    { "김철수", 20 }, { "이영희", 22 }, { "박민수", 21 }
};
Console.WriteLine(studentAges["이영희"]); // 바로 22 출력

// 2. 중복 검사를 짤 필요도 없이, 그릇 자체가 알아서 걸러줌
string[] entries = { "김철수", "이영희", "김철수", "박민수" };

HashSet<string> players = new HashSet<string>(entries);
Console.WriteLine(players.Count); // 중복이 날아간 3 출력
```

## 5. 실전 활용 예시 (상점 구매 시스템)
`Dictionary`로 가격표를 만들고, `HashSet`으로 구매 내역(중복 구매 불가)을 관리합니다.

```csharp
class Shop
{
    // 이름표(아이템 이름) → 내용물(가격)
    private readonly Dictionary<string, int> _priceTable = new Dictionary<string, int>
    {
        { "체력 물약", 100 }, { "마나 물약", 120 }, { "강철 검", 500 }
    };

    // 이미 산 아이템 기록 (중복 불가)
    private readonly HashSet<string> _purchased = new HashSet<string>();

    public void Buy(string itemName, ref int gold)
    {
        // 1) 파는 물건인가? (가격 정보 안전하게 빼오기)
        if (!_priceTable.TryGetValue(itemName, out int price))
        {
            Console.WriteLine($"{itemName}은(는) 팔지 않습니다");
            return;
        }

        // 2) 이미 샀는가? (Add가 false를 주면 이미 있다는 뜻)
        if (!_purchased.Add(itemName))
        {
            Console.WriteLine($"{itemName}은(는) 이미 보유 중입니다");
            return;
        }

        // 3) 돈이 모자라면? 방금 넣은 기록을 롤백(제거)한다.
        if (gold < price)
        {
            _purchased.Remove(itemName);
            Console.WriteLine($"골드가 {price - gold}G 부족합니다.");
            return;
        }

        gold -= price;
        Console.WriteLine($"{itemName} 구매 완료");
    }
}
```

## 6. Unity 실무 최적화 팁

### 6.1 인스펙터에 안 보이는 딕셔너리, 이렇게 풉니다
유니티의 인스펙터는 `Dictionary`를 직렬화(저장/노출)하지 못합니다. 그래서 기획자가 데이터를 세팅해야 하는 경우 **"인스펙터 노출용 `List`"** 와 **"게임 로직용 `Dictionary`"** 를 분리합니다.

```csharp
using System.Collections.Generic;
using UnityEngine;

public class ItemDatabase : MonoBehaviour
{
    [System.Serializable]
    public class ItemEntry { public string id; public int price; }

    // 1. 기획자가 에디터에서 편하게 채우는 공간
    [SerializeField] private List<ItemEntry> _entries = new List<ItemEntry>();

    // 2. 실제 게임 중 초고속 검색을 담당할 공간
    private readonly Dictionary<string, int> _priceTable = new Dictionary<string, int>();

    private void Awake()
    {
        // 게임 시작 시, 리스트를 순회하며 딕셔너리로 싹 옮겨 담습니다.
        foreach (ItemEntry entry in _entries)
        {
            if (!_priceTable.TryAdd(entry.id, entry.price))
                Debug.LogWarning($"[경고] 중복된 아이템 ID가 있습니다: {entry.id}");
        }
        
        // 메모리를 아끼려면 옮겨 담은 후 리스트를 비우는 것도 좋습니다.
        _entries.Clear(); 
    }
}
```

### 6.2 [팁] 딕셔너리와 해시셋의 Capacity 최적화
이 두 그릇은 속도는 빛처럼 빠르지만, 내부에 복잡한 방(해시 테이블)을 만들기 때문에 **처음 생성할 때 `List`보다 메모리를 훨씬 많이 먹습니다.** 또한 방이 꽉 차서 2배로 늘릴 때(Resizing) 엄청난 렉(스파이크)이 걸립니다.\
데이터가 대략 몇 개 들어올지 안다면, **생성자에 미리 크기(Capacity)를 적어주어 렉을 완벽히 차단하세요.**
```csharp
// "어차피 아이템 1000개 들어올 거니까 처음부터 방 1000개짜리로 만들어놔"
Dictionary<string, int> itemTable = new Dictionary<string, int>(1000); 
```

## 7. 실습 문제 및 복습

**Q1. `Dictionary`에서 `dict.Add("키", 1)` 과 `dict["키"] = 1` 의 결정적인 차이는 무엇인가요?**
> `Add()`는 이미 해당 키가 존재하면 가차 없이 `ArgumentException` 예외를 던지며 프로그램을 중단시킵니다(엄격함). 반면 인덱서(`[]`) 대입은 키가 있으면 **새로운 값으로 조용히 덮어씌웁니다**(유연함).

**Q2. 문자열 배열 `string[] names`에 1만 개의 이름이 들어있습니다. 여기서 중복된 이름을 모두 제거하고 고유한 이름만 남기려면 코드를 어떻게 짜야 가장 빠를까요?**
> `for`문으로 빙빙 돌며 `List.Contains`를 쓰면 시간이 엄청나게 오래 걸립니다. 컬렉션 초기화자를 이용해 **`HashSet<string> uniqueNames = new HashSet<string>(names);`** 단 한 줄로 생성하면 내부적으로 즉시 중복이 모두 걸러집니다.

**Q3. `HashSet`에서 `Add`와 `Remove` 메서드가 `void`가 아니라 `bool`을 반환하는 이유는 무엇이며, 실무에서 이를 어떻게 활용하나요?**
> 성공과 실패를 예외(에러) 없이 안전하게 알려주기 위함입니다. `if (mySet.Add(item))` 구문 하나로 **"이 아이템이 이미 존재하는지 검사"** 하는 작업과 **"없으면 추가"** 하는 두 가지 작업을 단번에 수행할 수 있어 로직이 극도로 깔끔해집니다.

## 8. 주의사항 및 안전 습관

* **없는 키를 `[]`로 바로 읽지 마라**: `int age = dict["없는키"];`를 치는 순간 게임은 크래시가 납니다. 항상 `TryGetValue`나 `GetValueOrDefault`로 안전하게 빼오세요.
* **순서를 믿지 마라**: 두 그릇 모두 넣은 순서대로 출력된다는 보장이 없습니다. 순서가 중요한 랭킹 데이터 같은 곳에는 절대 쓰면 안 됩니다.
* **`ContainsValue`는 지옥이다**: 딕셔너리에서 `.ContainsKey()`는 $O(1)$로 즉시 찾아내지만, `.ContainsValue()`는 값을 찾기 위해 1번 방부터 끝 방까지 다 뒤지는 $O(N)$ 연산입니다. 값으로 찾아야 할 일이 많다면 키(Key) 설계를 잘못한 것입니다.
* **키(Key) 값은 불변이어야 한다**: 클래스 객체를 키로 집어넣고 나서 그 객체의 내부 변수 내용을 바꿔버리면, 해시(Hash) 계산이 꼬여서 영원히 그 데이터를 찾을 수 없는 미아가 됩니다. 키는 `int`, `string` 등 변하지 않는 값을 주로 써야 합니다.
