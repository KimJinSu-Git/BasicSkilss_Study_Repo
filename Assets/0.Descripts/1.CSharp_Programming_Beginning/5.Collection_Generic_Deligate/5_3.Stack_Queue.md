# [컬렉션과 제네릭] 3. `Stack<T>` 와 `Queue<T>`

## 1. Stack과 Queue란?
모든 것을 담고 중간에서 마음대로 뺄 수 있는 `List<T>`와 달리, 넣고 빼는 순서에 **엄격한 규칙(제약)** 을 걸어둔 특수 목적의 컬렉션입니다.

> **카드 더미와 드라이브 스루**
> * **`Stack<T>` (카드 더미)** : 카드는 맨 위에만 올려놓을 수 있고, 집을 때도 맨 위 한 장만 집을 수 있습니다. 가장 마지막에 놓은 카드가 가장 먼저 손에 들어옵니다. **LIFO (Last-In, First-Out)**
> * **`Queue<T>` (드라이브 스루)** : 차는 뒤에 와서 붙고, 주문을 받고 나가는 것은 언제나 맨 앞 차입니다. 중간에 끼어들 수도, 중간 차가 먼저 빠져나갈 수도 없습니다. **FIFO (First-In, First-Out)**

**왜 필요한가? `List<T>` 하나면 다 되지 않나?**\
'되돌리기(Undo)' 기능을 `List`로 만든다고 해봅시다. 가장 최근 작업은 맨 끝에 있으니 `history[history.Count - 1]`로 읽고 `RemoveAt(history.Count - 1)`로 지워야 합니다. 빼는 순서를 지키는 일이 전부 개발자의 몫이고, 인덱스를 한 칸이라도 잘못 적으면 엉뚱한 작업이 날아갑니다.

`Stack<T>`을 쓰면 이 골치 아픈 계산이 완전히 사라집니다. `Push`로 넣고 `Pop`으로 꺼내면 끝이며, 인덱스가 없으니 인덱스 버그를 낼 방법 자체가 원천 차단됩니다. **"제약이 곧 안전장치"** 가 되는 프로그래밍의 묘미입니다.

> **주의: 자료구조 Stack과 스택 메모리는 다른 것입니다**\
> 이전 챕터에서 배운 '스택 메모리'는 OS가 관리하는 메모리 영역의 이름이고, 여기서 배우는 `Stack<T>`는 내가 직접 데이터를 담기 위해 `new`로 만드는 객체(컬렉션)입니다. 둘 다 LIFO 규칙으로 움직이기 때문에 이름이 같을 뿐, 본질은 다릅니다.

## 2. 핵심 요약

| 구분 | `Stack<T>` (스택) | `Queue<T>` (큐) |
| :--- | :--- | :--- |
| **규칙** | **LIFO** ➔ 마지막에 넣은 것이 먼저 나옴 | **FIFO** ➔ 먼저 넣은 것이 먼저 나옴 |
| **넣기** | `Push(값)` ➔ 맨 **위**에 올림 | `Enqueue(값)` ➔ 맨 **뒤**에 줄을 세움 |
| **꺼내기** | `Pop()` ➔ 맨 **위**를 꺼내며 제거함 | `Dequeue()` ➔ 맨 **앞**을 꺼내며 제거함 |
| **확인만** | `Peek()` ➔ 맨 위를 제거하지 않고 확인만 함 | `Peek()` ➔ 맨 앞을 제거하지 않고 확인만 함 |
| **인덱스** | `stack[0]` 불가능 (중간 훔쳐보기 금지) | `queue[0]` 불가능 (중간 새치기 금지) |
| **대표 쓰임새**| 되돌리기(Undo), UI 뒤로가기 창, 재귀 추적 | 몬스터 스폰 대기열, 패킷 버퍼, 순서 보장 |

## 3. 세부 개념 및 원리

### 3.1 `Stack<T>` — 위에 쌓고 위에서 꺼낸다
```csharp
using System.Collections.Generic;

Stack<int> cardPile = new Stack<int>();

cardPile.Push(10);
cardPile.Push(20);
cardPile.Push(30); // 맨 위는 30

// Peek: 훔쳐만 보기 (개수가 줄지 않음)
Console.WriteLine(cardPile.Peek());  // 30 출력, Count는 여전히 3

// Pop: 꺼내서 가져가기 (개수가 줄어듦)
Console.WriteLine(cardPile.Pop());   // 30 출력, Count는 2로 줄어듦
Console.WriteLine(cardPile.Pop());   // 20 출력, Count는 1로 줄어듦
```

### 3.2 `Queue<T>` — 뒤에 붙이고 앞에서 꺼낸다
```csharp
Queue<string> waitingLine = new Queue<string>();

waitingLine.Enqueue("앨리스");
waitingLine.Enqueue("밥");
waitingLine.Enqueue("찰리"); // 맨 앞은 여전히 앨리스, 맨 뒤에 찰리

// 스택과 헷갈림 주의: 큐의 Peek은 맨 '앞(처음 넣은 것)'을 보여줍니다.
Console.WriteLine(waitingLine.Peek()); // 앨리스 출력

Console.WriteLine(waitingLine.Dequeue()); // 앨리스 출력 (줄에서 빠져나감)
Console.WriteLine(waitingLine.Dequeue()); // 밥 출력
```

### 3.3 왜 `List.RemoveAt(0)` 대신 `Queue`를 써야 할까? (순환 배열의 마법)
앞선 챕터에서 `List`의 0번 인덱스를 지우면 뒤에 있는 100만 개의 데이터가 한 칸씩 앞으로 당겨지며 엄청난 성능을 깎아먹는다고 배웠습니다.\
그럼 `Queue`에서 `Dequeue()`로 맨 앞사람을 빼내면 뒤에 있는 사람들이 다 한 칸씩 앞으로 당겨질까요? **아닙니다**\
`Queue`는 내부적으로 **원형 큐(Circular Array)** 라는 마법을 씁니다. 맨 앞사람이 빠져나가면 뒤를 당겨오는 게 아니라, **"맨 앞이 여기다"라고 가리키는 화살표(Head 포인터)만 한 칸 뒤로 살짝 옮깁니다.** 덕분에 데이터가 수백만 개여도 0.0001초 만에 요소를 뺄 수 있습니다.

### 3.4 빈 컬렉션: 예외와 `Try` 짝꿍
비어 있는 스택/큐에서 `Pop`이나 `Dequeue`를 부르면 `InvalidOperationException`을 던지며 게임이 멈춥니다.\
이를 막는 방법이 **`Try` 패턴**입니다.

```csharp
Stack<string> history = new Stack<string>();

// 나쁜 예: 비어있으면 크래시
// string last = history.Pop(); 

// 정석 1: 묻고 따지기
if (history.Count > 0) { Console.WriteLine(history.Pop()); }

// 정석 2: 시도해보고 성공하면 뽑아라
if (history.TryPop(out string action))
{
    Console.WriteLine($"취소된 액션: {action}");
}
else
{
    Console.WriteLine("더 이상 되돌릴 작업이 없습니다."); // 에러 없이 부드러운 분기 처리
}
```

## 4. 실전 활용 예시 (블록 퍼즐 게임)
퍼즐 게임에서 '되돌리기(Undo)'와 '다음 블록 예고' 기능을 구현합니다.\
되돌리기는 가장 최근 것부터 빠져야 하니 **`Stack`**, 예고 블록은 만들어진 순서대로 나와야 하니 **`Queue`** 가 완벽합니다.

```csharp
using System;
using System.Collections.Generic;

class PuzzleBoard
{
    // 놓은 블록 기록 (LIFO)
    private Stack<string> _placedBlocks = new Stack<string>();

    // 앞으로 나올 블록 예고 (FIFO)
    private Queue<string> _upcomingBlocks = new Queue<string>();
    private string[] _shapes = { "I", "O", "T", "L", "S" };

    public void Ready()
    {
        // 큐에 3개의 미리보기 블록을 채워둠
        for (int i = 0; i < 3; i++) 
            _upcomingBlocks.Enqueue(_shapes[new Random().Next(_shapes.Length)]);
    }

    public string TakeNextBlock()
    {
        // 1. 큐의 맨 앞에서 다음 블록을 뺀다
        string next = _upcomingBlocks.Dequeue();
        
        // 2. 큐의 맨 뒤에 새 블록을 채워 3개를 유지한다
        _upcomingBlocks.Enqueue(_shapes[new Random().Next(_shapes.Length)]);

        // 3. 방금 꺼낸 블록을 화면에 놓았다고 치고 스택에 기록한다
        _placedBlocks.Push(next);
        
        return next;
    }

    public void Undo()
    {
        // 스택의 맨 위(가장 최근) 블록을 빼서 취소한다
        if (_placedBlocks.TryPop(out string canceled))
            Console.WriteLine($"되돌림: {canceled} 블록 취소 완료");
        else
            Console.WriteLine("되돌릴 블록이 없습니다.");
    }
}
```

## 5. Unity 최적화 팁
### 5.1 유니티에서는 어디에 쓸까?
* **`Stack`**: UI 팝업 창 관리. 창을 켤 때마다 `Push`하고, [ESC] 키나 [뒤로가기]를 누를 때마다 `Pop`해서 꺼버리면 완벽한 창 관리가 됩니다.
* **`Queue`**: 몬스터 스폰 대기열, 코루틴 체인, 오브젝트 풀링(Object Pooling).

### 5.2 인스펙터에 안 보인다고요? (꼼수)
유니티의 직렬화(Serialization)는 `List`와 배열만 지원하므로, `[SerializeField] private Queue<GameObject> _pool;`을 써도 인스펙터에 나타나지 않습니다. 기획자가 에디터에서 초기 스폰 목록을 세팅해야 한다면 이렇게 풉니다.

```csharp
public class WaveSpawner : MonoBehaviour
{
    // 1. 기획자가 인스펙터에서 편하게 채우는 리스트 (노출용)
    [SerializeField] private List<GameObject> _initialEnemies;
    
    // 2. 실제 런타임에 게임 로직이 돌아가는 큐 (숨김용)
    private Queue<GameObject> _enemyQueue;

    void Awake()
    {
        // 게임 시작 시, 리스트의 내용물을 큐로 싹 옮겨 담습니다
        _enemyQueue = new Queue<GameObject>(_initialEnemies);
        
        // 메모리를 아끼려면 리스트는 비워줍니다.
        _initialEnemies.Clear(); 
    }

    public void SpawnNext()
    {
        if (_enemyQueue.TryDequeue(out GameObject enemyPrefab))
        {
            Instantiate(enemyPrefab);
        }
    }
}
```

## 6. 실습 문제 및 복습

**Q1. `Queue`를 순회하면서 모든 요소를 출력해야 합니다. 요소들을 큐에서 제거하지 않고(보존하면서) 내용만 확인하려면 어떤 반복문을 써야 하나요?**
> `foreach` 문을 사용하면 됩니다. `while(queue.Count > 0)`과 `Dequeue()`를 조합하면 출력과 동시에 큐가 텅 비게 되지만, `foreach (var item in queue)`를 사용하면 내용물을 줄이지 않고 처음부터 끝까지 훑어볼 수 있습니다. (단, 도는 중에 요소를 넣거나 빼면 에러가 납니다.)

**Q2. `Queue<int> source`를 넘겨받아 순서가 완벽히 뒤집힌 새로운 큐를 반환하는 메서드를 만드세요. (`Stack`을 활용할 것)**
```csharp
static Queue<int> ReverseQueue(Queue<int> source)
{
    Stack<int> buffer = new Stack<int>();

    // 1. 큐에서 차례대로 빼서 스택에 쌓는다 (순서가 뒤집힘)
    while (source.Count > 0) buffer.Push(source.Dequeue());

    Queue<int> result = new Queue<int>();

    // 2. 스택에서 빼서 새 큐에 넣는다 (뒤집힌 순서로 줄을 섬)
    while (buffer.Count > 0) result.Enqueue(buffer.Pop());

    return result;
}
```

> 2. 웹 브라우저의 [뒤로 가기] 기록 ➔ **`Stack`** (가장 마지막에 본 페이지부터 취소)

## 7. 주의사항 및 안전 습관

* **인덱스(`[]`) 접근 금지**: 스택과 큐는 중간에 있는 값을 빼거나 훔쳐보려는 순간 존재 의의가 사라집니다. 만약 중간 값을 찾아야 한다면 설계가 잘못된 것이니 당장 `List<T>`로 바꾸세요.
* **`Peek`과 `Pop/Dequeue` 혼동 주의**: 둘 다 같은 값을 돌려주므로 버그가 당장 안 보입니다. `Count`가 줄어야 하는 상황인지 확인하세요.
* **큐의 `Peek`은 맨 앞이다**: 스택의 `Peek`은 가장 최근에 넣은 것(맨 위)을 보여주지만, 큐의 `Peek`은 **가장 오래전에 넣은 것(맨 앞)** 을 보여줍니다. 이 방향성을 헷갈리지 마세요.
* **비어있는지 확인하는 습관**: `Pop`과 `Dequeue`를 부르기 전에는 무조건 `Count > 0`을 확인하거나 `Try` 짝꿍을 쓰세요.
