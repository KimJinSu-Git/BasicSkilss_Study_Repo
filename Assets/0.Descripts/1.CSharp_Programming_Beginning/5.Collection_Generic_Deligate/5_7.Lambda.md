# [컬렉션과 제네릭] 7. Lambda (람다식)

## 1. 람다(Lambda)란?
람다식은 메서드의 이름, 반환 타입 등을 다 떼어버리고 **`=>` (화살표)** 기호를 사용해 그 자리에서 즉석으로 함수를 만들어내는 '이름 없는 함수(Anonymous Function)'입니다.

> **정식 문서 vs 포스트잇**
> * **정식 메서드 (문서)** : `void OnClickStart()`처럼 이름(제목)을 붙이고, 클래스 내부에 고정된 자리를 차지하며 보관됩니다.
> * **람다식 (포스트잇)** : 짧은 지시사항을 **그 자리에 즉석으로 적어 붙입니다.**
> * **핵심** : 버튼 클릭이나 데이터 필터링처럼, 딱 한 번 쓰고 마는 짧은 함수를 만들 때 코드의 파편화를 막아줍니다.

**왜 필요한가?**
```csharp
void Start()
{
    // 정식 메서드로 분리하면, 이 버튼이 뭘 하는지 보려고 아래로 스크롤해야 합니다.
    button.onClick.AddListener(OnClickStart);
}
void OnClickStart() { Debug.Log("시작"); }
```
위 코드를 람다식으로 바꾸면 **코드의 흐름(맥락)이 완벽히 한곳에 모입니다.**
```csharp
button.onClick.AddListener(() => Debug.Log("시작"));
```
버튼이 10개일 때, 의미 없는 1줄짜리 잡동사니 함수 10개가 클래스를 어지럽히는 것을 막아줍니다.

## 2. 핵심 요약

| 개념            | 문법 형태 | 한 줄 설명 |
|:--------------| :--- | :--- |
| **입력이 없을 때**  | `() => Debug.Log("안녕");` | 빈 괄호 `()`로 시작 |
| **입력이 1개일 때** | `item => item.Price > 1000;` | 괄호 및 타입 생략 가능 |
| **입력이 여러 개**  | `(hp, max) => hp / max;` | 괄호로 묶어서 쉼표로 구분 |
| **여러 줄일 때**   | `() => { Play(); Log(); };` | 중괄호 `{ }`로 묶음 |
| **식 본문 멤버**   | `public int Damage => power * 2;` | 프로퍼티나 메서드 몸통을 람다 기호로 축약 |
| **함정**        | `OnHpChanged -= (hp) => ...` | **람다로 구독(`+=`)하면 절대 해제(`-=`)할 수 없음** |

## 3. 세부 개념 및 원리

### 3.1 읽는 법: `=>` ("받아서 ~한다")
`=>` 기호를 기준으로 **왼쪽이 '받는 값(매개변수)'**, **오른쪽이 '그 값으로 하는 일(반환 또는 실행)'** 입니다.
```csharp
(hp, maxHp) => hpBar.SetValue(hp / (float)maxHp)
```
*"hp와 maxHp를 **받아서**, 체력바 게이지를 갱신**한다**"* 라고 문장처럼 읽으면 됩니다.

### 3.2 델리게이트 변수에 람다 담기
앞 챕터에서 배운 `Action`, `Func` 델리게이트 그릇에 람다식을 바로 쏙 집어넣을 수 있습니다.
```csharp
// 입력도 반환도 없는 람다 -> Action
Action methodA = () => Debug.Log("methodA");
methodA.Invoke(); 

// int를 받아서 bool을 반환하는 람다 -> Func<int, bool> (조건식에 많이 쓰임)
Func<int, bool> isEven = (num) => num % 2 == 0;
bool check = isEven(4); // true
```

### 3.3 식 본문 멤버 (Expression-bodied Member)
메서드나 프로퍼티의 내용이 딱 1줄뿐이라면, 람다 화살표(`=>`)를 써서 극도로 짧게 줄일 수 있습니다. (※ 주의: 값을 저장해 두는 게 아니라 **부를 때마다 우측 연산을 재실행**합니다.)
```csharp
// 1. 프로퍼티의 축약 (get-only)
public string FullName => $"{FirstName} {LastName}"; 

// 2. 메서드의 축약
public int GetDouble(int value) => value * 2;
```

## 4. 주의사항 (면접 단골 질문)

### 4.1 람다로 구독하면 해제(`-=`)할 수 없다
유니티의 이벤트(`Action` 등)에 람다식을 던지면 매우 위험합니다.
```csharp
// ❌ 구독은 성공하지만 해제는 실패한다 (좀비 콜백, 메모리 누수 발생)
player.HpChanged += (hp) => Refresh(hp); 
player.HpChanged -= (hp) => Refresh(hp); // 글자만 같지, 완전히 다른 새로운 포스트잇임
```
컴파일러는 람다식을 볼 때마다 보이지 않는 새로운 익명 클래스와 메서드를 메모리에 계속 찍어냅니다. 즉 `+=` 할 때 붙인 포스트잇과 `-=` 할 때 떼려는 포스트잇은 서로 다른 객체입니다.\
**[해결책]** 해제(`-=`)가 필요한 이벤트라면 반드시 변수에 담아두거나 정식 메서드를 쓰세요.
```csharp
Action<int> handler = (hp) => Refresh(hp);
player.HpChanged += handler; // ⭕ 안전한 구독
player.HpChanged -= handler; // ⭕ 완벽한 해제 (같은 변수니까)
```

### 4.2 클로저 캡처 함정 (Closure Capture in `for` loop)
람다는 람다 바깥쪽에 있는 지역 변수를 포스트잇 내부로 끌고 들어와 쓸 수 있습니다. (이를 클로저라고 합니다.) 이때 **값이 아니라 '변수의 메모리 주소 자체'를 공유**합니다.
```csharp
// ❌ 버튼 3개를 눌러보면 전부 "3"만 출력됩니다
for (int i = 0; i < 3; i++) {
    buttons[i].onClick.AddListener(() => Debug.Log(i)); 
}
// 람다들은 i라는 하나의 변수를 같이 쳐다보고 있는데, 루프가 끝나면 i는 최종값인 3이 되어있기 때문입니다.

// ⭕ 올바른 방법: 반복문 안쪽에 지역 변수를 새로 파서 복사해 줍니다.
for (int i = 0; i < 3; i++) {
    int index = i; // 매 턴마다 새로운 메모리 공간에 값이 복사됨
    buttons[i].onClick.AddListener(() => Debug.Log(index)); 
}
```
*(참고: C# 5.0부터 `foreach`의 반복 변수는 회차마다 새로 만들어지도록 수정되어 안전하지만, `for`문은 여전히 이 버그가 발생합니다.)*

## 5. 실전 활용 예시 (람다와 LINQ의 파괴력)
람다식이 C#에 도입된 진짜 이유는 데이터 컬렉션에 **LINQ(Language Integrated Query)** 를 쓰기 위해서입니다.

```csharp
using System.Linq; // LINQ 사용을 위해 필수
using System.Collections.Generic;

public class Item { public string Name; public int Price; public bool IsWeapon; }

// 인벤토리에 아이템 5개가 있습니다.
List<Item> items = new List<Item> { /* ... */ };

// 기획자 요구사항: "무기 중에서 1000원 이상인 것만 비싼 순서대로 정렬해서, 그 이름들만 리스트로 뽑아줘"

// 람다(LINQ)가 없던 시절 (for문과 if문)
List<string> result = new List<string>();
foreach (var item in items) {
    if (item.IsWeapon && item.Price >= 1000) {
        result.Add(item.Name);
    }
}
// 정렬은 구현하기도 벅참...

// 람다와 LINQ (단 한 줄로 영어 읽듯이 끝)
List<string> result = items
    .Where(item => item.IsWeapon && item.Price >= 1000) // 필터링 (Func<Item, bool> 조건식 넘기기)
    .OrderByDescending(item => item.Price)              // 가격 기준 내림차순 정렬
    .Select(item => item.Name)                          // 이름만 추출
    .ToList();                                          // 다시 리스트로 묶기
```
> **람다식을 `Func` 대리자에 던지는 것만으로, 수십 줄의 코드를 한 줄의 우아한 데이터 파이프라인으로 바꿀 수 있습니다.**

## 6. Unity에서의 람다

### 6.1 람다는 이미 유니티 곳곳에 있습니다
1. **UI 버튼**: `button.onClick.AddListener(() => OpenShop());`
2. **이벤트 구독**: `player.OnDied += () => Debug.Log("게임 오버");` (해제 불필요 시)
3. **LINQ 필터링**: `enemies.Where(e => e.Hp > 0).ToList();` (살아있는 적만 추려내기)
4. **비동기/지연 타이머**: DOTween이나 코루틴에서 콜백 남길 때 `DOFade(0, 1f).OnComplete(() => Destroy(gameObject));`

### 6.2 팀 컨벤션: 람다를 언제 써야 할까?
* **람다를 쓰는 곳**: 코드가 1~3줄 이내이며, 이벤트 등록 해제(`-=`)를 할 필요가 없이 오브젝트와 수명을 함께하는 1회성 콜백일 때.
* **정식 메서드를 쓰는 곳**: 해제(`-=`)가 반드시 필요한 로직이거나, 코드가 너무 길어져서(4줄 이상) 중괄호 `{ }`가 비대해져 가독성을 해칠 때, 또는 여러 곳에서 중복으로 호출해야 할 때.

## 7. 실습 문제 및 복습

**Q1. 다음 `for`문 안에 있는 람다식이 가진 치명적 버그를 설명하고, 올바르게 고치세요.**
```csharp
for (int i = 0; i < 5; i++) {
    actionList.Add(() => Console.WriteLine(i)); 
}
```
> **설명**: 람다식이 `i` 변수를 값으로 복사하지 않고 참조(메모리 주소)로 포획(Closure Capture)합니다. 루프가 다 끝나면 `i`는 5가 되어 있으므로, 나중에 `actionList` 안의 함수들을 실행하면 전부 "5"만 출력됩니다.\
> **수정**: `for`문 안쪽에 `int temp = i;`로 지역변수를 새로 파서 람다식에 `temp`를 넘겨주어야 합니다.

**Q2. 다음 코드를 람다식(식 본문 멤버 `=>`)을 사용하여 단 1줄로 줄이세요.**
```csharp
public int Add(int a, int b) 
{
    return a + b;
}
```
> **답**: `public int Add(int a, int b) => a + b;`

**Q3. `Action<int, int>` 델리게이트 매개변수에 람다식을 익명으로 넘겨보세요. (출력 형태: "HP: {현재}/{최대}")**
```csharp
// Greet(Action<int, int> action) 함수가 있다고 가정할 때
Greet((current, max) => Console.WriteLine($"HP: {current}/{max}"));
```

## 8. 주의사항 및 안전 습관

* **람다 내부에 무거운 로직 금지**: 람다는 포스트잇입니다. 포스트잇에 소설을 쓰지 마세요. 코드가 길어지면 주저 없이 밖으로 빼서 정식 메서드로 만드세요.
* **`=>` 식 본문 멤버에 무거운 연산 금지**: `public Rigidbody2D Body => GetComponent<Rigidbody2D>();` 이렇게 쓰면, 다른 코드에서 `Body` 변수를 부를 때마다 `GetComponent`가 매번 무한 실행되어 렉을 유발합니다. 1번만 찾아서 담아두는 필드로 바꾸세요.
* **람다 내부에서 `this`의 수명 주의**: `Action` 람다식 내부에 자기 자신(`gameObject` 등)을 참조하면, 이 오브젝트가 파괴(`Destroy`)되어도 델리게이트가 살아있는 한 메모리에서 수거(GC)되지 않는 메모리 릭이 발생할 수 있습니다.
