# [C# 기초] 10. 메서드 (Method)

## 1. 메서드란? (Method)
메서드(Method)는 특정 작업을 수행하는 재사용 가능한 코드 묶음에 이름을 붙여둔 것입니다. 객체 지향 프로그래밍에서는 클래스 내부에 정의된 함수(Function)를 메서드라고 부릅니다.

> **비유 : 나만의 커피 주문 레시피**
> * **레시피 이름 (메서드 이름)** : `MakeCafeLatte`
> * **재료 (매개변수)** : 에스프레소 샷, 우유의 양
> * **만드는 과정 (메서드 본문)** : 샷을 내리고, 우유를 데우고, 섞는다.
> * **완성된 커피 (반환값)** : 카페라떼 한 잔

**왜 필요한가?**
1. **재사용성**: 똑같은 코드를 복붙할 필요 없이 메서드 이름만 호출하면 됩니다.
2. **가독성**: 30줄의 복잡한 수식보다 `CalculateFinalDamage()`라는 이름 한 줄이 의도를 명확하게 전달합니다.
3. **문제 분해**: 거대한 게임을 '이동', '공격', 'UI 갱신' 단위로 나누어 지능적으로 해결할 수 있습니다.

## 2. 핵심 요약

| 키워드 | 한 줄 설명 |
| :--- | :--- |
| **메서드 (Method)** | 이름이 붙은 재사용 가능한 코드 블록 |
| **매개변수 (Parameter)**| 메서드를 **정의**할 때 외부에서 받을 값을 선언한 변수 |
| **인자 (Argument)** | 메서드를 **호출**할 때 통로로 실제로 넘겨주는 값 |
| **반환값 (Return Value)**| `return` 키워드로 호출한 쪽에 돌려주는 결과 값 |
| **`void`** | 이 메서드는 돌려줄 반환값이 없다는 뜻의 키워드 |
| **오버로딩 (Overloading)**| 매개변수의 타입이나 개수가 다르면 **같은 이름의 메서드를 여러 개** 만들 수 있는 기능 |

## 3. 세부 개념 및 원리

### 3.1 수학의 $f(x)$와 메서드
수학 시간에 $f(x) = 3x + 1$ 이라고 쓰면, $x$ 자리에 $2$를 넣었을 때 $7$이 나온다는 약속입니다. 메서드는 이 약속을 코드로 적어 둔 것입니다.
```csharp
// 수학의 f(x) = 3x + 1 을 그대로 옮긴 메서드
int CalcY(int x)
{
    int result = 3 * x + 1; // 본문: 받은 값으로 계산한다
    return result;          // 계산 결과를 호출한 곳으로 돌려준다
}

int y = CalcY(2); // y 변수에는 7이 저장됨
```

### 3.2 메서드의 구조
```csharp
// [접근제한자] [반환타입] [메서드이름] ( [매개변수] )
public int Add(int a, int b)
{
    // 본문 (Body)
    int sum = a + b;
    return sum; // 반환 (Return)
}
```
* **접근제한자**: 이 메서드를 누가 부를 수 있는지 정합니다. (`public`은 누구나 호출 가능)
* **반환 타입**: 돌려줄 값의 자료형입니다. (`int`, `string`, `bool` 등). 없으면 `void`를 씁니다.
* **이름**: `PascalCase` (첫 글자 대문자) + 동사구로 짓습니다. (예: `CalculateDamage`)
* **매개변수**: 외부에서 재료를 받을 통로입니다. `(자료형 이름, ...)` 형태로 적습니다.

### 3.3 값 복사 (Pass by Value) 원칙
메서드에 인자를 넘길 때, C#은 원본 변수를 주지 않고 **'값만 복사'** 해서 넘깁니다.
```csharp
void AddTen(int number) 
{ 
    number = number + 10; // 복사본을 사용함
}

int myGold = 50;
AddTen(myGold); 
Console.WriteLine(myGold); // 여전히 50 원본은 안전하게 보호됩니다.
```

### 3.4 메서드 오버로딩 (Overloading)
매개변수의 형태(타입이나 개수)만 다르다면, **똑같은 이름의 메서드를 여러 개** 만들 수 있습니다. 컴파일러가 알아서 알맞은 메서드를 찾아갑니다.
```csharp
public int Add(int a, int b) { return a + b; }
public float Add(float a, float b) { return a + b; } // 이름이 같아도 OK!
```

## 5. 실전 활용 예시 (게임 도메인)

진입점(`Main` 메서드)만 읽어도 프로그램이 무슨 일을 하는지 한눈에 알 수 있습니다. **"메서드 이름이 곧 주석을 대신한다"** 는 점을 느껴보세요.

```csharp
class Program
{
    static void Main()
    {
        // 조립 — 호출자는 짧고 의도가 명확합니다.
        AnnounceBattleStart();
        
        bool isCrit = RollCritical();
        int dmg = CalculateDamage(50, 15, isCrit);
        
        AnnounceAttack("전사", "고블린", dmg);
    }

    static void AnnounceBattleStart()
    {
        Console.WriteLine("⚔전투가 시작되었습니다!");
    }

    // 단일 책임 원칙(SRP): 이 메서드는 오직 '데미지 계산'만 책임집니다.
    static int CalculateDamage(int atk, int def, bool isCritical)
    {
        int dmg = atk - def;
        if (dmg < 0) dmg = 0; // 음수 방어
        if (isCritical) dmg *= 2; // 크리티컬 적용
        
        return dmg;
    }

    static void AnnounceAttack(string attacker, string target, int dmg)
    {
        Console.WriteLine($"{attacker} ➔ {target}: {dmg}의 데미지를 입혔습니다.");
    }

    static bool RollCritical()
    {
        // 0~99 중 20 미만일 확률 -> 20%
        return Random.Shared.Next(0, 100) < 20; 
    }
}
```

## 6. Unity에서의 메서드

Unity에서 스크립트를 생성하면 처음부터 `Start()`, `Update()` 같은 메서드가 작성되어 있습니다.

```csharp
using UnityEngine;

public class Player : MonoBehaviour
{
    public int attackPower = 50;

    // 1. Unity 라이프사이클 메서드 — 엔진이 특정 타이밍에 '자동 호출' 해줍니다.
    void Start() { /* 시작할 때 1번 호출 */ }
    void Update() { /* 매 프레임 호출 */ }

    // 2. 일반 메서드 — 우리가 직접 만들고 직접 호출합니다.
    public int CalculateDamage(int targetDefense)
    {
        int dmg = attackPower - targetDefense;
        return Mathf.Max(0, dmg); // Unity의 수학 도우미 활용
    }

    // 3. 이벤트 핸들러 메서드 — 물리 충돌이 일어났을 때 엔진이 호출해 줍니다.
    void OnCollisionEnter(Collision col)
    {
        if (col.gameObject.TryGetComponent<Enemy>(out var enemy))
        {
            int dmg = CalculateDamage(enemy.defense);
            enemy.TakeDamage(dmg);
        }
    }
}
```

## 7. 실습 문제 및 복습

**Q1. `int[]` 배열을 받아 가장 큰 원소를 반환하는 `FindMax` 메서드를 작성하세요. 이때 최댓값을 담을 변수의 초기값은 무엇으로 해야 하며 이유는 무엇인가요?**
```csharp
public int FindMax(int[] numbers)
{
    // 초기값을 0으로 하면 배열 내에 음수만 있을 때 0이 최댓값으로 잘못 나옵니다.
    // 배열의 0번째 요소를 초기 기준으로 삼는 것이 가장 안전합니다.
    int max = numbers[0];           

    // 0번은 이미 기준이 되었으니 1번부터 비교를 시작합니다.
    for (int i = 1; i < numbers.Length; i++)   
    {
        if (max < numbers[i]) max = numbers[i];
    }
    return max;
}
```

**Q2. 아래 `CanEnterDungeon` 메서드는 "레벨 20 이상 **그리고** 1000골드 이상"이어야 입장 가능합니다. 논리 오류를 찾아 고치세요.**
```csharp
// 오답: 레벨만 20이 넘으면 골드를 검사하기도 전에 true로 통과해 버립니다! (OR처럼 동작함)
public bool BadCanEnterDungeon(int playerLevel, int playerGold)
{
    if (playerLevel >= 20) return true;     
    if (playerGold >= 1000) return true;
    return false;
}

// 정답: 두 조건을 모두 만족해야 하므로 AND(&&) 연산자를 사용해 깔끔하게 묶습니다.
public bool GoodCanEnterDungeon(int playerLevel, int playerGold)
{
    return playerLevel >= 20 && playerGold >= 1000;
}
```

**Q3. `SumAndMultiply(5, 3)` 처럼 합계와 곱셈을 동시에 하는 메서드는 무엇이 문제인가요?**
> **단일 책임 원칙(SRP) 위배**입니다. 메서드 이름에 `And`가 들어간다면, 한 메서드가 두 가지 이상의 일을 하고 있다는 경고 신호입니다.\
> `SumTo()`로 합계를 구하는 기능만 빼내고, 곱하기 연산은 이 메서드를 호출하는 쪽에서 처리하도록 분리하는 것이 좋습니다.

## 8. 주의사항 및 안전 습관

* **메서드가 20줄을 넘어가면 분리를 의심하라**: 한눈에 들어오지 않는 긴 코드는 버그의 온상이 됩니다. 논리적인 덩어리별로 메서드를 쪼개세요.
* **단일 책임 원칙 (SRP)**: "이 메서드는 무슨 일을 하나요?" 라고 물었을 때 "~~하고 ~~합니다"라고 대답하게 된다면 당장 메서드를 2개로 나누세요.
* **이미 존재하는 이름은 피하라**: `Math.Max`가 이미 있는데 내가 만든 메서드 이름을 `Max`로 지으면 읽는 사람이 헷갈립니다. 동사를 붙여 `FindMax`, `GetMax`처럼 명확하게 지어주세요.
* **네이밍 컨벤션**: C#에서 메서드 이름은 반드시 **PascalCase(첫 글자 대문자)**로 작성합니다! (`calculateDamage` ❌ ➔ `CalculateDamage` ⭕)
