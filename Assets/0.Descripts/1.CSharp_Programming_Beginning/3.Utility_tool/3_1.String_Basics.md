# [실용 도구] 1. 문자열 기초 (String Basics)

## 1. 문자열이란?
프로그래밍에서 문자열(`string`)은 `"Hello, World!"` 처럼 글자들의 연속을 다루는 데이터 타입입니다.\
C#에서 `string`은 단순한 텍스트 묶음이 아니라, **불변성(Immutability)** 이라는 매우 중요하고도 까다로운 특징을 가진 특별한 존재입니다.

> **한 번 새기면 끝인 돌판**
> * 돌판의 글자를 읽거나 다른 빈 돌판에 똑같이 복사본을 뜰 수는 있습니다.
> * 하지만 **이미 새겨진 돌판의 글자 일부만 지우고 덧쓰는 것은 절대 불가능**합니다.
> * 글자를 바꾸고 싶다면, 원하는 글자가 모두 새겨진 **완전히 새로운 돌판을 처음부터 다시 깎아야** 합니다. (그리고 옛날 돌판은 가비지 컬렉터가 버립니다.)

이러한 불변 특성 덕분에 C#의 문자열은 다중 스레드 환경에서도 예측 가능하고 안전하게 동작합니다. 텍스트를 표현하고 조작하는 가장 핵심 수단입니다.

---

## 2. 핵심 요약

| 특징 | 한 줄 설명                                                          |
| :--- |:----------------------------------------------------------------|
| **선언** | `"(큰따옴표)`로 둘러싸서 작성                                              |
| **타입** | 힙(Heap)에 저장되는 **참조 타입(Class)** 이지만, 동작은 **값 타입(Struct)** 처럼 안전함 |
| **불변성 (Immutability)**| **한 번 만들어진 객체는 절대 수정 불가.** (수정 시 새로운 객체가 힙에 생성됨)                |
| **메서드 특징** | `+`, `Replace()`, `ToUpper()` 등은 원본을 바꾸지 않고 **새 문자열 객체를 반환**함   |
| **주요 연산** | `+` (결합), `.Length` (길이), `[]` (인덱서 읽기 전용), `$"..."` (보간)       |

## 3. 세부 개념 및 문법

### 3.1 문자열 보간 (String Interpolation) - `$""`
과거에는 `+` 연산자로 텍스트와 변수를 힘들게 더했지만, 달러 기호(`$`)를 붙이면 중괄호 `{}` 안에 변수를 직접 넣어 깔끔하게 텍스트를 조립할 수 있습니다.
```csharp
string name = "Mage"; 
int level = 50; 
string info = $"[Lv.{level}] {name}"; // "[Lv.50] Mage"
```

### 3.2 이스케이프와 축자 문자열 (`@`)
문자열 안에 줄바꿈이나 큰따옴표 같은 특수 문자를 넣을 때는 이스케이프(`\`)를 씁니다.\
하지만 파일 경로나 정규식처럼 `\`가 많이 들어가는 경우, 문자열 앞에 `@`를 붙이면(축자 문자열) 쓰여진 그대로 인식합니다.
```csharp
string path1 = "C:\\Games\\MyGame"; // 일반 이스케이프
string path2 = @"C:\Games\MyGame";  // 축자 문자열 (가독성 상승)
```

### 3.3 문자열 리터럴 (`"""`) (C# 11+)
여러 줄의 텍스트나, 큰따옴표(`"`)가 잔뜩 들어간 JSON/HTML 데이터를 다룰 때는 따옴표 3개를 연달아 쓰는 방식을 추천합니다. 내부의 모든 특수문자를 있는 그대로 인식합니다.
```csharp
string jsonPayload = """
{
    "playerName": "광전사",
    "level": 99
}
""";
```

### 3.4 빈 문자열과 Null의 안전한 검사
`string`은 참조 타입이므로 `null`이 될 수 있습니다. 실무에서는 외부에서 텍스트를 입력받았을 때, 에러를 막기 위해 C#이 제공하는 전용 메서드로 유효성을 검사합니다.
```csharp
string input = Console.ReadLine();

// 1. null이거나 ""(길이가 0)인지 한 방에 검사
if (string.IsNullOrEmpty(input)) return; 

// 2. null이거나 ""이거나 "   "(공백만 가득한지)까지 한 방에 검사 (가장 많이 씀)
if (string.IsNullOrWhiteSpace(input)) return; 
```

## 4. 코드로 보는 문자열 조작

### 4.1 기본 연산
```csharp
string playerName = "Legendary Warrior";

// 1. 길이 구하기
int len = playerName.Length; // 17

// 2. 특정 위치의 문자 읽기 (0부터 시작)
char firstChar = playerName[0]; // 'L'

// 3. 문자열 잘라내기 (시작 인덱스, 가져올 개수)
string shortName = playerName.Substring(0, 9); // "Legendary"
```

### 4.2 흔한 실수와 올바른 사용법
```csharp
// ❌ 1. 인덱서로 직접 수정 시도
string greeting = "Hello";
// greeting[0] = 'h'; ➔ 컴파일 에러 : 돌판의 글자를 파낼 수 없음.

// ❌ 2. 메서드 반환값을 무시 (아무 일도 안 일어남)
string s = "World";
s.ToUpper(); 
Console.WriteLine(s); // "World" (원본은 절대 안 바뀜)

// ⭕ 올바른 해결책: 반환되는 새 문자열을 변수에 다시 덮어씌운다.
s = s.ToUpper(); 
Console.WriteLine(s); // "WORLD"

// ⭕ 체이닝(Chaining) 기법: 여러 변환을 한 줄로 깔끔하게 처리
string dirtyInput = "  MyName  ";
string cleanInput = dirtyInput.Trim().ToLower(); // 앞뒤 공백 제거 후 소문자로 (결과: "myname")
```

## 5. 실전 활용 예시 (킬 로그 생성기)

```csharp
public class LogGenerator
{
    public string CreateKillLog(string killer, string victim, string weapon)
    {
        // 삼항 연산자를 이용해 이름이 너무 길면 잘라내기
        string shortKiller = killer.Length > 5 ? killer.Substring(0, 5) + "..." : killer;

        // DateTime.Now 포맷팅 활용
        string time = DateTime.Now.ToString("HH:mm:ss");
        
        // 보간 문자열($)로 깔끔하게 조립
        string log = $"[{time}] [KILL] {shortKiller}이(가) {victim}을(를) {weapon}(으)로 처치";

        return log;
    }
}

// 실행 결과
// [12:34:56] [KILL] Legen...이(가) Goblin_5을(를) 낡은 검(으)로 처치
```

## 6. Unity에서의 문자열 다루기

Unity에서 가장 경계해야 할 것이 `Update()` 문 안에서의 문자열 연산입니다.

```csharp
using UnityEngine;
using TMPro;

public class HUD : MonoBehaviour
{
    [SerializeField] private TMP_Text playerNameText;
    public string playerName = "Player";
    public int level = 1;
    public int hp = 100, maxHp = 100;

    void Update()
    {
        // 최악의 패턴: 매 프레임마다 무의미하게 새로운 문자열 객체를 생성(힙 할당)하여 GC 스파이크 유발
        // playerNameText.text = $"{playerName} Lv.{level} ({hp}/{maxHp})";
    }

    // ⭕ 올바른 패턴: 체력이나 레벨 등 '데이터가 변했을 때만' 텍스트를 갱신하도록 분리
    public void OnHealthChanged()
    {
        playerNameText.text = $"{playerName} Lv.{level} ({hp}/{maxHp})";
        
        if (hp < maxHp * 0.2f)
        {
            Debug.LogWarning($"[Player] {playerName} 체력 위급!");
        }
    }
}
```
> **Unity 최적화 팁**: 반복문 내부나 `Update`에서 문자열을 `+` 로 더하거나 `$""` 보간을 사용하면, 돌판(string)을 부수고 새로 깎는 작업이 매 프레임 일어나 프레임 드랍이 발생합니다. `StringBuilder`가 이 문제를 해결해 줍니다!

## 7. 실습 문제 및 복습

**Q1. `string`의 가장 중요한 특징은 무엇이며, 이로 인해 문자열을 조작할 때 내부적으로 어떤 일이 일어나나요?**
> 가장 중요한 특징은 **불변성(Immutability)** 입니다. 문자열을 결합하거나 자르거나 바꾸는 모든 행위(`+`, `Replace` 등)는 원본 데이터를 수정하는 것이 아니라, 메모리(힙)에 **새로운 문자열 객체를 만들어 반환**합니다. 기존 문자열은 가비지 컬렉터(GC)에 의해 수거됩니다.

**Q2. 아래 코드는 0부터 999까지의 숫자를 하나로 이어붙입니다. 왜 비효율적인지 설명하고, 대안을 제시하세요.**
```csharp
string result = "";
for (int i = 0; i < 1000; i++)
    result = result + i.ToString();
```
> **원인**: 루프를 1000번 도는 동안 `result + i`가 실행될 때마다 힙 메모리에 새로운 문자열 객체가 1000번 생성되고 999번 버려집니다. 최악의 성능 저하와 GC 스파이크를 유발합니다.\
> **대안**: 텍스트를 대량으로 조립할 때는 불변성 제약이 없는 **`StringBuilder`** 를 사용해야 합니다.

**Q3. 외부에서 입력받은 `string input`에 대해, 내용이 아예 없거나 띄어쓰기만 가득한 뻘글인지 한 번에 확인하는 C# 내장 메서드는?**
> `if (string.IsNullOrWhiteSpace(input))`\
> (`null` 참조 에러, 빈 문자열 `""`, 공백 `"   "`을 한 줄로 모두 차단하는 메서드입니다.)

## 8. 주의사항 및 안전 습관

* **`s = s.Method()` 패턴을 외워라**: 문자열 변환 메서드(`Replace`, `ToUpper` 등)는 호출만 한다고 원본이 바뀌지 않습니다. 반드시 반환되는 새 문자열을 다시 변수에 담아야 합니다.
* **`+` 연산자는 2~3개까지만**: 여러 개의 문자열을 조립할 때는 `+` 보다 보간(`$""`)을 쓰고, 반복문 안에서는 무조건 `StringBuilder`를 쓰세요.
* **경로 복사/붙여넣기 할 때는 `@`나 `"""` 활용**: 파일 경로나 JSON 텍스트를 다룰 때 이스케이프(`\`) 에러로 고통받지 마세요.
* **배열이나 리스트의 상태 출력은 `string.Join`**: 루프를 돌며 일일이 더하지 말고 `Console.WriteLine(string.Join(", ", array));` 한 줄로 깔끔하게 처리하세요.
